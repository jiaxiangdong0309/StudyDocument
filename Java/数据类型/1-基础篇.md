# Java 数据类型基础篇（Android 视角）

> 很多人把“数据类型”当成最基础、最不值得花时间的部分，但 Android 里很多性能问题、空指针问题、建模问题，本质上都是数据类型没选好。

## 一、为什么会有数据类型？

计算机处理数据，得先知道这份数据到底是什么：

- 是整数，还是小数？
- 是真/假状态，还是一段文本？
- 是一个具体值，还是指向对象的引用？

如果没有类型，程序就像一个什么都往里塞的抽屉：能塞，但拿出来的时候很容易乱。

### Android 里的现实场景

比如一个文章列表页：

```kotlin
data class ArticleUiModel(
    val id: Long,
    val title: String,
    val liked: Boolean,
    val commentCount: Int,
    val coverUrl: String?
)
```

这几个字段为什么不是都写成 `String`？

因为它们语义不同：

- `id` 是唯一标识，适合整数
- `liked` 是状态位，适合 `Boolean`
- `commentCount` 要做加减比较，适合 `Int`
- `coverUrl` 可能为空，适合可空引用类型

**数据类型的本质，就是给数据加上“身份标签”和“操作边界”。**

## 二、Java 数据类型总览

Java 数据类型分两大类：

| 类别 | 包含内容 | 特点 |
|---|---|---|
| **基本类型** | `byte`、`short`、`int`、`long`、`float`、`double`、`char`、`boolean` | 值本身直接参与计算，轻量、高效 |
| **引用类型** | 类、接口、数组、枚举、注解、`String` 等 | 变量里存的是“引用”，对象本体一般在堆上 |

可以先粗暴理解成：

- **基本类型**：手里直接拿的是货
- **引用类型**：手里拿的是仓库地址

## 三、8 种基本数据类型

### 3.1 整体表格

| 类型 | 大小 | 默认值 | 适合场景 | Android 常见用途 |
|---|---:|---|---|---|
| `byte` | 1 字节 | `0` | 小范围整数 | 二进制协议、图片/音频字节流 |
| `short` | 2 字节 | `0` | 较少单独使用 | 音频 PCM 数据、底层数据解析 |
| `int` | 4 字节 | `0` | 最常用整数 | position、count、状态码 |
| `long` | 8 字节 | `0L` | 大整数 | 数据库 id、时间戳 |
| `float` | 4 字节 | `0.0f` | 单精度小数 | 动画参数、图形计算 |
| `double` | 8 字节 | `0.0d` | 高精度小数 | 金融/高精度计算（Android 业务中相对少） |
| `char` | 2 字节 | `'\u0000'` | 单个字符 | 字符处理 |
| `boolean` | 规范未严格定义 JVM 存储大小 | `false` | true / false 状态 | 开关位、登录态、权限态 |

### 3.2 最常用的是哪几个？

Android 业务开发里，最常见的是：

- `int`
- `long`
- `boolean`
- `float`

原因很简单：

- `int` 适合计数、索引、状态码
- `long` 适合 id 和时间戳
- `boolean` 适合开关和状态
- `float` 常用于 UI、动画、绘制

### 3.3 一个经验法则

**整数默认优先考虑 `int`，只有在范围不够时再用 `long`。**

比如：

```kotlin
val page = 1          // Int
val totalCount = 120  // Int
val userId = 998877665544L // Long
val createTime = System.currentTimeMillis() // Long
```

因为 `int` 在 CPU、内存、JIT 优化层面通常都是最自然的选择。

## 四、引用类型是什么？

引用类型包括：

- 普通类：`User`、`Article`
- 字符串：`String`
- 数组：`IntArray`、`Array<String>`
- 集合：`List<String>`、`Map<Int, User>`
- 接口、枚举、注解等

### 4.1 引用类型的关键特点

引用变量里存的不是对象内容本体，而是对象位置的“引用”。

```kotlin
val name: String = "Android"
val list = arrayListOf("A", "B", "C")
```

这里：

- `name` 本身不是字符串对象本体
- `list` 本身也不是整个数组列表本体
- 它们保存的是“指向对象的引用”

### 4.2 基本类型 vs 引用类型

| 对比项 | 基本类型 | 引用类型 |
|---|---|---|
| 保存内容 | 值本身 | 对象引用 |
| 是否可为 `null` | 不可以 | 可以 |
| 默认是否有对象分配 | 没有 | 往往关联对象创建 |
| 性能 | 更轻量 | 往往更重 |
| Android 建议 | 状态位、计数、索引优先用基本类型 | 复杂结构、可空语义才用引用类型 |

## 五、成员变量、局部变量、默认值

### 5.1 成员变量有默认值

```java
class UserState {
    int page;
    boolean loading;
    String title;
}
```

默认值分别是：

- `page = 0`
- `loading = false`
- `title = null`

### 5.2 局部变量没有默认值

```java
void test() {
    int count;
    // System.out.println(count); // 编译报错：变量未初始化
}
```

这点在面试里很常见，但更重要的是理解设计意图：

- 成员变量属于对象状态，JVM 会给默认初始值
- 局部变量属于方法内部临时状态，必须明确赋值，避免脏数据

### Android 里的意义

在 `Activity` 或 `ViewModel` 里：

```kotlin
class FeedViewModel : ViewModel() {
    private var page = 0
    private var isLoading = false
    private var keyword: String? = null
}
```

这种显式初始化虽然不是强制的，但非常推荐，因为代码意图更清晰。

## 六、包装类型：为什么会有 `Integer`、`Long`、`Boolean`？

Java 既有：

- `int`
- `long`
- `boolean`

又有：

- `Integer`
- `Long`
- `Boolean`

包装类型的意义，不是“再造一遍基本类型”，而是为了让基本值进入**面向对象世界**。

### 6.1 为什么需要包装类型？

因为很多 Java 能力都只接受对象，不接受基本类型，比如：

- 泛型
- 集合
- 反射
- 某些框架 API

例如：

```java
List<Integer> ids = new ArrayList<>();
ids.add(1);
ids.add(2);
```

这里不能写成：

```java
// 错误写法
List<int> ids = new ArrayList<>();
```

### 6.2 包装类型和基本类型怎么选？

| 场景 | 推荐 |
|---|---|
| 一定有值，且频繁计算 | 基本类型 |
| 需要放到泛型/集合里 | 包装类型 |
| 需要表达“可能为空” | 包装类型 |
| ORM/JSON 字段可能缺失 | 包装类型更常见 |

### Android 里的典型例子

```kotlin
data class UserDto(
    val id: Long?,
    val age: Int?,
    val vip: Boolean?
)
```

接口返回的数据可能缺字段，所以 DTO 层常用包装语义（在 Kotlin 里体现为可空类型）。

但到了 UI 或业务层，通常会转成更稳定的模型：

```kotlin
data class UserUiModel(
    val id: Long,
    val age: Int,
    val vip: Boolean
)
```

这就是“网络层允许不确定，业务层尽量收敛确定”。

## 七、自动装箱与拆箱：最容易被忽略的坑

### 7.1 什么是装箱？

```java
Integer a = 10; // 自动装箱，本质是 Integer.valueOf(10)
```

把基本类型 `int` 变成包装类型 `Integer`，叫**装箱**。

### 7.2 什么是拆箱？

```java
Integer a = 10;
int b = a; // 自动拆箱，本质是 a.intValue()
```

把包装类型还原成基本类型，叫**拆箱**。

### 7.3 Android 里为什么要警惕？

因为装箱会带来：

- 额外对象语义
- 可能的 GC 压力
- 拆箱时的空指针风险

```kotlin
val count: Int? = null
// val result = count + 1 // Kotlin 编译期就帮你拦了
```

如果换成 Java：

```java
Integer count = null;
int result = count + 1; // 拆箱时 NPE
```

### 7.4 一个典型性能场景

```java
List<Integer> numbers = new ArrayList<>();
for (int i = 0; i < 10000; i++) {
    numbers.add(i); // 不断装箱
}
```

如果这段逻辑在高频调用路径里，比如：

- 埋点组装
- 大列表数据变换
- 图片索引处理
- 布局计算

那就会产生不必要的对象压力。

## 八、数值类型之间的转换

### 8.1 自动类型提升

小范围类型参与运算时，通常会先提升到 `int`。

```java
byte a = 1;
byte b = 2;
int c = a + b;
```

注意：`a + b` 的结果是 `int`，不是 `byte`。

### 8.2 强制类型转换

```java
int value = 130;
byte result = (byte) value;
```

这会发生截断。

### 8.3 Android 开发中的注意点

#### 场景 1：dp / px 转换

```kotlin
val px = (16 * resources.displayMetrics.density).toInt()
```

这里小数转整数，本质上就涉及类型转换和精度损失。

#### 场景 2：时间戳

```kotlin
val time = System.currentTimeMillis() // Long
```

不要随手转成 `Int`，很容易溢出。

#### 场景 3：JSON 数字解析

后端给的字段可能是：

- `1`
- `1.0`
- `99999999999`

如果本地模型类型定义得太死，解析时就容易出问题。

## 九、`==`、`equals()`、值比较

这是数据类型里最容易“知其然不知其所以然”的部分。

### 9.1 基本类型的 `==`

基本类型用 `==` 比较的是**值**。

```java
int a = 10;
int b = 10;
System.out.println(a == b); // true
```

### 9.2 引用类型的 `==`

引用类型用 `==` 比较的是**是不是同一个对象引用**。

```java
String a = new String("abc");
String b = new String("abc");
System.out.println(a == b); // false
```

### 9.3 `equals()` 比较的是“内容是否相等”

```java
System.out.println(a.equals(b)); // true
```

### Android 实战建议

#### 比较字符串，不要偷懒

```kotlin
val currentTab = "home"
if (currentTab == "home") {
    // Kotlin 里的 == 会转成 equals，比 Java 更安全
}
```

但如果你在看 Java 源码或写 Java 工具类，必须牢牢记住：

- `==`：比较引用或基本值
- `equals()`：比较对象语义内容

## 十、`String` 为什么很特殊？

`String` 是引用类型，但它又和普通对象不太一样。

原因在于：

- 不可变
- 有字符串常量池
- 使用非常高频

### 10.1 不可变的好处

- 线程安全
- 可缓存 hash
- 可作为 `HashMap` key
- 安全性更高

### 10.2 Android 里的意义

例如：

- 路由 path
- Bundle key
- SharedPreferences key
- 网络参数 key

这些 key 必须稳定，不然哈希结构会出问题。

## 十一、值传递：Java 永远都是值传递

这句话很多人背过，但没真正懂。

### 11.1 基本类型传的是值副本

```java
void addOne(int x) {
    x++;
}
```

调用后，原变量不变。

### 11.2 引用类型传的是“引用的副本”

```java
void rename(User user) {
    user.name = "新名字";
}
```

这不是“引用传递”，而是“把引用复制一份传进去”。

所以：

- 你可以通过这份引用副本修改对象内容
- 但你不能通过修改参数本身，让外部变量指向新对象

### Android 中的常见误区

比如把列表传进方法：

```kotlin
fun clearData(list: MutableList<String>) {
    list.clear()
}
```

外部列表会被清空，因为你操作的是同一个列表对象。

但如果你在方法里重新赋值：

```kotlin
fun resetList(list: MutableList<String>) {
    // list = mutableListOf() // Kotlin 参数不可重新赋值；Java 里重新赋值也不影响外部
}
```

外部变量并不会跟着变。

## 十二、Android 开发中的类型选择经验

### 12.1 经验 1：状态位优先用 `boolean`

```kotlin
var isLoading = false
var isLogin = true
```

不要用：

```kotlin
var loginState = 0 // 0/1 可读性差
```

除非你的状态确实不止两种。

### 12.2 经验 2：id 和时间戳优先 `long`

```kotlin
val messageId: Long
val timestamp: Long
```

因为：

- 数据库主键常常增长很大
- 毫秒时间戳本来就是 `long`

### 12.3 经验 3：热路径尽量少装箱

例如列表滚动、动画计算、批量遍历这些地方，尽量避免无意义的包装对象创建。

### 12.4 经验 4：DTO 可空，领域模型尽量非空

这是 Android 项目里非常实用的一条：

- 网络返回层：接受不稳定现实
- 业务模型层：收敛成稳定结构
- UI 层：尽量拿到“可直接渲染”的数据

## 十三、本篇小结

你现在至少要建立这几个核心认知：

1. Java 数据类型分为**基本类型**和**引用类型**
2. 基本类型更轻量，适合高频计算和确定值场景
3. 包装类型是为了进入对象世界，也能表达 `null`
4. 自动装箱/拆箱很方便，但有性能和空指针代价
5. `==` 和 `equals()` 的语义完全不同
6. Java 永远是**值传递**
7. 在 Android 里，数据类型选型不是语法题，而是性能题、稳定性题、建模题

## 面试题（基础篇）

### 1. Java 有哪些基本数据类型？
**结论**：有 8 种，分别是 `byte`、`short`、`int`、`long`、`float`、`double`、`char`、`boolean`。

**原理**：它们不是对象，表示的是最基础的值类型，用于高效计算和存储。

**Android 例子**：`RecyclerView` 的位置索引常用 `int`，时间戳和数据库 id 常用 `long`。

### 2. `int` 和 `Integer` 有什么区别？
**结论**：`int` 是基本类型，`Integer` 是包装类型。

**原理**：`int` 更轻量，不能为 `null`；`Integer` 是对象，支持泛型和空值语义。

**Android 例子**：接口字段可能缺失时，DTO 层更适合用 `Integer?` / `Int?` 语义。

### 3. 为什么 `String` 用 `==` 经常出问题？
**结论**：因为引用类型的 `==` 比较的是地址，不一定比较内容。

**原理**：两个内容相同的字符串对象，可能不是同一个引用。

**Android 例子**：判断路由 path、tab 标识、接口状态字符串时，应该比较内容而不是引用。

### 4. 自动拆箱为什么可能触发空指针？
**结论**：因为包装类型为 `null` 时，拆箱要调用诸如 `intValue()`，会直接 NPE。

**原理**：自动拆箱本质是编译器帮你补了方法调用。

**Android 例子**：接口返回的可空数值字段如果直接参与运算，就可能在业务层崩溃。

### 5. Java 是值传递还是引用传递？
**结论**：Java 只有值传递。

**原理**：传基本类型时传的是值副本；传对象时传的是引用副本。

**Android 例子**：把 `MutableList` 传给方法后在方法内 `clear()`，外部列表会受影响，因为操作的是同一个对象。
