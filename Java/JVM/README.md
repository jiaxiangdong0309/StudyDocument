# JVM（Java Virtual Machine）—— Android 视角

> 作为 Android 开发者，学 JVM 不是为了背八股，而是为了理解 ART 虚拟机、优化 App 内存、排查 OOM 问题。

## 为什么 Android 开发者要学 JVM？

```
学 JVM 内存结构  →  理解 Android Profiler 中的 Java Heap
学 GC 原理      →  知道 GC 为什么会导致卡顿，如何避免
学 类加载机制   →  理解热修复（Tinker）、插件化（RePlugin）的实现原理
学 对象创建     →  理解 ViewHolder 复用、Message.obtain() 的设计智慧
学 引用类型     →  理解 WeakReference 在内存泄漏排查中的应用
```

## JVM vs ART 速查表

| 特性 | JVM (HotSpot) | ART (Android) |
|-----|---------------|---------------|
| 字节码 | .class | .dex |
| 编译方式 | JIT | AOT + JIT |
| GC STW | 较长 | 2-3ms |
| 启动速度 | 慢（需预热） | 快（AOT 预编译） |

## 一句话总结

**堆放对象，栈放变量，方法区放类；GC 回收垃圾，泄漏就是该回收却回收不了。**

## Android 内存优化核心原则

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    Android 内存优化三板斧                                │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                         │
│  1️⃣ 减少创建：对象能复用就复用（ViewHolder、对象池、Message.obtain）     │
│                                                                         │
│  2️⃣ 及时释放：用完就释放（Bitmap.recycle、close 资源、注销监听器）        │
│                                                                         │
│  3️⃣ 避免泄漏：注意引用关系（static、匿名内部类、单例持有 Context）        │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```
