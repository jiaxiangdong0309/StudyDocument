# Java 注解（Annotation）

> 注解是 Java 的"元数据标签"——给代码贴上说明书，让编译器、工具和框架能够读懂开发者的意图。

## 为什么要学注解？

| 应用场景 | 说明 |
|---------|------|
| **框架配置** | Spring Boot、MyBatis 等现代框架几乎完全基于注解配置 |
| **代码生成** | Lombok、MapStruct 等工具通过注解自动生成代码 |
| **编译检查** | `@Override`、`@Deprecated` 等帮助编译器发现错误 |
| **运行时处理** | 反射读取注解实现 AOP、依赖注入、序列化等功能 |
| **文档生成** | Javadoc、Swagger 等通过注解生成 API 文档 |

**重要程度**：⭐⭐⭐⭐⭐（现代 Java 开发必备，框架基石）

## 核心问题预览

### 基础篇
1. 什么是注解？注解和注释有什么区别？
2. 四个元注解（`@Target`、`@Retention`、`@Documented`、`@Inherited`）分别有什么作用？
3. 如何定义和使用自定义注解？
4. `RetentionPolicy` 的三个级别（SOURCE、CLASS、RUNTIME）有什么区别？

### 进阶篇
1. 编译时注解处理器（APT）是如何工作的？
2. 运行时如何通过反射读取注解信息？
3. Spring 中的 `@Autowired`、`@Transactional` 是如何实现的？
4. Lombok 的 `@Data` 是如何自动生成代码的？

### 源码篇
1. 注解在字节码中是如何存储的？
2. 为什么注解的属性只能是基本类型、String、Class、枚举、注解或它们的数组？
3. `AnnotatedElement` 接口的设计有什么妙处？
4. 注解的动态代理实现机制是什么？

## 注解的发展历史

| 版本 | 重要更新 |
|-----|---------|
| **JDK 5** | 引入注解机制，提供 `@Override`、`@Deprecated`、`@SuppressWarnings` |
| **JDK 6** | 引入 Pluggable Annotation Processing API（JSR 269） |
| **JDK 7** | 引入 `@SafeVarargs` |
| **JDK 8** | 引入 `@FunctionalInterface`、类型注解（`@Target(ElementType.TYPE_USE)`）、可重复注解（`@Repeatable`） |
| **JDK 9+** | 模块化对注解处理的影响 |
