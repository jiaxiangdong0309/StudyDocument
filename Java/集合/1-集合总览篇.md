# Java 集合总览篇

> 在深入每一种集合之前，先把整体地图建立起来。搞清楚 Java 集合框架的分层结构、底层依赖的数据结构，以及选型时真正在比较什么。

---

## 一、Java 集合框架整体结构

Java 集合框架（Java Collections Framework，JCF）分为两大阵营：

```
java.util
├── Collection（单值集合）
│   ├── List（有序、可重复）
│   │   ├── ArrayList
│   │   ├── LinkedList
│   │   └── Vector
│   ├── Set（无序、不可重复）
│   │   ├── HashSet
│   │   ├── LinkedHashSet
│   │   └── TreeSet
│   └── Queue（队列）
│       ├── LinkedList
│       ├── PriorityQueue
│       └── ArrayDeque
└── Map（键值对）
    ├── HashMap
    ├── LinkedHashMap
    ├── TreeMap
    ├── Hashtable
    └── ConcurrentHashMap
```

**为什么分 Collection 和 Map 两大阵营？**

- `Collection` 存的是单个元素，关注"一组值"
- `Map` 存的是键值对，关注"映射关系"

两者设计目标不同，接口自然分开。

## 二、底层数据结构

Java 集合的所有实现，底层都依赖这几种基础数据结构：

### 1. 数组（Array）

```
index:  0    1    2    3    4
value: [10] [20] [30] [40] [50]
```

**优点：**
- 随机访问 O(1)，通过下标直接定位
- 内存连续，CPU 缓存命中率高，实际性能好

**缺点：**
- 插入/删除需要移动元素，中间插入 O(n)
- 长度固定，扩容需要新建数组并复制

**代表集合：** `ArrayList`、`Vector`

---

### 2. 链表（LinkedList）

```
[10 | next] → [20 | next] → [30 | next] → null
```

双向链表还有 prev 指针：

```
null ← [prev | 10 | next] ↔ [prev | 20 | next] ↔ [prev | 30 | next] → null
```

**优点：**
- 插入/删除只需修改指针，O(1)（前提是已知节点位置）
- 不需要连续内存，动态扩展无需复制

**缺点：**
- 随机访问 O(n)，必须从头遍历
- 每个节点额外存储指针，内存开销更大
- 内存不连续，CPU 缓存不友好，实际性能往往比数组差

**代表集合：** `LinkedList`

---

### 3. 哈希表（Hash Table）

核心思想：用哈希函数把 key 映射到数组下标，实现 O(1) 的存取。

```
key → hashCode() → 取模 → 数组下标 → 存/取 value
```

```
index: 0    1    2    3    4    5    6    7
       [  ] [K1] [  ] [K2] [  ] [K3] [  ] [  ]
```

**优点：**
- 查找、插入、删除平均 O(1)
- 非常适合做缓存、索引、去重

**缺点：**
- 哈希碰撞（两个不同 key 映射到同一下标）需要额外处理
- 不保证顺序
- 最坏情况退化为 O(n)

**代表集合：** `HashMap`、`HashSet`、`Hashtable`

---

### 4. 红黑树（Red-Black Tree）

一种自平衡二叉搜索树，保证树的高度在 O(log n) 级别。

```
        [黑: 20]
       /         \
   [红: 10]    [红: 30]
   /     \     /     \
 [黑:5] [黑:15] [黑:25] [黑:35]
```

**优点：**
- 查找、插入、删除都是 O(log n)
- 天然有序，支持范围查询

**缺点：**
- 实现复杂，旋转操作有额外开销
- 比哈希表慢（O(log n) vs O(1)）

**代表集合：** `TreeMap`、`TreeSet`，以及 Java 8 后 `HashMap` 链表过长时的转换结构

---

### 5. 数组 + 链表/红黑树（复合结构）

`HashMap` 的底层就是这种复合结构：

```
数组（桶）
index 0: → null
index 1: → [K1,V1] → [K2,V2]   ← 链表（碰撞时）
index 2: → null
index 3: → [红黑树节点]          ← 链表长度 ≥ 8 时转红黑树
...
```

## 三、各数据结构复杂度对比

| 操作 | 数组 | 链表 | 哈希表（平均） | 红黑树 |
|------|------|------|--------------|--------|
| 随机访问 | O(1) | O(n) | O(1) | O(log n) |
| 头部插入 | O(n) | O(1) | - | - |
| 尾部插入 | O(1)* | O(1) | - | - |
| 中间插入 | O(n) | O(1)** | - | - |
| 查找 | O(n) | O(n) | O(1) | O(log n) |
| 删除 | O(n) | O(1)** | O(1) | O(log n) |
| 是否有序 | 是 | 是 | 否 | 是 |

> *数组尾部插入均摊 O(1)，扩容时 O(n)
> **链表插入/删除前提是已知节点引用，若需先查找则是 O(n)

## 四、Collection 接口体系

```
Iterable
  └── Collection
        ├── List        有序、可重复、支持下标访问
        ├── Set         无序（TreeSet 有序）、不可重复
        └── Queue       队列，FIFO 或优先级
              └── Deque 双端队列，可当栈用
```

**核心接口方法：**

```java
// Collection 通用方法
boolean add(E e)
boolean remove(Object o)
boolean contains(Object o)
int size()
void clear()
Iterator<E> iterator()

// List 额外方法
E get(int index)
E set(int index, E element)
void add(int index, E element)
int indexOf(Object o)

// Map 独立接口
V put(K key, V value)
V get(Object key)
boolean containsKey(Object key)
Set<K> keySet()
Collection<V> values()
Set<Map.Entry<K,V>> entrySet()
```

## 五、选型思维

遇到"用哪个集合"的问题，按这个顺序思考：

```
需要键值对映射？
  ├── 是 → 用 Map
  │         ├── 需要排序？ → TreeMap
  │         ├── 需要插入顺序？ → LinkedHashMap
  │         ├── 需要线程安全？ → ConcurrentHashMap
  │         └── 普通场景 → HashMap
  └── 否 → 用 Collection
            ├── 需要去重？ → Set
            │     ├── 需要排序？ → TreeSet
            │     ├── 需要插入顺序？ → LinkedHashSet
            │     └── 普通场景 → HashSet
            └── 允许重复？ → List
                  ├── 频繁随机访问？ → ArrayList
                  ├── 频繁头部插入/删除？ → LinkedList（或 ArrayDeque）
                  └── 需要线程安全？ → CopyOnWriteArrayList
```

## 六、null 支持与线程安全速查

| 集合 | null key | null value | 线程安全 |
|------|----------|------------|----------|
| ArrayList | - | 允许 | 否 |
| LinkedList | - | 允许 | 否 |
| Vector | - | 允许 | 是（synchronized）|
| HashSet | 允许（1个）| - | 否 |
| LinkedHashSet | 允许（1个）| - | 否 |
| TreeSet | 不允许 | - | 否 |
| HashMap | 允许（1个）| 允许 | 否 |
| LinkedHashMap | 允许（1个）| 允许 | 否 |
| TreeMap | 不允许 | 允许 | 否 |
| Hashtable | 不允许 | 不允许 | 是（synchronized）|
| ConcurrentHashMap | 不允许 | 不允许 | 是（分段锁）|

## 七、小结

| 数据结构 | 核心优势 | 核心劣势 | 对应集合 |
|----------|----------|----------|----------|
| 数组 | 随机访问快 | 插入删除慢、固定大小 | ArrayList |
| 链表 | 插入删除快 | 随机访问慢、内存开销大 | LinkedList |
| 哈希表 | 存取 O(1) | 无序、哈希碰撞 | HashMap、HashSet |
| 红黑树 | 有序、O(log n) | 实现复杂、比哈希慢 | TreeMap、TreeSet |

理解了这四种底层结构，集合的所有行为差异都能解释清楚。
