# Java 泛型 — 基础篇

## 一、为什么需要泛型？

### 技术演进：从"万能容器"到"类型安全容器"

Java 1.5 之前，集合类只能存 `Object`：

```java
// Java 1.4 时代的写法（理解历史用）
List list = new ArrayList();
list.add("hello");
list.add(123);  // 编译不报错！

// 取出时必须强转，一不小心就 ClassCastException
String s = (String) list.get(1);  // 运行时崩溃！
```

这就像一个"万能抽屉"——什么都能放，但取出来不知道是什么，用之前必须猜。

泛型的出现，让编译器帮你检查类型：

```kotlin
// Kotlin（Android 开发实际写法）
val list: MutableList<String> = mutableListOf()
list.add("hello")
// list.add(123)  // 编译直接报错，问题在编译期暴露

val s: String = list[0]  // 不需要强转，类型安全
```

**Android 视角**：`LiveData<User>` 就是泛型的典型应用——你声明持有的是 `User` 类型，观察者拿到的就一定是 `User`，不需要强转，也不会类型错误。

## 二、泛型基础语法

### 2.1 泛型类

```kotlin
// Kotlin 泛型类：类型安全的"盒子"
class Box<T>(val value: T) {
    fun get(): T = value
}

// 使用
val stringBox = Box("Hello Android")
val intBox = Box(42)

val s: String = stringBox.get()  // 类型安全，无需强转
```

**Android 真实场景**：`MutableStateFlow<T>` 就是这种泛型类的设计：

```kotlin
// ViewModel 中用泛型持有 UI 状态
class ArticleViewModel : ViewModel() {
    // MutableStateFlow<T> 是泛型类，T = UiState
    private val _uiState = MutableStateFlow<UiState>(UiState.Loading)
    val uiState: StateFlow<UiState> = _uiState.asStateFlow()

    fun loadArticles() {
        viewModelScope.launch {
            _uiState.value = UiState.Loading
            val result = repository.getArticles()
            // 编译器保证这里只能赋值 UiState 类型
            _uiState.value = UiState.Success(result)
        }
    }
}

sealed class UiState {
    object Loading : UiState()
    data class Success(val articles: List<Article>) : UiState()
    data class Error(val message: String) : UiState()
}
```

### 2.2 泛型方法

```kotlin
// 泛型方法：方法级别的类型参数
fun <T> List<T>.secondOrNull(): T? {
    return if (size >= 2) this[1] else null
}

// 使用：类型自动推断
val articles: List<Article> = getArticles()
val second: Article? = articles.secondOrNull()  // T 推断为 Article
```

**Android 场景**：`findViewById` 的 Kotlin 扩展就是泛型方法：

```kotlin
// 简化版原理（实际 Android 源码类似）
inline fun <reified T : View> Activity.find(@IdRes id: Int): T {
    return findViewById(id) as T
}

// 使用：不需要手动强转
val button: Button = find(R.id.btn_submit)
val textView: TextView = find(R.id.tv_title)
```

### 2.3 泛型接口

```kotlin
// 泛型接口：定义通用行为契约
interface Repository<T> {
    suspend fun getById(id: Long): T?
    suspend fun getAll(): List<T>
    suspend fun save(item: T)
}

// 实现时指定具体类型
class ArticleRepository : Repository<Article> {
    override suspend fun getById(id: Long): Article? { /* ... */ }
    override suspend fun getAll(): List<Article> { /* ... */ }
    override suspend fun save(item: Article) { /* ... */ }
}
```

### 2.4 类型参数约束（上界）

```kotlin
// <T : Comparable<T>> 约束 T 必须是可比较的
fun <T : Comparable<T>> max(a: T, b: T): T {
    return if (a > b) a else b
}

// Android 场景：约束必须是 View 的子类
fun <T : View> T.visibleIf(condition: Boolean): T {
    visibility = if (condition) View.VISIBLE else View.GONE
    return this
}

// 使用
button.visibleIf(isLoggedIn)
textView.visibleIf(hasContent)
```

## 三、通配符（Wildcard）

通配符是泛型中最让人头疼的部分，但理解了它，Gson/Retrofit 的源码就豁然开朗。

### 3.1 无界通配符 `?`

"我不关心类型是什么，只想读取"：

```kotlin
// Kotlin 中用 * 表示无界通配符（对应 Java 的 ?）
fun printList(list: List<*>) {
    for (item in list) {
        println(item)  // item 类型是 Any?，只能读，不能写
    }
}

printList(listOf("a", "b"))   // OK
printList(listOf(1, 2, 3))    // OK
```

### 3.2 上界通配符 `? extends T`（协变）

"我只读，不写"——生产者用上界：

```kotlin
// Kotlin 用 out 关键字表示协变（对应 Java 的 ? extends T）
fun sumNumbers(list: List<out Number>): Double {
    return list.sumOf { it.toDouble() }
}

val ints: List<Int> = listOf(1, 2, 3)
val doubles: List<Double> = listOf(1.0, 2.0)

sumNumbers(ints)     // OK：Int 是 Number 的子类
sumNumbers(doubles)  // OK：Double 是 Number 的子类
```

**Android 场景**：`LiveData` 的 `observe` 方法：

```kotlin
// LiveData 源码简化版
class LiveData<T> {
    // 观察者只能"读"数据，所以用 out（协变）
    fun observe(owner: LifecycleOwner, observer: Observer<in T>) { }
}

// 使用：LiveData<User> 可以赋值给 LiveData<out Any>
val userLiveData: LiveData<User> = viewModel.user
val anyLiveData: LiveData<out Any> = userLiveData  // OK，因为协变
```

### 3.3 下界通配符 `? super T`（逆变）

"我只写，不读"——消费者用下界：

```kotlin
// Kotlin 用 in 关键字表示逆变（对应 Java 的 ? super T）
fun addNumbers(list: MutableList<in Int>) {
    list.add(1)
    list.add(2)
    // 只能写 Int，读出来是 Any?（因为不知道具体类型）
}

val ints = mutableListOf<Int>()
val numbers = mutableListOf<Number>()
val anys = mutableListOf<Any>()

addNumbers(ints)     // OK
addNumbers(numbers)  // OK：Number 是 Int 的父类
addNumbers(anys)     // OK：Any 是 Int 的父类
```

### 3.4 PECS 原则

> **P**roducer **E**xtends, **C**onsumer **S**uper

记住这个口诀：
- **生产者**（你从它读数据）→ 用 `extends`（Kotlin: `out`）
- **消费者**（你往它写数据）→ 用 `super`（Kotlin: `in`）

```kotlin
// 经典例子：集合复制
// src 是生产者（我们从它读），用 out
// dst 是消费者（我们往它写），用 in
fun <T> copy(src: List<out T>, dst: MutableList<in T>) {
    for (item in src) {
        dst.add(item)
    }
}

val articles: List<Article> = getArticles()
val anyList: MutableList<Any> = mutableListOf()
copy(articles, anyList)  // OK
```

**Android 场景**：`Comparator` 就是典型的消费者：

```kotlin
// 排序文章列表：Comparator<in Article> 消费 Article
val sortedArticles = articles.sortedWith(
    Comparator { a, b -> a.publishTime.compareTo(b.publishTime) }
)
```

## 四、Android 中的泛型应用

### 4.1 RecyclerView 适配器

```kotlin
// 泛型适配器基类，避免每个列表都写重复代码
abstract class BaseAdapter<T, VH : RecyclerView.ViewHolder>(
    private val items: MutableList<T> = mutableListOf()
) : RecyclerView.Adapter<VH>() {

    override fun getItemCount() = items.size

    fun submitList(newItems: List<T>) {
        items.clear()
        items.addAll(newItems)
        notifyDataSetChanged()
    }

    fun getItem(position: Int): T = items[position]
}

// 具体适配器只需关注 ViewHolder 绑定逻辑
class ArticleAdapter : BaseAdapter<Article, ArticleAdapter.ViewHolder>() {

    class ViewHolder(view: View) : RecyclerView.ViewHolder(view) {
        fun bind(article: Article) { /* 绑定数据 */ }
    }

    override fun onCreateViewHolder(parent: ViewGroup, viewType: Int): ViewHolder {
        val view = LayoutInflater.from(parent.context)
            .inflate(R.layout.item_article, parent, false)
        return ViewHolder(view)
    }

    override fun onBindViewHolder(holder: ViewHolder, position: Int) {
        holder.bind(getItem(position))
    }
}
```

### 4.2 网络请求结果封装

```kotlin
// 泛型封装网络请求结果，统一处理成功/失败
sealed class Result<out T> {
    data class Success<T>(val data: T) : Result<T>()
    data class Error(val exception: Exception) : Result<Nothing>()
    object Loading : Result<Nothing>()
}

// Repository 层
class ArticleRepository(private val api: ArticleApi) {
    suspend fun getArticles(): Result<List<Article>> {
        return try {
            val articles = api.fetchArticles()
            Result.Success(articles)
        } catch (e: Exception) {
            Result.Error(e)
        }
    }
}

// ViewModel 层
class ArticleViewModel(private val repo: ArticleRepository) : ViewModel() {
    private val _result = MutableLiveData<Result<List<Article>>>()
    val result: LiveData<Result<List<Article>>> = _result

    fun loadArticles() {
        viewModelScope.launch {
            _result.value = Result.Loading
            _result.value = repo.getArticles()
        }
    }
}

// UI 层
viewModel.result.observe(this) { result ->
    when (result) {
        is Result.Loading -> showLoading()
        is Result.Success -> showArticles(result.data)  // 类型安全，data 是 List<Article>
        is Result.Error -> showError(result.exception.message)
    }
}
```

## 五、面试检验

**Q1：泛型的作用是什么？**

结论：编译期类型检查，消除强制类型转换，提高代码复用性。

原理：泛型让编译器在编译阶段就能发现类型不匹配的问题，而不是等到运行时抛 `ClassCastException`。

Android 实例：`LiveData<User>` 保证观察者拿到的一定是 `User` 对象，不需要强转，也不会类型错误。

---

**Q2：`List<?>` 和 `List<Object>` 有什么区别？**

结论：`List<?>` 是未知类型的列表（只读），`List<Object>` 是 Object 类型的列表（可读写）。

原理：
- `List<String>` 可以赋值给 `List<?>`，但不能赋值给 `List<Object>`（泛型不协变）
- `List<?>` 只能读（读出来是 `Object`），不能写（除了 `null`）

```kotlin
val strings: List<String> = listOf("a", "b")
val wildcardList: List<*> = strings      // OK
// val objectList: List<Any> = strings   // 编译错误！
```

---

**Q3：什么是 PECS 原则？**

结论：Producer Extends, Consumer Super——生产者用上界，消费者用下界。

原理：上界（`out`）保证只读类型安全；下界（`in`）保证只写类型安全。

Android 实例：`Flow<out T>` 是生产者（你从它读数据），所以用 `out`；`Channel<in T>` 是消费者（你往它发数据），所以用 `in`。

---

**Q4：泛型类和泛型方法的区别？**

- 泛型类：类级别的类型参数，整个类的方法都能用
- 泛型方法：方法级别的类型参数，只在该方法内有效，可以在非泛型类中定义

Android 实例：`ViewModel` 是非泛型类，但 `viewModelScope.launch {}` 内部用了泛型方法来处理不同类型的返回值。

---

**Q5：`<T : View>` 这个约束有什么用？**

结论：限制类型参数必须是 `View` 的子类，可以在方法内调用 `View` 的方法。

```kotlin
// 没有约束，只能调用 Any 的方法
fun <T> hide(view: T) { /* 不能调用 view.visibility */ }

// 有约束，可以调用 View 的方法
fun <T : View> hide(view: T) {
    view.visibility = View.GONE  // OK，因为 T 一定是 View 或其子类
}
```
