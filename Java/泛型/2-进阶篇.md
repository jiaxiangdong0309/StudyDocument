# Java 泛型 — 进阶篇

## 一、类型擦除：泛型最大的"坑"

### 什么是类型擦除？

Java 泛型是"假泛型"——编译后，所有泛型信息都被擦除了。

```
编译前：List<String>  →  编译后：List（原始类型）
编译前：List<User>    →  编译后：List（原始类型）
```

就像你写了一封信，信封上写了"收件人：张三"，但邮局投递时把信封撕掉了，只剩信的内容——运行时根本不知道这封信是给谁的。

```java
// Java 代码（理解类型擦除用）
List<String> strings = new ArrayList<>();
List<Integer> ints = new ArrayList<>();

// 运行时，两者的 Class 完全相同！
System.out.println(strings.getClass() == ints.getClass());  // true
System.out.println(strings.getClass().getName());  // java.util.ArrayList
```

```kotlin
// Kotlin 验证类型擦除
val strings: List<String> = listOf("a", "b")
val ints: List<Int> = listOf(1, 2)

println(strings::class == ints::class)  // true，运行时类型相同
```

### 类型擦除的规则

| 泛型声明 | 擦除后 |
|---------|--------|
| `List<T>` | `List` |
| `List<String>` | `List` |
| `<T extends View>` | `View`（擦除为上界） |
| `<T>` | `Object`（擦除为 Object） |

### 类型擦除带来的问题

```kotlin
// 问题1：无法在运行时判断泛型类型
fun <T> isListOf(list: List<*>): Boolean {
    // return list is List<T>  // 编译警告：运行时无法检查 T
    return true  // 永远为 true，因为类型信息已擦除
}

// 问题2：无法直接创建泛型数组
// val array = Array<T>(10)  // 编译错误

// 问题3：无法直接实例化泛型类型
// val t = T()  // 编译错误，不知道 T 的构造函数
```

**Android 最典型的坑——Gson 解析 List：**

```kotlin
// ❌ 错误写法：类型擦除导致解析失败
val json = """[{"name":"张三"},{"name":"李四"}]"""
val users = Gson().fromJson(json, List::class.java)
// users 是 List<LinkedTreeMap>，不是 List<User>！
// 因为运行时 Gson 不知道 T 是 User

// ✅ 正确写法：用 TypeToken 保留类型信息
val type = object : TypeToken<List<User>>() {}.type
val users: List<User> = Gson().fromJson(json, type)
// TypeToken 通过匿名内部类的技巧，在运行时保留了 List<User> 的类型信息
```

## 二、TypeToken 模式：绕过类型擦除

### 为什么匿名内部类能保留泛型信息？

这是 Gson 最精妙的设计之一。

```java
// Java 代码（理解原理用）
// 关键：匿名内部类的父类泛型信息不会被擦除！
// 因为它被记录在 .class 文件的 Signature 属性中
TypeToken<List<User>> token = new TypeToken<List<User>>() {};
// 等价于创建了一个匿名子类：class $1 extends TypeToken<List<User>>

// 通过反射获取父类的泛型参数
Type type = token.getClass().getGenericSuperclass();
// type = TypeToken<List<User>>（ParameterizedType）

ParameterizedType paramType = (ParameterizedType) type;
Type listType = paramType.getActualTypeArguments()[0];
// listType = List<User>（还是 ParameterizedType）
```

```kotlin
// Kotlin 版本
inline fun <reified T> Gson.fromJsonTyped(json: String): T {
    val type = object : TypeToken<T>() {}.type
    return fromJson(json, type)
}

// 使用
val users: List<User> = Gson().fromJsonTyped<List<User>>(json)
```

### reified 关键字：Kotlin 的解决方案

Kotlin 的 `inline + reified` 让泛型在运行时可用：

```kotlin
// reified 让 T 在运行时可用（内联函数，编译时替换）
inline fun <reified T> String.fromJson(): T {
    return Gson().fromJson(this, T::class.java)
}

// 使用：简洁优雅
val user: User = jsonString.fromJson<User>()
val users: List<User> = jsonString.fromJson<List<User>>()  // 注意：List 内部仍有擦除问题

// 更完整的版本，处理泛型集合
inline fun <reified T> String.fromJsonSafe(): T {
    val type = object : TypeToken<T>() {}.type
    return Gson().fromJson(this, type)
}
```

**注意**：`reified` 只在 `inline` 函数中有效，且只能用于 Kotlin。

## 三、泛型与反射：获取运行时类型信息

### ParameterizedType 详解

```kotlin
// 通过反射获取泛型参数类型
class UserRepository : Repository<User>  // 实现泛型接口

fun getGenericType(clazz: Class<*>): Type? {
    val superclass = clazz.genericSuperclass
    return if (superclass is ParameterizedType) {
        superclass.actualTypeArguments[0]
    } else null
}

// 获取 UserRepository 的泛型参数 User
val type = getGenericType(UserRepository::class.java)
println(type)  // class com.example.User
```

**Android 实战**：ViewModel 工厂中的泛型反射：

```kotlin
// 通用 ViewModel 工厂，通过反射创建 ViewModel
class ViewModelFactory(
    private val repository: Any
) : ViewModelProvider.Factory {

    @Suppress("UNCHECKED_CAST")
    override fun <T : ViewModel> create(modelClass: Class<T>): T {
        // 通过反射找到接受 repository 参数的构造函数
        val constructor = modelClass.getConstructor(repository::class.java)
        return constructor.newInstance(repository) as T
    }
}

// 使用
val factory = ViewModelFactory(articleRepository)
val viewModel: ArticleViewModel by viewModels { factory }
```

### 桥接方法（Bridge Method）

类型擦除后，编译器会自动生成桥接方法来保证多态正确性：

```java
// Java 代码（理解原理用）
// 你写的代码
class StringComparator implements Comparator<String> {
    @Override
    public int compare(String a, String b) {
        return a.compareTo(b);
    }
}

// 编译器生成的字节码（伪代码）
class StringComparator implements Comparator {
    // 你写的方法（擦除后）
    public int compare(String a, String b) {
        return a.compareTo(b);
    }

    // 编译器自动生成的桥接方法（保证多态）
    public int compare(Object a, Object b) {
        return compare((String) a, (String) b);  // 调用上面的方法
    }
}
```

## 四、Retrofit 泛型解析实战

Retrofit 是 Android 中泛型应用最复杂的框架之一，理解它能让你对泛型有质的飞跃。

### Retrofit 如何解析 `Call<List<User>>`？

```kotlin
// 你定义的 API 接口
interface ArticleApi {
    @GET("articles")
    suspend fun getArticles(): List<Article>

    @GET("articles/{id}")
    fun getArticle(@Path("id") id: Long): Call<Article>
}
```

Retrofit 内部通过反射获取方法的返回类型：

```java
// Retrofit 源码简化版（Java，理解原理用）
// ServiceMethod.java
static <T> ServiceMethod<T> parseAnnotations(Retrofit retrofit, Method method) {
    // 获取方法的泛型返回类型
    Type returnType = method.getGenericReturnType();
    // returnType = Call<Article>（ParameterizedType）

    // 获取 Call 的泛型参数
    if (returnType instanceof ParameterizedType) {
        ParameterizedType paramType = (ParameterizedType) returnType;
        Type responseType = paramType.getActualTypeArguments()[0];
        // responseType = Article.class
    }
}
```

```kotlin
// Kotlin 版本：理解 Retrofit 的泛型解析
fun parseReturnType(method: Method): Type {
    val returnType = method.genericReturnType
    // 如果是 Call<Article>，获取 Article 类型
    return if (returnType is ParameterizedType) {
        returnType.actualTypeArguments[0]
    } else {
        returnType
    }
}
```

### 自定义 Retrofit Converter 处理泛型

```kotlin
// 自定义 Gson Converter，正确处理泛型类型
class GsonConverterFactory private constructor(
    private val gson: Gson
) : Converter.Factory() {

    override fun responseBodyConverter(
        type: Type,  // 这里的 type 已经是完整的泛型类型，如 List<Article>
        annotations: Array<Annotation>,
        retrofit: Retrofit
    ): Converter<ResponseBody, *> {
        return GsonResponseBodyConverter(gson, type)
    }
}

class GsonResponseBodyConverter<T>(
    private val gson: Gson,
    private val type: Type  // 保留完整类型信息
) : Converter<ResponseBody, T> {

    override fun convert(value: ResponseBody): T {
        // 使用完整的 type（包含泛型参数），而不是擦除后的 Class
        return gson.fromJson(value.charStream(), type)
    }
}
```

## 五、泛型的边界认知

### 什么时候泛型不够用？

```kotlin
// 场景1：需要在运行时知道具体类型
// ❌ 普通泛型做不到
fun <T> createInstance(): T {
    // return T()  // 编译错误，不知道 T 的构造函数
}

// ✅ 用 reified（仅限 inline 函数）
inline fun <reified T> createInstance(): T {
    return T::class.java.newInstance()
}

// 场景2：泛型数组
// ❌ 不能直接创建
// val array = arrayOf<T>()

// ✅ 用 Array(size) { } 或反射
inline fun <reified T> createArray(size: Int): Array<T> {
    return Array(size) { _ -> T::class.java.newInstance() }
}
```

### 泛型 vs Any（Object）

| 对比维度 | 泛型 `<T>` | Any/Object |
|---------|-----------|-----------|
| 类型安全 | 编译期检查 | 运行时检查 |
| 性能 | 无装箱（基本类型除外） | 可能装箱 |
| 代码复用 | 高 | 高（但不安全） |
| 适用场景 | 类型明确的通用逻辑 | 真正不关心类型时 |

**Android 建议**：能用泛型就用泛型，`Any` 只在真正不关心类型时使用（如日志工具）。

### 泛型与 Kotlin 的 `Nothing` 类型

```kotlin
// Nothing 是所有类型的子类型，用于"永不返回"的函数
sealed class Result<out T> {
    data class Success<T>(val data: T) : Result<T>()
    // Nothing 是 T 的子类型，所以 Result<Nothing> 是 Result<T> 的子类型
    data class Error(val exception: Exception) : Result<Nothing>()
    object Loading : Result<Nothing>()
}

// 这样 Loading 和 Error 可以赋值给任何 Result<T>
val result: Result<User> = Result.Loading  // OK
val result2: Result<Article> = Result.Error(Exception("网络错误"))  // OK
```

## 六、面试检验

**Q1：什么是类型擦除？它带来了哪些问题？**

结论：Java 泛型在编译后会擦除类型信息，运行时无法获取泛型参数的具体类型。

问题：
1. 无法在运行时判断泛型类型（`instanceof List<String>` 不合法）
2. 无法直接创建泛型类型的实例
3. 序列化框架（Gson）无法自动推断泛型类型

Android 实例：`Gson().fromJson(json, List::class.java)` 会返回 `List<LinkedTreeMap>` 而不是 `List<User>`，必须用 `TypeToken` 解决。

---

**Q2：TypeToken 为什么要用匿名内部类？**

结论：匿名内部类的父类泛型信息会被保存在 `.class` 文件中，不会被擦除，可以通过 `getGenericSuperclass()` 在运行时获取。

原理：`class $1 extends TypeToken<List<User>>` 这个匿名类的父类类型 `TypeToken<List<User>>` 被记录在字节码的 `Signature` 属性中，反射可以读取。

---

**Q3：Kotlin 的 `reified` 关键字解决了什么问题？**

结论：`reified` 让内联函数的泛型参数在运行时可用，解决了类型擦除问题。

原理：`inline` 函数在编译时会将函数体内联到调用处，同时将 `T` 替换为实际类型，所以运行时 `T` 是已知的。

限制：只能用于 `inline` 函数，不能用于类或普通函数。

---

**Q4：`List<out T>` 和 `List<in T>` 分别在什么场景用？**

- `out T`（协变）：只读场景，如 `Flow<out T>`、`LiveData<out T>`
- `in T`（逆变）：只写场景，如 `Comparator<in T>`、`Channel<in T>`

Android 实例：`ListAdapter<T, VH>` 的 `submitList(list: List<T>)` 参数用 `out` 是因为我们只从 list 读数据。

---

**Q5：为什么 `List<String>` 不能赋值给 `List<Any>`？**

结论：泛型默认不协变，`List<String>` 和 `List<Any>` 是完全不同的类型。

原因：如果允许，就可以往 `List<Any>` 里加 `Int`，但实际是 `List<String>`，会破坏类型安全。

```kotlin
// 假设允许（实际编译报错）
val strings: MutableList<String> = mutableListOf("a")
val anys: MutableList<Any> = strings  // 假设 OK
anys.add(123)  // 往 strings 里加了 Int！
val s: String = strings[1]  // ClassCastException！
```

解决：用 `List<out Any>`（只读），因为只读不会破坏类型安全。

---

**Q6：Retrofit 如何在运行时获取 `Call<User>` 中的 `User` 类型？**

结论：通过 `Method.getGenericReturnType()` 获取方法的泛型返回类型，再通过 `ParameterizedType.getActualTypeArguments()` 获取泛型参数。

原理：方法签名中的泛型信息（如 `Call<User>`）不会被擦除，保存在字节码的 `Signature` 属性中，可以通过反射读取。

这就是为什么 Retrofit 的接口方法必须声明返回类型——Retrofit 需要通过反射读取这个类型信息来决定如何解析响应体。
