# Fragment 进阶篇

## Fragment 通信

Fragment 与 Activity、Fragment 与 Fragment 之间的通信是实际开发中的常见需求。掌握正确的通信方式，是写出高质量代码的关键。

### 通信方式对比

| 方式 | 适用场景 | 优点 | 缺点 |
|-----|---------|------|------|
| 接口回调 | Fragment → Activity | 解耦、类型安全 | 代码量较多 |
| ViewModel 共享 | Activity ↔ Fragment | 生命周期安全、现代推荐 | 需要理解 ViewModel 作用域 |
| Fragment Result API | Fragment ↔ Fragment | 官方推荐、解耦 | 需要 Fragment 1.3+ |
| EventBus | 全局通信 | 使用简单 | 难以追踪、维护性差 |

### 方式1：接口回调（传统方式）

```kotlin
// ================== 定义通信接口 ==================
interface OnItemSelectedListener {
    fun onItemSelected(item: Item)
}

// ================== Fragment 端 ==================
class ListFragment : Fragment() {
    
    // 通过接口与 Activity 通信
    private var listener: OnItemSelectedListener? = null
    
    override fun onAttach(context: Context) {
        super.onAttach(context)
        // 检查 Activity 是否实现了接口
        listener = context as? OnItemSelectedListener
            ?: throw ClassCastException("$context must implement OnItemSelectedListener")
    }
    
    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)
        
        binding.recyclerView.adapter = ItemAdapter { item ->
            // 点击条目时通知 Activity
            listener?.onItemSelected(item)
        }
    }
    
    override fun onDetach() {
        super.onDetach()
        listener = null  // 避免内存泄漏
    }
}

// ================== Activity 端 ==================
class MainActivity : AppCompatActivity(), OnItemSelectedListener {
    
    override fun onItemSelected(item: Item) {
        // 收到 Fragment 的通知，显示详情
        showDetail(item)
    }
}
```

### 方式2：共享 ViewModel（推荐）

这是现代 Android 开发的推荐方式，利用 Activity 级别的 ViewModel 在 Fragment 之间共享数据。

```kotlin
// ================== 共享 ViewModel ==================
class SharedViewModel : ViewModel() {
    
    // 用于通信的 LiveData
    private val _selectedItem = MutableLiveData<Item>()
    val selectedItem: LiveData<Item> = _selectedItem
    
    fun selectItem(item: Item) {
        _selectedItem.value = item
    }
}

// ================== 列表 Fragment ==================
class ListFragment : Fragment() {
    
    // 使用 activityViewModels() 获取 Activity 级别的 ViewModel
    // 这样同一个 Activity 中的所有 Fragment 共享同一个 ViewModel 实例
    private val sharedViewModel: SharedViewModel by activityViewModels()
    
    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)
        
        binding.recyclerView.adapter = ItemAdapter { item ->
            // 点击条目时，通过 ViewModel 通知
            sharedViewModel.selectItem(item)
        }
    }
}

// ================== 详情 Fragment ==================
class DetailFragment : Fragment() {
    
    // 获取同一个 ViewModel 实例
    private val sharedViewModel: SharedViewModel by activityViewModels()
    
    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)
        
        // 观察数据变化
        sharedViewModel.selectedItem.observe(viewLifecycleOwner) { item ->
            displayItem(item)
        }
    }
}
```

### 方式3：Fragment Result API（官方推荐）

Fragment 1.3.0 引入的新 API，专门用于 Fragment 之间的结果传递，类似于 Activity Result API。

```kotlin
// ================== 发送结果的 Fragment ==================
class SelectionFragment : Fragment() {
    
    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)
        
        binding.buttonConfirm.setOnClickListener {
            // 发送结果
            setFragmentResult(
                "selection_key",  // 请求键，接收方用这个来监听
                bundleOf("selected_value" to "用户选择的值")
            )
            // 关闭自己
            parentFragmentManager.popBackStack()
        }
    }
}

// ================== 接收结果的 Fragment ==================
class RequestFragment : Fragment() {
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        // 设置结果监听器（要在 STARTED 状态之前设置）
        setFragmentResultListener("selection_key") { requestKey, bundle ->
            val result = bundle.getString("selected_value")
            // 处理接收到的结果
            handleResult(result)
        }
    }
    
    private fun openSelection() {
        parentFragmentManager.beginTransaction()
            .replace(R.id.container, SelectionFragment())
            .addToBackStack(null)
            .commit()
    }
}
```

**父子 Fragment 之间传递结果**：

```kotlin
// 子 Fragment 发送结果给父 Fragment
class ChildFragment : Fragment() {
    
    private fun sendResultToParent() {
        // 使用 parentFragmentManager 而不是 childFragmentManager
        parentFragmentManager.setFragmentResult(
            "child_result",
            bundleOf("data" to "来自子Fragment的数据")
        )
    }
}

// 父 Fragment 接收子 Fragment 的结果
class ParentFragment : Fragment() {
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        // 在 childFragmentManager 上设置监听器
        childFragmentManager.setFragmentResultListener("child_result", this) { _, bundle ->
            val data = bundle.getString("data")
            // 处理结果
        }
    }
}
```

## ViewPager 与 Fragment

### ViewPager2 + FragmentStateAdapter（推荐）

ViewPager2 是 ViewPager 的替代品，内部使用 RecyclerView 实现，性能更好，功能更强。

```kotlin
// ================== Adapter ==================
class MyPagerAdapter(
    fragmentActivity: FragmentActivity,
    private val fragments: List<Fragment>
) : FragmentStateAdapter(fragmentActivity) {
    
    override fun getItemCount(): Int = fragments.size
    
    override fun createFragment(position: Int): Fragment = fragments[position]
}

// ================== 使用 ==================
class MainActivity : AppCompatActivity() {
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)
        
        val fragments = listOf(
            HomeFragment.newInstance(),
            CategoryFragment.newInstance(),
            ProfileFragment.newInstance()
        )
        
        val viewPager = findViewById<ViewPager2>(R.id.viewPager)
        viewPager.adapter = MyPagerAdapter(this, fragments)
        
        // 配合 TabLayout
        val tabLayout = findViewById<TabLayout>(R.id.tabLayout)
        TabLayoutMediator(tabLayout, viewPager) { tab, position ->
            tab.text = when (position) {
                0 -> "首页"
                1 -> "分类"
                2 -> "我的"
                else -> ""
            }
        }.attach()
    }
}
```

### 懒加载实现

**什么是懒加载？**

在 ViewPager 中，默认会预加载相邻的页面（offscreenPageLimit 默认为 1）。懒加载就是让 Fragment 在真正可见时才加载数据，避免不必要的资源消耗。

**ViewPager2 + setMaxLifecycle（推荐方案）**

ViewPager2 结合 FragmentStateAdapter 默认就支持真正的懒加载：

```kotlin
// FragmentStateAdapter 内部会调用 setMaxLifecycle
// 不可见的 Fragment 最多到 STARTED 状态，不会到 RESUMED
// 因此只需要在 onResume 中加载数据即可实现懒加载

class LazyFragment : Fragment() {
    
    private var isDataLoaded = false
    
    override fun onResume() {
        super.onResume()
        // 只有真正可见时才会调用 onResume
        if (!isDataLoaded) {
            loadData()
            isDataLoaded = true
        }
    }
    
    private fun loadData() {
        // 加载数据
        viewModel.fetchData()
    }
}
```

**传统 ViewPager + setUserVisibleHint（已废弃）**

如果你还在维护使用传统 ViewPager 的老项目：

```kotlin
// ❌ 旧方式（已废弃，但可能在老项目中遇到）
class OldLazyFragment : Fragment() {
    
    private var isViewCreated = false
    private var isVisibleToUser = false
    
    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)
        isViewCreated = true
        lazyLoadIfReady()
    }
    
    @Deprecated("已废弃，ViewPager2 不会调用")
    override fun setUserVisibleHint(isVisibleToUser: Boolean) {
        super.setUserVisibleHint(isVisibleToUser)
        this.isVisibleToUser = isVisibleToUser
        lazyLoadIfReady()
    }
    
    private fun lazyLoadIfReady() {
        if (isViewCreated && isVisibleToUser) {
            loadData()
        }
    }
}
```

## Navigation 组件

Navigation 是 Google 推荐的导航方案，支持单 Activity 多 Fragment 架构。

### 基本使用

**1. 添加依赖**

```kotlin
// build.gradle.kts (Module)
dependencies {
    val nav_version = "2.7.6"
    implementation("androidx.navigation:navigation-fragment-ktx:$nav_version")
    implementation("androidx.navigation:navigation-ui-ktx:$nav_version")
}
```

**2. 创建导航图**

```xml
<!-- res/navigation/nav_graph.xml -->
<?xml version="1.0" encoding="utf-8"?>
<navigation xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:app="http://schemas.android.com/apk/res-auto"
    android:id="@+id/nav_graph"
    app:startDestination="@id/homeFragment">

    <fragment
        android:id="@+id/homeFragment"
        android:name="com.example.HomeFragment"
        android:label="首页">
        
        <!-- 定义导航动作 -->
        <action
            android:id="@+id/action_home_to_detail"
            app:destination="@id/detailFragment"
            app:enterAnim="@anim/slide_in_right"
            app:exitAnim="@anim/slide_out_left"
            app:popEnterAnim="@anim/slide_in_left"
            app:popExitAnim="@anim/slide_out_right" />
    </fragment>

    <fragment
        android:id="@+id/detailFragment"
        android:name="com.example.DetailFragment"
        android:label="详情">
        
        <!-- 定义参数 -->
        <argument
            android:name="itemId"
            app:argType="long" />
    </fragment>

</navigation>
```

**3. 在 Activity 中设置导航宿主**

```xml
<!-- activity_main.xml -->
<androidx.fragment.app.FragmentContainerView
    android:id="@+id/nav_host_fragment"
    android:name="androidx.navigation.fragment.NavHostFragment"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    app:defaultNavHost="true"
    app:navGraph="@navigation/nav_graph" />
```

**4. 执行导航**

```kotlin
class HomeFragment : Fragment() {
    
    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)
        
        binding.buttonDetail.setOnClickListener {
            // 方式1：使用 action ID
            findNavController().navigate(R.id.action_home_to_detail)
            
            // 方式2：使用 Safe Args（推荐，类型安全）
            // 需要添加 Safe Args 插件
            val action = HomeFragmentDirections.actionHomeToDetail(itemId = 123L)
            findNavController().navigate(action)
        }
    }
}
```

### 与 BottomNavigationView 配合

```kotlin
class MainActivity : AppCompatActivity() {
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)
        
        val navHostFragment = supportFragmentManager

        val navController = navHostFragment.navController

        bottomNav.setupWithNavController(navController)
    }
}
```

### Navigation 的优缺点

| 优点 | 缺点 |
|-----|------|
| 可视化编辑导航图 | 学习成本 |
| 类型安全的参数传递（Safe Args） | 复杂场景需要自定义 |
| 自动处理返回栈 | Fragment 切换默认会销毁 View |
| 支持深度链接 | 与某些第三方库可能冲突 |
| 官方维护，长期支持 | - |

## 性能优化

### 1. 优化 Fragment 切换

**问题**：使用 replace 切换 Fragment 时，每次都会销毁重建 View。

```kotlin
// ❌ 每次切换都 replace，View 反复创建销毁
fun switchFragment(fragment: Fragment) {
    supportFragmentManager.beginTransaction()
        .replace(R.id.container, fragment)
        .commit()
}

// ✅ 使用 hide/show，保留 View 状态
class MainActivity : AppCompatActivity() {
    
    private val fragmentMap = mutableMapOf<Int, Fragment>()
    private var currentFragment: Fragment? = null
    
    fun switchFragment(menuId: Int) {
        val targetFragment = fragmentMap[menuId] ?: createFragment(menuId).also {
            fragmentMap[menuId] = it
        }
        
        if (targetFragment == currentFragment) return
        
        supportFragmentManager.beginTransaction().apply {
            // 隐藏当前
            currentFragment?.let { hide(it) }
            
            // 显示目标（如果还没添加则添加）
            if (!targetFragment.isAdded) {
                add(R.id.container, targetFragment, menuId.toString())
            } else {
                show(targetFragment)
            }
            
            currentFragment = targetFragment
        }.commit()
    }
    
    private fun createFragment(menuId: Int): Fragment {
        return when (menuId) {
            R.id.menu_home -> HomeFragment.newInstance()
            R.id.menu_profile -> ProfileFragment.newInstance()
            else -> throw IllegalArgumentException()
        }
    }
}
```

### 2. 使用 FragmentContainerView

```xml
<!-- ❌ 旧方式 -->
<FrameLayout
    android:id="@+id/container"
    android:layout_width="match_parent"
    android:layout_height="match_parent" />

<!-- ✅ 推荐：使用 FragmentContainerView -->
<androidx.fragment.app.FragmentContainerView
    android:id="@+id/container"
    android:layout_width="match_parent"
    android:layout_height="match_parent" />
```

**FragmentContainerView 的优势**：
- 修复了 Fragment z-ordering 问题
- 支持 `android:name` 属性静态添加 Fragment
- 更好的动画支持
- 是官方推荐的容器

### 3. 优化 ViewPager2 预加载

```kotlin
// 控制预加载数量
viewPager.offscreenPageLimit = 1  // 默认值，预加载1个

// 如果 Fragment 较轻量，可以增加预加载数量减少切换时的加载
viewPager.offscreenPageLimit = 2

// 完全禁用预加载（需要谨慎，可能导致切换时闪烁）
// ViewPager2 不支持设置为 0，最小为 1
```

### 4. 避免在 onCreateView 中做耗时操作

```kotlin
// ❌ 错误：在 onCreateView 中做耗时操作
override fun onCreateView(inflater: LayoutInflater, container: ViewGroup?, savedInstanceState: Bundle?): View {
    val binding = FragmentBinding.inflate(inflater, container, false)
    
    // 耗时操作会阻塞 UI
    val data = loadDataFromDatabase()  // 💥 ANR 风险
    binding.textView.text = data
    
    return binding.root
}

// ✅ 正确：异步加载
override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
    super.onViewCreated(view, savedInstanceState)
    
    viewLifecycleOwner.lifecycleScope.launch {
        // 在协程中加载数据
        val data = withContext(Dispatchers.IO) {
            loadDataFromDatabase()
        }
        // 回到主线程更新 UI
        binding.textView.text = data
    }
}
```

## 横向对比

### Fragment vs Activity

| 对比点 | Fragment | Activity |
|-------|----------|----------|
| 重量级 | 轻量 | 重量 |
| 启动开销 | 小 | 大（IPC） |
| 生命周期 | 复杂（依赖 Activity） | 相对简单 |
| 复用性 | 高（可嵌入多个 Activity） | 低 |
| 测试性 | 可单独测试 | 需要完整环境 |
| 适用场景 | 模块化 UI、Tab 切换 | 独立页面 |

### Fragment vs Compose

| 对比点 | Fragment | Compose |
|-------|----------|---------|
| 编程模式 | 命令式 | 声明式 |
| 状态管理 | 手动管理生命周期 | 自动重组 |
| 学习曲线 | 中等 | 较陡 |
| 生态成熟度 | 非常成熟 | 快速成熟中 |
| 性能 | 取决于使用方式 | 理论上更优 |
| 未来趋势 | 维护模式 | 官方主推 |

> **建议**：新项目可以考虑 Compose，老项目继续用 Fragment 维护，可以逐步迁移。

## 边界认知

### Fragment 不适用的场景

1. **完全独立的页面**：如登录、设置等，用 Activity 更清晰
2. **需要独立任务栈**：Fragment 无法独立存在于任务栈
3. **复杂的页面转场动画**：Activity 转场动画更成熟
4. **需要与其他应用交互**：Intent 只能启动 Activity

### 常见坑点

1. **Fragment 重叠**：配置变更时没检查 savedInstanceState
2. **getActivity() 为 null**：异步回调时 Fragment 已 detach
3. **View 生命周期与 Fragment 生命周期不同步**：ViewPager 场景
4. **嵌套 Fragment**：用错 FragmentManager
5. **commit 崩溃**：在 onSaveInstanceState 后提交事务

## 面试检验

### 进阶题

**Q1: Fragment 与 Activity 之间有哪些通信方式？各有什么优缺点？**

> **答案**：
> 1. **接口回调**：传统方式，Fragment 定义接口，Activity 实现。优点是解耦、类型安全；缺点是代码量多。
> 2. **共享 ViewModel**：使用 `activityViewModels()` 获取 Activity 级别的 ViewModel。优点是生命周期安全、官方推荐；缺点是需要理解 ViewModel 作用域。
> 3. **Fragment Result API**：Fragment 1.3+ 引入，通过 key-value 传递结果。优点是官方推荐、解耦；缺点是只支持 Bundle。
> 4. **EventBus**：全局事件总线。优点是简单；缺点是难以追踪、维护性差。
> 
> **推荐**：简单场景用 Fragment Result API，复杂数据共享用 ViewModel。

**Q2: ViewPager + Fragment 如何实现懒加载？ViewPager2 有什么不同？**

> **答案**：
> **ViewPager（旧）**：
> - 方式1：重写 `setUserVisibleHint()`（已废弃）
> - 方式2：使用 `BEHAVIOR_RESUME_ONLY_CURRENT_FRAGMENT`
> 
> **ViewPager2（新，推荐）**：
> - 内部使用 `setMaxLifecycle()` 控制 Fragment 生命周期
> - 不可见的 Fragment 最多到 STARTED 状态
> - 只需在 `onResume()` 中加载数据即可
> 
> ViewPager2 的懒加载是"真懒加载"，不需要额外处理。

**Q3: setMaxLifecycle() 是什么？有什么用？**

> **答案**：
> `setMaxLifecycle()` 是 Fragment 1.1.0 引入的方法，用于限制 Fragment 的最大生命周期状态。
> 
> 用途：
> - ViewPager2 用它实现懒加载（限制不可见 Fragment 为 STARTED）
> - 可以手动控制 Fragment 不进入某些生命周期状态
> 
> 例如：`setMaxLifecycle(fragment, Lifecycle.State.STARTED)` 会让 Fragment 最多到 onStart，不会调用 onResume。

**Q4: Navigation 组件有什么优势？适合什么场景？**

> **答案**：
> **优势**：
> - 可视化编辑导航关系
> - Safe Args 提供类型安全的参数传递
> - 自动处理返回栈
> - 支持深度链接
> - 与 BottomNavigationView、DrawerLayout 无缝配合
> 
> **适合场景**：
> - 单 Activity 多 Fragment 架构
> - 需要复杂导航逻辑的应用
> - 需要深度链接的应用
> 
> **不适合场景**：
> - 多 Activity 架构
> - 非常简单的应用

**Q5: FragmentContainerView 相比 FrameLayout 有什么优势？**

> **答案**：
> 1. 修复了 Fragment 的 z-ordering 问题（动画时 Fragment 层级正确）
> 2. 支持 `android:name` 属性静态添加 Fragment
> 3. 更好的动画支持
> 4. 避免了一些与 Fragment 相关的已知 Bug
>
