# LiveData 进阶篇

## Transformations：数据转换

### 为什么需要数据转换？

实际开发中，数据源的格式往往不是 UI 直接需要的：

```kotlin
// Repository 返回的数据
data class UserEntity(
    val id: Long,
    val firstName: String,
    val lastName: String,
    val birthTimestamp: Long,
    val avatarUrl: String?
)

// UI 需要展示的数据
data class UserDisplay(
    val fullName: String,      // 需要拼接
    val age: Int,              // 需要计算
    val avatarUrl: String      // 需要默认值
)
```

直接在 UI 层转换？不优雅。在 ViewModel 里每次都转换？重复代码。这时候就需要 `Transformations`。

### map：一对一转换

`map` 用于将一种类型的 LiveData 转换为另一种类型：

```kotlin
class UserViewModel : ViewModel() {
    
    private val _userEntity = MutableLiveData<UserEntity>()
    
    // 使用 map 转换为 UI 需要的格式
    val userDisplay: LiveData<UserDisplay> = _userEntity.map { entity ->
        UserDisplay(
            fullName = "${entity.firstName} ${entity.lastName}",
            age = calculateAge(entity.birthTimestamp),
            avatarUrl = entity.avatarUrl ?: "default_avatar.png"
        )
    }
    
    // 只取部分数据
    val userName: LiveData<String> = _userEntity.map { entity ->
        "${entity.firstName} ${entity.lastName}"
    }
    
    // 格式化展示
    val userAge: LiveData<String> = _userEntity.map { entity ->
        val age = calculateAge(entity.birthTimestamp)
        "${age}岁"
    }
    
    private fun calculateAge(birthTimestamp: Long): Int {
        // 计算年龄的逻辑
        val birthYear = // ...
        return Calendar.getInstance().get(Calendar.YEAR) - birthYear
    }
}
```

**map 的特点**：
- **同步转换**：转换函数在主线程执行
- **一对一**：一个输入值对应一个输出值
- **惰性求值**：只有当有观察者时才执行转换

### switchMap：动态切换数据源

`switchMap` 用于根据一个 LiveData 的值，切换到另一个 LiveData：

```kotlin
class SearchViewModel(
    private val repository: SearchRepository
) : ViewModel() {
    
    // 搜索关键词
    private val _searchQuery = MutableLiveData<String>()
    
    // 根据关键词动态切换搜索结果
    val searchResults: LiveData<List<SearchResult>> = _searchQuery.switchMap { query ->
        if (query.isBlank()) {
            // 空查询返回空结果
            liveData { emit(emptyList()) }
        } else {
            // 执行搜索，返回新的 LiveData
            repository.search(query)  // 返回 LiveData<List<SearchResult>>
        }
    }
    
    fun search(query: String) {
        _searchQuery.value = query
    }
}

// Repository
class SearchRepository {
    fun search(query: String): LiveData<List<SearchResult>> {
        return liveData {
            val results = api.search(query)
            emit(results)
        }
    }
}
```

**switchMap 的特点**：
- **动态切换**：根据输入值返回不同的 LiveData
- **自动取消**：切换时自动停止观察旧的 LiveData
- **适合异步操作**：返回的是 LiveData，可以包含异步加载逻辑

### map vs switchMap：何时用哪个？

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        map vs switchMap 对比                                 │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  map: 同步转换，返回值                                                       │
│  ┌────────────────┐      ┌────────────────┐                                │
│  │  LiveData<A>   │ ───► │  LiveData<B>   │                                │
│  │  value = a     │  f   │  value = f(a)  │                                │
│  └────────────────┘      └────────────────┘                                │
│                                                                             │
│  switchMap: 动态切换，返回 LiveData                                          │
│  ┌────────────────┐      ┌────────────────┐                                │
│  │  LiveData<A>   │ ───► │  LiveData<B>   │ ◄─┐                            │
│  │  value = a     │  f   │  订阅 f(a)     │   │                            │
│  └────────────────┘      └────────────────┘   │                            │
│                                 ▲              │                            │
│                                 │              │                            │
│                          ┌─────┴─────┐  ┌─────┴─────┐                      │
│                          │LiveData<B>│  │LiveData<B>│  ...                 │
│                          │ 数据源 1  │  │ 数据源 2  │                      │
│                          └───────────┘  └───────────┘                      │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

| 场景 | 使用 | 原因 |
|-----|-----|------|
| 格式化显示（User → "张三"） | map | 简单同步转换 |
| 类型转换（Entity → VO） | map | 一对一映射 |
| 根据 ID 加载详情 | switchMap | 需要异步请求，返回 LiveData |
| 搜索功能 | switchMap | 关键词变化要切换数据源 |
| 根据 Tab 切换列表 | switchMap | 不同 Tab 对应不同数据源 |

### 实际案例：用户详情页

```kotlin
class UserDetailViewModel(
    private val userRepository: UserRepository,
    private val postRepository: PostRepository
) : ViewModel() {
    
    // 当前查看的用户 ID
    private val _userId = MutableLiveData<String>()
    
    // 用户基本信息
    val user: LiveData<User> = _userId.switchMap { id ->
        userRepository.getUser(id)
    }
    
    // 用户昵称（同步转换）
    val userName: LiveData<String> = user.map { it.name }
    
    // 用户的帖子列表（根据用户 ID 切换数据源）
    val userPosts: LiveData<List<Post>> = _userId.switchMap { id ->
        postRepository.getPostsByUser(id)
    }
    
    // 帖子数量（同步转换）
    val postCount: LiveData<String> = userPosts.map { posts ->
        "${posts.size} 篇帖子"
    }
    
    fun loadUser(userId: String) {
        _userId.value = userId
    }
}
```

## MediatorLiveData：多数据源合并

### 什么是 MediatorLiveData？

当需要观察多个 LiveData，并根据它们的组合值更新时，使用 `MediatorLiveData`：

```kotlin
class CheckoutViewModel : ViewModel() {
    
    val cartItems = MutableLiveData<List<CartItem>>()
    val coupon = MutableLiveData<Coupon?>()
    val shippingFee = MutableLiveData<Double>()
    
    // 合并多个数据源计算总价
    val totalPrice: LiveData<Double> = MediatorLiveData<Double>().apply {
        // 添加数据源：购物车商品
        addSource(cartItems) { items ->
            value = calculateTotal()
        }
        // 添加数据源：优惠券
        addSource(coupon) { _ ->
            value = calculateTotal()
        }
        // 添加数据源：运费
        addSource(shippingFee) { _ ->
            value = calculateTotal()
        }
    }
    
    private fun calculateTotal(): Double {
        val itemsTotal = cartItems.value?.sumOf { it.price * it.quantity } ?: 0.0
        val discount = coupon.value?.discount ?: 0.0
        val shipping = shippingFee.value ?: 0.0
        return itemsTotal - discount + shipping
    }
}
```

### 常见使用场景

**场景一：表单多字段验证**

```kotlin
class RegisterViewModel : ViewModel() {
    
    val username = MutableLiveData<String>()
    val email = MutableLiveData<String>()
    val password = MutableLiveData<String>()
    val confirmPassword = MutableLiveData<String>()
    
    // 表单是否全部有效
    val isFormValid: LiveData<Boolean> = MediatorLiveData<Boolean>().apply {
        fun validate() {
            val user = username.value ?: ""
            val mail = email.value ?: ""
            val pass = password.value ?: ""
            val confirm = confirmPassword.value ?: ""
            
            value = user.length >= 3 
                && mail.contains("@") 
                && pass.length >= 6 
                && pass == confirm
        }
        
        addSource(username) { validate() }
        addSource(email) { validate() }
        addSource(password) { validate() }
        addSource(confirmPassword) { validate() }
    }
    
    // 各字段的错误提示
    val usernameError: LiveData<String?> = username.map { 
        if (it.length < 3) "用户名至少3个字符" else null 
    }
    
    val emailError: LiveData<String?> = email.map { 
        if (!it.contains("@")) "邮箱格式不正确" else null 
    }
    
    val passwordError: LiveData<String?> = password.map { 
        if (it.length < 6) "密码至少6个字符" else null 
    }
}
```

**场景二：加载状态合并**

```kotlin
class DashboardViewModel : ViewModel() {
    
    private val _userLoading = MutableLiveData<Boolean>()
    private val _ordersLoading = MutableLiveData<Boolean>()
    private val _notificationsLoading = MutableLiveData<Boolean>()
    
    // 任一模块加载中，就显示加载状态
    val isLoading: LiveData<Boolean> = MediatorLiveData<Boolean>().apply {
        fun updateLoading() {
            value = _userLoading.value == true 
                || _ordersLoading.value == true 
                || _notificationsLoading.value == true
        }
        
        addSource(_userLoading) { updateLoading() }
        addSource(_ordersLoading) { updateLoading() }
        addSource(_notificationsLoading) { updateLoading() }
    }
}
```

**场景三：动态添加/移除数据源**

```kotlin
class ChatViewModel : ViewModel() {
```

## 粘性事件问题（Sticky Event）

### 什么是粘性事件？

这是 LiveData 最常见的"坑"，也是高频面试题！

```kotlin
class EventViewModel : ViewModel() {
    private val _showToast = MutableLiveData<String>()
    val showToast: LiveData<String> = _showToast
    
    fun triggerToast(message: String) {
        _showToast.value = message
    }
}

class MyActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        viewModel.showToast.observe(this) { message ->
            Toast.makeText(this, message, Toast.LENGTH_SHORT).show()
        }
    }
}
```

**问题场景**：
1. 用户点击按钮，触发 Toast
2. 用户旋转屏幕
3. Activity 重建，重新 observe
4. **Toast 又弹了一次！** 😱

这就是"粘性事件"：新的观察者会立即收到 LiveData 的最新值，即使这个值已经被处理过了。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           粘性事件问题示意                                    │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  时间线 ──────────────────────────────────────────────────────────────────►  │
│                                                                             │
│  1. 点击按钮                                                                 │
│     └─► setValue("显示Toast")                                               │
│         └─► Observer 收到 ──► 显示 Toast ✅                                  │
│                                                                             │
│  2. 屏幕旋转，Activity 重建                                                  │
│     └─► 新 Observer 订阅                                                    │
│         └─► LiveData 依然持有 "显示Toast"                                   │
│             └─► 新 Observer 立即收到 ──► 又显示 Toast ❌                      │
│                                                                             │
│  期望：事件只消费一次                                                         │
│  实际：每次订阅都会收到                                                       │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 为什么会这样？

LiveData 的设计初衷是**持有状态**，新观察者应该立即获得当前状态。这对于"用户名"、"加载状态"等数据是正确的，但对于"显示 Toast"、"导航到某页面"这类**一次性事件**就不合适了。

### 解决方案一：Event 包装类（推荐）

Google 官方示例中使用的方案：

```kotlin
/**
 * 用于包装一次性事件的数据类
 * 事件只会被消费一次，重复获取返回 null
 */
open class Event<out T>(private val content: T) {
    
    // 标记事件是否已被处理
    private var hasBeenHandled = false
    
    /**
     * 获取事件内容，只能获取一次
     * 第二次调用返回 null
     */
    fun getContentIfNotHandled(): T? {
        return if (hasBeenHandled) {
            null
        } else {
            hasBeenHandled = true
            content
        }
    }
    
    /**
     * 获取事件内容，不管是否已处理
     * 用于需要重复读取的场景（如日志）
     */
    fun peekContent(): T = content
}

// 使用
class EventViewModel : ViewModel() {
    
    private val _navigateToDetail = MutableLiveData<Event<String>>()
    val navigateToDetail: LiveData<Event<String>> = _navigateToDetail
    
    private val _showSnackbar = MutableLiveData<Event<String>>()
    val showSnackbar: LiveData<Event<String>> = _showSnackbar
    
    fun onItemClick(itemId: String) {
        _navigateToDetail.value = Event(itemId)
    }
    
    fun onError(message: String) {
        _showSnackbar.value = Event(message)
    }
}

// Activity 中使用
class ListActivity : AppCompatActivity() {
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        viewModel.navigateToDetail.observe(this) { event ->
            // 只有未处理过的事件才会执行
            event.getContentIfNotHandled()?.let { itemId ->
                startActivity(DetailActivity.newIntent(this, itemId))
            }
        }
        
        viewModel.showSnackbar.observe(this) { event ->
            event.getContentIfNotHandled()?.let { message ->
                Snackbar.make(binding.root, message, Snackbar.LENGTH_SHORT).show()
            }
        }
    }
}
```

**进一步封装：EventObserver**

```kotlin
/**
 * 简化 Event 观察的 Observer
 */
class EventObserver<T>(private val onEventUnhandled: (T) -> Unit) : Observer<Event<T>> {
    override fun onChanged(event: Event<T>) {
        event.getContentIfNotHandled()?.let { value ->
            onEventUnhandled(value)
        }
    }
}

// 扩展函数，更简洁的使用方式
inline fun <T> LiveData<Event<T>>.observeEvent(
    owner: LifecycleOwner,
    crossinline onEventUnhandled: (T) -> Unit
) {
    observe(owner, EventObserver { onEventUnhandled(it) })
}

// 使用
viewModel.navigateToDetail.observeEvent(this) { itemId ->
    startActivity(DetailActivity.newIntent(this, itemId))
}
```

### 解决方案二：SingleLiveEvent

另一种常见方案，但有多观察者时的问题：

```kotlin
/**
 * 只会通知一个观察者的 LiveData
 * 注意：多观察者时只有一个能收到！
 */
class SingleLiveEvent<T> : MutableLiveData<T>() {
    
    private val pending = AtomicBoolean(false)
    
    override fun observe(owner: LifecycleOwner, observer: Observer<in T>) {
        // 警告：多观察者时只有一个能收到
        if (hasActiveObservers()) {
            Log.w("SingleLiveEvent", "Multiple observers registered but only one will be notified")
        }
        
        super.observe(owner) { t ->
            if (pending.compareAndSet(true, false)) {
                observer.onChanged(t)
            }
        }
    }
    
    override fun setValue(value: T?) {
        pending.set(true)
        super.setValue(value)
    }
    
    fun call() {
        value = null
    }
}

// 使用
class MyViewModel : ViewModel() {
    val navigateEvent = SingleLiveEvent<String>()
    
    fun onItemClick(id: String) {
        navigateEvent.value = id
    }
}
```

### 解决方案三：使用 Channel/Flow（现代方案）

对于一次性事件，使用 Kotlin Flow 的 Channel 是更优雅的方案：

```kotlin
class ModernViewModel : ViewModel() {
    
    // 使用 Channel 发送一次性事件
    private val _events = Channel<UiEvent>(Channel.BUFFERED)
    val events = _events.receiveAsFlow()
    
    fun showToast(message: String) {
        viewModelScope.launch {
            _events.send(UiEvent.ShowToast(message))
        }
    }
    
    fun navigateTo(destination: String) {
        viewModelScope.launch {
            _events.send(UiEvent.Navigate(destination))
        }
    }
}

sealed class UiEvent {
    data class ShowToast(val message: String) : UiEvent()
    data class Navigate(val destination: String) : UiEvent()
}

// Activity 中收集
class ModernActivity : AppCompatActivity() {
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        lifecycleScope.launch {
            repeatOnLifecycle(Lifecycle.State.STARTED) {
                viewModel.events.collect { event ->
                    when (event) {
                        is UiEvent.ShowToast -> {
                            Toast.makeText(this@ModernActivity, event.message, Toast.LENGTH_SHORT).show()
                        }
                        is UiEvent.Navigate -> {
                            // 导航逻辑
                        }
                    }
                }
            }
        }
    }
}
```

## LiveData vs Kotlin Flow

### 核心区别

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                      LiveData vs Flow 对比                                   │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  LiveData                              Flow                                 │
│  ────────                              ────                                 │
│  • 生命周期感知                         • 需要手动处理生命周期                  │
│  • 只在主线程                           • 支持任意线程                         │
│  • 只能持有最新值                        • 支持多值流                          │
│  • API 简单                             • 操作符丰富                          │
│  • 粘性（新观察者收到最新值）              • StateFlow 粘性，SharedFlow 可配置   │
│                                                                             │
│  适合：                                 适合：                                │
│  • 简单 UI 状态                         • 复杂数据流                          │
│  • 一次性数据                           • 需要操作符转换                       │
│  • 老项目                               • 新项目                              │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 详细对比

| 特性 | LiveData | StateFlow | SharedFlow |
|-----|----------|-----------|------------|
| 生命周期感知 | ✅ 内置 | ❌ 需配合 repeatOnLifecycle | ❌ 需配合 repeatOnLifecycle |
| 粘性（replay） | ✅ 始终有 | ✅ 始终有 | 可配置（0-n） |
| 初始值 | 可选 | 必须有 | 不需要 |
| 线程 | 主线程 | 任意线程 | 任意线程 |
| 操作符 | map/switchMap | 丰富（map/filter/combine...） | 丰富 |
| 背压处理 | 无 | 有 | 有 |

## 实战技巧

### 技巧一：加载状态统一封装

```kotlin
/**
 * 通用的 UI 状态封装
 */
sealed class UiState<out T> {
    object Loading : UiState<Nothing>()
    data class Success<T>(val data: T) : UiState<T>()
    data class Error(val message: String, val retry: (() -> Unit)? = null) : UiState<Nothing>()
}

// ViewModel 中使用
class ArticleViewModel(private val repository: ArticleRepository) : ViewModel() {
    
    private val _articles = MutableLiveData<UiState<List<Article>>>()
    val articles: LiveData<UiState<List<Article>>> = _articles
    
    fun loadArticles() {
        viewModelScope.launch {
            _articles.value = UiState.Loading
            
            try {
                val data = repository.getArticles()
                _articles.value = UiState.Success(data)
            } catch (e: Exception) {
                _articles.value = UiState.Error(
                    message = e.message ?: "加载失败",
                    retry = { loadArticles() }  // 提供重试方法
                )
            }
        }
    }
}

// UI 层统一处理
fun <T> Fragment.observeUiState(
    liveData: LiveData<UiState<T>>,
    onLoading: () -> Unit,
    onSuccess: (T) -> Unit,
    onError: (String, (() -> Unit)?) -> Unit
) {
    liveData.observe(viewLifecycleOwner) { state ->
        when (state) {
            is UiState.Loading -> onLoading()
            is UiState.Success -> onSuccess(state.data)
            is UiState.Error -> onError(state.message, state.retry)
        }
    }
}

// 使用
observeUiState(
    liveData = viewModel.articles,
    onLoading = { binding.progressBar.isVisible = true },
    onSuccess = { articles -> 
        binding.progressBar.isVisible = false
        adapter.submitList(articles)
    },
    onError = { message, retry ->
        binding.progressBar.isVisible = false
        Snackbar.make(binding.root, message, Snackbar.LENGTH_INDEFINITE)
            .setAction("重试") { retry?.invoke() }
            .show()
    }
)
```

### 技巧二：防止配置变更后重复请求

```kotlin
class SmartViewModel : ViewModel() {
    
    private val _user = MutableLiveData<User>()
    val user: LiveData<User> = _user
    
    // 记录是否已加载
    private var isLoaded = false
    
    fun loadUserIfNeeded() {
        if (isLoaded) return  // 已加载过，不重复请求
        
        viewModelScope.launch {
            val data = repository.getUser()
            _user.value = data
            isLoaded = true
        }
    }
    
    // 强制刷新（下拉刷新时使用）
    fun refresh() {
        isLoaded = false
        loadUserIfNeeded()
    }
}
```

### 技巧三：组合多个异步结果

```kotlin
class DashboardViewModel : ViewModel() {
    
    private val _dashboardData = MutableLiveData<DashboardData>()
    val dashboardData: LiveData<DashboardData> = _dashboardData
    
    fun loadDashboard() {
        viewModelScope.launch {
            // 并行加载多个数据
            val userDeferred = async { userRepository.getCurrentUser() }
            val ordersDeferred = async { orderRepository.getRecentOrders() }
            val notificationsDeferred = async { notificationRepository.getUnread() }
            
            // 等待所有结果
            val user = userDeferred.await()
            val orders = ordersDeferred.await()
            val notifications = notificationsDeferred.await()
            
            // 组合结果
            _dashboardData.value = DashboardData(
                user = user,
                recentOrders = orders,
                unreadCount = notifications.size
            )
        }
    }
}

    val user: User,
    val recentOrders: List<Order>,
    val unreadCount: Int
)
```

## 边界认知：LiveData 的局限性

### 1. 不适合高频数据

```kotlin
// ❌ 不适合：传感器数据、实时股价
// LiveData 没有背压处理，高频数据会堆积

// ✅ 应该用 Flow + buffer/conflate
sensorFlow
    .conflate()  // 丢弃中间值，只保留最新
    .collect { data -> updateUI(data) }
```

### 2. 不适合复杂转换

```kotlin
// ❌ LiveData 的 Transformations 功能有限
// 只有 map 和 switchMap

// ✅ Flow 的操作符丰富
flow
    .filter { it.isValid }
    .map { transform(it) }
    .debounce(300)
    .distinctUntilChanged()
    .catch { emit(fallback) }
    .collect { ... }
```

### 3. 粘性特性难以关闭

```kotlin
// LiveData 的粘性是内置的，无法关闭
// 对于一次性事件必须用 Event 包装

// Flow 可以选择
val stateFlow = MutableStateFlow(initial)  // 粘性
val sharedFlow = MutableSharedFlow<Event>(replay = 0)  // 非粘性
```

## 面试检验

### 进阶应用题

**Q1：什么是 LiveData 的"粘性事件"？怎么解决？**

> **答案**：粘性事件指新的观察者会立即收到 LiveData 的最新值，即使这个值已经被之前的观察者处理过。
> 
> 这对于状态数据（如用户名）是正确的，但对于一次性事件（如 Toast、导航）会导致重复执行。
> 
> 解决方案：
> 1. **Event 包装类**：包装数据，标记是否已处理，`getContentIfNotHandled()` 返回 null
> 2. **SingleLiveEvent**：只通知一个观察者（有多观察者问题）
> 3. **Channel/SharedFlow**：使用 `replay = 0` 的 SharedFlow 或 Channel

**Q2：map 和 switchMap 有什么区别？什么场景用哪个？**

> **答案**：
> - **map**：同步转换，返回值。`LiveData<A>` → `(A) -> B` → `LiveData<B>`
> - **switchMap**：动态切换数据源，返回 LiveData。`LiveData<A>` → `(A) -> LiveData<B>` → `LiveData<B>`
> 
> 使用场景：
> - map：格式化、类型转换、取部分字段
> - switchMap：根据参数加载不同数据（如根据 userId 加载用户详情）

**Q3：如何合并多个 LiveData 数据源？**

> **答案**：使用 `MediatorLiveData`：
> ```kotlin
> val merged = MediatorLiveData<Result>().apply {
>     addSource(sourceA) { a -> value = combine(a, sourceB.value) }
>     addSource(sourceB) { b -> value = combine(sourceA.value, b) }
> }
> ```
> 
> 也可以动态添加/移除数据源：`addSource()`、`removeSource()`

**Q4：LiveData 和 Kotlin Flow 该如何选择？**

> **答案**：
> 
> | 选 LiveData | 选 Flow |
> |------------|---------|
> | 简单 UI 状态 | 复杂数据流转换 |
> | 老项目兼容 | 新项目 |
> | 团队不熟悉 Flow | 需要丰富操作符 |
> | - | 一次性事件（Channel） |
> | - | 高频数据（背压处理） |
> 
> 折中方案：ViewModel 内部用 Flow，暴露 `asLiveData()` 给 UI。

**Q5：连续调用 postValue 会有什么问题？**

> **答案**：连续调用 postValue 只有最后一次会生效，中间的值会被覆盖。
> 
> 原因：postValue 是将更新任务 post 到主线程队列，多次调用时后面的会覆盖前面的 pending 值。
> 
> 如果需要每次都通知观察者，应该用 setValue（在主线程），或者改用 Channel/Flow。
