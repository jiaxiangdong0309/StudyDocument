# React Hooks 基础篇

> 全面掌握 useState、useEffect、useRef 三大基础 Hooks，以及 Hooks 的核心规则。

---

## 什么是 Hooks？

### 定义

**Hooks** 是 React 16.8 引入的特性，让你在**不编写类组件**的情况下使用 state 和其他 React 特性。

核心特点：
- **函数组件也能有状态**：以前只有类组件能用 `this.state`
- **逻辑复用更简单**：通过自定义 Hooks 共享逻辑，比高阶组件（HOC）和 Render Props 更直观
- **副作用管理更清晰**：`useEffect` 统一处理生命周期相关逻辑

### 通俗理解

**类组件时代的痛点**：
```typescript
// 类组件：复杂且难以复用逻辑
class Counter extends React.Component {
  constructor(props) {
    super(props);
    this.state = { count: 0 };
    this.handleClick = this.handleClick.bind(this); // 烦人的 bind
  }
  
  componentDidMount() {
    document.title = `点击了 ${this.state.count} 次`;
  }
  
  componentDidUpdate() {
    document.title = `点击了 ${this.state.count} 次`; // 重复代码
  }
  
  handleClick() {
    this.setState({ count: this.state.count + 1 });
  }
  
  render() {
    return <button onClick={this.handleClick}>{this.state.count}</button>;
  }
}
```

**Hooks 时代**：
```typescript
function Counter() {
  const [count, setCount] = useState(0);
  
  // 副作用自动同步
  useEffect(() => {
    document.title = `点击了 ${count} 次`;
  }, [count]);
  
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

**类比**：Hooks 就像给函数组件安装了「插件系统」，`useState` 是「状态插件」，`useEffect` 是「副作用插件」。

## 一、useState：组件的记忆

### 1.1 基本用法

```typescript
import { useState } from 'react';

function Counter() {
  // 声明一个状态变量
  const [count, setCount] = useState(0);
  //     ↑状态值  ↑更新函数      ↑初始值
  
  return (
    <div>
      <p>当前计数：{count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
    </div>
  );
}
```

**关键点**：
- `useState` 返回一个数组：`[当前值, 更新函数]`
- 约定用**数组解构**命名：`[xxx, setXxx]`
- 调用 `setCount` 会**触发重新渲染**

### 1.2 多个状态变量

```typescript
function UserProfile() {
  const [name, setName] = useState('Tom');
  const [age, setAge] = useState(18);
  const [isVip, setIsVip] = useState(false);
  
  return (
    <div>
      <p>{name}, {age}岁, {isVip ? 'VIP' : '普通用户'}</p>
      <button onClick={() => setAge(age + 1)}>过生日</button>
    </div>
  );
}
```

**为什么可以多次调用 useState？**  
React 通过**调用顺序**区分不同的 state（后面「Hooks 规则」会详细讲）。

### 1.3 状态的初始值

```typescript
// 简单值
const [count, setCount] = useState(0);

// 对象
const [user, setUser] = useState({ name: 'Tom', age: 18 });

// 数组
const [list, setList] = useState([1, 2, 3]);

// 惰性初始化（初始值计算复杂时使用）
const [data, setData] = useState(() => {
  // 只在首次渲染时执行
  const initialData = expensiveComputation();
  return initialData;
});
```

**什么时候用惰性初始化？**
```typescript
// ❌ 不好：每次渲染都执行，但只用第一次的结果
const [list, setList] = useState(Array(10000).fill(0));

// ✅ 好：只在挂载时执行一次
const [list, setList] = useState(() => Array(10000).fill(0));
```

### 1.4 更新状态的两种方式

#### 方式一：直接传新值

```typescript
const [count, setCount] = useState(0);

// 直接传新值
setCount(5); // count 变成 5
setCount(count + 1); // count 变成 6
```

#### 方式二：函数式更新（推荐）

```typescript
// 函数式更新：接收上一个状态，返回新状态
setCount(prevCount => prevCount + 1);
```

**什么时候必须用函数式更新？**

```typescript
function Counter() {
  const [count, setCount] = useState(0);
  
  const handleClick = () => {
    // ❌ 错误：连续调用，但只 +1
    setCount(count + 1); // count 是 0，设置成 1
    setCount(count + 1); // count 还是 0（闭包），又设置成 1
    setCount(count + 1); // 同上
    // 最终 count = 1（而不是 3）
    
    // ✅ 正确：每次基于最新的 state
    setCount(c => c + 1); // 1
    setCount(c => c + 1); // 2
    setCount(c => c + 1); // 3
    // 最终 count = 3
  };
  
  return <button onClick={handleClick}>{count}</button>;
}
```

**原理**：React 会**批量更新** state，多次 `setState` 会合并成一次渲染。函数式更新保证每次拿到最新值。

### 1.5 状态的不可变性 ⭐️

**核心原则**：永远不要直接修改 state，而是创建新的对象/数组。

#### 错误示范

```typescript
// ❌ 对象：直接修改
const [user, setUser] = useState({ name: 'Tom', age: 18 });
user.age = 19; // 不会触发重渲染！
setUser(user); // React 认为引用没变，不会更新

// ❌ 数组：直接修改
const [list, setList] = useState([1, 2, 3]);
list.push(4); // 不会触发重渲染！
setList(list);
```

#### 正确做法

```typescript
// ✅ 对象：展开运算符创建新对象
const [user, setUser] = useState({ name: 'Tom', age: 18 });
setUser({ ...user, age: 19 }); // 创建新对象

// ✅ 数组：使用不可变方法
const [list, setList] = useState([1, 2, 3]);

// 添加元素
setList([...list, 4]); // [1, 2, 3, 4]
setList([0, ...list]); // [0, 1, 2, 3]

// 删除元素
setList(list.filter(item => item !== 2)); // [1, 3]

// 修改元素
setList(list.map(item => item === 2 ? 20 : item)); // [1, 20, 3]

// 替换元素
const newList = [...list];
newList[1] = 20;
setList(newList);
```

#### 复杂嵌套对象

```typescript
const [user, setUser] = useState({
  name: 'Tom',
  address: {
    city: 'Beijing',
    street: 'Main St'
  }
});

// ❌ 错误：只展开了第一层
setUser({ ...user, address.city: 'Shanghai' }); // 语法错误

// ✅ 正确：逐层展开
setUser({
  ...user,
  address: {
    ...user.address,
    city: 'Shanghai'
  }
});

// 💡 更好：使用 immer 库（实战中推荐）
import { useImmer } from 'use-immer';

const [user, updateUser] = useImmer({
  name: 'Tom',
  address: { city: 'Beijing' }
});

// 可以直接"修改"（实际是 immer 帮你创建新对象）
updateUser(draft => {
  draft.address.city = 'Shanghai';
});
```

**为什么必须不可变？**
1. React 通过**引用比较**（`Object.is`）判断 state 是否变化
2. 直接修改不改变引用，React 认为没变化，不会重渲染
3. 不可变数据也利于时间旅行调试、撤销重做等功能

## 二、useEffect：处理副作用

### 2.1 什么是副作用？

**副作用（Side Effect）**：组件渲染之外的操作，如：
- **数据请求**：调用 API
- **订阅**：WebSocket、事件监听
- **操作 DOM**：修改标题、手动聚焦
- **定时器**：`setTimeout`、`setInterval`
- **日志**：上报埋点、打印调试信息

**为什么需要 useEffect？**  
函数组件每次渲染都是一次全新的函数调用，如果在组件体内直接写副作用：

```typescript
function Bad() {
  // ❌ 每次渲染都会执行！
  fetch('/api/user'); // 会导致无限请求
  document.title = 'xxx'; // 每次渲染都改标题
  
  return <div>...</div>;
}
```

`useEffect` 让你**控制副作用的执行时机**。

### 2.2 基本用法

```typescript
import { useEffect } from 'react';

useEffect(() => {
  // 副作用代码
  document.title = '新标题';
}, [依赖数组]);
```

**语法**：
- 第一个参数：副作用函数
- 第二个参数：依赖数组（决定何时执行）

### 2.3 依赖数组的三种情况

#### 情况一：没有依赖数组（几乎不用）

```typescript
useEffect(() => {
  console.log('每次渲染后都执行');
});
// ⚠️ 每次渲染后都执行，容易造成性能问题
```

#### 情况二：空依赖数组 `[]`（常用）

```typescript
useEffect(() => {
  console.log('只在挂载时执行一次');
  
  // 模拟 componentDidMount
  fetchUserData();
}, []); // 空数组表示不依赖任何变量
```

**常见用途**：
- 初始化数据请求
- 订阅（配合清理函数）
- 只执行一次的初始化

#### 情况三：有依赖 `[a, b, ...]`（最常用）

```typescript
function UserProfile({ userId }) {
  const [user, setUser] = useState(null);
  
  useEffect(() => {
    // userId 变化时重新请求
    fetchUser(userId).then(setUser);
  }, [userId]); // 依赖 userId
  
  return <div>{user?.name}</div>;
}
```

**规则**：依赖数组里必须包含副作用函数中用到的**所有外部变量**。

### 2.4 清理函数（Cleanup）

**为什么需要清理？**  
避免内存泄漏和意外行为（如组件卸载后定时器还在跑）。

```typescript
useEffect(() => {
  // 设置副作用
  const timer = setInterval(() => {
    console.log('tick');
  }, 1000);
  
  // 返回清理函数
  return () => {
    clearInterval(timer); // 在卸载时清理
  };
}, []);
```

**清理函数的执行时机**：
1. **组件卸载时**
2. **依赖变化导致副作用重新执行前**

```typescript
function Chat({ roomId }) {
  useEffect(() => {
    console.log(`连接到房间 ${roomId}`);
    const connection = connectToRoom(roomId);
    
    return () => {
      console.log(`断开房间 ${roomId}`);
      connection.disconnect();
    };
  }, [roomId]);
  
  return <div>聊天室: {roomId}</div>;
}

// roomId 从 'general' 变成 'tech' 时的执行顺序：
// 1. 断开房间 general（清理函数）
// 2. 连接到房间 tech（副作用函数）
```

### 2.5 常见副作用场景

#### 场景一：数据请求

```typescript
function UserList() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(false);
  
  useEffect(() => {
    setLoading(true);
    
    fetch('/api/users')
      .then(res => res.json())
      .then(data => {
        setUsers(data);
        setLoading(false);
      });
  }, []); // 只在挂载时请求一次
  
  if (loading) return <div>加载中...</div>;
  return <ul>{users.map(u => <li key={u.id}>{u.name}</li>)}</ul>;
}
```

#### 场景二:事件监听

```typescript
function MouseTracker() {
  const [position, setPosition] = useState({ x: 0, y: 0 });
  
  useEffect(() => {
    const handleMove = (e: MouseEvent) => {
      setPosition({ x: e.clientX, y: e.clientY });
    };
    
    window.addEventListener('mousemove', handleMove);
    
    // 清理函数：移除监听
    return () => {
      window.removeEventListener('mousemove', handleMove);
    };
  }, []); // 只绑定一次
  
  return <div>鼠标位置: {position.x}, {position.y}</div>;
}
```

#### 场景三：订阅与取消订阅

```typescript
function StockPrice({ symbol }) {
  const [price, setPrice] = useState(0);
  
  useEffect(() => {
    // 订阅股票价格
    const subscription = stockAPI.subscribe(symbol, newPrice => {
      setPrice(newPrice);
    });
    
    // 清理：取消订阅
    return () => {
      subscription.unsubscribe();
    };
  }, [symbol]); // symbol 变化时重新订阅
  
  return <div>{symbol}: ${price}</div>;
}
```

#### 场景四：定时器

```typescript
function Timer() {
  const [seconds, setSeconds] = useState(0);
  
  useEffect(() => {
    const timer = setInterval(() => {
      setSeconds(s => s + 1);
    }, 1000);
    
    return () => clearInterval(timer); // 清理定时器
  }, []);
  
  return <div>已运行: {seconds}秒</div>;
}
```

### 2.6 依赖数组的常见错误

#### 错误一：遗漏依赖

```typescript
function Bad({ userId }) {
  const [user, setUser] = useState(null);
  
  useEffect(() => {
    fetchUser(userId).then(setUser); // 用了 userId
  }, []); // ❌ 但依赖数组是空的
  
  // 问题：userId 变化时不会重新请求
}

// ✅ 正确
useEffect(() => {
  fetchUser(userId).then(setUser);
}, [userId]); // 包含所有依赖
```

**如何检查？**  
安装 ESLint 插件 `eslint-plugin-react-hooks`，它会自动提示遗漏的依赖。

#### 错误二：依赖总是变化（引用类型）

```typescript
function Bad() {
  const options = { page: 1, size: 10 }; // ❌ 每次渲染都是新对象
  
  useEffect(() => {
    fetchData(options);
  }, [options]); // 每次渲染 options 引用都变了，导致无限循环
}

// ✅ 解决方案一：把对象定义在 useEffect 内部
useEffect(() => {
  const options = { page: 1, size: 10 };
  fetchData(options);
}, []);

// ✅ 解决方案二：用 useMemo 缓存
const options = useMemo(() => ({ page: 1, size: 10 }), []);
useEffect(() => {
  fetchData(options);
}, [options]);
```

#### 错误三：在 useEffect 里操作 state 但不加依赖

```typescript
function Counter() {
  const [count, setCount] = useState(0);
  
  useEffect(() => {
    const timer = setInterval(() => {
      setCount(count + 1); // ❌ 闭包陷阱：count 永远是 0
    }, 1000);
    return () => clearInterval(timer);
  }, []); // count 没加到依赖里
  
  return <div>{count}</div>;
  // 结果：count 只从 0 变到 1，然后不再变化
}

// ✅ 解决方案一：加依赖（但会导致定时器频繁重建）
useEffect(() => {
  const timer = setInterval(() => {
    setCount(count + 1);
  }, 1000);
  return () => clearInterval(timer);
}, [count]); // 加上依赖

// ✅ 解决方案二：函数式更新（推荐）
useEffect(() => {
  const timer = setInterval(() => {
    setCount(c => c + 1); // 不依赖外部 count
  }, 1000);
  return () => clearInterval(timer);
}, []); // 依赖为空
```

### 2.7 useEffect 的执行时机

```typescript
function App() {
  const [count, setCount] = useState(0);
  
  console.log('1. 渲染阶段');
  
  useEffect(() => {
    console.log('3. useEffect 执行（在 DOM 更新后）');
  });
  
  return (
    <div>
      <button onClick={() => setCount(count + 1)}>点击</button>
      {console.log('2. return（React 开始操作 DOM）')}
    </div>
  );
}

// 点击按钮后的执行顺序：
// 1. 渲染阶段
// 2. return（React 开始操作 DOM）
// 3. useEffect 执行（在 DOM 更新后）
```

**关键点**：
- `useEffect` 在**浏览器绘制之后**异步执行，不阻塞渲染
- 如果需要**同步**执行（如测量 DOM），用 `useLayoutEffect`（但通常不需要）

## 三、useRef：持久化引用

### 3.1 useRef 是什么？

`useRef` 返回一个**可变的 ref 对象**，其 `.current` 属性可以存储任何值，且：
- **修改 `.current` 不会触发重渲染**
- **跨渲染保持同一个引用**

### 3.2 用途一：获取 DOM 元素

```typescript
import { useRef, useEffect } from 'react';

function AutoFocusInput() {
  const inputRef = useRef<HTMLInputElement>(null);
  
  useEffect(() => {
    // 挂载后自动聚焦
    inputRef.current?.focus();
  }, []);
  
  return <input ref={inputRef} type="text" />;
}
```

**更多 DOM 操作示例**：

```typescript
function VideoPlayer({ src }) {
  const videoRef = useRef<HTMLVideoElement>(null);
  
  const play = () => videoRef.current?.play();
  const pause = () => videoRef.current?.pause();
  
  return (
    <div>
      <video ref={videoRef} src={src} />
      <button onClick={play}>播放</button>
      <button onClick={pause}>暂停</button>
    </div>
  );
}
```

### 3.3 用途二：存储不触发渲染的值

```typescript
function Timer() {
  const [seconds, setSeconds] = useState(0);
  const timerRef = useRef<number>(); // 存储定时器 ID
  
  const start = () => {
    timerRef.current = setInterval(() => {
      setSeconds(s => s + 1);
    }, 1000);
  };
  
  const stop = () => {
    clearInterval(timerRef.current);
  };
  
  return (
    <div>
      <div>{seconds}秒</div>
      <button onClick={start}>开始</button>
      <button onClick={stop}>停止</button>
    </div>
  );
}
```

**为什么不用 useState 存定时器 ID？**
- `useState` 会触发重渲染（不需要）
- `useRef` 只是存个值，不影响 UI

### 3.4 用途三：记录上一次的值

```typescript
function usePrevious<T>(value: T) {
  const ref = useRef<T>();
  
  useEffect(() => {
    ref.current = value; // 渲染后更新
  });
  
  return ref.current; // 返回上一次的值
}

// 使用
function Counter() {
  const [count, setCount] = useState(0);
  const prevCount = usePrevious(count);
  
  return (
    <div>
      <p>当前: {count}</p>
      <p>上一次: {prevCount}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
    </div>
  );
}
```

### 3.5 useRef vs useState

| 特性 | useRef | useState |
|------|--------|----------|
| 修改后是否触发渲染 | ❌ 不会 | ✅ 会 |
| 是否跨渲染保持引用 | ✅ 是 | ❌ 否（每次渲染是新的状态快照） |
| 读取最新值 | 总能拿到最新的 `.current` | 可能有闭包陷阱 |
| 典型用途 | DOM 引用、定时器 ID、缓存 | UI 状态 |

**闭包陷阱示例**：

```typescript
function Bad() {
  const [count, setCount] = useState(0);
  
  const handleClick = () => {
    setTimeout(() => {
      console.log(count); // ❌ 打印的是点击时的 count（闭包）
    }, 3000);
  };
  
  return (
    <div>
      <p>{count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
      <button onClick={handleClick}>3秒后打印</button>
    </div>
  );
}

// 解决方案：用 useRef
function Good() {
  const [count, setCount] = useState(0);
  const countRef = useRef(count);
  
  useEffect(() => {
    countRef.current = count; // 同步最新值到 ref
  }, [count]);
  
  const handleClick = () => {
    setTimeout(() => {
      console.log(countRef.current); // ✅ 总是最新的
    }, 3000);
  };
  
  return (
    <div>
      <p>{count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
      <button onClick={handleClick}>3秒后打印</button>
    </div>
  );
}
```

## 四、Hooks 的规则 ⭐️

### 4.1 规则一：只能在顶层调用

**❌ 错误示范**：

```typescript
function Bad({ isLogin }) {
  if (isLogin) {
    const [user, setUser] = useState(null); // ❌ 不能在条件里
  }
  
  for (let i = 0; i < 3; i++) {
    useEffect(() => { /* ... */ }); // ❌ 不能在循环里
  }
  
  const handleClick = () => {
    const [count, setCount] = useState(0); // ❌ 不能在函数里
  };
}
```

**✅ 正确做法**：

```typescript
function Good({ isLogin }) {
  const [user, setUser] = useState(null); // ✅ 在顶层
  
  useEffect(() => {
    // 条件逻辑写在 Hook 内部
    if (isLogin) {
      fetchUser();
    }
  }, [isLogin]);
}
```

**为什么有这个规则？**  
React 通过**调用顺序**识别每个 Hook：

```typescript
// 第一次渲染
useState(0);     // Hook 1
useState('');    // Hook 2
useEffect(() => {}); // Hook 3

// 如果第二次渲染时跳过 Hook 1
useState('');    // 原本是 Hook 2，现在变成 Hook 1 ❌ 乱了
useEffect(() => {}); // 原本是 Hook 3，现在变成 Hook 2 ❌ 乱了
```

React 内部用**链表**存储 Hooks，按顺序读取。条件调用会破坏顺序。

### 4.2 规则二：只能在 React 函数中调用

**✅ 可以调用的地方**：
- React 函数组件
- 自定义 Hooks

**❌ 不能调用的地方**：
- 普通 JavaScript 函数
- 类组件

```typescript
// ❌ 错误
function normalFunction() {
  const [count, setCount] = useState(0); // 不是 React 组件
}

// ✅ 正确：React 组件
function MyComponent() {
  const [count, setCount] = useState(0);
}

// ✅ 正确：自定义 Hook
function useCounter() {
  const [count, setCount] = useState(0);
  return { count, setCount };
}
```

### 案例一：表单管理

```typescript
function LoginForm() {
  const [form, setForm] = useState({
    username: '',
    password: ''
  });
  const [errors, setErrors] = useState<Record<string, string>>({});
  
  const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    const { name, value } = e.target;
    setForm(prev => ({ ...prev, [name]: value }));
    
    // 清除该字段的错误
    if (errors[name]) {
      setErrors(prev => {
        const newErrors = { ...prev };
        delete newErrors[name];
        return newErrors;
      });
    }
  };
  
  const handleSubmit = (e: React.FormEvent) => {
    e.preventDefault();
    
    // 验证
    const newErrors: Record<string, string> = {};
    if (!form.username) newErrors.username = '请输入用户名';
    if (!form.password) newErrors.password = '请输入密码';
    
    if (Object.keys(newErrors).length > 0) {
      setErrors(newErrors);
      return;
    }
    
    // 提交
    console.log('提交:', form);
  };
  
  return (
    <form onSubmit={handleSubmit}>
      <div>
        <input
          name="username"
          value={form.username}
          onChange={handleChange}
          placeholder="用户名"
        />
        {errors.username && <span style={{color: 'red'}}>{errors.username}</span>}
      </div>
      
      <div>
        <input
          name="password"
          type="password"
          value={form.password}
          onChange={handleChange}
          placeholder="密码"
        />
        {errors.password && <span style={{color: 'red'}}>{errors.password}</span>}
      </div>
      
      <button type="submit">登录</button>
    </form>
  );
}
```

### 案例二：数据请求 + Loading 状态

```typescript
interface User {
  id: number;
  name: string;
}

function UserList() {
  const [users, setUsers] = useState<User[]>([]);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState<string | null>(null);
  
  useEffect(() => {
    let cancelled = false; // 处理竞态条件
    
    const fetchUsers = async () => {
      setLoading(true);
      setError(null);
      
      try {
        const res = await fetch('/api/users');
        if (!res.ok) throw new Error('请求失败');
        
        const data = await res.json();
        
        if (!cancelled) {
          setUsers(data);
        }
      } catch (err) {
        if (!cancelled) {
          setError(err instanceof Error ? err.message : '未知错误');
        }
      } finally {
        if (!cancelled) {
          setLoading(false);
        }
      }
    };
    
    fetchUsers();
    
    // 清理函数：组件卸载时取消请求
    return () => {
      cancelled = true;
    };
  }, []);
  
  if (loading) return <div>加载中...</div>;
  if (error) return <div style={{color: 'red'}}>错误: {error}</div>;
  
  return (
    <ul>
      {users.map(user => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}
```

### 案例三：防抖输入搜索

function SearchBox() {
  const [query, setQuery] = useState('');
  const [results, setResults] = useState<string[]>([]);
  
  useEffect(() => {
    // 防抖：500ms 后才执行搜索
    const timer = setTimeout(() => {

        // 模拟搜索
        fetch(`/api/search?q=${query}`)
          .then(res => res.json())
          .then(setResults);
      } else {
        setResults([]);
      }

    // 清理：query 变化时清除上一个定时器
    return () => clearTimeout(timer);
  }, [query]); // query 变化时重新设置定时器
  
  return (
    <div>
      <input
        value={query}
        onChange={e => setQuery(e.target.value)}
        placeholder="搜索..."
      />
      <ul>
        {results.map((item, i) => (
          <li key={i}>{item}</li>
        ))}
      </ul>
    </div>
  );
}

## 六、常见问题与陷阱

### Q1：为什么我的 useEffect 执行了两次？

**原因**：React 18 在**开发模式**下，会故意执行两次副作用，帮你发现问题。

```typescript
useEffect(() => {
  console.log('执行'); // 开发模式下会打印两次
}, []);
```

**解决**：
- 这是预期行为，帮你检查清理函数是否正确
- 生产环境只执行一次
- 如果副作用不幂等（如重复提交表单），说明代码需要优化

### Q2：setState 后立即读取，为什么还是旧值？

```typescript
const [count, setCount] = useState(0);

const handleClick = () => {
  setCount(count + 1);
  console.log(count); // ❌ 还是 0（不是 1）
};
```

**原因**：`setState` 是**异步**的，立即读取拿到的是当前渲染的快照。

**解决**：
```typescript
// 方案一：用 useEffect 监听变化
useEffect(() => {
  console.log('count 变成了', count);
}, [count]);

// 方案二：函数式更新
setCount(prevCount => {
  const newCount = prevCount + 1;
  console.log('新值是', newCount);
  return newCount;
});
```

### Q3：为什么不能在 useEffect 里直接写 async 函数？

```typescript
// ❌ 错误
useEffect(async () => {
  const data = await fetchData();
  setData(data);
}, []);
```

**原因**：`useEffect` 期望返回「清理函数」或「undefined」，但 async 函数返回 Promise。

**解决**：

```typescript
// ✅ 方案一：内部定义 async 函数
useEffect(() => {
  const fetchData = async () => {
    const data = await fetch('/api/data').then(r => r.json());
    setData(data);
  };
  fetchData();
}, []);

// ✅ 方案二：立即执行的 async 函数
useEffect(() => {
  (async () => {
    const data = await fetch('/api/data').then(r => r.json());
    setData(data);
  })();
}, []);
```

## 七、面试检验题

### 题目 1：说说 useState 的批量更新机制

**答案要点**：
1. **什么是批量更新**：多次 `setState` 合并成一次渲染，避免频繁重渲染
2. **React 18 之前**：只在事件处理函数里批量更新，`setTimeout`/Promise 里不会
3. **React 18**：自动批量更新（Automatic Batching），所有地方都会批量
4. **如何强制同步**：用 `flushSync` 包裹（很少用）

### 题目 2：useEffect 的清理函数什么时候执行？

**答案要点**：
1. **组件卸载时**
2. **依赖变化导致副作用重新执行前**（先清理旧的，再执行新的）
3. **典型场景**：取消订阅、清除定时器、断开连接

### 题目 3：如何避免 useEffect 的无限循环？

**答案要点**：
1. **原因**：依赖数组里的引用类型每次渲染都是新的（如对象、数组、函数）
2. **解决**：
   - 把对象/数组定义在 `useEffect` 内部
   - 用 `useMemo` 缓存对象/数组
   - 只依赖基本类型（如 `userId` 而不是 `{ userId }`）
   - 用 `useCallback` 缓存函数

### 题目 4：useRef 和 useState 有什么区别？

**答案要点**：
1. **触发渲染**：`useRef` 不会，`useState` 会
2. **引用稳定性**：`useRef.current` 是同一个对象，`useState` 每次渲染是新快照
3. **使用场景**：
   - `useRef`：DOM 引用、存储定时器 ID、记录上次值
   - `useState`：UI 状态

### 题目 5：为什么 Hooks 不能写在条件判断里？

**答案要点**：
1. **原因**：React 通过**调用顺序**识别每个 Hook
2. **实现**：内部用**链表**存储 Hooks，按顺序读取
3. **后果**：条件调用会导致前后顺序不一致，状态错乱
4. **正确做法**：Hooks 写在顶层，条件逻辑写在 Hook 内部

## 总结

### 核心要点

| Hook | 用途 | 关键点 |
|------|------|--------|
| `useState` | 状态管理 | 不可变更新、函数式更新 |
| `useEffect` | 副作用管理 | 依赖数组、清理函数 |
| `useRef` | 持久化引用 | 不触发渲染、获取 DOM |

3. **避免陷阱**：闭包陷阱、无限循环、引用类型依赖
4. **看进阶篇**：学习 `useReducer`、自定义 Hooks、性能优化
