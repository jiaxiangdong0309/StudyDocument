# Activity 进阶篇

## 启动模式深入理解

### 为什么需要启动模式？

想象你在用一个 App：

```
场景1：从首页跳转到商品详情页，再跳转到另一个商品详情页...
问题：返回时要一页一页退出，用户体验差

场景2：从任何页面跳转到登录页
问题：登录成功后，按返回键又回到登录页？

场景3：从首页打开设置页，再从设置页打开首页
问题：首页被创建两次，内存浪费
```

启动模式就是为了解决这些问题——**控制 Activity 实例的创建和复用策略**。

### 任务栈（Task）基础

在理解启动模式之前，必须先理解任务栈：

```
┌─────────────────────────────────────────────────────────────────┐
│                        任务栈 (Task)                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   任务栈就像一摞盘子，后放的在上面，先拿走的也是上面的            │
│                                                                 │
│        ┌─────────┐                                              │
│        │ 详情页C │  ← 栈顶（当前显示）                           │
│        ├─────────┤                                              │
│        │ 详情页B │                                              │
│        ├─────────┤                                              │
│        │ 列表页  │                                              │
│        ├─────────┤                                              │
│        │ 首页    │  ← 栈底                                      │
│        └─────────┘                                              │
│                                                                 │
│   用户按返回键：详情页C 出栈销毁 → 详情页B 显示                   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**关键概念**：
- **Task**：一组相关联的 Activity 集合
- **TaskAffinity**：任务亲和性，决定 Activity 属于哪个任务
- **Back Stack**：返回栈，管理用户的导航历史

### 四种启动模式详解

#### 1. standard（标准模式）

**特点**：每次都创建新实例，不管栈中是否已存在

```
启动 A → A
再启动 A → A → A'
再启动 A → A → A' → A''

栈：[A, A', A''] ← 三个独立实例
```

**适用场景**：大多数普通页面，如商品详情页、文章页

```kotlin
// 默认就是 standard，不需要特别声明
<activity android:name=".DetailActivity" />

// 或者显式声明
<activity 
    android:name=".DetailActivity"
    android:launchMode="standard" />
```

#### 2. singleTop（栈顶复用）

**特点**：如果栈顶已经是目标 Activity，则复用它，调用 `onNewIntent`

```
栈：[A, B]
启动 B → 复用栈顶 B，调用 B.onNewIntent()
栈：[A, B] ← 还是两个

栈：[A, B]
启动 A → 创建新 A（因为 A 不在栈顶）
栈：[A, B, A']
```

**适用场景**：
- 通知点击跳转的页面（避免重复创建）
- 搜索结果页（刷新而非新建）

```kotlin
<activity 
    android:name=".SearchResultActivity"
    android:launchMode="singleTop" />

// 接收新 Intent
class SearchResultActivity : AppCompatActivity() {
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        handleIntent(intent)
    }
    
    // 复用时会调用这个方法
    override fun onNewIntent(intent: Intent) {
        super.onNewIntent(intent)
        // 更新 intent，否则 getIntent() 返回的还是旧的
        setIntent(intent)
        handleIntent(intent)
    }
    
    private fun handleIntent(intent: Intent) {
        val query = intent.getStringExtra("query")
        // 执行搜索
    }
}
```

#### 3. singleTask（栈内复用）

**特点**：
- 整个任务栈中只有一个实例
- 如果已存在，会把它上面的所有 Activity 清除（clearTop 效果）
- 会调用 `onNewIntent`

```
栈：[A, B, C, D]
启动 B（singleTask）
→ 找到 B，清除 B 上面的 C、D
→ 调用 B.onNewIntent()
栈：[A, B]
```

**适用场景**：
- 应用主页（从任何地方返回主页）
- 浏览器的主 Activity

```kotlin
<activity 
    android:name=".MainActivity"
    android:launchMode="singleTask" />

// 从任何页面跳转到主页并清空上面的页面
fun goToMain() {
    val intent = Intent(this, MainActivity::class.java)
    // 这两个 flag 配合 singleTask 效果更明确
    intent.flags = Intent.FLAG_ACTIVITY_CLEAR_TOP or Intent.FLAG_ACTIVITY_SINGLE_TOP
    startActivity(intent)
}
```

#### 4. singleInstance（单实例）

**特点**：
- 独占一个任务栈，这个栈里只有它一个
- 全局唯一实例

```
App1 启动 A(singleInstance)
→ 创建新任务栈 Task2，放入 A

App2 启动 A(singleInstance)
→ 复用 Task2 中的 A，调用 onNewIntent

Task1: [首页, 列表]
Task2: [A]  ← A 独占一个栈
```

**适用场景**：
- 系统级页面（如来电界面）
- 需要全局共享的页面（如悬浮窗控制页）

```kotlin
<activity 
    android:name=".CallActivity"
    android:launchMode="singleInstance" />
```

### 启动模式对比

| 模式 | 是否创建新实例 | 是否独占任务栈 | 调用 onNewIntent | 典型场景 |
|-----|--------------|--------------|-----------------|---------|
| standard | 总是 | 否 | 否 | 普通页面 |
| singleTop | 栈顶时不创建 | 否 | 栈顶复用时 | 通知跳转、搜索结果 |
| singleTask | 栈内有则不创建 | 否 | 栈内复用时 | 主页、浏览器主页 |
| singleInstance | 有则不创建 | 是 | 复用时 | 来电界面、悬浮窗 |

### Intent Flags

除了在 Manifest 中声明，还可以通过 Intent Flags 动态控制：

```kotlin
val intent = Intent(this, TargetActivity::class.java)

// FLAG_ACTIVITY_NEW_TASK：在新任务栈中启动
// 常用于从 Service 启动 Activity
intent.addFlags(Intent.FLAG_ACTIVITY_NEW_TASK)

// FLAG_ACTIVITY_CLEAR_TOP：清除目标之上的所有 Activity
// 类似 singleTask 的效果
intent.addFlags(Intent.FLAG_ACTIVITY_CLEAR_TOP)

// FLAG_ACTIVITY_SINGLE_TOP：等同于 singleTop
intent.addFlags(Intent.FLAG_ACTIVITY_SINGLE_TOP)

// 组合使用：跳转到主页并清空返回栈
intent.flags = Intent.FLAG_ACTIVITY_NEW_TASK or 
               Intent.FLAG_ACTIVITY_CLEAR_TASK

startActivity(intent)
```

### TaskAffinity 详解

TaskAffinity 决定 Activity "想要"属于哪个任务：

```kotlin
<!-- 默认 affinity 是包名 -->
<activity android:name=".MainActivity" />  <!-- affinity = "com.example.app" -->

<!-- 自定义 affinity -->
<activity 
    android:name=".ShareActivity"
    android:taskAffinity="com.example.share"
    android:launchMode="singleTask" />
```

**注意**：TaskAffinity 只有和 `singleTask`、`allowTaskReparenting` 或 `FLAG_ACTIVITY_NEW_TASK` 配合才生效。

## 状态保存与恢复进阶

### 三种状态保存机制对比

| 机制 | 存活范围 | 数据大小限制 | 适用数据 |
|-----|---------|-------------|---------|
| onSaveInstanceState | 配置变更、进程死亡 | ~1MB | UI 状态、少量数据 |
| ViewModel | 配置变更 | 无限制 | 业务数据、UI 状态 |
| Persistent Storage | 永久 | 无限制 | 需要持久化的数据 |

```
┌─────────────────────────────────────────────────────────────────┐
│                    状态保存机制选择                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   用户输入的临时数据？                                           │
│      │                                                          │
│      ├── 是 → 需要跨进程恢复？                                  │
│      │         │                                                │
│      │         ├── 是 → onSaveInstanceState                    │
│      │         │                                                │
│      │         └── 否 → ViewModel                              │
│      │                                                          │
│      └── 否 → 需要永久保存？                                    │
│                │                                                │
│                ├── 是 → Room/DataStore                         │
│                │                                                │
│                └── 否 → ViewModel 或内存缓存                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### SavedStateHandle（推荐方案）

结合 ViewModel 和 SavedState 的优点：

```kotlin
// 添加依赖
// implementation("androidx.lifecycle:lifecycle-viewmodel-savedstate:2.7.0")

class MyViewModel(
    private val savedStateHandle: SavedStateHandle
) : ViewModel() {
    
    // 自动保存到 SavedState，配置变更和进程死亡都能恢复
    var searchQuery: String
        get() = savedStateHandle["query"] ?: ""
        set(value) { savedStateHandle["query"] = value }
    
    // 也可以作为 LiveData 使用
    val queryLiveData: MutableLiveData<String> = 
        savedStateHandle.getLiveData("query", "")
}

// Activity 中使用
class SearchActivity : AppCompatActivity() {
    
    // by viewModels() 会自动注入 SavedStateHandle
    private val viewModel: MyViewModel by viewModels()
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        // 无需手动处理 onSaveInstanceState
        searchInput.setText(viewModel.searchQuery)
        
        searchInput.doAfterTextChanged {
            viewModel.searchQuery = it.toString()
        }
    }
}
```

## 多窗口与画中画

### 多窗口模式（Multi-Window）

Android 7.0+ 支持分屏显示多个应用。

```kotlin
<activity
    android:name=".MainActivity"
    android:resizeableActivity="true"  <!-- 允许调整大小 -->
    android:supportsPictureInPicture="true">  <!-- 支持画中画 -->
</activity>

class MainActivity : AppCompatActivity() {
    
    override fun onMultiWindowModeChanged(
        isInMultiWindowMode: Boolean,
        newConfig: Configuration
    ) {
        super.onMultiWindowModeChanged(isInMultiWindowMode, newConfig)
        
        if (isInMultiWindowMode) {
            // 进入多窗口模式：隐藏非必要 UI，优化布局
            toolbar.visibility = View.GONE
        } else {
            // 退出多窗口模式：恢复完整 UI
            toolbar.visibility = View.VISIBLE
        }
    }
    
    // 检查是否在多窗口模式
    private fun checkMultiWindow() {
        if (isInMultiWindowMode) {
            // 调整布局
        }
    }
}
```

### 画中画模式（Picture-in-Picture）

Android 8.0+ 支持视频播放等场景的画中画：

```kotlin
class VideoActivity : AppCompatActivity() {
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_video)
    }
    
    // 用户按 Home 键时进入画中画
    override fun onUserLeaveHint() {
        super.onUserLeaveHint()
        enterPipMode()
    }
    
    private fun enterPipMode() {
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
            val params = PictureInPictureParams.Builder()
                .setAspectRatio(Rational(16, 9))  // 16:9 比例
                .build()
            
            enterPictureInPictureMode(params)
        }
    }
    
    override fun onPictureInPictureModeChanged(
        isInPictureInPictureMode: Boolean,
        newConfig: Configuration
    ) {
        super.onPictureInPictureModeChanged(isInPictureInPictureMode, newConfig)
        
        if (isInPictureInPictureMode) {
            // 进入画中画：隐藏控制按钮，只显示视频
            playerControls.visibility = View.GONE
        } else {
            // 退出画中画：显示完整控制界面
            playerControls.visibility = View.VISIBLE
        }
    }
}
```

### 优化策略

#### 1. Application 优化

```kotlin
class MyApplication : Application() {
    
    override fun onCreate() {
        super.onCreate()

        // initSDK1()
        // initSDK2()

        }.start()

    }
```

```kotlin
class MainActivity : AppCompatActivity() {

        // 在 super.onCreate 之前设置主题，避免白屏
        setTheme(R.style.AppTheme)
        super.onCreate(savedInstanceState)

        val binding = ActivityMainBinding.inflate(layoutInflater)
        setContentView(binding.root)

        binding.root.post {

        }

}
```

## 横向对比

### Activity vs Fragment

| 特性 | Activity | Fragment |
|-----|----------|----------|
| 独立性 | 完全独立，有自己的窗口 | 依附于 Activity |
| 生命周期 | 由系统管理 | 由宿主 Activity 管理 |
| 通信 | Intent | 直接引用/ViewModel/接口 |
| 返回栈 | 系统管理 | 需要手动管理 FragmentManager |
| 复杂度 | 简单 | 生命周期更复杂 |
| 适用场景 | 独立页面 | 界面模块化、平板适配 |

### Activity vs Compose

```kotlin
// 传统 Activity + View
class TraditionalActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_main)
        
        val button = findViewById<Button>(R.id.button)
        button.setOnClickListener { /* ... */ }
    }
}

// Compose Activity
class ComposeActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContent {
            MyTheme {
                // 声明式 UI
                Button(onClick = { /* ... */ }) {
                    Text("Click me")
                }
            }
        }
    }
}
```

**Compose 中 Activity 的角色变化**：

| 方面 | 传统方式 | Compose 方式 |
|-----|---------|-------------|
| UI 定义 | XML + Activity/Fragment | Composable 函数 |
| 状态管理 | Activity 持有状态 | 状态提升、ViewModel |
| 导航 | Activity 切换 | Navigation Compose（单 Activity） |
| Activity 角色 | UI 容器 + 逻辑 | 仅作为入口容器 |

## 边界认知

### Activity 的局限性

**1. 大量 Activity 切换性能问题**

```
问题：频繁 startActivity 导致卡顿
原因：每次切换都涉及 IPC 通信、View 层级创建
解决：使用 Fragment 替代内部页面切换
```

**2. 深层页面栈问题**

```
问题：栈太深导致按返回键退出时间长
场景：电商 App 首页→分类→商品→评价→用户→商品→...
解决：
- 合理设计导航，避免过深
- 使用 singleTask 清空不必要的页面
- 考虑使用 Navigation Component
```

**3. 配置变更处理复杂**

```
问题：屏幕旋转、语言切换导致 Activity 重建
影响：数据丢失、网络请求重复
解决：
- ViewModel 保持数据
- SavedStateHandle 保持 UI 状态
- 必要时使用 configChanges（但不推荐滥用）
```

### 什么时候不该用 Activity

| 场景 | 为什么不用 Activity | 替代方案 |
|-----|-------------------|---------|
| Tab 页切换 | 创建销毁开销大 | Fragment/ViewPager |
| 底部弹窗 | 过于重量级 | BottomSheetDialogFragment |
| 小型对话框 | 完全没必要 | AlertDialog |
| 应用内导航 | 单 Activity 更高效 | Navigation Component |

## 实战经验

### 1. 登录态管理

```kotlin
// 方案：使用 singleTask 主页 + 启动拦截
object LoginManager {
    var isLoggedIn = false
    
    // 检查登录态的启动拦截
    fun startActivityWithLogin(
        context: Context,
        intent: Intent,
        needLogin: Boolean = true
    ) {
        if (needLogin && !isLoggedIn) {
            // 保存目标 Intent，登录后再跳转
            val loginIntent = Intent(context, LoginActivity::class.java)
            loginIntent.putExtra("targetIntent", intent)
            context.startActivity(loginIntent)
        } else {
            context.startActivity(intent)
        }
    }
}

// LoginActivity
class LoginActivity : AppCompatActivity() {
    
    private fun onLoginSuccess() {
        // 登录成功，跳转到原目标
        val targetIntent = intent.getParcelableExtra<Intent>("targetIntent")
        if (targetIntent != null) {
            startActivity(targetIntent)
        } else {
            // 没有目标，跳转主页
            startActivity(Intent(this, MainActivity::class.java))
        }
        finish()
    }
}
```

### 2. 退出应用的正确姿势

```kotlin
// ❌ 错误方式：强制杀进程（可能导致数据丢失）
// System.exit(0)
// android.os.Process.killProcess(android.os.Process.myPid())

// ✅ 正确方式1：清空任务栈回到主页，主页 finish
class MainActivity : AppCompatActivity() {
    
    private var backPressedTime = 0L
    
    override fun onBackPressed() {
        if (System.currentTimeMillis() - backPressedTime < 2000) {
            super.onBackPressed()  // 真正退出
        } else {
            backPressedTime = System.currentTimeMillis()
            Toast.makeText(this, "再按一次退出", Toast.LENGTH_SHORT).show()
        }
    }
}

// ✅ 正确方式2：使用 finishAffinity
fun exitApp() {
    finishAffinity()  // 关闭同一任务栈的所有 Activity
}

// ✅ 正确方式3：从任何页面安全退出
fun exitFromAnywhere(activity: Activity) {
    val intent = Intent(activity, MainActivity::class.java)
    intent.flags = Intent.FLAG_ACTIVITY_CLEAR_TOP or Intent.FLAG_ACTIVITY_SINGLE_TOP
    intent.putExtra("exit", true)
    activity.startActivity(intent)
}

// MainActivity 中处理
override fun onNewIntent(intent: Intent) {
    super.onNewIntent(intent)
    if (intent.getBooleanExtra("exit", false)) {
        finish()
    }
}
```

### 3. 处理 Activity 被杀恢复

```kotlin
class RobustActivity : AppCompatActivity() {
    
    private val viewModel: MyViewModel by viewModels()
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_robust)
        
        // 检查是否是从被杀状态恢复
        if (savedInstanceState != null) {
            // 可能需要重新加载数据
            val wasKilled = savedInstanceState.getBoolean("wasInitialized", false)
            if (wasKilled && viewModel.data.value == null) {
                // ViewModel 数据也丢了（进程被杀），需要重新加载
                viewModel.loadData()
            }
        } else {
            // 首次创建
            viewModel.loadData()
        }
    }
    
    override fun onSaveInstanceState(outState: Bundle) {
        super.onSaveInstanceState(outState)
        outState.putBoolean("wasInitialized", true)
    }
}
```

## 面试检验

### 进阶题

**Q1: 四种启动模式的区别？分别适用什么场景？**

> **答案**：
> - **standard**：每次创建新实例，适用于普通页面如商品详情
> - **singleTop**：栈顶存在则复用，适用于通知跳转、搜索结果
> - **singleTask**：栈内存在则复用并清除上方，适用于主页
> - **singleInstance**：独占任务栈，适用于来电界面等系统级页面

**Q2: onSaveInstanceState 和 ViewModel 有什么区别？如何选择？**

> **答案**：
> - **onSaveInstanceState**：存活范围广（包括进程死亡），但有大小限制（约 1MB），适合存储 UI 状态
> - **ViewModel**：只在配置变更时存活，无大小限制，适合存储业务数据
> - **选择原则**：UI 状态用 SavedStateHandle（结合了两者优点），业务数据用 ViewModel，需要持久化的用数据库

**Q3: 如何优化 Activity 的启动速度？**

> **答案**：
> 1. **Application 优化**：延迟/异步初始化非必要 SDK
> 2. **布局优化**：减少嵌套层级，使用 ViewStub 延迟加载
> 3. **启动页优化**：使用 windowBackground 避免白屏
> 4. **onCreate 优化**：避免耗时操作，使用 ViewBinding
> 5. **测量**：使用 `adb shell am start -W` 测量冷启动时间

**Q4: Intent 的 FLAG_ACTIVITY_CLEAR_TOP 是什么作用？**

> **答案**：如果目标 Activity 已在栈中，会销毁它上面的所有 Activity。
> 
> 例如栈为 [A, B, C, D]，启动 B 并带此 flag，结果为 [A, B]。
> 
> 注意：默认会销毁并重建 B，如果想复用 B，需要配合 FLAG_ACTIVITY_SINGLE_TOP。

**Q5: singleTask 和 FLAG_ACTIVITY_CLEAR_TOP + FLAG_ACTIVITY_SINGLE_TOP 有什么区别？**

> **答案**：
> - **效果相似**：都会清除目标之上的 Activity，都会调用 onNewIntent
> - **区别**：
>   - singleTask 会考虑 TaskAffinity，可能在新任务中启动
>   - CLEAR_TOP + SINGLE_TOP 只在当前任务栈内操作
>   - singleTask 是静态声明，Flags 是动态控制
