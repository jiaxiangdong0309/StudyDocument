# Java 注解基础篇

> 注解就像给代码贴便签——你可以在便签上写任何信息，关键是谁来读、什么时候读。

## 一、什么是注解？

### 1.1 定义

**注解（Annotation）** 是 JDK 5 引入的一种元数据机制，用于为代码（类、方法、字段、参数等）附加额外信息。注解本身不影响程序逻辑，但可以被编译器、工具或运行时读取处理。

### 1.2 通俗理解

想象你是图书馆管理员，需要给每本书做标记：

| 标记类型 | 作用 | 类比注解场景 |
|---------|------|-------------|
| 彩色便签 | 标记"热门书籍" | `@Popular` |
| 条形码 | 供扫描器读取 | 编译器/工具读取 |
| 分类标签 | "计算机/编程" | `@Category("编程")` |
| 借阅记录 | 运行时查询 | 运行时注解处理 |

**一句话总结**：注解 = 代码的"元数据标签"，用于描述代码而非执行代码。

### 1.3 注解 vs 注释

```java
// 这是注释：给人看的，编译后消失
/* 编译器完全忽略 */

@Override  // 这是注解：给编译器/工具/程序看的
public String toString() {
    return "Hello";
}
```

| 特性 | 注释（Comment） | 注解（Annotation） |
|-----|----------------|-------------------|
| 读者 | 人类开发者 | 编译器、工具、程序 |
| 编译后 | 完全消失 | 可保留到 .class 或运行时 |
| 作用 | 解释代码 | 影响编译行为、生成代码、运行时处理 |
| 语法 | `//` 或 `/* */` | `@AnnotationName` |

### 1.4 技术演进：为什么需要注解？

**JDK 5 之前**：配置地狱

```xml
<!-- struts-config.xml：几百行 XML 配置 -->
<action-mappings>
    <action path="/login" type="com.example.LoginAction" name="loginForm">
        <forward name="success" path="/welcome.jsp"/>
        <forward name="failure" path="/login.jsp"/>
    </action>
</action-mappings>
```

**JDK 5 之后**：注解简化配置

```java
// 一个注解搞定
@RequestMapping("/login")
public class LoginController {
    @GetMapping("/welcome")
    public String welcome() {
        return "welcome";
    }
}
```

**注解解决的核心问题**：
1. **消除样板代码**：减少重复的配置文件
2. **就近原则**：配置和代码放在一起，易于维护
3. **类型安全**：编译期检查，避免字符串配置的拼写错误

## 二、注解的基本语法

### 2.1 注解的定义

```java
// 使用 @interface 关键字定义注解（不是 interface！）
public @interface MyAnnotation {
    // 注解的属性（看起来像方法，但叫"属性"或"元素"）
    String value();              // 必填属性
    int count() default 1;       // 带默认值的属性
    String[] tags() default {};  // 数组类型属性
}
```

### 2.2 注解的使用

```java
// 完整写法
@MyAnnotation(value = "hello", count = 5, tags = {"a", "b"})
public class Demo {}

// 简化写法1：只有 value 属性时，可省略 "value ="
@MyAnnotation("hello")
public class Demo2 {}

// 简化写法2：使用默认值的属性可以不写
@MyAnnotation(value = "hello")  // count 和 tags 使用默认值
public class Demo3 {}

// 数组只有一个元素时可省略花括号
@MyAnnotation(value = "hello", tags = "single")
public class Demo4 {}
```

### 2.3 注解属性的类型限制

注解属性只能是以下类型（这是 JVM 规范的限制）：

| 类型 | 示例 |
|-----|------|
| 基本类型 | `int`、`long`、`boolean`、`double` 等 |
| String | `String value();` |
| Class | `Class<?> targetClass();` |
| 枚举 | `RetentionPolicy policy();` |
| 注解 | `Author author();`（嵌套注解） |
| 以上类型的数组 | `String[] names();` |

```java
// ❌ 不允许的类型
public @interface Invalid {
    Object obj();        // 不能用 Object
    List<String> list(); // 不能用集合
    Integer num();       // 不能用包装类（但可以用 int）
}
```

> 💡 **为什么有这个限制？** 因为注解信息要存储在字节码中，JVM 只支持这些可序列化的常量类型。

## 三、四大元注解

元注解（Meta-Annotation）是"注解的注解"，用于定义注解的行为特性。

### 3.1 @Target：注解能用在哪？

```java
@Target(ElementType.METHOD)  // 只能用在方法上
public @interface OnlyForMethod {}

@Target({ElementType.TYPE, ElementType.METHOD})  // 可用在类和方法上
public @interface ForTypeAndMethod {}
```

**ElementType 枚举值**：

| 值 | 说明 | 示例 |
|---|------|------|
| `TYPE` | 类、接口、枚举、注解 | `@Entity class User {}` |
| `FIELD` | 字段（含枚举常量） | `@Column String name;` |
| `METHOD` | 方法 | `@Override toString()` |
| `PARAMETER` | 方法参数 | `void foo(@NotNull String s)` |
| `CONSTRUCTOR` | 构造器 | `@Inject public User()` |
| `LOCAL_VARIABLE` | 局部变量 | （很少用，运行时无法获取） |
| `ANNOTATION_TYPE` | 注解类型 | `@Target @interface Meta {}` |
| `PACKAGE` | 包（在 package-info.java 中使用） | `@PackageDoc package com.x;` |
| `TYPE_PARAMETER` | 泛型参数（JDK 8+） | `class Box<@NonNull T> {}` |
| `TYPE_USE` | 任何类型使用处（JDK 8+） | `@NonNull String @NonNull []` |
| `MODULE` | 模块（JDK 9+） | `@Deprecated module foo {}` |
| `RECORD_COMPONENT` | Record 组件（JDK 16+） | `record Point(@NonNull int x)` |

### 3.2 @Retention：注解保留到什么时候？

这是最重要的元注解，决定注解的"生命周期"：

```java
@Retention(RetentionPolicy.RUNTIME)  // 运行时可通过反射读取
public @interface RuntimeAnno {}

@Retention(RetentionPolicy.CLASS)    // 保留到字节码，但运行时不可读
public @interface ClassAnno {}

@Retention(RetentionPolicy.SOURCE)   // 只在源码中，编译后消失
public @interface SourceAnno {}
```

**三种保留策略对比**：

```
┌────────────────────────────────────────────────────────────┐
│                      注解生命周期                           │
├──────────────┬──────────────┬──────────────┬──────────────┤
│   源码阶段    │   编译阶段    │  字节码文件   │   运行时     │
├──────────────┼──────────────┼──────────────┼──────────────┤
│   SOURCE ────┼──── ✗        │      ✗       │      ✗       │
│   CLASS  ────┼──────────────┼───── ✓       │      ✗       │
│   RUNTIME ───┼──────────────┼───── ✓       │      ✓       │
└──────────────┴──────────────┴──────────────┴──────────────┘
```

| 策略 | 典型用途 | 示例 |
|-----|---------|------|
| `SOURCE` | 编译检查、IDE 提示、代码生成 | `@Override`、`@SuppressWarnings`、Lombok |
| `CLASS` | 字节码增强、静态分析 | 部分 FindBugs 注解（较少用） |
| `RUNTIME` | 反射处理、框架功能 | `@Autowired`、`@Test`、`@RequestMapping` |

### 3.3 @Documented：是否包含在 Javadoc 中

```java
@Documented  // 使用此注解的元素会在 Javadoc 中显示该注解
@interface Important {}
```

默认情况下注解不会出现在 Javadoc 中，加上 `@Documented` 后会显示。

### 3.4 @Inherited：注解能否被继承

```java
@Inherited  // 子类会继承父类的此注解
@interface InheritedAnno {}

@InheritedAnno
class Parent {}

class Child extends Parent {}  // Child 也有 @InheritedAnno
```

> ⚠️ **注意**：`@Inherited` 只对类有效，对接口、方法、字段上的注解无效。

### 3.5 元注解使用示例

```java
import java.lang.annotation.*;

/**
 * 自定义注解的标准写法
 */
@Target({ElementType.TYPE, ElementType.METHOD})  // 可用于类和方法
@Retention(RetentionPolicy.RUNTIME)              // 运行时可读取
@Documented                                       // 包含在文档中
@Inherited                                        // 可被继承
public @interface Api {
    String value() default "";       // API 描述
    String version() default "1.0";  // 版本号
    boolean deprecated() default false;  // 是否废弃
}
```

## 四、JDK 内置注解

### 4.1 编译检查注解

```java
public class BuiltInAnnotations {

    // 1. @Override：检查是否正确重写父类方法
    @Override
    public String toString() {
        return "Hello";
    }
    
    // 2. @Deprecated：标记已废弃的元素
    @Deprecated(since = "1.5", forRemoval = true)  // JDK 9+ 增强
    public void oldMethod() {
        // 调用此方法会产生编译警告
    }
    
    // 3. @SuppressWarnings：抑制编译器警告
    @SuppressWarnings("unchecked")  // 抑制未检查类型转换警告
    public void suppressDemo() {
        List list = new ArrayList();  // 原始类型警告被抑制
    }
    
    // 4. @SafeVarargs：抑制可变参数的泛型警告（JDK 7+）
    @SafeVarargs
    public final <T> void safeVarargs(T... items) {
        for (T item : items) {
            System.out.println(item);
        }
    }
    
    // 5. @FunctionalInterface：标记函数式接口（JDK 8+）
    @FunctionalInterface
    interface MyFunction {
        void apply();
        // void another();  // 加上这行会编译报错
    }
}
```

### 4.2 @SuppressWarnings 常用值

| 值 | 说明 |
|---|------|
| `"unchecked"` | 未检查的类型转换 |
| `"deprecation"` | 使用了废弃的 API |
| `"rawtypes"` | 使用原始类型（无泛型） |
| `"unused"` | 未使用的变量/方法 |
| `"serial"` | 可序列化类缺少 serialVersionUID |
| `"all"` | 抑制所有警告（不推荐） |

## 五、自定义注解实战

### 5.1 场景：实现简单的字段校验

**需求**：用注解标记必填字段，运行时检查是否为空。

**Step 1：定义注解**

```java
import java.lang.annotation.*;

@Target(ElementType.FIELD)           // 只能用在字段上
@Retention(RetentionPolicy.RUNTIME)  // 运行时可读取
public @interface NotNull {
    String message() default "字段不能为空";
}
```

**Step 2：定义实体类**

```java
public class User {
    @NotNull(message = "用户名不能为空")
    private String username;
    
    @NotNull
    private String email;
    
    private String nickname;  // 没有 @NotNull，可以为空
    
    // getter/setter 省略
    public User(String username, String email, String nickname) {
        this.username = username;
        this.email = email;
        this.nickname = nickname;
    }
}
```

**Step 3：实现校验器**

```java
import java.lang.reflect.Field;

public class Validator {
    
    /**
     * 校验对象中带 @NotNull 注解的字段是否为空
     * @return 校验失败的错误信息，通过则返回 null
     */
    public static String validate(Object obj) {
        if (obj == null) {
            return "对象不能为 null";
        }
        
        Class<?> clazz = obj.getClass();
        
        // 遍历所有声明的字段
        for (Field field : clazz.getDeclaredFields()) {
            // 检查字段是否有 @NotNull 注解
            if (field.isAnnotationPresent(NotNull.class)) {
                field.setAccessible(true);  // 允许访问私有字段
                
                try {
                    Object value = field.get(obj);
                    if (value == null || (value instanceof String && ((String) value).isEmpty())) {
                        // 获取注解中的 message 属性
                        NotNull annotation = field.getAnnotation(NotNull.class);
                        return field.getName() + ": " + annotation.message();
                    }
                } catch (IllegalAccessException e) {
                    return "校验失败: " + e.getMessage();
                }
            }
        }
        return null;  // 校验通过
    }
}
```

**Step 4：测试使用**

```java
public class ValidatorTest {
    public static void main(String[] args) {
        // 测试1：正常数据
        User user1 = new User("zhangsan", "test@example.com", null);
        String result1 = Validator.validate(user1);
        System.out.println("测试1: " + (result1 == null ? "通过" : result1));
        // 输出：测试1: 通过
        
        // 测试2：username 为空
        User user2 = new User("", "test@example.com", "nick");
        String result2 = Validator.validate(user2);
        System.out.println("测试2: " + result2);
        // 输出：测试2: username: 用户名不能为空
        
        // 测试3：email 为 null
        User user3 = new User("lisi", null, "nick");
        String result3 = Validator.validate(user3);
        System.out.println("测试3: " + result3);
        // 输出：测试3: email: 字段不能为空
    }
}
```

### 5.2 注解属性的特殊用法

```java
// 1. value 属性的简化用法
@interface Description {
    String value();
}

@Description("这是描述")  // 等价于 @Description(value = "这是描述")
class Demo {}

// 2. 嵌套注解
@interface Author {
    String name();
}

@interface Book {
    String title();
    Author author();  // 嵌套注解
}

@Book(title = "Java编程思想", author = @Author(name = "Bruce Eckel"))
class JavaBook {}

// 3. 注解数组
@interface Authors {
    Author[] value();
}

@Authors({
    @Author(name = "张三"),
    @Author(name = "李四")
})
class MultiAuthorBook {}
```

## 六、可重复注解（JDK 8+）

JDK 8 之前，同一个注解不能在同一位置重复使用。JDK 8 引入 `@Repeatable` 解决这个问题。

### 6.1 定义可重复注解

```java
// Step 1：定义容器注解
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@interface Schedules {
    Schedule[] value();  // 必须有一个 value 属性，类型是可重复注解的数组
}

// Step 2：定义可重复注解，使用 @Repeatable 指定容器
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Repeatable(Schedules.class)
@interface Schedule {
    String dayOfWeek();
    String time();
}
```

### 6.2 使用可重复注解

```java
// JDK 8+ 写法：直接重复使用
@Schedule(dayOfWeek = "Monday", time = "09:00")
@Schedule(dayOfWeek = "Wednesday", time = "14:00")
@Schedule(dayOfWeek = "Friday", time = "16:00")
class WeeklyTask {}

// 等价于 JDK 8 之前的写法
@Schedules({
    @Schedule(dayOfWeek = "Monday", time = "09:00"),
    @Schedule(dayOfWeek = "Wednesday", time = "14:00"),
    @Schedule(dayOfWeek = "Friday", time = "16:00")
})
class WeeklyTaskOld {}
```

### 6.3 读取可重复注解

```java
public class RepeatableDemo {
    public static void main(String[] args) {
        Class<WeeklyTask> clazz = WeeklyTask.class;
        
        // 方式1：通过 getAnnotationsByType 获取所有重复注解
        Schedule[] schedules = clazz.getAnnotationsByType(Schedule.class);
        for (Schedule s : schedules) {
            System.out.println(s.dayOfWeek() + " at " + s.time());
        }
        
        // 方式2：获取容器注解
        Schedules container = clazz.getAnnotation(Schedules.class);
        if (container != null) {
            for (Schedule s : container.value()) {
                System.out.println(s.dayOfWeek() + " at " + s.time());
            }
        }
    }
}
```

## 七、类型注解（JDK 8+）

JDK 8 扩展了注解的使用位置，通过 `ElementType.TYPE_USE` 可以在任何类型使用的地方添加注解。

```java
@Target(ElementType.TYPE_USE)
@Retention(RetentionPolicy.RUNTIME)
@interface NonNull {}

public class TypeAnnotationDemo {
    // 1. 泛型参数
    private List<@NonNull String> names;
    
    // 2. 类型转换
    public void cast(Object obj) {
        String str = (@NonNull String) obj;
    }
    
    // 3. 实现/继承
    class MyList implements @NonNull List<String> {
        // ...
    }
    
    // 4. 异常声明
    public void risky() throws @NonNull RuntimeException {
        // ...
    }
    
    // 5. 数组（注解位置不同，含义不同）
    @NonNull String[] arr1;       // 数组本身非空
    String @NonNull [] arr2;       // 数组元素非空
    @NonNull String @NonNull [] arr3;  // 都非空
}
```

> 💡 **应用场景**：配合静态分析工具（如 Checker Framework）进行空指针检查。

## 八、常见问题与踩坑

### 8.1 注解属性默认值的坑

```java
@interface Config {
    String[] values() default {};
}

// ❌ 错误：试图用 null 作为默认值
@interface WrongConfig {
    String value() default null;  // 编译错误！默认值不能是 null
}
```

### 8.2 注解的比较

```java
// 注解实例可以用 equals 比较，但不能用 ==
@interface Tag {
    String value();
}

@Tag("test")
class A {}

@Tag("test")
class B {}

Tag tagA = A.class.getAnnotation(Tag.class);
Tag tagB = B.class.getAnnotation(Tag.class);

System.out.println(tagA == tagB);      // false（不同对象）
System.out.println(tagA.equals(tagB)); // true（内容相同）
```

### 8.3 注解继承的限制

```java
@Inherited
@interface ParentAnno {}

@ParentAnno
class Parent {}

class Child extends Parent {}

// ✅ 类可以继承注解
System.out.println(Child.class.isAnnotationPresent(ParentAnno.class)); // true

// ❌ 方法不会继承注解
class Parent2 {
    @Override
    public String toString() { return "parent"; }
}

class Child2 extends Parent2 {
    @Override
    public String toString() { return "child"; }
}

// Child2.toString() 没有 @Override（它是重新声明的）
```

## 九、面试检验

### Q1：注解和注释有什么区别？

**答案**：
- **注释**给人看，编译后消失；**注解**给程序看，可保留到运行时
- 注释不影响程序行为；注解可以被编译器、工具、框架读取并产生实际作用
- 注解有严格的语法（`@interface` 定义），注释是任意文本

### Q2：@Retention 的三个值有什么区别？

**答案**：
| 策略 | 保留时机 | 典型应用 |
|-----|---------|---------|
| `SOURCE` | 仅源码 | `@Override`、Lombok 代码生成 |
| `CLASS` | 源码+字节码 | 字节码分析工具（较少用） |
| `RUNTIME` | 源码+字节码+运行时 | Spring、JUnit 等框架注解 |

框架开发最常用 `RUNTIME`，因为需要通过反射读取注解。

### Q3：如何自定义一个注解？需要哪些元注解？

**答案**：
```java
@Target(ElementType.METHOD)           // 1. 指定使用位置
@Retention(RetentionPolicy.RUNTIME)   // 2. 指定保留策略
public @interface MyAnnotation {
    String value() default "";        // 3. 定义属性
}
```

至少需要 `@Retention` 指定保留策略。如果需要运行时通过反射读取，必须是 `RUNTIME`。

### Q4：为什么注解的属性类型有限制？

**答案**：
因为注解信息要存储在 class 文件的常量池中，JVM 规范限定常量池只能存储：
- 基本类型
- String
- Class 引用
- 枚举常量
- 其他注解
- 以上类型的数组

不能使用 Object、集合、自定义类等类型。

### Q5：@Inherited 注解有什么作用？有什么限制？

**答案**：
- **作用**：让子类自动继承父类上的注解
- **限制**：
  1. 只对**类**有效，接口上的注解不会被实现类继承
  2. 只对**类级别**注解有效，方法、字段上的注解不会被继承
  3. 子类如果重新声明了注解，会覆盖父类的
