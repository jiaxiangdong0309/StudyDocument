# Android 事件分发机制（Event Dispatch）

## 技术定位

事件分发机制是 Android **触摸交互的核心基础**，也是理解 View 体系和解决滑动冲突的必备知识。

**一句话理解**：事件分发就像公司里的"审批流程"——触摸事件从老板（Activity）传到部门经理（ViewGroup），经理可以自己处理，也可以继续下发给员工（View），如果没人处理，就逐级上报回去。

## 核心问题预览

### 基础篇

1. **MotionEvent 有哪些事件类型？** ACTION_DOWN、ACTION_MOVE、ACTION_UP 的含义？
2. **事件分发的三个核心方法是什么？** dispatchTouchEvent、onInterceptTouchEvent、onTouchEvent 各自的作用？
3. **事件是如何从 Activity 传递到 View 的？** 分发流程是怎样的？
4. **为什么 ACTION_DOWN 特别重要？** 它决定了什么？

### 进阶篇

5. **滑动冲突有哪几种类型？** 怎么解决？
6. **内部拦截法和外部拦截法的区别是什么？** 各自适用什么场景？
7. **NestedScrolling 机制是什么？** 为什么要设计它？
8. **如何实现一个可拖拽的自定义 View？**

### 源码篇

9. **ViewGroup 是如何找到事件目标的？** TouchTarget 是什么？
10. **requestDisallowInterceptTouchEvent 的原理是什么？**
11. **多点触控是如何分发的？** pointerId 有什么作用？
12. **事件分发机制有哪些设计上的巧妙之处？**
