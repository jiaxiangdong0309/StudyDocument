# 布局优化 (Layout Optimization)

## 为什么要做布局优化？

布局渲染就像画画——笔画越少画得越快，涂抹次数越少越清晰。布局层级越深、过度绘制越多，界面就越卡顿。

**布局问题的三大表现**：

| 问题 | 用户感知 | 原因 |
|-----|---------|------|
| 层级过深 | 界面加载慢、卡顿 | 测量、布局、绘制耗时长 |
| 过度绘制 | 掉帧、卡顿 | 同一像素被绘制多次 |
| 主线程阻塞 | 界面无响应 | 在主线程进行耗时操作 |

## 一、布局渲染原理

### 1.1 渲染流程

```
┌─────────────────────────────────────────────────────────────────┐
│                     一帧的渲染流程（16.6ms）                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   ┌─────────┐   ┌─────────┐   ┌─────────┐   ┌─────────┐        │
│   │ Measure │ → │ Layout  │ → │  Draw   │ → │ Display │        │
│   │  测量    │   │  布局    │   │  绘制    │   │  显示    │        │
│   └─────────┘   └─────────┘   └─────────┘   └─────────┘        │
│                                                                 │
│   计算 View    确定 View     绘制 View     合成显示              │
│   的大小       的位置        的内容        到屏幕                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**为什么是 16.6ms？**
- 屏幕刷新率 60Hz，即每秒 60 帧
- 每帧时间 = 1000ms / 60 = **16.6ms**
- 超过这个时间就会掉帧、卡顿

### 1.2 测量次数问题

不同布局的测量次数不同：

| 布局 | 测量次数 | 说明 |
|-----|---------|------|
| FrameLayout | 1 次 | 最简单，最快 |
| LinearLayout (无 weight) | 1 次 | 简单线性排列 |
| LinearLayout (有 weight) | 2 次 | 需要二次测量分配权重 |
| RelativeLayout | 2 次 | 横向、纵向各测量一次 |
| ConstraintLayout | 1-2 次 | 优化后的约束布局 |

**嵌套的代价**：假设 3 层嵌套，每层都是 RelativeLayout：
- 测量次数 = 2³ = 8 次！

## 二、减少布局层级

### 2.1 使用 ConstraintLayout

ConstraintLayout 是 Google 推荐的扁平化布局，可以实现复杂布局而不需要嵌套。

```xml
<!-- ❌ 多层嵌套的传统写法 -->
<LinearLayout
    android:layout_width="match_parent"
    android:layout_height="wrap_content"
    android:orientation="horizontal">
    
    <ImageView
        android:id="@+id/avatar"
        android:layout_width="48dp"
        android:layout_height="48dp"/>
    
    <LinearLayout
        android:layout_width="0dp"
        android:layout_height="wrap_content"
        android:layout_weight="1"
        android:orientation="vertical">
        
        <TextView
            android:id="@+id/name"
            android:layout_width="wrap_content"
            android:layout_height="wrap_content"/>
        
        <TextView
            android:id="@+id/desc"
            android:layout_width="wrap_content"
            android:layout_height="wrap_content"/>
    </LinearLayout>
</LinearLayout>
```

```xml
<!-- ✅ ConstraintLayout 扁平化写法 -->
<androidx.constraintlayout.widget.ConstraintLayout
    android:layout_width="match_parent"
    android:layout_height="wrap_content">
    
    <ImageView
        android:id="@+id/avatar"
        android:layout_width="48dp"
        android:layout_height="48dp"
        app:layout_constraintStart_toStartOf="parent"
        app:layout_constraintTop_toTopOf="parent"/>
    
    <TextView
        android:id="@+id/name"
        android:layout_width="0dp"
        android:layout_height="wrap_content"
        app:layout_constraintStart_toEndOf="@id/avatar"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintTop_toTopOf="parent"/>
    
    <TextView
        android:id="@+id/desc"
        android:layout_width="0dp"
        android:layout_height="wrap_content"
        app:layout_constraintStart_toEndOf="@id/avatar"
        app:layout_constraintEnd_toEndOf="parent"
        app:layout_constraintTop_toBottomOf="@id/name"/>
        
</androidx.constraintlayout.widget.ConstraintLayout>
```

### 2.2 使用 merge 标签

`<merge>` 可以减少一层布局嵌套，适用于：
- 自定义 View 时，避免多余的根布局
- include 时，避免重复的容器

```xml
<!-- ❌ 不使用 merge，多了一层 LinearLayout -->
<!-- custom_view.xml -->
<LinearLayout
    android:layout_width="match_parent"
    android:layout_height="wrap_content">
    
    <TextView android:id="@+id/text1" ... />
    <TextView android:id="@+id/text2" ... />
</LinearLayout>
```

```xml
<!-- ✅ 使用 merge，减少一层嵌套 -->
<!-- custom_view.xml -->
<merge xmlns:android="http://schemas.android.com/apk/res/android">
    
    <TextView android:id="@+id/text1" ... />
    <TextView android:id="@+id/text2" ... />
</merge>
```

```kotlin
// 在自定义 View 中使用
class CustomView(context: Context) : LinearLayout(context) {
    init {
        // inflate 时，merge 中的 View 会直接添加到 this
        LayoutInflater.from(context).inflate(R.layout.custom_view, this, true)
    }
}
```

### 2.3 使用 ViewStub 延迟加载

`ViewStub` 是一个不可见、零尺寸的 View，只有在需要时才会加载布局。

适用场景：
- 错误页面
- 加载中状态
- 不常用的功能模块

```xml
<ViewStub
    android:id="@+id/stub_error"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:layout="@layout/layout_error"/>
```

```kotlin
// 需要时才加载
val errorView = findViewById<ViewStub>(R.id.stub_error).inflate()

// 或者设置可见性时自动加载
findViewById<ViewStub>(R.id.stub_error).visibility = View.VISIBLE
```

**注意**：ViewStub 只能 inflate 一次，之后再调用会抛异常。

### 2.4 include 复用布局

```xml
<!-- 复用 toolbar.xml -->
<include
    android:id="@+id/toolbar"
    layout="@layout/toolbar"
    android:layout_width="match_parent"
    android:layout_height="wrap_content"/>
```

## 三、减少过度绘制

### 3.1 什么是过度绘制？

过度绘制（Overdraw）是指同一个像素在一帧中被绘制多次。

```
过度绘制等级（开发者选项可查看）：
┌─────────────────────────────────────┐
│  颜色    │  含义                     │
├─────────────────────────────────────┤
│  无色    │  没有过度绘制（1 次）      │
│  蓝色    │  过度绘制 1 次（2 次）     │
│  绿色    │  过度绘制 2 次（3 次）     │
│  粉色    │  过度绘制 3 次（4 次）     │
│  红色    │  过度绘制 4+ 次（5+ 次）   │
└─────────────────────────────────────┘

目标：尽量让界面是蓝色，避免红色
```

### 3.2 减少过度绘制的方法

#### 移除不必要的背景

```xml
<!-- ❌ 不必要的背景 -->
<FrameLayout
    android:background="@color/white">  <!-- 背景 1 -->
    
    <LinearLayout
        android:background="@color/white">  <!-- 背景 2（重复） -->
        
        <TextView
            android:background="@color/white"/>  <!-- 背景 3（重复） -->
    </LinearLayout>
</FrameLayout>

<!-- ✅ 只保留最外层背景 -->
<FrameLayout
    android:background="@color/white">
    
    <LinearLayout>
        <TextView/>
    </LinearLayout>
</FrameLayout>
```

#### 移除 Window 默认背景

```kotlin
// 在 Activity 中移除 Window 背景
override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    // 如果布局已经有背景，可以移除 Window 背景
    window.setBackgroundDrawable(null)
    // 或者
    window.decorView.background = null
}
```

```xml
<!-- 或者在主题中设置 -->
<style name="AppTheme" parent="Theme.MaterialComponents.Light.NoActionBar">
    <item name="android:windowBackground">@null</item>
</style>
```

#### 使用 clipRect 裁剪

自定义 View 时，使用 `clipRect` 避免绘制被遮挡的区域：

```kotlin
class CardStackView(context: Context) : View(context) {
    
    override fun onDraw(canvas: Canvas) {
        for (i in cards.indices) {
            // 只绘制可见的部分
            canvas.save()
            
            if (i < cards.lastIndex) {
                // 裁剪掉被下一张卡片遮挡的区域
                canvas.clipRect(
                    cards[i].left,
                    cards[i].top,
                    cards[i].right,
                    cards[i + 1].top  // 只绘制到下一张卡片的顶部
                )
            }
            
            cards[i].draw(canvas)
            canvas.restore()
        }
    }
}
```

## 四、布局加载优化

### 4.1 异步加载布局

布局 inflate 是在主线程进行的，复杂布局会阻塞主线程。

#### 使用 AsyncLayoutInflater

```kotlin
// ❌ 同步加载，阻塞主线程
setContentView(R.layout.activity_main)

// ✅ 异步加载，不阻塞主线程
AsyncLayoutInflater(this).inflate(R.layout.activity_main, null) { view, _, _ ->
    setContentView(view)
    // 在这里初始化 View
    initViews()
}
```

**注意事项**：
- 异步加载的布局不能包含 Fragment
- 不能使用 `<merge>` 标签作为根布局
- 加载完成前不能操作 View

#### 使用 Compose（推荐）

Jetpack Compose 采用声明式 UI，没有 XML 解析和反射创建 View 的开销：

```kotlin
// Compose 方式
setContent {
    MyApp()
}

@Composable
fun MyApp() {
    MaterialTheme {
        // UI 代码
    }
}
```

### 4.2 预加载和缓存

#### 预加载布局

```kotlin
// 在后台线程预加载布局
fun preloadLayout(context: Context, @LayoutRes layoutId: Int) {
    Thread {
        val inflater = LayoutInflater.from(context)
        val view = inflater.inflate(layoutId, null)
        // 缓存到内存中
        viewCache[layoutId] = view
    }.start()
}
```

#### 复用 View

RecyclerView 已经实现了 View 复用，对于自定义场景：

```kotlin
// View 复用池
class ViewPool(private val maxSize: Int = 5) {
    private val pool = ArrayDeque<View>()
    
    fun obtain(context: Context, @LayoutRes layoutId: Int): View {
        return pool.pollFirst() 
            ?: LayoutInflater.from(context).inflate(layoutId, null)
    }
    
    fun recycle(view: View) {
        if (pool.size < maxSize) {
            // 重置 View 状态
            view.visibility = View.VISIBLE
            pool.addLast(view)
        }
    }
}
```

## 五、实用技巧

### 5.1 选择合适的布局

| 场景 | 推荐布局 | 原因 |
|-----|---------|------|
| 简单线性排列 | LinearLayout | 简单高效 |
| 层叠布局 | FrameLayout | 测量最快 |
| 复杂布局 | ConstraintLayout | 扁平化，避免嵌套 |
| 相对定位 | ConstraintLayout | 比 RelativeLayout 更高效 |
| 列表 | RecyclerView | View 复用 |

### 5.2 布局优化 Checklist

- [ ] 布局层级不超过 5 层
- [ ] 使用 ConstraintLayout 实现复杂布局
- [ ] 使用 merge 减少嵌套
- [ ] 使用 ViewStub 延迟加载
- [ ] 移除不必要的背景
- [ ] 使用 Layout Inspector 检查层级
- [ ] 开启过度绘制检测，消除红色区域

### 5.3 性能检测工具

#### Systrace

分析整个系统的渲染性能：

```bash
# 抓取 trace
python systrace.py -o trace.html gfx view wm

# 分析 trace.html 中的：
# - Choreographer#doFrame：每帧的开始
# - measure/layout/draw：各阶段耗时
# - 超过 16.6ms 的帧会被标红
```

#### GPU 渲染模式分析

开发者选项 → GPU 渲染模式分析 → 在屏幕上显示为条形图

```
每根柱子代表一帧的渲染时间：
- 绿色水平线：16ms 基准线
- 蓝色：绘制时间
- 红色：执行命令时间
- 橙色：GPU 处理时间

柱子超过绿线 = 掉帧
```

## 六、面试题精选

### Q1：布局优化有哪些方法？

**答**：
1. **减少层级**：使用 ConstraintLayout、merge、ViewStub
2. **减少过度绘制**：移除不必要的背景、使用 clipRect
3. **异步加载**：AsyncLayoutInflater、预加载
4. **选择合适布局**：简单用 LinearLayout，复杂用 ConstraintLayout

### Q2：ConstraintLayout 为什么比 RelativeLayout 高效？

**答**：
1. **测量优化**：使用约束求解器，减少测量次数
2. **扁平化**：可以实现复杂布局而不需要嵌套
3. **链式布局**：替代 LinearLayout 的 weight，无需二次测量
4. **Barrier/Guideline**：提供更灵活的布局方式

### Q3：什么是过度绘制？如何检测和优化？

**答**：过度绘制是同一像素在一帧中被绘制多次。

**检测**：开发者选项 → 调试 GPU 过度绘制

**优化**：
1. 移除不必要的背景（布局背景、Window 背景）
2. 使用 clipRect 裁剪不可见区域
3. 使用 canvas.quickReject() 跳过不在绘制区域的内容

### Q4：ViewStub 和 include 有什么区别？

**答**：

| 特性 | ViewStub | include |
|-----|---------|---------|
| 加载时机 | 按需加载（延迟） | 立即加载 |
| 占用空间 | 不占用（0尺寸） | 占用 |
| 可复用性 | 只能 inflate 一次 | 可多次使用 |
| 适用场景 | 不常显示的布局 | 需要复用的布局 |

### Q5：如何检测布局性能问题？

**答**：
1. **Layout Inspector**：查看布局层级
2. **Systrace**：分析 measure/layout/draw 耗时
3. **GPU 渲染模式**：查看每帧渲染时间
4. **过度绘制检测**：查看绘制次数
5. **Android Profiler**：CPU 分析布局相关方法
