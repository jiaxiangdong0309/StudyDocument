# 包体积优化 (APK Size Optimization)

## 为什么要做包体积优化？

APK 大小就像行李箱——越小越容易带上飞机。包体积影响下载转化率、安装成功率和用户存储空间。

**包体积优化的价值**：

| 影响 | 数据 |
|-----|------|
| 下载转化率 | APK 每增大 6MB，安装转化率下降 1% |
| 安装失败 | 存储空间不足导致安装失败 |
| 更新意愿 | 包太大用户不愿更新 |
| 渠道要求 | 应用商店可能有大小限制 |

## 一、APK 结构分析

### 1.1 APK 组成

```
app-release.apk
├── classes.dex          # Java/Kotlin 代码编译产物（通常最大）
├── classes2.dex         # 多 dex 分包
├── res/                 # 资源文件
│   ├── drawable/        # 图片资源
│   ├── layout/          # 布局文件
│   ├── values/          # 字符串、颜色等
│   └── ...
├── lib/                 # Native 库（.so 文件）
│   ├── armeabi-v7a/
│   ├── arm64-v8a/
│   └── x86/
├── assets/              # 原始资源文件
├── resources.arsc       # 资源索引表
├── AndroidManifest.xml  # 清单文件
└── META-INF/            # 签名信息
```

## 二、代码优化

### 2.1 开启 R8/ProGuard 混淆

混淆不仅能保护代码，还能减小包体积：

```kotlin
// build.gradle (app)
android {
    buildTypes {
        release {
            // 开启混淆
            minifyEnabled true
            // 开启资源压缩
            shrinkResources true
            // 混淆规则
            proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'), 'proguard-rules.pro'
        }
    }
}
```

**R8 优化效果**：
- 移除无用代码（Dead Code Elimination）
- 类/方法/字段名缩短（a, b, c...）
- 内联优化
- 代码优化

## 三、资源优化

### 3.1 图片优化

#### 使用 WebP 格式

WebP 比 PNG 小 25-35%，比 JPEG 小 25-34%：

```kotlin
// Android Studio 可以批量转换
// 右键图片 → Convert to WebP

// 或使用命令行
// cwebp input.png -o output.webp -q 80
```

#### 使用矢量图

```xml
<!-- 用 VectorDrawable 替代 PNG -->
<!-- 一个文件适配所有分辨率 -->
<vector xmlns:android="http://schemas.android.com/apk/res/android"
    android:width="24dp"
    android:height="24dp"
    android:viewportWidth="24"
    android:viewportHeight="24">
    <path
        android:fillColor="#FF000000"
        android:pathData="M12,2L2,7l10,5l10,-5L12,2z"/>
</vector>
```

**适用场景**：
- 图标、Logo
- 简单图形
- 需要动画的图形

**不适用**：
- 复杂图片、照片
- 渐变复杂的图形

#### 压缩图片

```bash
# 使用 pngquant 压缩 PNG
pngquant --quality=65-80 image.png

# 使用 jpegoptim 压缩 JPEG
jpegoptim --max=80 image.jpg

# 使用 TinyPNG API
# https://tinypng.com/
```

#### 按需提供分辨率

```kotlin
// build.gradle
android {
    defaultConfig {
        // 只保留需要的分辨率
        resConfigs "xxhdpi", "xxxhdpi"
    }
    
    // 或按 ABI 分包
    splits {
        density {
            enable true
            reset()
            include "mdpi", "hdpi", "xhdpi", "xxhdpi", "xxxhdpi"
            compatibleScreens 'small', 'normal', 'large', 'xlarge'
        }
    }
}
```

### 3.3 资源混淆

使用 AndResGuard 混淆资源名称：

```kotlin
// build.gradle
apply plugin: 'AndResGuard'

andResGuard {
    mappingFile = null
    use7zip = true
    useSign = true
    keepRoot = false
    
    whiteList = [
        "R.drawable.icon",
        "R.string.app_name"
    ]
    
    compressFilePattern = [
        "*.png",
        "*.jpg",
        "*.jpeg",
        "*.gif"
    ]
}
```

效果：`res/drawable/icon_home.png` → `res/a/a.png`

## 四、Native 库优化

### 4.1 按 ABI 分包

```kotlin
android {
    splits {
        abi {
            enable true
            reset()
            // 只包含常用架构
            include "armeabi-v7a", "arm64-v8a"
            // 不生成通用 APK
            universalApk false
        }
    }
}
```

### 4.2 使用 App Bundle

```kotlin
// build.gradle
android {
    bundle {
        language {
            enableSplit = true  // 按语言分包
        }
        density {
            enableSplit = true  // 按屏幕密度分包
        }
        abi {
            enableSplit = true  // 按 ABI 分包
        }
    }
}

// 生成 App Bundle
// ./gradlew bundleRelease
```

App Bundle 由 Google Play 根据设备特性生成定制 APK，可减小 20-50% 下载大小。

### 4.3 动态加载 So

```kotlin
// 首次使用时从服务器下载 so 文件
class SoLoader {
    
    fun loadSo(context: Context, soName: String) {
        val soFile = File(context.filesDir, "$soName.so")
        
        if (!soFile.exists()) {
            // 从服务器下载
            downloadSo(soName, soFile)
        }
        
        // 加载 so
        System.load(soFile.absolutePath)
    }
}
```

## 七、包体积监控

### 7.1 CI 集成

```bash
#!/bin/bash
# ci_check_apk_size.sh

APK_PATH="app/build/outputs/apk/release/app-release.apk"
MAX_SIZE=20971520  # 20MB

APK_SIZE=$(stat -f%z "$APK_PATH")

if [ $APK_SIZE -gt $MAX_SIZE ]; then
    echo "APK 大小 ${APK_SIZE} 超过限制 ${MAX_SIZE}"
    exit 1
fi

echo "APK 大小检查通过: ${APK_SIZE} bytes"
```

## 九、面试题精选

### Q1：APK 由哪些部分组成？

**答**：
- **classes.dex**：Java/Kotlin 代码
- **res/**：资源文件（图片、布局等）
- **lib/**：Native 库（.so 文件）
- **assets/**：原始资源文件
- **resources.arsc**：资源索引表
- **AndroidManifest.xml**：清单文件
- **META-INF/**：签名信息

### Q2：如何减小 APK 大小？

**答**：

**代码优化**：
- 开启 R8/ProGuard 混淆
- 移除无用代码和依赖
- 使用更轻量的库

**资源优化**：
- 使用 WebP 替代 PNG
- 使用矢量图
- 移除无用资源
- 只保留必要的语言和分辨率

**Native 库优化**：
- 按 ABI 分包
- 使用 App Bundle
- 动态加载 So

**动态下发**：
- Dynamic Feature Module
- 资源按需下载

### Q3：R8 和 ProGuard 的区别？

**答**：

| 特性 | ProGuard | R8 |
|-----|---------|-----|
| 开发者 | GuardSquare | Google |
| 速度 | 较慢 | 更快 |
| 优化效果 | 一般 | 更好 |
| 兼容性 | 需要额外配置 | 与 D8 集成 |
| 维护 | 第三方 | Android 官方 |

R8 是 ProGuard 的替代品，AGP 3.4+ 默认使用 R8。

### Q4：App Bundle 是什么？

**答**：App Bundle 是 Google 推出的新发布格式（.aab），Google Play 会根据用户设备特性生成定制的 APK，只包含该设备需要的资源和代码。

**优势**：
- 自动按 ABI、屏幕密度、语言分包
- 减小 20-50% 下载大小
- 支持动态交付模块

### Q5：如何监控包体积？

**答**：
1. **APK Analyzer**：分析包组成，对比版本差异
2. **CI 集成**：设置大小阈值，超过报警
3. **版本对比**：记录每个版本大小，绘制趋势图
4. **依赖分析**：定期审查依赖库大小
