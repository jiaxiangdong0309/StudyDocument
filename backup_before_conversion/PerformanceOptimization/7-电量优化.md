# 电量优化 (Battery Optimization)

## 为什么要做电量优化？

电量就像手机的生命值——App 太耗电，用户就会卸载。电量优化对于后台运行的 App 尤为重要。

**耗电问题的影响**：

| 影响 | 后果 |
|-----|------|
| 用户抱怨 | 差评、卸载 |
| 系统限制 | 被系统杀死、限制后台 |
| 品牌形象 | 被贴上「耗电大户」标签 |

## 二、WakeLock 优化

### 2.1 什么是 WakeLock？

WakeLock 可以阻止系统休眠，让 CPU 保持运行。但使用不当会严重耗电。

```kotlin
// ❌ 错误示例：忘记释放 WakeLock
class BadService : Service() {
    
    private val wakeLock by lazy {
        (getSystemService(POWER_SERVICE) as PowerManager)
            .newWakeLock(PowerManager.PARTIAL_WAKE_LOCK, "MyApp::MyWakeLock")
    }
    
    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
        wakeLock.acquire()  // 获取 WakeLock
        
        doWork()
        
        // ❌ 忘记释放，手机永远不会休眠！
        return START_STICKY
    }
}
```

```kotlin
// ✅ 正确示例：使用超时 + 确保释放
class GoodService : Service() {
    
    private val wakeLock by lazy {
        (getSystemService(POWER_SERVICE) as PowerManager)
            .newWakeLock(PowerManager.PARTIAL_WAKE_LOCK, "MyApp::MyWakeLock")
    }
    
    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
        // 设置超时，最多持有 10 分钟
        wakeLock.acquire(10 * 60 * 1000L)
        
        try {
            doWork()
        } finally {
            // 确保释放
            if (wakeLock.isHeld) {
                wakeLock.release()
            }
        }
        
        return START_STICKY
    }
}
```

### 2.2 WakeLock 最佳实践

```kotlin
// 使用 WorkManager 替代手动 WakeLock
class MyWorker(context: Context, params: WorkerParameters) : Worker(context, params) {
    
    override fun doWork(): Result {
        // WorkManager 会自动管理 WakeLock
        doBackgroundWork()
        return Result.success()
    }
}

// 提交任务
WorkManager.getInstance(context)
    .enqueue(OneTimeWorkRequestBuilder<MyWorker>().build())
```

## 三、后台任务优化

### 3.1 使用 JobScheduler

JobScheduler 可以让系统智能调度任务，合并多个任务一起执行：

```kotlin
// 定义 JobService
class MyJobService : JobService() {
    
    override fun onStartJob(params: JobParameters): Boolean {
        // 在这里执行后台任务
        thread {
            doWork()
            // 任务完成
            jobFinished(params, false)
        }
        return true  // true 表示任务在后台线程运行
    }
    
    override fun onStopJob(params: JobParameters): Boolean {
        // 任务被系统取消时调用
        return true  // true 表示需要重新调度
    }
}

// 调度任务
fun scheduleJob(context: Context) {
    val jobScheduler = context.getSystemService<JobScheduler>()
    
    val jobInfo = JobInfo.Builder(JOB_ID, ComponentName(context, MyJobService::class.java))
        .setRequiredNetworkType(JobInfo.NETWORK_TYPE_UNMETERED)  // 需要 Wi-Fi
        .setRequiresCharging(true)  // 需要充电中
        .setRequiresDeviceIdle(true)  // 需要设备空闲
        .setPersisted(true)  // 重启后保留
        .build()
    
    jobScheduler?.schedule(jobInfo)
}
```

### 3.2 使用 WorkManager（推荐）

WorkManager 是 JobScheduler 的封装，提供更简单的 API：

```kotlin
// 定义 Worker
class SyncWorker(context: Context, params: WorkerParameters) : CoroutineWorker(context, params) {
    
    override suspend fun doWork(): Result {
        return try {
            syncData()
            Result.success()
        } catch (e: Exception) {
            Result.retry()
        }
    }
}

// 调度任务
val constraints = Constraints.Builder()
    .setRequiredNetworkType(NetworkType.UNMETERED)  // 需要 Wi-Fi
    .setRequiresCharging(true)  // 需要充电
    .setRequiresBatteryNotLow(true)  // 电量不低
    .build()

val workRequest = PeriodicWorkRequestBuilder<SyncWorker>(
    repeatInterval = 1,
    repeatIntervalTimeUnit = TimeUnit.HOURS
)
    .setConstraints(constraints)
    .setBackoffCriteria(
        BackoffPolicy.EXPONENTIAL,
        WorkRequest.MIN_BACKOFF_MILLIS,
        TimeUnit.MILLISECONDS
    )
    .build()

WorkManager.getInstance(context)
    .enqueueUniquePeriodicWork(
        "sync",
        ExistingPeriodicWorkPolicy.KEEP,
        workRequest
    )
```

### 3.3 Doze 模式适配

Android 6.0+ 引入 Doze 模式，设备静止一段时间后会进入低功耗状态：

```kotlin
// Doze 模式下的限制：
// - 网络访问暂停
// - WakeLock 被忽略
// - Alarm 被延迟
// - Wi-Fi 扫描暂停
// - JobScheduler 暂停

// 应对策略：
// 1. 使用 setAndAllowWhileIdle（仍有限制）
val alarmManager = getSystemService<AlarmManager>()
alarmManager?.setAndAllowWhileIdle(
    AlarmManager.ELAPSED_REALTIME_WAKEUP,
    SystemClock.elapsedRealtime() + 60 * 60 * 1000,
    pendingIntent
)

// 2. 使用高优先级 FCM 消息唤醒
// FCM 的高优先级消息可以突破 Doze 限制
```

## 四、定位优化

### 4.1 选择合适的定位方式

| 方式 | 精度 | 耗电 | 适用场景 |
|-----|------|------|---------|
| GPS | 高（10m） | 高 | 导航、运动轨迹 |
| 网络定位 | 中（100m） | 低 | 天气、附近推荐 |
| 被动定位 | 取决于其他 App | 极低 | 后台记录位置 |

```kotlin
// ✅ 根据场景选择定位方式
val locationRequest = LocationRequest.Builder(
    Priority.PRIORITY_BALANCED_POWER_ACCURACY,  // 平衡精度和功耗
    10 * 60 * 1000  // 10 分钟更新一次
)
    .setMinUpdateIntervalMillis(5 * 60 * 1000)  // 最小间隔 5 分钟
    .setMaxUpdateDelayMillis(15 * 60 * 1000)    // 最大延迟 15 分钟（允许批量）
    .build()
```

### 4.2 及时停止定位

```kotlin
class LocationActivity : AppCompatActivity() {
    
    private lateinit var fusedLocationClient: FusedLocationProviderClient
    private lateinit var locationCallback: LocationCallback
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        fusedLocationClient = LocationServices.getFusedLocationProviderClient(this)
        
        locationCallback = object : LocationCallback() {
            override fun onLocationResult(result: LocationResult) {
                // 处理位置更新
            }
        }
    }
    
    override fun onResume() {
        super.onResume()
        // 开始定位
        startLocationUpdates()
    }
    
    override fun onPause() {
        super.onPause()
        // ✅ 及时停止定位
        fusedLocationClient.removeLocationUpdates(locationCallback)
    }
}
```

## 六、Alarm 优化

### 6.1 使用 inexact Alarm

```kotlin
// ❌ 精确 Alarm
alarmManager.setExact(
    AlarmManager.ELAPSED_REALTIME_WAKEUP,
    triggerTime,
    pendingIntent
)

// ✅ 不精确 Alarm（系统可以合并）
alarmManager.setInexactRepeating(
    AlarmManager.ELAPSED_REALTIME_WAKEUP,
    triggerTime,
    AlarmManager.INTERVAL_HOUR,
    pendingIntent
)
```

### 6.2 使用 WorkManager 替代 Alarm

```kotlin
// WorkManager 会智能调度，减少唤醒次数
val workRequest = PeriodicWorkRequestBuilder<MyWorker>(1, TimeUnit.HOURS)
    .build()

WorkManager.getInstance(context).enqueue(workRequest)
```

### 7.2 代码监控

```kotlin
// 注册电量变化广播
class BatteryReceiver : BroadcastReceiver() {
    
    override fun onReceive(context: Context, intent: Intent) {
        val level = intent.getIntExtra(BatteryManager.EXTRA_LEVEL, -1)
        val scale = intent.getIntExtra(BatteryManager.EXTRA_SCALE, -1)
        val batteryPct = level * 100 / scale
        
        // 低电量时减少后台任务
        if (batteryPct < 20) {
            WorkManager.getInstance(context).cancelAllWork()
        }
    }
}
```

## 九、面试题精选

### Q1：Android App 主要耗电在哪些方面？

**答**：
1. **网络请求**：频繁请求唤醒网络模块
2. **定位服务**：GPS 持续工作耗电严重
3. **WakeLock**：阻止 CPU 休眠
4. **后台任务**：持续运行消耗 CPU
5. **Alarm**：频繁唤醒设备

### Q2：如何优化后台任务的耗电？

**答**：
1. **使用 WorkManager**：智能调度，合并任务
2. **设置约束条件**：充电中、Wi-Fi 下执行
3. **批量处理**：合并多个小任务
4. **适配 Doze**：不要对抗系统省电机制

### Q3：WakeLock 使用注意事项？

**答**：
1. **设置超时**：`wakeLock.acquire(timeout)`
2. **配对释放**：acquire 和 release 必须配对
3. **try-finally**：确保异常时也能释放
4. **优先 WorkManager**：让系统管理 WakeLock

### Q4：Doze 模式是什么？如何适配？

**答**：Doze 是 Android 6.0+ 的省电机制，设备静止一段时间后进入低功耗状态。

**限制**：
- 网络访问暂停
- WakeLock 被忽略
- Alarm 被延迟

**适配**：
- 使用 WorkManager
- 使用 setAndAllowWhileIdle（有限制）
- 使用高优先级 FCM 消息

### Q5：如何检测 App 耗电问题？

**答**：
1. **Battery Historian**：可视化分析电池使用
2. **Android Vitals**：Google Play 提供的监控
3. **dumpsys batterystats**：命令行查看电池统计
4. **代码监控**：记录 WakeLock、定位、网络使用
