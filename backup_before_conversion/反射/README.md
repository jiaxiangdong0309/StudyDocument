# Java 反射（Reflection）技术

## 为什么 Android 开发者要学反射？

反射是 Android 中**很多黑科技**的基石：

```
组件化路由（ARouter）     → 反射实例化目标 Activity
插件化（VirtualAPK）      → 反射加载未安装的 APK
热修复（Tinker）          → 反射替换类加载器
依赖注入（Dagger/Hilt）   → 反射+注解实现自动装配
序列化（Gson）            → 反射读写私有字段
事件总线（EventBus）      → 反射调用订阅方法
```

**一句话总结**：反射就是程序运行时的"X光机"，能看到和操作任何类的内部结构，哪怕是私有的。

## 技术对比：反射 vs 其他方案

| 方案 | 优势 | 劣势 | Android 典型应用 |
|-----|------|------|-----------------|
| **运行时反射** | 灵活、能访问私有成员 | 性能差、类型不安全 | Gson、EventBus 3.0 之前 |
| **编译时注解 (APT)** | 性能好、类型安全 | 需要预生成代码、包体积大一点 | ButterKnife、ARouter、Room |
| **动态代理** | 性能中等、能拦截方法 | 只能代理接口 | Retrofit |
| **字节码插桩** | 性能最好、能修改字节码 | 复杂、调试困难 | AspectJ、Transform API |

## Android 中的反射应用场景

### ✅ 适合用反射
- **框架初始化**：启动时一次性反射，后续缓存（ARouter 路由表）
- **配置解析**：JSON/XML 转对象（Gson、Jackson）
- **插件化/热修复**：动态加载代码（Tinker、VirtualAPK）
- **单元测试**：访问私有方法进行白盒测试

### ❌ 不适合用反射
- **高频调用**：如列表滑动时（用 ViewHolder 模式）
- **性能敏感**：启动优化、动画（改用 APT）
- **类型安全要求高**：大型项目（改用编译时注解）

1. **先用起来**：阅读基础篇，写几个反射示例

5. **底层原理**：阅读 JDK 源码，理解 Method.invoke 底层
