# 开发服务器原理 (Dev Server)

## 1. 解决什么问题？

> **一句话直击核心**：Vite 开发服务器通过"按需编译"替代"预先打包"，实现毫秒级启动。

* **痛点**：Webpack 在启动时需要分析整个项目依赖并打包，项目越大启动越慢
* **作用**：Vite 利用浏览器原生 ES Modules，只在浏览器请求模块时才进行编译

---

## 2. 通俗理解

### 核心定义

Vite Dev Server 是一个基于原生 ES Modules 的开发服务器。它不会像 Webpack 那样在启动时打包所有代码，而是启动一个轻量级 HTTP 服务器，当浏览器请求某个模块时，才对该模块进行实时编译并返回。

### 生活化比喻

**Webpack 像预制菜餐厅**：
- 客人还没来，厨房就把所有菜都做好
- 菜品越多，准备时间越长
- 即使客人只点一道菜，也要等所有菜都做完

**Vite 像现做小炒店**：
- 客人点什么就做什么
- 点一道菜，几分钟就上桌
- 不需要提前准备所有菜品

## 3. 工作原理

```
┌─────────────────────────────────────────────────────────────────┐
│                 Vite Dev Server 工作流程                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  浏览器                    Vite Server                          │
│    │                           │                                │
│    │  1. 请求 index.html       │                                │
│    │ ─────────────────────────>│                                │
│    │                           │  处理 HTML，注入 HMR 客户端     │
│    │<───────────────────────── │                                │
│    │                           │                                │
│    │  2. 请求 /src/main.js     │                                │
│    │ ─────────────────────────>│                                │
│    │                           │  按需编译 main.js               │
│    │<───────────────────────── │                                │
│    │                           │                                │
│    │  3. 请求 /src/App.vue     │                                │
│    │ ─────────────────────────>│                                │
│    │                           │  编译 Vue SFC                  │
│    │<───────────────────────── │                                │
│    │                           │                                │
│    │  4. 请求依赖 vue          │                                │
│    │ ─────────────────────────>│                                │
│    │                           │  返回预构建的 vue               │
│    │<───────────────────────── │                                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 核心技术点

1. **原生 ES Modules**
   - 现代浏览器原生支持 `<script type="module">`
   - 浏览器会自动解析 `import` 语句并发起 HTTP 请求

2. **按需编译**
   - 只编译当前页面用到的模块
   - 未访问的代码不会被编译

3. **esbuild 预构建**
   - 将 node_modules 中的依赖预先打包
   - 将 CommonJS 转换为 ES Modules
   - 合并小模块，减少 HTTP 请求

## 4. 核心代码实战

### 场景一：理解模块请求过程

```html
<!-- index.html -->
<!DOCTYPE html>
<html>
  <body>
    <div id="app"></div>
    <!-- 浏览器发现 type="module"，开始模块加载流程 -->
    <script type="module" src="/src/main.js"></script>
  </body>
</html>
```

```javascript
// src/main.js - 浏览器请求这个文件时，Vite 进行转换
import { createApp } from 'vue'  // 浏览器会请求 /node_modules/.vite/vue.js
import App from './App.vue'      // 浏览器会请求 /src/App.vue

createApp(App).mount('#app')
```

**Vite 返回给浏览器的实际内容**：

```javascript
// 原始代码
import { createApp } from 'vue'

// Vite 转换后
import { createApp } from '/node_modules/.vite/deps/vue.js?v=xxxxx'
```

### 场景二：服务器配置

```javascript
// vite.config.js
export default {
  server: {
    // 端口号
    port: 3000,

    // 严格端口，如果端口被占用则退出
    strictPort: true,

    // 监听所有地址（允许局域网访问）
    host: '0.0.0.0',

    // 自动打开浏览器
    open: true,

    // 配置代理，解决跨域问题
    proxy: {
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true,
        rewrite: (path) => path.replace(/^\/api/, '')
      }
    },

    // 配置 CORS
    cors: true,

    // 自定义请求头
    headers: {
      'X-Custom-Header': 'value'
    }
  }
}
```

### 场景三：HTTPS 配置

```javascript
// vite.config.js
import fs from 'fs'
import path from 'path'

export default {
  server: {
    https: {
      key: fs.readFileSync(path.resolve(__dirname, 'keys/key.pem')),
      cert: fs.readFileSync(path.resolve(__dirname, 'keys/cert.pem'))
    }
  }
}

// 或者使用 @vitejs/plugin-basic-ssl 自动生成证书
import basicSsl from '@vitejs/plugin-basic-ssl'

export default {
  plugins: [basicSsl()],
  server: {
    https: true
  }
}
```

## 5. 请求处理流程

### Vite 服务器处理不同类型文件的方式

| 文件类型 | 处理方式 |
|---------|---------|
| `.html` | 注入 HMR 客户端代码 |
| `.js/.ts` | esbuild 转换，处理 import 路径 |
| `.vue` | @vitejs/plugin-vue 编译为 JS |
| `.jsx/.tsx` | esbuild 转换为 JS |
| `.css` | 转换为 JS 模块，支持 HMR |
| `.scss/.less` | 对应预处理器编译后处理 |
| 图片/字体 | 返回文件 URL 或 base64 |
| `.json` | 转换为 ES Module 导出 |

### 模块路径重写

```javascript
// 源代码
import Vue from 'vue'
import logo from './logo.png'
import styles from './style.module.css'

// Vite 转换后
import Vue from '/node_modules/.vite/deps/vue.js?v=abc123'
import logo from '/src/logo.png?import'
import styles from '/src/style.module.css?import'
```

## 6. 中间件机制

Vite 开发服务器基于 Connect 中间件架构：

```javascript
// vite.config.js - 自定义中间件
export default {
  server: {
    // 在 Vite 内部中间件之前执行
    middlewareMode: false
  },
  plugins: [
    {
      name: 'custom-middleware',
      configureServer(server) {
        // 在所有中间件之前
        server.middlewares.use((req, res, next) => {
          if (req.url === '/custom') {
            res.end('Custom response')
            return
          }
          next()
        })

        // 返回一个函数，在所有中间件之后执行
        return () => {
          server.middlewares.use((req, res, next) => {
            // 后置中间件
            next()
          })
        }
      }
    }
  ]
}
```

## 7. 最佳实践

### 性能优化建议

```javascript
// vite.config.js
export default {
  server: {
    // 预热常用文件，加速首次访问
    warmup: {
      clientFiles: [
        './src/main.js',
        './src/App.vue',
        './src/components/*.vue'
      ]
    },

    // 文件系统监听配置
    watch: {
      // 忽略不需要监听的目录
      ignored: ['**/node_modules/**', '**/dist/**']
    }
  },

  // 优化依赖预构建
  optimizeDeps: {
    // 强制预构建某些依赖
    include: ['lodash-es', 'axios'],
    // 排除某些依赖
    exclude: ['your-local-package']
  }
}
```

### 跨域代理配置

```javascript
// vite.config.js
export default {
  server: {
    proxy: {
      // 简写
      '/foo': 'http://localhost:4567',

      // 完整配置
      '/api': {
        target: 'http://jsonplaceholder.typicode.com',
        changeOrigin: true,
        rewrite: (path) => path.replace(/^\/api/, ''),
        // 配置请求头
        configure: (proxy, options) => {
          proxy.on('proxyReq', (proxyReq, req, res) => {
            proxyReq.setHeader('X-Custom-Header', 'value')
          })
        }
      },

      // WebSocket 代理
      '/socket.io': {
        target: 'ws://localhost:5173',
        ws: true
      }
    }
  }
}
```

## 8. 常见问题与解决方案

### Q1：开发服务器启动慢？

**可能原因和解决方案**：

```javascript
// 1. 依赖预构建范围过大
export default {
  optimizeDeps: {
    exclude: ['large-unused-package']
  }
}

// 2. 文件监听范围过大
export default {
  server: {
    watch: {
      ignored: ['!**/node_modules/your-package/**']
    }
  }
}
```

### Q2：页面首次加载慢？

**原因**：大量模块请求导致瀑布流加载。

```javascript
// 解决：预热关键文件
export default {
  server: {
    warmup: {
      clientFiles: ['./src/App.vue', './src/router/index.js']
    }
  }
}
```

### Q3：代理不生效？

**检查清单**：
1. 确认 target 地址是否正确
2. 检查 rewrite 规则
3. 确认后端服务是否运行
4. 查看浏览器网络请求的实际地址

```javascript
// 添加日志调试
export default {
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true,
        configure: (proxy) => {
          proxy.on('proxyReq', (proxyReq, req) => {
            console.log('Proxying:', req.method, req.url)
          })
        }
      }
    }
  }
}
```

## 9. 扩展思考

### Vite vs Webpack Dev Server

| 特性 | Vite Dev Server | Webpack Dev Server |
|-----|-----------------|-------------------|
| 启动原理 | No-Bundle，按需编译 | 先打包再启动 |
| 启动速度 | 毫秒级 | 秒到分钟级 |
| HMR 速度 | 毫秒级，只更新变化模块 | 较慢，需重新打包 |
| 模块格式 | 原生 ES Modules | Bundle 后的代码 |
| 内存占用 | 较低 | 较高 |

### 底层技术栈

```
┌─────────────────────────────────────────┐
│           Vite Dev Server               │
├─────────────────────────────────────────┤
│  Connect (HTTP 中间件框架)               │
├─────────────────────────────────────────┤
│  chokidar (文件监听)                     │
├─────────────────────────────────────────┤
│  esbuild (TypeScript/JSX 转换)          │
├─────────────────────────────────────────┤
│  ws (WebSocket，用于 HMR)               │
└─────────────────────────────────────────┘
```
