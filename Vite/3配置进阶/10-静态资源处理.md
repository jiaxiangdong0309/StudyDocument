# 静态资源处理 (Static Asset Handling)

## 1. 解决什么问题？
> 让各类静态资源（图片、字体、文件）被正确引用和优化

* **痛点**：项目中有图片、字体、JSON 等资源，如何引入？构建后路径如何处理？小文件如何优化？
* **作用**：Vite 提供统一的资源导入方式，自动处理路径、哈希、内联优化等问题

## 2. 通俗理解

### 核心定义
静态资源处理是指 Vite 对非 JavaScript/CSS 文件的处理方式。根据资源类型和大小，Vite 会自动选择最优的处理策略：URL 引用、base64 内联或原样复制。

### 生活化比喻
把静态资源想象成搬家时的物品：
- **public 目录** = 直接搬走的大件（冰箱、沙发），原样放到新家
- **src/assets 目录** = 需要打包的物品，贴上标签（哈希），整理后搬运
- **小于 4KB 的文件** = 小物件直接塞口袋（内联 base64），不单独打包

## 3. 工作原理

```mermaid
graph TB
    A[导入资源] --> B{资源位置?}
    B -->|public/| C[原样复制到输出目录]
    B -->|src/assets/| D{文件大小?}
    D -->|< 4KB| E[内联为 base64]
    D -->|>= 4KB| F[输出独立文件 + 哈希]

    C --> G[绝对路径引用]
    E --> H[data:image/png;base64,...]
    F --> I[/assets/logo-a1b2c3d4.png]
```

## 4. 核心代码实战

### 业务场景：电商网站资源管理

#### 目录结构

```
my-project/
├── public/              # 不经过构建处理
│   ├── favicon.ico      # 网站图标
│   ├── robots.txt       # SEO 文件
│   └── images/
│       └── logo.png     # 大图，需要 CDN 路径
├── src/
│   ├── assets/          # 经过构建处理
│   │   ├── images/
│   │   │   ├── icon-cart.svg   # 小图标
│   │   │   └── banner.jpg      # 大图
│   │   └── fonts/
│   │       └── custom.woff2
│   └── ...
```

#### 图片资源导入

```js
<script setup lang="ts">
// 方式一：import 导入（推荐）
// 构建后自动添加哈希，支持缓存优化
import bannerUrl from '@/assets/images/banner.jpg'
import cartIcon from '@/assets/images/icon-cart.svg'

// 方式二：URL 构造器（动态路径）
const getImageUrl = (name: string) => {
  // 必须是相对路径，Vite 才能正确处理
  return new URL(`../assets/images/${name}`, import.meta.url).href
}

// 方式三：public 目录资源（绝对路径）
const logoUrl = '/images/logo.png'  // 直接用绝对路径
</script>

<template>
  <!-- import 导入的资源 -->
  <img :src="bannerUrl" alt="Banner" />
  <img :src="cartIcon" alt="购物车" />

  <!-- public 目录资源 -->
  <img :src="logoUrl" alt="Logo" />

  <!-- 动态图片 -->
  <img :src="getImageUrl('product-1.jpg')" alt="商品" />
</template>
```

#### 特殊导入方式

```typescript
// 1. 显式导入为 URL
import imgUrl from './img.png?url'

// 2. 导入为原始字符串（SVG 内联）
import svgContent from './icon.svg?raw'

// 3. 导入 JSON
import config from './config.json'            // 默认导出整个对象
import { version } from './package.json'      // 具名导入

// 4. 导入 Web Worker
import Worker from './worker.js?worker'
const worker = new Worker()

// 5. 导入 WASM
import init from './module.wasm?init'
init().then(instance => {
  instance.exports.main()
})
```

### vite.config.js 资源配置

```javascript
// vite.config.js
export default defineConfig({
  // 资源内联阈值：小于 4KB 转 base64
  build: {
    assetsInlineLimit: 4096,

    // 自定义资源文件名
    rollupOptions: {
      output: {
        // 根据文件类型分目录
        assetFileNames: (assetInfo) => {
          // 获取文件扩展名
          const ext = assetInfo.name.split('.').pop()

          // 图片放 images 目录
          if (/png|jpe?g|gif|svg|webp|ico/.test(ext)) {
            return 'images/[name]-[hash][extname]'
          }
          // 字体放 fonts 目录
          if (/woff2?|eot|ttf|otf/.test(ext)) {
            return 'fonts/[name]-[hash][extname]'
          }
          // 其他资源
          return 'assets/[name]-[hash][extname]'
        }
      }
    }
  },

  // 资源处理配置
  assetsInclude: ['**/*.gltf', '**/*.glb'],  // 额外的资源类型
})
```

## 5. 最佳实践

### 性能考虑
- **小图标用 SVG**：可内联、可缩放、体积小
- **合理设置 assetsInlineLimit**：太大会增加 HTML/JS 体积，太小会增加请求数
- **大图使用 CDN**：放 public 目录，配合 CDN 使用

### public vs assets 选择

| 特性 | public 目录 | src/assets 目录 |
|------|-------------|-----------------|
| 构建处理 | 原样复制 | 经过处理 |
| 文件名哈希 | ❌ 无 | ✅ 有 |
| 引用方式 | 绝对路径 | import 导入 |
| 缓存策略 | 需手动控制 | 自动长期缓存 |
| 适用场景 | favicon、robots.txt | 业务图片、图标 |

### 注意事项
- **public 资源路径**：始终从根路径引用，不会被处理
- **动态导入限制**：`import()` 中的路径必须以 `./` 或 `../` 开头
- **base 路径影响**：设置 `base` 后，public 资源路径不受影响

## 6. 常见错误与解决方案

### 错误 1：动态路径导入失败

```javascript
// ❌ 错误：完全动态的路径无法处理
const name = 'logo'
import(`./images/${name}.png`)  // 可能失败

// ✅ 正确：使用 URL 构造器或 import.meta.glob
const getImage = (name) => {
  return new URL(`./images/${name}.png`, import.meta.url).href
}

// 或者使用 glob 导入
const images = import.meta.glob('./images/*.png', { eager: true })
const logoUrl = images['./images/logo.png'].default
```

### 错误 2：public 资源路径错误

```javascript
// ❌ 错误：使用相对路径引用 public 资源
const logo = '../public/logo.png'

// ✅ 正确：使用绝对路径
const logo = '/logo.png'
```

### 错误 3：构建后图片路径 404

```javascript
// ❌ 错误：在 CSS 中使用别名可能出问题
.bg {
  background: url(@/assets/bg.png);  // 某些情况可能失败
}

// ✅ 正确：使用相对路径
.bg {
  background: url(../assets/bg.png);
}

// 或者在 vite.config.js 中配置 CSS 别名解析
css: {
  preprocessorOptions: {
    scss: {
      additionalData: `@use "@/styles/variables" as *;`
    }
  }
}
```

## 7. 扩展思考

### import.meta.glob 批量导入

```typescript
// 批量导入所有图片
const images = import.meta.glob('./images/**/*.{png,jpg,svg}')
// 返回: { './images/a.png': () => import('./images/a.png'), ... }

// 立即加载（不懒加载）
const imageModules = import.meta.glob('./images/*.png', {
  eager: true,
  import: 'default'  // 直接获取默认导出
})
// 返回: { './images/a.png': '/assets/a-xxx.png', ... }

// 导入为原始字符串
const svgIcons = import.meta.glob('./icons/*.svg', {
  query: '?raw',
  import: 'default'
})
```
