# 组件基础 · 基础篇

> 组件是什么、什么时候用、如何使用（TypeScript + 函数组件），以及常见问题。

---

## 一、组件是什么？

### 定义

**组件（Component）** 是 React 中用来描述 UI 的一小块、可复用的逻辑单元。你写一个**函数**，接收 **Props**，返回 **JSX**，React 负责在数据变化时把这块 UI 渲染到页面上。

### 通俗理解

可以把组件想成「乐高积木」：每一块积木（组件）有自己的形状和插口（Props），拼在一起（组合）就能搭出完整页面。同一块积木可以在多处重复使用。

### 函数组件（现代写法）

现在推荐用**函数组件**，不用 Class 组件。

**为什么不用 Class 组件？**

- **官方与生态主推**：React 官方和文档、新特性（如 Hooks）都围绕函数组件，新项目、教程、库示例多以函数组件为主。
- **写法更简单**：函数组件就是「接收 props、返回 JSX」的一个函数，没有 `this`、`constructor`、生命周期方法那一套，逻辑更直观。
- **Hooks 只能在函数里用**：`useState`、`useEffect` 等只能在函数组件（或自定义 Hook）里调用，Class 里没有等价且统一的写法。
- **Class 容易踩坑**：`this` 绑定、生命周期命名多且容易记混（如 `componentDidMount` vs `componentDidUpdate`），逻辑分散在多个方法里，不如函数 + Hooks 好维护。

所以**现代 React 以函数组件 + Hooks 为准**，除非维护老项目，否则不必再写 Class 组件。

```typescript
// 一个最简单的函数组件：接收 props，返回 JSX
function Welcome({ name }: { name: string }) {
  return <h1>你好，{name}</h1>
}

// 使用
<Welcome name="张三" />
```

**必须用 function 吗？用 const 定义组件是啥意思？**

不必须。组件本质就是一个**能返回 JSX 的函数**，用 `function` 声明或用 `const` 赋值为箭头函数都可以，React 不区分：

```typescript
// 写法一：function 声明
function Welcome({ name }: { name: string }) {
  return <h1>你好，{name}</h1>
}

// 写法二：const + 箭头函数（很多人这样写）
const Welcome = ({ name }: { name: string }) => {
  return <h1>你好，{name}</h1>
}
```

用 `const Component = () => {}` 的常见原因：和项目里其它箭头函数风格统一、写法简短、有些人习惯「变量即组件」的写法。两种写法功能完全一样，选一种在项目里统一即可。

## 二、JSX 是什么？怎么用？

### 是什么

**JSX** 是写在 JavaScript/TypeScript 里的「像 HTML 的语法」，最终会被编译成 `React.createElement(...)`。你在组件里写 JSX，就是在描述「数据对应什么样的 UI」。

### 基本规则

| 规则 | 说明 | 示例 |
|------|------|------|
| 一个根节点 | 组件 return 的 JSX 要有**一个**根元素 | 用 `<div>` 或 `<>...</>` 包一层 |
| 标签要闭合 | 单标签也要闭合 | `<input />`、`<img />` |
| 用 className | class 是 JS 保留字，用 `className` | `<div className="card">` |
| 用 camelCase | 事件、样式属性用驼峰 | `onClick`、`backgroundColor` |
| 插值用 `{}` | 在 JSX 里写表达式用大括号 | `<span>{user.name}</span>` |

### 条件渲染

根据数据或状态决定显示哪一块 UI：

```typescript
// 方式一：三元
function Greeting({ isLoggedIn, name }: { isLoggedIn: boolean; name: string }) {
  return <div>{isLoggedIn ? `欢迎，${name}` : '请登录'}</div>
}

// 方式二：短路
function Alert({ message }: { message: string | null }) {
  return <div>{message && <span className="alert">{message}</span>}</div>
}

// 方式三：提前 return，逻辑更清晰
function UserCard({ user }: { user: User | null }) {
  if (!user) return <div>加载中...</div>
  return (
    <div>
      <h2>{user.name}</h2>
      <p>{user.email}</p>
    </div>
  )
}
```

## 三、Props：父传子的数据

### 是什么

**Props** 是父组件传给子组件的数据（或回调），在子组件里是**只读**的。修改「来自父组件的数据」要在父组件里改 state，再通过 props 传下来（单向数据流）。

### 什么时候用

- 父组件要把**数据**传给子组件展示（如列表项、卡片内容）
- 父组件要把**回调**传给子组件，让子组件通知父组件（如点击、提交）

### 如何使用

```typescript
// 用 interface 定义 Props 类型，清晰且可复用
interface ProductCardProps {
  title: string
  price: number
  onAddCart: (id: string) => void
}

function ProductCard({ title, price, onAddCart }: ProductCardProps) {
  const handleClick = () => onAddCart('product-1')
  return (
    <div>
      <h3>{title}</h3>
      <p>¥{price}</p>
      <button onClick={handleClick}>加入购物车</button>
    </div>
  )
}
```

### 默认值与 children

```typescript
interface ButtonProps {
  children: React.ReactNode  // 标签之间的内容
  variant?: 'primary' | 'secondary'
}

function Button({ children, variant = 'primary' }: ButtonProps) {
  return <button className={`btn btn-${variant}`}>{children}</button>
}

// 使用
<Button variant="secondary">提交</Button>
<Button>
  <span>图标</span> 保存
</Button>
```

## 四、列表渲染与 key

### 什么时候用

从接口或 state 拿到数组，要**一条数据对应一个子组件**时（如商品列表、评论列表）。

### 如何使用

```typescript
interface Todo {
  id: string
  text: string
  done: boolean
}

function TodoList({ todos, onToggle }: { todos: Todo[]; onToggle: (id: string) => void }) {
  return (
    <ul>
      {todos.map((todo) => (
        <li key={todo.id}>
          <input
            type="checkbox"
            checked={todo.done}
            onChange={() => onToggle(todo.id)}
          />
          <span>{todo.text}</span>
        </li>
      ))}
    </ul>
  )
}
```

### 为什么要有 key？常见错误

- **作用**：key 帮助 React 识别「哪一项变了、哪一项是新增/删除」，从而正确更新 DOM、保留组件状态。
- **不要用 index 当 key**（在列表会**增删、重排**时）：用 index 会导致状态错位、渲染错乱。用**稳定且唯一**的 id（如接口返回的 `id`）。
- **key 要在直接 map 出来的顶层元素上**，不要放在再包一层的子组件内部。

```typescript
// ❌ 不好：列表会增删时用 index 当 key
{todos.map((todo, index) => <TodoItem key={index} todo={todo} />)}

// ✅ 好：用稳定唯一 id
{todos.map((todo) => <TodoItem key={todo.id} todo={todo} />)}
```

## 五、事件处理

### 是什么

在 JSX 里用 `onClick`、`onChange` 等 **驼峰命名** 的事件属性，传一个**函数**（不要加括号调用，否则会立即执行）。

### 什么时候用

用户操作需要触发逻辑：点击按钮、输入内容、提交表单等。

### 如何使用

```typescript
function SearchBar({ onSearch }: { onSearch: (keyword: string) => void }) {
  const [keyword, setKeyword] = useState('')

  const handleSubmit = (e: React.FormEvent) => {
    e.preventDefault()  // 阻止表单默认提交
    onSearch(keyword)
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        value={keyword}
        onChange={(e) => setKeyword(e.target.value)}
      />
      <button type="submit">搜索</button>
    </form>
  )
}
```

## 六、受控组件 vs 非受控组件（表单）

### 区别

| 方式 | 值的来源 | 典型写法 | 适用场景 |
|------|----------|----------|----------|
| **受控** | 由 React state 管理 | `value={state}` + `onChange` 更新 state | 需要即时校验、联动、提交前统一读值时 |
| **非受控** | 值在 DOM 里，用 ref 取 | `defaultValue` + `ref`，提交时再读 | 简单表单、大表单性能敏感、集成非 React 库时 |

### 受控组件示例（推荐多数场景）

```typescript
function LoginForm({ onSubmit }: { onSubmit: (data: { email: string; password: string }) => void }) {
  const [email, setEmail] = useState('')
  const [password, setPassword] = useState('')

  const handleSubmit = (e: React.FormEvent) => {
    e.preventDefault()
    onSubmit({ email, password })
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        type="email"
        value={email}
        onChange={(e) => setEmail(e.target.value)}
      />
      <input
        type="password"
        value={password}
        onChange={(e) => setPassword(e.target.value)}
      />
      <button type="submit">登录</button>
    </form>
  )
}
```

### 非受控组件示例

```typescript
function UncontrolledForm() {
  const inputRef = useRef<HTMLInputElement>(null)

  const handleSubmit = (e: React.FormEvent) => {
    e.preventDefault()
    const value = inputRef.current?.value
    console.log(value)
  }

  return (
    <form onSubmit={handleSubmit}>
      <input ref={inputRef} defaultValue="" />
      <button type="submit">提交</button>
    </form>
  )
}
```

## 七、常见问题

| 问题 | 原因 | 解决 |
|------|------|------|
| 直接修改 props | Props 只读，React 依赖「引用/值不变」检测变化 | 在父组件用 setState 更新，再通过 props 传下来 |
| 列表用 index 当 key 导致错乱 | 增删/排序后 index 和项不对应 | 用稳定唯一 id 当 key |
| 事件里拿到的是旧 state | 闭包或异步导致拿到的是旧快照 | 用 `setX(prev => ...)` 函数式更新，或检查依赖 |
| 表单不更新 | 写了 `value` 没写 `onChange`，或 value 不是 state | 受控必须：`value={state}` + `onChange` 里 setState |
| 组件名没大写 | JSX 里小写会被当 HTML 标签 | 组件名首字母大写 |

## 八、实用检验（自测）

1. **组件是什么？和 Props 的关系？**  
   组件是接收 Props、返回 JSX 的函数。Props 是父传子的只读数据（或回调）。

2. **列表渲染为什么要写 key？为什么不要用 index？**  
   key 让 React 正确做 Diff 和复用。index 在增删、排序时会和「项」错位，导致状态错乱、渲染错误。

3. **受控和非受控表单的区别？**  
   受控：值由 state 管，`value` + `onChange`。非受控：值在 DOM，用 `ref` 在需要时读取。

4. **子组件想通知父组件「用户点了确定」该怎么做？**  
   父组件通过 props 传一个回调，如 `onConfirm`，子组件在点击时调用 `onConfirm()`。

5. **条件渲染有几种常见写法？**  
   三元 `a ? <A /> : <B />`、短路 `flag && <X />`、提前 return（根据条件 return 不同 JSX）。
