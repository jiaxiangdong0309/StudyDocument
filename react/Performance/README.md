# React 性能优化（Performance Optimization）

> 性能优化不是炫技，而是在用户体感卡顿时，能精准定位瓶颈并给出合理方案的能力。

---

## 这组文档解决什么问题？

| 你遇到的困境 | 这里能找到什么 |
|-------------|---------------|
| 页面越写越卡，不知道从哪下手 | 系统的性能分析方法论 + React DevTools 实战 |
| memo/useMemo/useCallback 到处写，效果不明显 | 什么时候该用、什么时候是多余的，有判断标准 |
| 列表几百条就掉帧 | 虚拟列表方案 + 实际业务接入指南 |
| 首屏加载 3 秒以上 | 代码分割、Bundle 分析、资源加载策略 |
| 搜索/筛选输入卡顿 | useTransition + useDeferredValue 并发特性实战 |
| 做完需求就完了，不知道怎么体现技术深度 | 真实项目优化案例 + 量化指标思路 |

## 核心理念

```
先量化，再优化，最后验证
          ↓
  1. 用 Profiler 找到「真正慢」的组件
  2. 分析原因（重渲染？计算重？DOM 多？Bundle 大？）
  3. 选择最小代价的方案
  4. 优化后对比数据，确认有效
```

**不要凭感觉优化**——每一次优化都应该能回答：优化了什么、提升了多少、为什么选这个方案。
