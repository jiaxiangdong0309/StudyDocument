# Java 注解进阶篇

> 注解的真正威力在于"处理器"——没有处理器的注解就像没有读者的便签，毫无意义。

## 一、注解处理的两种方式

### 1.1 编译时处理 vs 运行时处理

| 维度 | 编译时处理（APT） | 运行时处理（反射） |
|-----|-----------------|------------------|
| 处理时机 | javac 编译时 | 程序运行时 |
| 注解保留策略 | SOURCE 或 CLASS | **必须是 RUNTIME** |
| 性能影响 | 零运行时开销 | 有反射开销 |
| 典型代表 | Lombok、MapStruct、Dagger | Spring、JUnit、Jackson |
| 能做什么 | 生成代码、生成文件、编译检查 | 读取注解信息、动态行为 |

```
┌─────────────────────────────────────────────────────────────────┐
│                        注解处理时机                              │
│                                                                 │
│   .java 文件                                                    │
│       │                                                         │
│       ▼  ← APT 介入（编译时处理）                                │
│   ┌───────┐                                                     │
│   │ javac │ ──▶ 生成额外 .java 文件 ──▶ 再次编译                 │
│   └───────┘                                                     │
│       │                                                         │
│       ▼                                                         │
│   .class 文件                                                   │
│       │                                                         │
│       ▼  ← 反射介入（运行时处理）                                │
│   ┌───────┐                                                     │
│   │  JVM  │ ──▶ 读取注解 ──▶ 执行相应逻辑                        │
│   └───────┘                                                     │
└─────────────────────────────────────────────────────────────────┘
```

## 二、运行时注解处理（基于反射）

### 2.1 AnnotatedElement 接口

所有可以被注解的元素（Class、Method、Field、Constructor、Package）都实现了 `AnnotatedElement` 接口：

```java
public interface AnnotatedElement {
    // 判断是否存在指定注解
    boolean isAnnotationPresent(Class<? extends Annotation> annotationClass);
    
    // 获取指定注解（含继承的）
    <T extends Annotation> T getAnnotation(Class<T> annotationClass);
    
    // 获取所有注解（含继承的）
    Annotation[] getAnnotations();
    
    // 获取直接声明的注解（不含继承的）
    Annotation[] getDeclaredAnnotations();
    
    // JDK 8+：获取可重复注解
    <T extends Annotation> T[] getAnnotationsByType(Class<T> annotationClass);
}
```

### 2.2 完整的反射读取示例

```java
import java.lang.annotation.*;
import java.lang.reflect.*;

// 定义注解
@Target({ElementType.TYPE, ElementType.METHOD, ElementType.FIELD})
@Retention(RetentionPolicy.RUNTIME)
@interface Info {
    String author() default "unknown";
    String version() default "1.0";
    String[] tags() default {};
}

// 使用注解
@Info(author = "张三", version = "2.0", tags = {"核心", "重要"})
class UserService {
    
    @Info(author = "李四")
    private String serviceName;
    
    @Info(version = "1.5", tags = {"API"})
    public void process() {
        System.out.println("处理中...");
    }
}

// 读取注解
public class AnnotationReader {
    public static void main(String[] args) throws Exception {
        Class<UserService> clazz = UserService.class;
        
        // 1. 读取类上的注解
        if (clazz.isAnnotationPresent(Info.class)) {
            Info classInfo = clazz.getAnnotation(Info.class);
            System.out.println("类注解 - 作者: " + classInfo.author());
            System.out.println("类注解 - 版本: " + classInfo.version());
            System.out.println("类注解 - 标签: " + String.join(", ", classInfo.tags()));
        }
        
        System.out.println("---");
        
        // 2. 读取字段上的注解
        Field field = clazz.getDeclaredField("serviceName");
        Info fieldInfo = field.getAnnotation(Info.class);
        if (fieldInfo != null) {
            System.out.println("字段注解 - 作者: " + fieldInfo.author());
        }
        
        System.out.println("---");
        
        // 3. 读取方法上的注解
        Method method = clazz.getMethod("process");
        Info methodInfo = method.getAnnotation(Info.class);
        if (methodInfo != null) {
            System.out.println("方法注解 - 版本: " + methodInfo.version());
            System.out.println("方法注解 - 标签: " + String.join(", ", methodInfo.tags()));
        }
    }
}
```

**输出**：
```
类注解 - 作者: 张三
类注解 - 版本: 2.0
类注解 - 标签: 核心, 重要
---
字段注解 - 作者: 李四
---
方法注解 - 版本: 1.5
方法注解 - 标签: API
```

### 2.3 实战：实现简易的依赖注入框架

模拟 Spring 的 `@Autowired` 功能：

**Step 1：定义注解**

```java
@Target(ElementType.FIELD)
@Retention(RetentionPolicy.RUNTIME)
public @interface Inject {}

@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
public @interface Component {}
```

**Step 2：定义组件**

```java
@Component
public class UserRepository {
    public String findUser(Long id) {
        return "User-" + id;
    }
}

@Component
public class UserService {
    @Inject
    private UserRepository userRepository;  // 需要被自动注入
    
    public String getUser(Long id) {
        return userRepository.findUser(id);
    }
}
```

**Step 3：实现容器**

```java
import java.lang.reflect.Field;
import java.util.HashMap;
import java.util.Map;

public class SimpleContainer {
    // 存储组件实例：类型 -> 实例
    private final Map<Class<?>, Object> beans = new HashMap<>();
    
    /**
     * 注册组件
     */
    public void register(Class<?>... classes) throws Exception {
        for (Class<?> clazz : classes) {
            // 只处理标记了 @Component 的类
            if (clazz.isAnnotationPresent(Component.class)) {
                Object instance = clazz.getDeclaredConstructor().newInstance();
                beans.put(clazz, instance);
            }
        }
        
        // 注册完成后，处理依赖注入
        for (Object bean : beans.values()) {
            injectDependencies(bean);
        }
    }
    
    /**
     * 处理依赖注入
     */
    private void injectDependencies(Object bean) throws Exception {
        Class<?> clazz = bean.getClass();
        
        for (Field field : clazz.getDeclaredFields()) {
            // 查找标记了 @Inject 的字段
            if (field.isAnnotationPresent(Inject.class)) {
                Class<?> fieldType = field.getType();
                Object dependency = beans.get(fieldType);
                
                if (dependency == null) {
                    throw new RuntimeException("找不到依赖: " + fieldType.getName());
                }
                
                field.setAccessible(true);
                field.set(bean, dependency);  // 注入依赖
            }
        }
    }
    
    /**
     * 获取组件
     */
    @SuppressWarnings("unchecked")
    public <T> T getBean(Class<T> clazz) {
        return (T) beans.get(clazz);
    }
}
```

**Step 4：测试使用**

```java
public class ContainerTest {
    public static void main(String[] args) throws Exception {
        SimpleContainer container = new SimpleContainer();
        
        // 注册组件
        container.register(UserRepository.class, UserService.class);
        
        // 获取并使用
        UserService userService = container.getBean(UserService.class);
        String result = userService.getUser(123L);
        
        System.out.println(result);  // 输出: User-123
    }
}
```

> 💡 这个简易容器展示了 Spring IOC 的核心原理：扫描注解 → 创建实例 → 注入依赖。

## 三、编译时注解处理（APT）

### 3.1 什么是 APT？

**APT（Annotation Processing Tool）** 是 javac 编译器的插件机制，允许在编译时扫描和处理注解，生成额外的源文件或资源文件。

```
┌────────────────────────────────────────────────────────────┐
│                    APT 处理流程                             │
│                                                            │
│   源代码 (.java)                                           │
│       │                                                    │
│       ▼                                                    │
│   ┌────────────────────────────────────────────┐          │
│   │              javac 编译器                   │          │
│   │  ┌──────────────────────────────────────┐  │          │
│   │  │    轮次1：解析源码，发现注解            │  │          │
│   │  │              ↓                       │  │          │
│   │  │    调用注解处理器（APT）               │  │          │
│   │  │              ↓                       │  │          │
│   │  │    生成新的 .java 文件？               │  │          │
│   │  │         ↓是      ↓否                 │  │          │
│   │  │    轮次2：编译新文件 → 结束编译        │  │          │
│   │  └──────────────────────────────────────┘  │          │
│   └────────────────────────────────────────────┘          │
│       │                                                    │
│       ▼                                                    │
│   字节码 (.class) + 生成的代码                              │
└────────────────────────────────────────────────────────────┘
```

### 3.2 实战：实现简易的 Builder 生成器

模拟 Lombok 的 `@Builder` 功能。

**Step 1：定义注解（放在独立模块 annotation-api）**

```java
package com.example.annotation;

import java.lang.annotation.*;

@Target(ElementType.TYPE)
@Retention(RetentionPolicy.SOURCE)  // 只需要在编译时处理
public @interface Builder {}
```

**Step 2：实现注解处理器（放在独立模块 annotation-processor）**

```java
package com.example.processor;

import com.example.annotation.Builder;
import javax.annotation.processing.*;
import javax.lang.model.SourceVersion;
import javax.lang.model.element.*;
import javax.tools.JavaFileObject;
import java.io.IOException;
import java.io.PrintWriter;
import java.util.*;

@SupportedAnnotationTypes("com.example.annotation.Builder")
@SupportedSourceVersion(SourceVersion.RELEASE_17)
public class BuilderProcessor extends AbstractProcessor {
    
    @Override
    public boolean process(Set<? extends TypeElement> annotations, 
                          RoundEnvironment roundEnv) {
        // 遍历所有标记了 @Builder 的类
        for (Element element : roundEnv.getElementsAnnotatedWith(Builder.class)) {
            if (element.getKind() != ElementKind.CLASS) {
                continue;
            }
            
            TypeElement classElement = (TypeElement) element;
            try {
                generateBuilderClass(classElement);
            } catch (IOException e) {
                processingEnv.getMessager().printMessage(
                    Diagnostic.Kind.ERROR, 
                    "生成 Builder 失败: " + e.getMessage()
                );
            }
        }
        return true;  // 表示注解已被处理
    }
    
    private void generateBuilderClass(TypeElement classElement) throws IOException {
        String className = classElement.getSimpleName().toString();
        String packageName = processingEnv.getElementUtils()
            .getPackageOf(classElement).getQualifiedName().toString();
        String builderClassName = className + "Builder";
        
        // 收集所有字段
        List<VariableElement> fields = new ArrayList<>();
        for (Element enclosed : classElement.getEnclosedElements()) {
            if (enclosed.getKind() == ElementKind.FIELD) {
                fields.add((VariableElement) enclosed);
            }
        }
        
        // 生成新的 Java 文件
        JavaFileObject builderFile = processingEnv.getFiler()
            .createSourceFile(packageName + "." + builderClassName);
        
        try (PrintWriter out = new PrintWriter(builderFile.openWriter())) {
            // 包声明
            out.println("package " + packageName + ";");
            out.println();
            
            // 类声明
            out.println("public class " + builderClassName + " {");
            
            // 字段
            for (VariableElement field : fields) {
                out.printf("    private %s %s;%n", 
                    field.asType(), field.getSimpleName());
            }
            out.println();
            
            // setter 方法（返回 this 实现链式调用）
            for (VariableElement field : fields) {
                String fieldName = field.getSimpleName().toString();
                String fieldType = field.asType().toString();
                out.printf("    public %s %s(%s %s) {%n", 
                    builderClassName, fieldName, fieldType, fieldName);
                out.printf("        this.%s = %s;%n", fieldName, fieldName);
                out.println("        return this;");
                out.println("    }");
                out.println();
            }
            
            // build 方法
            out.printf("    public %s build() {%n", className);
            out.printf("        %s instance = new %s();%n", className, className);
            for (VariableElement field : fields) {
                String fieldName = field.getSimpleName().toString();
                // 假设有 setter 方法
                String setterName = "set" + capitalize(fieldName);
                out.printf("        instance.%s(this.%s);%n", setterName, fieldName);
            }
            out.println("        return instance;");
            out.println("    }");
            
            out.println("}");
        }
    }
    
    private String capitalize(String str) {
        return str.substring(0, 1).toUpperCase() + str.substring(1);
    }
}
```

**Step 3：注册处理器**

在 `META-INF/services/javax.annotation.processing.Processor` 文件中添加：


### 3.3 APT 核心 API

| 类/接口 | 作用 |
|--------|------|
| `AbstractProcessor` | 注解处理器基类，继承它实现处理逻辑 |
| `ProcessingEnvironment` | 处理环境，提供工具类访问 |
| `RoundEnvironment` | 当前轮次信息，获取被注解的元素 |
| `Filer` | 文件创建工具，用于生成源文件 |
| `Messager` | 消息输出工具，报告错误/警告 |
| `Elements` | 元素工具类，操作元素信息 |
| `Types` | 类型工具类，操作类型信息 |

### 3.4 Lombok 原理简析

Lombok 不是标准的 APT，它使用了更"黑科技"的方式：

```
┌─────────────────────────────────────────────────────────┐
│                  Lombok 工作原理                         │
│                                                         │
│   标准 APT：只能生成新文件，不能修改现有文件              │
│                     ↓                                   │
│   Lombok：通过非公开 API 直接修改 AST（抽象语法树）       │
│                                                         │
│   ┌─────────┐    ┌─────────┐    ┌─────────┐            │
│   │ 源代码  │ ──▶ │   AST   │ ──▶ │ 字节码  │            │
│   └─────────┘    └────┬────┘    └─────────┘            │
│                       │                                 │
│                  Lombok 在此                            │
│                  注入代码                               │
└─────────────────────────────────────────────────────────┘
```

> ⚠️ **注意**：Lombok 的实现方式依赖编译器内部 API，不同 JDK/IDE 版本可能需要不同适配。

```java
// Spring 容器启动时的注解处理（简化版）
public class SpringAnnotationProcessor {
    public void processBean(Object bean) {
        Class<?> clazz = bean.getClass();
        
        // 处理 @Autowired
        for (Field field : clazz.getDeclaredFields()) {
            if (field.isAnnotationPresent(Autowired.class)) {
                Object dependency = findBean(field.getType());
                field.setAccessible(true);
                field.set(bean, dependency);
            }
        }
        
        // 处理 @Value
        for (Field field : clazz.getDeclaredFields()) {
            Value valueAnno = field.getAnnotation(Value.class);
            if (valueAnno != null) {
                String key = valueAnno.value();
                Object value = resolveProperty(key);
                field.setAccessible(true);
                field.set(bean, value);
            }
        }
    }
}
```

## 五、注解的性能考量

### 5.1 反射读取注解的性能

```java
// 性能测试：读取注解 vs 直接访问
public class AnnotationPerformanceTest {
    
    @Info(author = "test")
    public void annotatedMethod() {}
    
    public static void main(String[] args) throws Exception {
        Method method = AnnotationPerformanceTest.class
            .getMethod("annotatedMethod");
        
        // 预热
        for (int i = 0; i < 10000; i++) {
            method.getAnnotation(Info.class);
        }
        
        // 测试
        long start = System.nanoTime();
        for (int i = 0; i < 1000000; i++) {
            Info info = method.getAnnotation(Info.class);
            String author = info.author();
        }
        long end = System.nanoTime();
        
        System.out.printf("100万次注解读取耗时: %.2f ms%n", 
            (end - start) / 1_000_000.0);
        // 典型结果：约 50-100ms（受 JIT 优化影响）
    }
}
```

### 5.2 优化策略

```java
// 优化1：缓存注解实例
public class AnnotationCache {
    // 缓存：Method -> 注解
    private static final Map<Method, Info> cache = new ConcurrentHashMap<>();
    
    public static Info getInfo(Method method) {
        return cache.computeIfAbsent(method, 
            m -> m.getAnnotation(Info.class));
    }
}

// 优化2：启动时预加载
@PostConstruct
public void init() {
    // 启动时扫描并缓存所有注解信息
    for (Method method : this.getClass().getDeclaredMethods()) {
        if (method.isAnnotationPresent(Info.class)) {
            cache.put(method, method.getAnnotation(Info.class));
        }
    }
}
```

**性能建议**：

| 场景 | 建议 |
|-----|------|
| 高频调用的注解读取 | 使用缓存 |
| 启动时一次性处理 | 无需特别优化 |
| 极端性能要求 | 考虑用 APT 在编译时处理 |

## 六、高级技巧

### 6.1 注解的组合（Meta-Annotation Pattern）

Spring 中大量使用这种模式：

```java
// Spring 的 @RestController 就是组合注解
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Controller           // 包含 @Controller 的语义
@ResponseBody         // 包含 @ResponseBody 的语义
public @interface RestController {
    @AliasFor(annotation = Controller.class)
    String value() default "";
}

// 使用时：一个注解 = 两个注解的效果
@RestController
public class UserController {
    // 等价于 @Controller + @ResponseBody
}
```

### 6.2 自定义组合注解

```java
// 定义一个组合注解：标记需要事务 + 日志的服务方法
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
@Transactional(rollbackFor = Exception.class)  // 包含事务语义
@Logged                                         // 包含日志语义
public @interface TransactionalService {
    String value() default "";
}

// 使用
@TransactionalService
public void createUser(User user) {
    // 自动具有事务管理和日志记录功能
}
```

### 6.3 条件化注解处理

```java
// 根据注解属性决定处理逻辑
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
public @interface ConditionalOn {
    String property();
    String havingValue() default "";
}

// 处理器
public class ConditionalProcessor {
    public boolean shouldProcess(Class<?> clazz) {
        ConditionalOn condition = clazz.getAnnotation(ConditionalOn.class);
        if (condition == null) {
            return true;
        }
        
        String property = condition.property();
        String expected = condition.havingValue();
        String actual = System.getProperty(property);
        
        return expected.isEmpty() ? actual != null : expected.equals(actual);
    }
}

// 使用
@ConditionalOn(property = "feature.enabled", havingValue = "true")
@Component
public class FeatureService {
    // 只有当 feature.enabled=true 时才会被注册
}
```

## 七、边界认知

### 7.1 注解不适用的场景

| 场景 | 原因 | 替代方案 |
|-----|------|---------|
| 复杂的配置逻辑 | 注解属性只能是常量 | 使用配置文件或 Java Config |
| 需要动态修改的配置 | 注解不能运行时修改 | 使用配置中心 |
| 跨模块的通用配置 | 注解分散在各处 | 集中配置文件 |
| 非 Java 团队协作 | 注解是 Java 特有的 | 使用 YAML/JSON 配置 |

### 7.2 注解的局限性

```java
// 1. 注解属性不能是 null
@interface Config {
    String value() default null;  // ❌ 编译错误
}

// 2. 注解不能继承
@interface Parent {
    String name();
}

// ❌ 注解不支持 extends
@interface Child extends Parent {  // 编译错误
    int age();
}

// 3. 运行时无法修改注解
Info info = clazz.getAnnotation(Info.class);
// info.author = "新作者";  // ❌ 没有 setter，无法修改
```

## 八、面试检验

### Q1：APT 和运行时反射处理注解有什么区别？

**答案**：

| 维度 | APT（编译时） | 反射（运行时） |
|-----|-------------|---------------|
| 处理时机 | javac 编译时 | JVM 运行时 |
| 注解保留策略 | SOURCE 或 CLASS 即可 | 必须是 RUNTIME |
| 性能影响 | 零运行时开销 | 有反射调用开销 |
| 能力范围 | 生成代码、生成文件 | 读取注解、动态执行 |
| 典型代表 | Lombok、MapStruct | Spring、JUnit |

### Q2：Spring 的 @Autowired 是如何实现的？

**答案**：
1. Spring 容器启动时，扫描所有 Bean 的字段和方法
2. 找到标记了 `@Autowired` 的成员
3. 根据类型（或 `@Qualifier` 指定的名称）从容器中查找匹配的 Bean
4. 通过反射的 `field.set()` 或 `method.invoke()` 注入依赖

核心原理就是：**反射读取注解 + 反射设置值**。

### Q3：Lombok 的 @Data 是如何自动生成代码的？

**答案**：
Lombok 使用 APT 机制，但不是标准的生成新文件方式，而是：
1. 在编译时拦截 AST（抽象语法树）
2. 直接修改现有类的 AST，添加 getter/setter/toString 等方法节点
3. 修改后的 AST 继续编译，生成包含这些方法的字节码

这种方式的好处是不产生额外文件，但依赖编译器内部 API。

### Q4：如何实现一个可重复使用的注解？

**答案**：
```java
// 1. 定义容器注解
@Retention(RetentionPolicy.RUNTIME)
@interface Schedules {
    Schedule[] value();
}

// 2. 定义可重复注解，指定容器
@Retention(RetentionPolicy.RUNTIME)
@Repeatable(Schedules.class)  // 关键：指定容器注解
@interface Schedule {
    String time();
}

// 3. 使用
@Schedule(time = "09:00")
@Schedule(time = "14:00")
class Task {}

// 4. 读取
Schedule[] schedules = Task.class.getAnnotationsByType(Schedule.class);
```

### Q5：注解的属性类型为什么有限制？

**答案**：
因为注解信息存储在 class 文件的常量池中，JVM 规范限定常量池只能存储：
- 基本类型字面量
- String 常量
- Class 常量引用
- 枚举常量
- 注解（嵌套）
- 以上类型的数组

这些都是**编译期可确定的常量值**，不能是运行时才能确定的对象引用。
