# Handler 消息机制

## 技术定位

Handler 是 Android 的**线程间通信核心机制**，也是理解 Android 应用运行原理的基石。

**一句话理解**：Handler 就像公司里的"邮件系统"——你写封邮件（Message）投进邮箱（MessageQueue），有个勤快的邮递员（Looper）不停地取邮件，然后交给指定的人（Handler）处理。

## 核心问题预览

### 基础篇

1. **为什么 Android 要设计 Handler 机制？** 直接用 synchronized 加锁不行吗？
2. **Handler、Looper、MessageQueue、Message 各自的职责是什么？**
3. **子线程能创建 Handler 吗？** 需要注意什么？
4. **为什么 Handler 会导致内存泄漏？** 怎么解决？

### 进阶篇

5. **什么是同步屏障？** 为什么 View 的绘制需要它？
6. **IdleHandler 是什么？** 有哪些实际应用场景？
7. **Handler 导致的 ANR 怎么排查？**
8. **Handler vs RxJava vs 协程**，各自的适用场景？

### 源码篇

9. **Looper.loop() 是个死循环，为什么不会卡死主线程？**
10. **MessageQueue 的 next() 方法是如何实现"等待"的？**
11. **为什么用 ThreadLocal 存储 Looper？**
12. **Handler 的设计有哪些可借鉴之处？**
