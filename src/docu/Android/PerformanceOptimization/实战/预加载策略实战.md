# 预加载策略实战

## 前言

预加载的核心思想：**在用户无感知时提前准备资源，用户操作时直接使用**。

本质是**时间换空间，空间换体验**：牺牲一些内存缓存预加载的内容，换取用户操作时的即时响应。

---

## 二、预加载时机选择

### 2.1 时机矩阵

| 时机 | 特点 | 适用场景 | 风险 |
|-----|------|---------|------|
| **Application 启动** | 最早，但会影响启动速度 | 全局资源、核心 SDK | 拖慢冷启动 |
| **Splash 显示期间** | 用户在看 Splash，可利用这段时间 | 首页布局、首页数据 | 无 |
| **IdleHandler** | 主线程空闲时 | WebView 预热、次要资源 | 时机不可控 |
| **页面跳转前** | 即将进入下一页时 | 下一页布局、数据 | 可能预测错误 |
| **用户行为预测** | 根据用户习惯预测 | 高频页面 | 需要数据支撑 |

### 2.2 时机决策树

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    预加载时机决策                                             │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   Q1: 这个资源是不是 100% 会用到？                                           │
│   ├── 是（如首页） → Q2                                                     │
│   └── 否（如详情页） → Q3                                                   │
│                                                                             │
│   Q2: 对启动速度有影响吗？                                                   │
│   ├── 有影响 → Splash 期间或 IdleHandler                                    │
│   └── 无影响 → Application 启动时                                           │
│                                                                             │
│   Q3: 能预测用户会用吗？                                                     │
│   ├── 能（如点击列表项后大概率进详情）→ 用户操作前预加载                       │
│   └── 不能 → 不预加载，或用 IdleHandler 低优先级预加载                       │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2.3 按确定性分类

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    预加载策略按确定性分类                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   高确定性（100% 会用）                                                      │
│   ├── 首页布局 → Splash 期间预加载                                          │
│   ├── 首页数据 → Splash 期间请求                                            │
│   └── WebView 内核 → Application 启动后 IdleHandler 预热                    │
│                                                                             │
│   中确定性（大概率会用）                                                      │
│   ├── 详情页数据 → 列表点击（ACTION_DOWN）时预加载                           │
│   ├── 下一页数据 → 滑动到底部时预加载                                        │
│   └── 活动页 → 首页显示后 IdleHandler 预加载                                │
│                                                                             │
│   低确定性（可能会用）                                                       │
│   ├── 图片 → 滚动时预加载即将显示的几张                                      │
│   └── 其他页面 → 不预加载，或 IdleHandler 低优先级                           │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 布局预加载器实现

```kotlin
/**
 * 布局预加载器
 * 
 * 核心思想：
 * 1. 在 Splash 显示期间，异步 inflate 首页布局
 * 2. 首页 Activity 创建时，直接使用预加载好的 View
 * 3. 如果预加载还没完成，回退到正常加载
 */
object LayoutPreloader {
    
    private const val TAG = "LayoutPreloader"
    
    // 预加载的布局缓存
    // 使用 SoftReference 避免内存压力时影响 GC
    private val viewCache = ConcurrentHashMap<Int, SoftReference<View>>()
    
    // 正在预加载的布局
    private val loadingLayouts = ConcurrentHashMap<Int, Boolean>()
    
    // 预加载完成的回调
    private val callbacks = ConcurrentHashMap<Int, MutableList<(View) -> Unit>>()
    
    /**
     * 预加载布局（异步）
     * 
     * @param context Application Context，避免内存泄漏
     * @param layoutRes 布局资源 ID
     * @param onComplete 预加载完成回调（可选）
     */
    fun preload(
        context: Context,
        @LayoutRes layoutRes: Int,
        onComplete: ((View) -> Unit)? = null
    ) {
        // 已经预加载过了
        if (viewCache.containsKey(layoutRes) && viewCache[layoutRes]?.get() != null) {
            onComplete?.invoke(viewCache[layoutRes]!!.get()!!)
            return
        }
        
        // 正在预加载
        if (loadingLayouts[layoutRes] == true) {
            onComplete?.let {
                callbacks.getOrPut(layoutRes) { mutableListOf() }.add(it)
            }
            return
        }
        
        loadingLayouts[layoutRes] = true
        
        // 注册回调
        onComplete?.let {
            callbacks.getOrPut(layoutRes) { mutableListOf() }.add(it)
        }
        
        val startTime = SystemClock.elapsedRealtime()
        
        // 使用 AsyncLayoutInflater 异步加载
        AsyncLayoutInflater(context).inflate(layoutRes, null) { view, resId, _ ->
            val cost = SystemClock.elapsedRealtime() - startTime
            Log.d(TAG, "预加载布局 $resId 完成，耗时 ${cost}ms")
            
            // 缓存预加载的 View
            viewCache[resId] = SoftReference(view)
            loadingLayouts.remove(resId)
            
            // 触发回调
            callbacks.remove(resId)?.forEach { callback ->
                callback(view)
            }
        }
    }
    
    /**
     * 获取预加载的布局
     * 
     * @param layoutRes 布局资源 ID
     * @return 预加载的 View，如果没有或已被回收则返回 null
     */
    fun getPreloadedView(@LayoutRes layoutRes: Int): View? {
        val view = viewCache.remove(layoutRes)?.get()
        if (view != null) {
            Log.d(TAG, "命中预加载布局: $layoutRes")
        }
        return view
    }
    
    /**
     * 获取预加载的布局，如果没有则同步加载
     * 
     * @param context Context
     * @param layoutRes 布局资源 ID
     * @param parent 父布局（用于正确的 LayoutParams）
     * @return View
     */
    fun getOrInflate(
        context: Context,
        @LayoutRes layoutRes: Int,
        parent: ViewGroup? = null
    ): View {
        return getPreloadedView(layoutRes)?.also {
            // 预加载的 View 需要重新设置 LayoutParams
            if (parent != null && it.layoutParams == null) {
                it.layoutParams = ViewGroup.LayoutParams(
                    ViewGroup.LayoutParams.MATCH_PARENT,
                    ViewGroup.LayoutParams.MATCH_PARENT
                )
            }
        } ?: LayoutInflater.from(context).inflate(layoutRes, parent, false)
    }
    
    /**
     * 检查布局是否已预加载完成
     */
    fun isPreloaded(@LayoutRes layoutRes: Int): Boolean {
        return viewCache[layoutRes]?.get() != null
    }
    
    /**
     * 清除所有缓存
     */
    fun clear() {
        viewCache.clear()
        loadingLayouts.clear()
        callbacks.clear()
    }
}
```

## 四、数据预加载

### 4.1 数据预加载器实现

```kotlin
/**
 * 数据预加载器
 * 
 * 核心思想：
 * 1. 在 Splash 期间发起首页数据请求
 * 2. 首页 Activity 创建时，数据可能已经返回了
 * 3. 如果数据还没返回，等待即可（至少减少了等待时间）
 */
object DataPreloader {
    
    private const val TAG = "DataPreloader"
    
    // 预加载的数据缓存
    private val dataCache = ConcurrentHashMap<String, Any>()
    
    // 正在加载的请求
    private val loadingRequests = ConcurrentHashMap<String, Deferred<*>>()
    
    // 协程作用域
    private val scope = CoroutineScope(SupervisorJob() + Dispatchers.IO)
    
    /**
     * 预加载首页数据
     */
    fun preloadHomeData() {
        // 预加载 Banner 数据
        preload("home_banner") {
            HomeRepository.getBannerList()
        }
        
        // 预加载推荐列表
        preload("home_recommend") {
            HomeRepository.getRecommendList()
        }
        
        // 预加载分类数据
        preload("home_category") {
            HomeRepository.getCategoryList()
        }
    }
    
    /**
     * 通用预加载方法
     * 
     * @param key 数据唯一标识
     * @param loader 数据加载逻辑
     */
    fun <T> preload(key: String, loader: suspend () -> T) {
        // 避免重复请求
        if (dataCache.containsKey(key) || loadingRequests.containsKey(key)) {
            return
        }
        
        Log.d(TAG, "开始预加载: $key")
        
        val deferred = scope.async {
            try {
                val data = loader()
                dataCache[key] = data as Any
                Log.d(TAG, "预加载完成: $key")
                data
            } catch (e: Exception) {
                Log.e(TAG, "预加载失败: $key", e)
                null
            } finally {
                loadingRequests.remove(key)
            }
        }
        
        loadingRequests[key] = deferred
    }
    
    /**
     * 获取预加载的数据
     * 
     * @param key 数据 key
     * @param timeout 最大等待时间（如果数据还在加载中）
     * @return 数据，如果超时或失败返回 null
     */
    @Suppress("UNCHECKED_CAST")
    suspend fun <T> getData(key: String, timeout: Long = 3000L): T? {
        // 先检查缓存
        dataCache[key]?.let {
            dataCache.remove(key)
            Log.d(TAG, "命中预加载缓存: $key")
            return it as T
        }
        
        // 如果正在加载，等待完成
        val deferred = loadingRequests[key] as? Deferred<T?>
        if (deferred != null) {
            return try {
                withTimeout(timeout) {
                    Log.d(TAG, "等待预加载完成: $key")
                    deferred.await()
                }
            } catch (e: TimeoutCancellationException) {
                Log.w(TAG, "等待预加载数据超时: $key")
                null
            }
        }
        
        Log.d(TAG, "预加载未命中: $key")
        return null
    }
    
    /**
     * 获取预加载的数据（同步版本，不等待）
     */
    @Suppress("UNCHECKED_CAST")
    fun <T> getDataIfReady(key: String): T? {
        return dataCache.remove(key) as? T
    }
    
    /**
     * 清除所有缓存
     */
    fun clear() {
        dataCache.clear()
        loadingRequests.values.forEach { it.cancel() }
        loadingRequests.clear()
    }
}
```

### 5.2 实现：列表点击预加载

```kotlin
/**
 * 商品列表 Adapter：实现点击预加载
 * 
 * 核心思想：
 * 1. 在 ACTION_DOWN（手指按下）时开始预加载详情数据
 * 2. 在 ACTION_UP（手指松开）时触发跳转
 * 3. 跳转到详情页时，数据可能已经加载好了
 */
class ProductAdapter(
    private val onItemClick: (Product) -> Unit
) : ListAdapter<Product, ProductAdapter.ViewHolder>(ProductDiffCallback()) {
    
    override fun onBindViewHolder(holder: ViewHolder, position: Int) {
        val product = getItem(position)
        holder.bind(product)
        
        // 设置触摸监听，在手指按下时预加载
        holder.itemView.setOnTouchListener { _, event ->
            when (event.action) {
                MotionEvent.ACTION_DOWN -> {
                    // 手指按下，开始预加载详情页数据
                    preloadDetailData(product.id)
                }
                MotionEvent.ACTION_CANCEL -> {
                    // 用户滑动了（不是点击），取消预加载
                    cancelPreload(product.id)
                }
                // ACTION_UP 由 OnClickListener 处理
            }
            false  // 返回 false，让点击事件继续传递
        }
        
        holder.itemView.setOnClickListener {
            onItemClick(product)
        }
    }
    
    /**
     * 预加载详情页数据
     */
    private fun preloadDetailData(productId: String) {
        DataPreloader.preload("product_detail_$productId") {
            ProductRepository.getProductDetail(productId)
        }
        Log.d("ProductAdapter", "开始预加载商品详情: $productId")
    }
    
    /**
     * 取消预加载（可选实现）
     */
    private fun cancelPreload(productId: String) {
        Log.d("ProductAdapter", "取消预加载: $productId")
    }
    
    class ViewHolder(view: View) : RecyclerView.ViewHolder(view) {
        private val ivCover: ImageView = view.findViewById(R.id.iv_cover)
        private val tvTitle: TextView = view.findViewById(R.id.tv_title)
        private val tvPrice: TextView = view.findViewById(R.id.tv_price)
        
        fun bind(product: Product) {
            tvTitle.text = product.title
            tvPrice.text = product.priceText
            Glide.with(ivCover).load(product.coverUrl).into(ivCover)
        }
    }
    
    class ProductDiffCallback : DiffUtil.ItemCallback<Product>() {
        override fun areItemsTheSame(oldItem: Product, newItem: Product) = oldItem.id == newItem.id
        override fun areContentsTheSame(oldItem: Product, newItem: Product) = oldItem == newItem
    }
}

/**
 * 详情页 ViewModel：使用预加载的数据
 */
class ProductDetailViewModel : ViewModel() {
    
    private val _detail = MutableLiveData<ProductDetail>()
    val detail: LiveData<ProductDetail> = _detail
    
    private val _loading = MutableLiveData<Boolean>()
    val loading: LiveData<Boolean> = _loading
    
    fun loadDetail(productId: String) {
        viewModelScope.launch {
            _loading.value = true
            
            // 尝试获取预加载的数据
            // 短超时，因为从列表跳转很快，预加载时间也短
            val preloaded = DataPreloader.getData<ProductDetail>(
                "product_detail_$productId",
                timeout = 500L
            )
            
            if (preloaded != null) {
                _detail.value = preloaded
                Log.d("DetailVM", "命中预加载")
            } else {
                // 未命中，正常请求
                _detail.value = ProductRepository.getProductDetail(productId)
                Log.d("DetailVM", "正常加载")
            }
            
            _loading.value = false
        }
    }
}
```

### 6.1 RecyclerView 图片预加载

```kotlin
/**
 * RecyclerView 图片预加载
 * 
 * 核心思想：利用 RecyclerView 的滚动监听，预加载即将显示的图片
 */
class ImagePreloadScrollListener(
    private val layoutManager: LinearLayoutManager,
    private val imageUrls: () -> List<String>,  // 获取图片 URL 的 lambda
    private val preloadCount: Int = 5           // 预加载数量
) : RecyclerView.OnScrollListener() {
    
    override fun onScrolled(recyclerView: RecyclerView, dx: Int, dy: Int) {
        super.onScrolled(recyclerView, dx, dy)
        
        // 只在向下滚动时预加载
        if (dy <= 0) return
        
        val lastVisiblePosition = layoutManager.findLastVisibleItemPosition()
        val totalCount = layoutManager.itemCount
        
        // 获取需要预加载的图片 URL
        val urls = imageUrls()
        val startPosition = lastVisiblePosition + 1
        val endPosition = minOf(startPosition + preloadCount, totalCount)
        
        // 预加载这些图片
        for (i in startPosition until endPosition) {
            if (i < urls.size) {
                preloadImage(recyclerView.context, urls[i])
            }
        }
    }
    
    private fun preloadImage(context: Context, url: String) {
        // 使用 Glide 预加载到内存缓存
        Glide.with(context)
            .load(url)
            .diskCacheStrategy(DiskCacheStrategy.ALL)
            .preload()  // 只预加载，不显示
    }
}

// 使用方式
class ProductListActivity : AppCompatActivity() {
    
    private val products = mutableListOf<Product>()
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_product_list)
        
        val recyclerView = findViewById<RecyclerView>(R.id.recycler_view)
        val layoutManager = LinearLayoutManager(this)
        recyclerView.layoutManager = layoutManager
        
        // 添加图片预加载监听
        recyclerView.addOnScrollListener(
            ImagePreloadScrollListener(
                layoutManager = layoutManager,
                imageUrls = { products.map { it.imageUrl } },
                preloadCount = 5
            )
        )
    }
}
```

## 七、WebView 预热池

### 7.1 为什么 WebView 需要预热？

WebView 首次创建需要初始化 WebKit 内核，耗时 **100-200ms**。后续创建只需 **~20ms**。

如果页面有 WebView，必须做预热。

### 7.2 增强版实现

```kotlin
/**
 * WebView 预热池（增强版）
 * 
 * 增强点：
 * 1. 支持预加载指定 URL
 * 2. 更好的生命周期管理
 * 3. Context 动态切换避免内存泄漏
 */
object WebViewPool {
    
    private const val TAG = "WebViewPool"
    
    // 通用 WebView 池
    private val commonPool = LinkedList<WebView>()
    
    // 预加载了特定 URL 的 WebView 缓存
    private val preloadedWebViews = ConcurrentHashMap<String, WebView>()
    
    private const val MAX_POOL_SIZE = 3
    private var isInitialized = false
    
    /**
     * 初始化（在 Application 中调用）
     */
    fun init(context: Context) {
        if (isInitialized) return
        isInitialized = true
        
        // 在主线程空闲时预创建 WebView
        Looper.myQueue().addIdleHandler {
            createWebViewAsync(context.applicationContext)
            false
        }
    }
    
    private fun createWebViewAsync(context: Context) {
        val startTime = System.currentTimeMillis()
        
        val webView = createWebView(context)
        
        synchronized(commonPool) {
            if (commonPool.size < MAX_POOL_SIZE) {
                commonPool.offer(webView)
            }
        }
        
        Log.d(TAG, "预创建 WebView 耗时: ${System.currentTimeMillis() - startTime}ms")
    }
    
    /**
     * 预加载指定 URL
     * 
     * 场景：已知用户大概率会访问某个 H5 页面（如活动页）
     */
    fun preloadUrl(context: Context, url: String) {
        if (preloadedWebViews.containsKey(url)) return
        
        val webView = obtain(context)
        webView.loadUrl(url)
        preloadedWebViews[url] = webView
        
        Log.d(TAG, "预加载 URL: $url")
    }
    
    /**
     * 获取 WebView
     * 
     * @param preloadedUrl 如果指定，尝试获取预加载了该 URL 的 WebView
     */
    fun obtain(context: Context, preloadedUrl: String? = null): WebView {
        // 优先获取预加载了指定 URL 的 WebView
        if (preloadedUrl != null) {
            preloadedWebViews.remove(preloadedUrl)?.let { webView ->
                updateContext(webView, context)
                Log.d(TAG, "命中预加载 URL: $preloadedUrl")
                return webView
            }
        }
        
        // 从通用池获取
        val pooledWebView = synchronized(commonPool) {
            commonPool.poll()
        }
        
        if (pooledWebView != null) {
            updateContext(pooledWebView, context)
            Log.d(TAG, "从池中获取 WebView")
            return pooledWebView
        }
        
        // 池空了，创建新的
        Log.d(TAG, "创建新 WebView")
        return createWebView(context)
    }
    
    /**
     * 回收 WebView
     */
    fun recycle(webView: WebView) {
        // 清理状态
        webView.stopLoading()
        webView.loadUrl("about:blank")
        webView.clearHistory()
        webView.clearCache(false)
        
        synchronized(commonPool) {
            if (commonPool.size < MAX_POOL_SIZE) {
                commonPool.offer(webView)
                Log.d(TAG, "WebView 回收到池中")
            } else {
                webView.destroy()
                Log.d(TAG, "池已满，销毁 WebView")
            }
        }
    }
    
    /**
     * 创建 WebView
     */
    private fun createWebView(context: Context): WebView {
        val webView = WebView(MutableContextWrapper(context))
        
        webView.settings.apply {
            javaScriptEnabled = true
            domStorageEnabled = true
            databaseEnabled = true
            cacheMode = WebSettings.LOAD_DEFAULT
            mixedContentMode = WebSettings.MIXED_CONTENT_ALWAYS_ALLOW
        }
        
        // 设置硬件加速
        webView.setLayerType(View.LAYER_TYPE_HARDWARE, null)
        
        // 预加载空白页，初始化内核
        webView.loadUrl("about:blank")
        
        return webView
    }
    
    /**
     * 更新 WebView 的 Context（避免内存泄漏）
     */
    private fun updateContext(webView: WebView, newContext: Context) {
        (webView.context as? MutableContextWrapper)?.baseContext = newContext
    }
    
    /**
     * 清理所有资源
     */
    fun destroy() {
        synchronized(commonPool) {
            commonPool.forEach { it.destroy() }
            commonPool.clear()
        }
        
        preloadedWebViews.values.forEach { it.destroy() }
        preloadedWebViews.clear()
        
        isInitialized = false
    }
    
    /**
     * 可变 Context 包装器
     * 
     * 为什么需要？
     * WebView 持有 Context 引用，如果使用 Activity Context 会导致内存泄漏
     * 使用 MutableContextWrapper 可以在需要时切换到正确的 Context
     */
    class MutableContextWrapper(base: Context) : ContextWrapper(base) {
        var baseContext: Context
            get() = super.getBaseContext()
            set(value) {
                try {
                    val field = ContextWrapper::class.java.getDeclaredField("mBase")
                    field.isAccessible = true
                    field.set(this, value)
                } catch (e: Exception) {
                    Log.e(TAG, "更新 Context 失败", e)
                }
            }
    }
}
```

## 八、预加载的权衡与陷阱

### 8.1 内存管理

```kotlin
/**
 * 预加载的内存管理
 * 
 * 问题：预加载太多会占用大量内存
 * 解决：
 * 1. 使用 SoftReference / WeakReference
 * 2. 监听内存警告，及时清理
 * 3. 限制预加载数量
 */
class MemoryAwarePreloader(application: Application) {
    
    init {
        // 监听内存警告
        application.registerComponentCallbacks(object : ComponentCallbacks2 {
            override fun onTrimMemory(level: Int) {
                when (level) {
                    ComponentCallbacks2.TRIM_MEMORY_RUNNING_LOW,
                    ComponentCallbacks2.TRIM_MEMORY_RUNNING_CRITICAL -> {
                        // 内存紧张，清理预加载缓存
                        clearAllPreloadCache()
                        Log.w("Preloader", "内存紧张，清理预加载缓存")
                    }
                }
            }
            
            override fun onConfigurationChanged(newConfig: Configuration) {}
            override fun onLowMemory() {
                clearAllPreloadCache()
            }
        })
    }
    
    private fun clearAllPreloadCache() {
        LayoutPreloader.clear()
        DataPreloader.clear()
        WebViewPool.destroy()
    }
}
```

### 8.2 预测失误的风险

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    预加载的风险                                               │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   场景：预测用户会进入详情页，提前加载了详情数据                                │
│                                                                             │
│   可能的问题：                                                               │
│   1. 用户没有进入详情页 → 浪费了网络请求和内存                                │
│   2. 用户进入了另一个详情页 → 预加载的数据没用上                              │
│   3. 数据有时效性 → 预加载的数据可能已过期                                    │
│                                                                             │
│   解决方案：                                                                 │
│   1. 只预加载高确定性的内容（如首页，100% 会访问）                            │
│   2. 低确定性内容使用「触发式预加载」（如手指按下时）                          │
│   3. 设置预加载数据的有效期（TTL）                                           │
│   4. 统计预加载命中率，持续优化策略                                          │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 8.3 预加载命中率统计

```kotlin
/**
 * 预加载命中率统计
 * 
 * 用于评估预加载策略的有效性
 */
object PreloadStats {
    
    private var preloadCount = 0    // 预加载次数
    private var hitCount = 0        // 命中次数
    private var missCount = 0       // 未命中次数
    
    fun onPreload(key: String) {
        preloadCount++
        Log.d("PreloadStats", "预加载: $key, 总次数: $preloadCount")
    }
    
    fun onHit(key: String) {
        hitCount++
        Log.d("PreloadStats", "命中: $key, 命中率: ${getHitRate()}%")
    }
    
    fun onMiss(key: String) {
        missCount++
        Log.d("PreloadStats", "未命中: $key, 命中率: ${getHitRate()}%")
    }
    
    fun getHitRate(): Float {
        val total = hitCount + missCount
        return if (total > 0) hitCount * 100f / total else 0f
    }
    
    fun report(): String {
        return """
            预加载统计:
            - 预加载次数: $preloadCount
            - 命中次数: $hitCount
            - 未命中次数: $missCount
            - 命中率: ${String.format("%.1f", getHitRate())}%
        """.trimIndent()
    }
    
    fun reset() {
        preloadCount = 0
        hitCount = 0
        missCount = 0
    }
}
```

## 九、面试回答模板

> **面试官**：你们项目是怎么做预加载优化的？
>
> **回答**：
>
> 我们项目的预加载分为三个层次：
>
> **1. 高确定性预加载**（100% 会用到）
> - **首页布局**：在 Splash 显示期间用 AsyncLayoutInflater 预加载，首页 setContentView 从 30ms 降到 5ms
> - **首页数据**：Splash 期间发起网络请求，首页创建时数据已经返回
> - **WebView**：Application 启动后用 IdleHandler 预创建 WebView，初始化 WebKit 内核
>
> **2. 中确定性预加载**（大概率会用到）
> - **详情页数据**：在列表 Item 的 `ACTION_DOWN` 事件时开始预加载
> - 用户手指按下到松开大约 200ms，这段时间足够完成数据请求
> - 实测从列表进详情页的耗时从 400ms 降到 150ms
>
> **3. 资源预加载**
> - **图片**：监听 RecyclerView 滚动，预加载即将显示的 5 张图片
> - **WebView URL**：首页显示后预加载活动页 URL
>
> **避免的陷阱**：
> - 用 SoftReference 缓存，避免内存压力
> - 注册 `onTrimMemory` 回调，内存紧张时清理缓存
> - 统计预加载命中率（目前约 85%），持续优化策略
