# Service 基础篇

## 一、Service 是什么？

### 1.1 定义

Service 是 Android 四大组件之一，用于在后台执行**长时间运行的操作**，没有用户界面。

> **大白话**：Service 就像餐厅的后厨——顾客（用户）看不见，但所有"硬菜"（后台任务）都在这里完成。Activity 是服务员，负责跟顾客打交道；Service 是厨师，负责在后面闷头干活。

### 1.2 Service vs Thread：经典面试题

这是一道 **99% 的人都答不全** 的面试题。

| 维度 | Service | Thread |
|-----|---------|--------|
| **本质** | Android 组件，有生命周期 | Java 类，执行代码的载体 |
| **运行线程** | 默认在**主线程**运行！ | 独立线程 |
| **生命周期** | 受系统管理，可被系统回收 | 不受系统管理，Activity 销毁后可能还在跑 |
| **优先级** | 有进程优先级，前台服务不易被杀 | 没有优先级概念 |
| **适用场景** | 需要系统感知的后台任务 | 单纯的异步执行 |

> **⚠️ 重点**：Service 默认运行在**主线程**！在 Service 中执行耗时操作会导致 ANR（Application Not Responding）！

```kotlin
// ❌ 错误示范：在 Service 中直接执行耗时操作
class WrongService : Service() {
    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
        // 这段代码在主线程执行，会卡住 UI，5秒后 ANR！
        Thread.sleep(10000)  
        return START_STICKY
    }
}

// ✅ 正确做法：在 Service 中开启子线程
class CorrectService : Service() {
    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
        // 开启子线程执行耗时任务
        thread {
            // 这里可以安全地执行耗时操作
            doHeavyWork()
        }
        return START_STICKY
    }
}
```

### 1.3 为什么有了 Thread 还需要 Service？

既然 Service 默认在主线程，为什么不直接用 Thread？

**答案在于「系统感知」**：

1. **进程优先级**：Service 所在进程的优先级较高，不容易被系统杀死
2. **生命周期管理**：系统知道你的应用在做什么，可以合理调度
3. **跨组件调用**：其他组件可以绑定 Service 进行交互
4. **前台服务**：可以提升为前台服务，获得最高优先级

> **类比**：Thread 就像你自己偷偷在家做蛋糕，没人知道；Service 就像开了一家注册的蛋糕店，工商局（系统）知道你在营业，不会随便来拆你店。

## 二、Service 的生命周期

### 2.1 两条生命周期路线

Service 有两种启动方式，生命周期完全不同：

```
┌─────────────────────────────────────────────────────────────────┐
│                    Service 生命周期                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   startService() 路线                bindService() 路线          │
│                                                                 │
│   ┌───────────────┐                  ┌───────────────┐          │
│   │   onCreate()  │                  │   onCreate()  │          │
│   └───────┬───────┘                  └───────┬───────┘          │
│           │                                  │                  │
│           ▼                                  ▼                  │
│   ┌───────────────┐                  ┌───────────────┐          │
│   │onStartCommand │ ◄─ 可多次调用     │   onBind()    │          │
│   └───────┬───────┘                  └───────┬───────┘          │
│           │                                  │                  │
│           │ stopSelf()/stopService()         │ 所有客户端解绑    │
│           ▼                                  ▼                  │
│   ┌───────────────┐                  ┌───────────────┐          │
│   │  onDestroy()  │                  │  onUnbind()   │          │
│   └───────────────┘                  └───────┬───────┘          │
│                                              │                  │
│                                              ▼                  │
│                                      ┌───────────────┐          │
│                                      │  onDestroy()  │          │
│                                      └───────────────┘          │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 生命周期方法详解

| 方法 | 调用时机 | 调用次数 | 说明 |
|-----|---------|---------|------|
| `onCreate()` | Service 首次创建 | 1 次 | 初始化资源，类似 Activity.onCreate |
| `onStartCommand()` | 调用 startService() | 多次 | 每次 startService 都会调用 |
| `onBind()` | 调用 bindService() | 1 次 | 返回 IBinder 供客户端交互 |
| `onUnbind()` | 所有客户端解绑 | 1 次 | 可返回 true 支持 rebind |
| `onRebind()` | 重新绑定（需 onUnbind 返回 true） | 多次 | 不常用 |
| `onDestroy()` | Service 销毁 | 1 次 | 清理资源 |

### 2.3 onStartCommand 返回值详解

`onStartCommand()` 的返回值决定了 Service 被杀死后的**重启策略**：

```kotlin
override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
    // 返回值决定被杀后如何重启
    return START_STICKY  // 或 START_NOT_STICKY / START_REDELIVER_INTENT
}
```

| 返回值 | 被杀后行为 | 适用场景 |
|-------|----------|---------|
| `START_STICKY` | 重启 Service，但 intent 为 null | 音乐播放器（不需要原始参数） |
| `START_NOT_STICKY` | 不重启，除非有新的 startService 调用 | 定时任务（任务完成了就不需要了） |
| `START_REDELIVER_INTENT` | 重启并重传最后一个 intent | 文件下载（需要知道下载什么） |

> **大白话**：
> - `START_STICKY`：被杀了会复活，但失忆了（不记得 intent）
> - `START_NOT_STICKY`：被杀了就躺平，不挣扎
> - `START_REDELIVER_INTENT`：被杀了会复活，还记得上次在干嘛

## 三、启动服务（Started Service）

### 3.1 基本用法

**第一步：创建 Service 类**

```kotlin
class DownloadService : Service() {
    
    override fun onCreate() {
        super.onCreate()
        Log.d("DownloadService", "Service 创建了")
    }

    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
        // 从 intent 获取参数
        val url = intent?.getStringExtra("url") ?: ""
        
        // 在子线程执行下载任务
        thread {
            downloadFile(url)
            // 任务完成后停止自己
            stopSelf()
        }
        
        // 被杀后重启并重传 intent（保证下载任务能完成）
        return START_REDELIVER_INTENT
    }

    override fun onBind(intent: Intent?): IBinder? = null  // 启动服务不需要绑定
    
    override fun onDestroy() {
        super.onDestroy()
        Log.d("DownloadService", "Service 销毁了")
    }
    
    private fun downloadFile(url: String) {
        // 模拟下载
        Log.d("DownloadService", "开始下载: $url")
        Thread.sleep(5000)
        Log.d("DownloadService", "下载完成: $url")
    }
}
```

**第二步：在 AndroidManifest.xml 注册**

```xml
<manifest>
    <application>
        <!-- Service 必须注册！ -->
        <service 
            android:name=".DownloadService"
            android:exported="false" />  <!-- Android 12+ 必须明确指定 -->
    </application>
</manifest>
```

**第三步：启动 Service**

```kotlin
// 在 Activity 中启动
class MainActivity : AppCompatActivity() {
    
    fun startDownload() {
        val intent = Intent(this, DownloadService::class.java).apply {
            putExtra("url", "https://example.com/file.zip")
        }
        startService(intent)
    }
    
    fun stopDownload() {
        val intent = Intent(this, DownloadService::class.java)
        stopService(intent)
    }
}
```

### 3.2 停止服务的两种方式

| 方式 | 说明 | 使用场景 |
|-----|------|---------|
| `stopSelf()` | Service 自己停止自己 | 任务完成后自动停止 |
| `stopService(intent)` | 外部组件停止 Service | 用户手动取消任务 |

> **注意**：如果多次调用 `startService()`，需要相同次数的 `stopService()` 或使用 `stopSelf(startId)` 来精确控制。

## 四、绑定服务（Bound Service）

### 4.1 什么时候用绑定服务？

绑定服务适用于**需要与 Service 进行交互**的场景：
- 音乐播放器：Activity 需要控制播放/暂停/进度
- 计步器：Activity 需要实时获取步数
- 后台计算：Activity 需要获取计算结果

### 4.2 基本用法（本地绑定）

**第一步：创建可绑定的 Service**

```kotlin
class MusicService : Service() {

    // 1. 创建 Binder 类，作为与客户端交互的桥梁
    inner class MusicBinder : Binder() {
        // 提供方法让客户端获取 Service 实例
        fun getService(): MusicService = this@MusicService
    }
    
    private val binder = MusicBinder()
    private var isPlaying = false
    
    // 2. onBind 返回 Binder 实例
    override fun onBind(intent: Intent?): IBinder = binder
    
    // 3. 提供给客户端调用的方法
    fun play() {
        isPlaying = true
        Log.d("MusicService", "开始播放")
    }
    
    fun pause() {
        isPlaying = false
        Log.d("MusicService", "暂停播放")
    }
    
    fun isPlaying(): Boolean = isPlaying
}
```

**第二步：在 Activity 中绑定**

```kotlin
class MusicActivity : AppCompatActivity() {
    
    private var musicService: MusicService? = null
    private var isBound = false
    
    // 1. 定义 ServiceConnection，监听连接状态
    private val connection = object : ServiceConnection {
        override fun onServiceConnected(name: ComponentName?, service: IBinder?) {
            // 绑定成功，获取 Service 实例
            val binder = service as MusicService.MusicBinder
            musicService = binder.getService()
            isBound = true
            Log.d("MusicActivity", "Service 已连接")
        }
        
        override fun onServiceDisconnected(name: ComponentName?) {
            // 异常断开（如 Service 被杀），不是 unbind 触发
            musicService = null
            isBound = false
            Log.d("MusicActivity", "Service 异常断开")
        }
    }
    
    override fun onStart() {
        super.onStart()
        // 2. 绑定 Service
        val intent = Intent(this, MusicService::class.java)
        bindService(intent, connection, Context.BIND_AUTO_CREATE)
    }
    
    override fun onStop() {
        super.onStop()
        // 3. 解绑 Service（必须！否则内存泄漏）
        if (isBound) {
            unbindService(connection)
            isBound = false
        }
    }
    
    // 4. 通过 Service 实例调用方法
    fun onPlayClick() {
        musicService?.play()
    }
    
    fun onPauseClick() {
        musicService?.pause()
    }
}
```

### 4.3 bindService 的 flags 参数

```kotlin
bindService(intent, connection, flags)
```

| Flag | 说明 |
|------|------|
| `BIND_AUTO_CREATE` | 绑定时自动创建 Service（最常用） |
| `BIND_DEBUG_UNBIND` | 调试用，unbind 时打印堆栈 |
| `BIND_NOT_FOREGROUND` | 不提升 Service 进程优先级 |
| `BIND_ABOVE_CLIENT` | Service 优先级高于客户端 |
| `BIND_WAIVE_PRIORITY` | 不影响 Service 进程优先级 |

### 4.4 同时使用 startService 和 bindService

一个 Service 可以同时被启动和绑定：

```kotlin
// 先启动（保证 Service 不会因为 unbind 而停止）
startService(Intent(this, MusicService::class.java))

// 再绑定（获得交互能力）
bindService(intent, connection, BIND_AUTO_CREATE)
```

**销毁条件**：必须同时满足：
1. 调用了 `stopService()` 或 `stopSelf()`
2. 所有客户端都 `unbindService()`

> **类比**：startService 是给饭店发了营业执照，bindService 是有顾客来吃饭。要关店必须：营业执照注销 + 所有顾客都走了。

## 五、Service 与四大组件的对比

| 组件 | 有界面 | 生命周期 | 主要职责 |
|-----|--------|---------|---------|
| Activity | ✅ | 受用户操作影响 | 用户界面交互 |
| Service | ❌ | 相对独立 | 后台任务执行 |
| BroadcastReceiver | ❌ | 极短（10秒） | 响应系统/应用广播 |
| ContentProvider | ❌ | 随进程存活 | 跨应用数据共享 |

## 六、常见问题与避坑指南

### 6.1 Service 在哪个线程运行？

**答案**：默认在**主线程（UI 线程）**运行！

```kotlin
class MyService : Service() {
    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
        // 打印当前线程名
        Log.d("MyService", "Thread: ${Thread.currentThread().name}")
        // 输出: Thread: main
        return START_STICKY
    }
}
```

**解决方案**：在 Service 中开启子线程，或使用 IntentService（已废弃）/WorkManager。

### 6.2 为什么 Service 会被杀死？

Android 系统在内存不足时会按照**进程优先级**杀死进程：

| 优先级（高→低） | 进程类型 | 说明 |
|---------------|---------|------|
| 1 | 前台进程 | 正在交互的 Activity、前台 Service |
| 2 | 可见进程 | 可见但不在前台的 Activity |
| 3 | 服务进程 | 普通 Service |
| 4 | 缓存进程 | 后台 Activity |
| 5 | 空进程 | 没有任何组件 |

> **保命技巧**：使用前台服务（`startForeground`）可以把进程提升到前台进程级别。

### 6.3 Service 的 ANR 时间

| 场景 | ANR 超时时间 |
|-----|-------------|
| 前台 Service | 20 秒 |
| 后台 Service | 200 秒 |

### 6.4 Android 8.0+ 后台限制

从 Android 8.0 开始，系统对后台 Service 进行了严格限制：

```kotlin
// ❌ Android 8.0+ 会抛出 IllegalStateException
if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
    startService(intent)  // 后台启动普通 Service 会崩溃！
}

// ✅ 正确做法：使用前台服务
if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
    startForegroundService(intent)  // 启动后必须在 5 秒内调用 startForeground()
}
```

## 七、面试检验

### 基础题

**Q1：Service 和 Thread 有什么区别？**

> **答案**：
> 1. **本质不同**：Service 是 Android 组件，Thread 是 Java 类
> 2. **运行线程**：Service 默认在主线程，Thread 是独立线程
> 3. **生命周期**：Service 受系统管理，Thread 不受管理
> 4. **优先级**：Service 有进程优先级，前台服务最高；Thread 没有优先级概念
> 
> **核心区别**：Service 解决的是「让系统知道你在做后台任务」的问题，不是「异步执行」的问题。

**Q2：Service 的 onStartCommand 返回值有什么区别？**

> **答案**：决定 Service 被系统杀死后的重启策略
> - `START_STICKY`：重启但 intent 为 null，适合音乐播放
> - `START_NOT_STICKY`：不重启，适合一次性任务
> - `START_REDELIVER_INTENT`：重启并重传 intent，适合下载任务

**Q3：启动服务和绑定服务的区别？**

> **答案**：
> | 维度 | 启动服务 | 绑定服务 |
> |-----|---------|---------|
> | 启动方式 | startService() | bindService() |
> | 生命周期 | 独立运行 | 与绑定组件共存亡 |
> | 交互方式 | 单向（只能通过 Intent 传参） | 双向（可调用 Service 方法） |
> | 停止方式 | stopService/stopSelf | 所有客户端解绑 |
> | 适用场景 | 一次性后台任务 | 需要持续交互的任务 |

**Q4：如何让 Service 不被系统杀死？**

> **答案**：
> 1. 使用前台服务（`startForeground`），显示通知
> 2. `onStartCommand` 返回 `START_STICKY`
> 3. 提高进程优先级
> 
> **注意**：过度保活是不推荐的，会影响用户体验和系统性能。
