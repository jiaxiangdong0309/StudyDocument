# Service 进阶篇

## 一、前台服务（Foreground Service）

### 1.1 为什么需要前台服务？

**问题背景**：从 Android 8.0 开始，系统严格限制后台 Service：
- 应用进入后台后，后台 Service 有几分钟的运行时间，然后会被停止
- 后台启动普通 Service 会抛出 `IllegalStateException`

**解决方案**：使用前台服务。前台服务必须显示一个**通知**，让用户知道有任务在执行。

> **大白话**：后台服务就像偷偷摸摸干活，系统不允许；前台服务就像光明正大干活，必须挂个工牌（通知）让用户知道。

### 1.2 前台服务实战

**第一步：添加权限（Android 9.0+）**

```xml
<manifest>
    <!-- Android 9.0+ 前台服务需要权限 -->
    <uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
    
    <!-- Android 14+ 需要声明前台服务类型 -->
    <uses-permission android:name="android.permission.FOREGROUND_SERVICE_MEDIA_PLAYBACK" />
    
    <application>
        <service 
            android:name=".MusicForegroundService"
            android:exported="false"
            android:foregroundServiceType="mediaPlayback" />  <!-- Android 10+ 必须声明类型 -->
    </application>
</manifest>
```

**第二步：创建前台服务**

```kotlin
class MusicForegroundService : Service() {

    companion object {
        const val NOTIFICATION_ID = 1001
        const val CHANNEL_ID = "music_channel"
    }

    override fun onCreate() {
        super.onCreate()
        // 创建通知渠道（Android 8.0+ 必须）
        createNotificationChannel()
    }

    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
        // 创建通知
        val notification = createNotification()
        
        // 启动前台服务（必须在 5 秒内调用！）
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.Q) {
            // Android 10+ 需要指定前台服务类型
            startForeground(
                NOTIFICATION_ID, 
                notification,
                ServiceInfo.FOREGROUND_SERVICE_TYPE_MEDIA_PLAYBACK
            )
        } else {
            startForeground(NOTIFICATION_ID, notification)
        }
        
        // 开始播放音乐（在子线程）
        startPlayMusic()
        
        return START_STICKY
    }
    
    private fun createNotificationChannel() {
        if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
            val channel = NotificationChannel(
                CHANNEL_ID,
                "音乐播放",
                NotificationManager.IMPORTANCE_LOW  // LOW 不会发出声音
            ).apply {
                description = "音乐播放服务通知"
            }
            val manager = getSystemService(NotificationManager::class.java)
            manager.createNotificationChannel(channel)
        }
    }
    
    private fun createNotification(): Notification {
        // 点击通知打开 Activity
        val pendingIntent = PendingIntent.getActivity(
            this,
            0,
            Intent(this, MainActivity::class.java),
            PendingIntent.FLAG_IMMUTABLE
        )
        
        return NotificationCompat.Builder(this, CHANNEL_ID)
            .setContentTitle("正在播放")
            .setContentText("歌曲名称 - 歌手")
            .setSmallIcon(R.drawable.ic_music)
            .setContentIntent(pendingIntent)
            .setOngoing(true)  // 常驻通知，用户无法滑动删除
            .build()
    }
    
    private fun startPlayMusic() {
        thread {
            // 播放音乐的逻辑
        }
    }
    
    override fun onBind(intent: Intent?): IBinder? = null
    
    override fun onDestroy() {
        super.onDestroy()
        // 停止前台服务，移除通知
        stopForeground(STOP_FOREGROUND_REMOVE)
    }
}
```

**第三步：启动前台服务**

```kotlin
// 在 Activity 中启动
fun startMusicService() {
    val intent = Intent(this, MusicForegroundService::class.java)
    
    if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
        // Android 8.0+ 必须使用 startForegroundService
        startForegroundService(intent)
    } else {
        startService(intent)
    }
}
```

### 1.3 前台服务类型（Android 10+）

从 Android 10 开始，前台服务必须声明类型：

| 类型 | 说明 | 额外权限 |
|-----|------|---------|
| `mediaPlayback` | 音乐/视频播放 | - |
| `location` | 定位 | ACCESS_FINE_LOCATION |
| `camera` | 相机 | CAMERA |
| `microphone` | 麦克风 | RECORD_AUDIO |
| `phoneCall` | 电话 | - |
| `connectedDevice` | 蓝牙/USB | - |
| `dataSync` | 数据同步 | - |
| `mediaProjection` | 屏幕录制 | - |

> **Android 14 重大变化**：必须在 `AndroidManifest.xml` 中明确声明 `foregroundServiceType`，否则会崩溃。

## 二、IntentService（已废弃但原理值得学习）

### 2.1 IntentService 是什么？

IntentService 是 Android 提供的一个 Service 子类，专门用于执行**异步任务**：
- 自动在**子线程**执行任务
- 任务执行完毕**自动停止**
- 多个任务**串行执行**（排队处理）

> **大白话**：普通 Service 像个光杆司令，你得自己招工人（开线程）；IntentService 像个包工头，自带一个工人（单线程），任务排队干完自动下班。

### 2.3 手动实现 IntentService

虽然 IntentService 已废弃，但理解其原理很重要：

```kotlin
// IntentService 的核心实现（简化版）
abstract class MyIntentService(name: String) : Service() {
    
    private lateinit var serviceHandler: ServiceHandler
    private lateinit var serviceLooper: Looper
    
    // 1. 在子线程中处理消息的 Handler
    private inner class ServiceHandler(looper: Looper) : Handler(looper) {
        override fun handleMessage(msg: Message) {
            // 在子线程执行任务
            onHandleIntent(msg.obj as? Intent)
            // 任务完成，尝试停止服务
            stopSelf(msg.arg1)
        }
    }
    
    override fun onCreate() {
        super.onCreate()
        // 2. 创建 HandlerThread（带消息队列的子线程）
        val thread = HandlerThread("IntentService[$name]")
        thread.start()
        
        serviceLooper = thread.looper
        serviceHandler = ServiceHandler(serviceLooper)
    }
    
    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
        // 3. 将任务封装成 Message 发送到子线程
        val msg = serviceHandler.obtainMessage().apply {
            arg1 = startId
            obj = intent
        }
        serviceHandler.sendMessage(msg)
        return START_REDELIVER_INTENT
    }
    
    override fun onBind(intent: Intent?): IBinder? = null
    
    override fun onDestroy() {
        serviceLooper.quit()  // 退出消息循环
    }
    
    // 4. 子类实现此方法，在子线程中执行
    protected abstract fun onHandleIntent(intent: Intent?)
}
```

### 2.4 为什么 IntentService 被废弃？

| 问题 | 说明 |
|-----|------|
| 后台限制 | Android 8.0+ 后台 Service 受限，IntentService 无法正常工作 |
| 单线程 | 串行执行任务，效率低 |
| 生命周期 | 任务执行中 Activity 销毁，可能丢失回调 |
| 更好的替代 | WorkManager 提供了更强大、更可靠的方案 |

**替代方案**：
- **WorkManager**：推荐，系统级调度，保证执行
- **Coroutine**：Kotlin 协程，更灵活
- **JobIntentService**：过渡方案，也已废弃

## 三、后台任务方案对比

### 3.1 四大方案横向对比

| 方案 | 执行时机 | 是否保证执行 | 跨进程 | 推荐程度 |
|-----|---------|-------------|--------|---------|
| **Service** | 立即执行 | ❌ 可能被杀 | ❌ | ⭐⭐ 特定场景 |
| **IntentService** | 立即执行 | ❌ 可能被杀 | ❌ | ❌ 已废弃 |
| **JobScheduler** | 系统调度 | ✅ 条件满足时 | ❌ | ⭐⭐⭐ 系统API |
| **WorkManager** | 系统调度 | ✅ 保证执行 | ❌ | ⭐⭐⭐⭐⭐ 首选 |

**选择建议**：

| 场景 | 推荐方案 |
|-----|---------|
| 音乐播放、导航、录音 | 前台 Service |
| 图片上传、日志上报 | WorkManager |
| 定时数据同步 | WorkManager（周期任务） |
| 网络请求、数据库操作 | Coroutine（不需要 Service） |
| 系统级任务（如 AlarmManager 触发） | JobScheduler |

## 四、跨进程通信（AIDL）

### 4.1 为什么需要跨进程？

**场景**：
- 音乐播放器：播放服务在独立进程，多个 App 可以控制
- 系统服务：如通知、电话、位置服务
- 多进程 App：主进程 + WebView 进程 + 推送进程

> **大白话**：普通的 Binder 绑定只能在同一个进程内通信，就像同一个办公室的同事可以直接说话；跨进程就像不同城市的分公司，需要用电话（AIDL/Messenger）沟通。

### 4.2 AIDL 基本用法

**第一步：创建 AIDL 文件**

在 `src/main/aidl/com/example/` 目录下创建 `IBookManager.aidl`：

```aidl
// IBookManager.aidl
package com.example;

// 声明要使用的数据类
import com.example.Book;

interface IBookManager {
    // 获取书籍列表
    List<Book> getBookList();
    
    // 添加书籍
    void addBook(in Book book);
}
```

**创建数据类 `Book.aidl`：**

```aidl
// Book.aidl
package com.example;

// 声明 Book 是 Parcelable
parcelable Book;
```

**创建 `Book.kt`（必须实现 Parcelable）：**

```kotlin
@Parcelize
data class Book(
    val id: Int,
    val name: String
) : Parcelable
```

**第二步：创建 Service**

```kotlin
class BookManagerService : Service() {
    
    private val bookList = mutableListOf<Book>()
    
    // 实现 AIDL 接口
    private val binder = object : IBookManager.Stub() {
        override fun getBookList(): List<Book> {
            return bookList
        }
        
        override fun addBook(book: Book) {
            bookList.add(book)
        }
    }
    
    override fun onBind(intent: Intent?): IBinder = binder
}
```

**在 AndroidManifest.xml 中声明独立进程：**

```xml
<service
    android:name=".BookManagerService"
    android:process=":remote"  <!-- 冒号表示私有进程 -->
    android:exported="true">   <!-- 允许其他应用绑定 -->
    <intent-filter>
        <action android:name="com.example.BookManagerService" />
    </intent-filter>
</service>
```

**第三步：客户端绑定**

```kotlin
class BookActivity : AppCompatActivity() {
    
    private var bookManager: IBookManager? = null
    
    private val connection = object : ServiceConnection {
        override fun onServiceConnected(name: ComponentName?, service: IBinder?) {
            // 获取跨进程代理对象
            bookManager = IBookManager.Stub.asInterface(service)
        }
        
        override fun onServiceDisconnected(name: ComponentName?) {
            bookManager = null
        }
    }
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        // 绑定服务
        val intent = Intent("com.example.BookManagerService")
        intent.setPackage("com.example")  // Android 5.0+ 必须显式指定包名
        bindService(intent, connection, BIND_AUTO_CREATE)
    }
    
    fun addBook() {
        // 跨进程调用
        bookManager?.addBook(Book(1, "Android 开发艺术探索"))
    }
    
    fun getBooks() {
        val books = bookManager?.bookList
        Log.d("BookActivity", "Books: $books")
    }
}
```

### 4.3 AIDL 数据传输方向

| 标记 | 含义 | 场景 |
|-----|------|------|
| `in` | 客户端传给服务端，服务端修改不影响客户端 | 默认，大多数情况 |
| `out` | 服务端传给客户端 | 需要服务端填充数据 |
| `inout` | 双向传输 | 客户端传入，服务端修改后客户端可见 |

### 4.4 Messenger vs AIDL

| 维度 | Messenger | AIDL |
|-----|-----------|------|
| 复杂度 | 简单 | 复杂 |
| 并发 | 串行处理 | 支持并发 |
| 返回值 | 只能通过回复 Message | 支持同步返回 |
| 适用场景 | 简单的单向通信 | 复杂的双向交互 |

## 五、进程保活策略

### 5.1 为什么需要保活？

**合理的保活场景**：
- 音乐播放器：用户听歌时不能中断
- 即时通讯：保持消息接收
- 运动健康：持续记录步数

**不合理的保活**（流氓行为）：
- 强制常驻后台，消耗电量
- 交叉唤醒，形成全家桶
- 用户杀不掉

> **原则**：保活是为了用户体验，不是为了刷数据。

### 5.2 常见保活策略

| 策略 | 原理 | 有效性 | 推荐度 |
|-----|------|--------|--------|
| 前台服务 | 提升进程优先级 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ 推荐 |
| 双进程守护 | 互相拉起 | ⭐⭐⭐ | ⭐⭐ 灰色地带 |
| WorkManager | 系统调度 | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ 推荐 |
| 1像素 Activity | 提升为可见进程 | ⭐⭐ | ❌ 已失效 |
| 后台播放无声音乐 | 模拟媒体播放 | ⭐⭐⭐ | ⭐ 流氓行为 |
| JobScheduler | 定时唤醒 | ⭐⭐⭐ | ⭐⭐⭐ 系统 API |

### 5.3 前台服务保活（推荐）

```kotlin
class KeepAliveService : Service() {
    
    override fun onCreate() {
        super.onCreate()
        startForeground(1, createNotification())
    }
    
    private fun createNotification(): Notification {
        // 创建通知...
        return NotificationCompat.Builder(this, CHANNEL_ID)
            .setContentTitle("应用运行中")
            .setSmallIcon(R.drawable.ic_notification)
            .setPriority(NotificationCompat.PRIORITY_MIN)  // 最低优先级，通知栏不显眼
            .build()
    }
    
    override fun onBind(intent: Intent?): IBinder? = null
}
```

### 5.4 WorkManager 保活

```kotlin
// 定义周期性任务
class KeepAliveWorker(context: Context, params: WorkerParameters) 
    : Worker(context, params) {
    
    override fun doWork(): Result {
        // 执行保活逻辑，如心跳上报
        return Result.success()
    }
}

// 调度任务
val keepAliveRequest = PeriodicWorkRequestBuilder<KeepAliveWorker>(
    15, TimeUnit.MINUTES  // 最小间隔 15 分钟
).build()

WorkManager.getInstance(context).enqueueUniquePeriodicWork(
    "keep_alive",
    ExistingPeriodicWorkPolicy.KEEP,
    keepAliveRequest
)
```

## 六、边界认知：什么情况下不用 Service？

| 场景 | 是否需要 Service | 推荐方案 |
|-----|-----------------|---------|
| 简单网络请求 | ❌ | Coroutine + ViewModel |
| 数据库操作 | ❌ | Room + Coroutine |
| 定时任务 | ❌ | WorkManager |
| 短时间后台任务 | ❌ | Coroutine |
| 音乐播放 | ✅ | 前台 Service |
| 文件下载（大文件） | ✅ | 前台 Service / WorkManager |
| 实时位置追踪 | ✅ | 前台 Service |

## 七、面试检验

### 进阶题

**Q1：什么是前台服务？Android 8.0 之后为什么要用前台服务？**

> **答案**：
> - **定义**：前台服务是用户可感知的服务，必须显示状态栏通知
> - **原因**：Android 8.0 引入了后台执行限制，普通后台 Service 会被系统停止
> - **使用**：调用 `startForegroundService()` 启动，5 秒内必须调用 `startForeground()` 显示通知
> - **适用场景**：音乐播放、导航、录音等用户感知的长时间任务

**Q2：IntentService 的原理？为什么被废弃？**

> **答案**：
> - **原理**：内部维护一个 HandlerThread（带消息队列的子线程），所有任务串行执行，执行完自动停止
> - **废弃原因**：
>   1. Android 8.0+ 后台 Service 受限
>   2. 单线程串行效率低
>   3. WorkManager 提供了更好的替代方案

**Q3：Service、JobScheduler、WorkManager 如何选择？**

> **答案**：
> - **Service**：需要立即执行 + 用户可感知 → 前台 Service
> - **JobScheduler**：系统级 API，适合精确控制执行条件
> - **WorkManager**：推荐首选，封装了 JobScheduler/AlarmManager，保证任务执行，支持链式任务、约束条件

**Q4：AIDL 和 Messenger 有什么区别？**

> **答案**：
> | 维度 | Messenger | AIDL |
> |-----|-----------|------|
> | 实现复杂度 | 简单 | 复杂 |
> | 并发处理 | 串行 | 并发 |
> | 同步调用 | 不支持 | 支持 |
> | 适用场景 | 简单单向通信 | 复杂双向交互 |

**Q5：如何实现进程保活？有哪些注意事项？**

> **答案**：
> 1. **推荐方案**：前台服务 + WorkManager
> 2. **原理**：前台服务提升进程优先级，WorkManager 保证任务执行
> 3. **注意事项**：
>    - 合理使用，不要做流氓软件
>    - Android 版本越高，保活越难，要做好降级
>    - 申请必要权限，如自启动、后台运行
