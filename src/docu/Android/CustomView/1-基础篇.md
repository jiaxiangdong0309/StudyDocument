# 自定义 View 基础篇

## 技术演进：为什么需要自定义 View？

### 从一个需求说起

产品经理拿着设计稿找你：

```
"这个圆形进度条要渐变色，中间显示百分比，还要有动画效果"
"这个折线图要能滑动，点击显示数据详情"
"这个头像要圆形的，边框要渐变色"
```

你翻遍了 Android 官方控件库，发现：**没有！**

这时候你只有两条路：
1. 找第三方库（可能有坑、体积大、不好定制）
2. **自己画**（灵活、可控、装 X 神器）

### 自定义 View 的本质

自定义 View 说白了就是：**告诉系统"这个控件长什么样、占多大地方、怎么响应触摸"**。

```
┌──────────────────────────────────────────┐
│              自定义 View 三板斧            │
├──────────────────────────────────────────┤
│                                          │
│   测量（Measure）：我要占多大地方？         │
│          ↓                               │
│   布局（Layout）：我的子 View 放哪里？      │
│          ↓                               │
│   绘制（Draw）：我长什么样？               │
│                                          │
└──────────────────────────────────────────┘
```

## 核心概念

### 1. View 的坐标系

Android 的坐标系跟数学课本不一样——**Y 轴是向下的**！

```
        (0,0)────────────────→ X 轴（向右为正）
          │
          │
          │    ┌─────────────┐
          │    │    View     │
          │    │   (x, y)    │
          │    └─────────────┘
          │
          ↓
         Y 轴（向下为正）
```

**为什么这样设计？** 因为屏幕的内容是从左上角开始"流"下来的，就像写字从左上角开始写一样。

### 获取 View 位置的方法

```kotlin
// View 相对于父容器的位置
view.left    // 左边界到父容器左边的距离
view.top     // 上边界到父容器顶部的距离
view.right   // 右边界到父容器左边的距离（= left + width）
view.bottom  // 下边界到父容器顶部的距离（= top + height）

// View 的宽高
view.width   // = right - left
view.height  // = bottom - top

// View 的位移（translationX/Y 改变后才有值）
view.translationX  // X 方向的位移
view.translationY  // Y 方向的位移

// View 在屏幕上的实际位置
view.x  // = left + translationX
view.y  // = top + translationY
```

**生活类比**：把屏幕想象成一张纸，View 就是纸上的一个贴纸。`left/top` 是贴纸最初贴的位置，`translationX/Y` 是你把贴纸挪动了多少，`x/y` 是贴纸现在的实际位置。

### 2. MeasureSpec：测量规格

MeasureSpec 是一个 32 位 int 值，包含两个信息：

```
┌────────────────────────────────────────┐
│            MeasureSpec（32位）           │
├────────────────────────────────────────┤
│   高2位：模式（mode）                     │
│   低30位：大小（size）                    │
└────────────────────────────────────────┘
```

**三种测量模式**：

| 模式 | 含义 | 对应的布局参数 | 类比 |
|-----|------|--------------|------|
| exactly | 精确值，就这么大 | `100dp` 或 `match_parent` | "你必须穿这件衣服" |
| AT_MOST | 最大值，不能超过 | `wrap_content` | "衣服随便穿，但别超过这个尺码" |
| unspecified | 不限制，随便 | 通常在 ScrollView 中 | "想穿多大穿多大" |

```kotlin
// MeasureSpec 的使用
val mode = MeasureSpec.getMode(measureSpec)
val size = MeasureSpec.getSize(measureSpec)

// 创建 MeasureSpec
val spec = MeasureSpec.makeMeasureSpec(size, mode)
```

### 3. 画布 Canvas

Canvas 就是一块**画布**，提供各种画图方法。

```kotlin
// Canvas 核心绘制方法
canvas.drawColor(Color.WHITE)              // 填充背景色
canvas.drawCircle(cx, cy, radius, paint)   // 画圆
canvas.drawRect(rect, paint)               // 画矩形
canvas.drawLine(x1, y1, x2, y2, paint)     // 画线
canvas.drawText("Hello", x, y, paint)      // 画文字
canvas.drawBitmap(bitmap, x, y, paint)     // 画图片
canvas.drawPath(path, paint)               // 画路径
```

**Canvas 的变换操作**：

```kotlin
canvas.translate(dx, dy)  // 平移画布（移动坐标原点）
canvas.rotate(degrees)    // 旋转画布
canvas.scale(sx, sy)      // 缩放画布
canvas.save()             // 保存当前画布状态
canvas.restore()          // 恢复之前保存的状态
```

**生活类比**：Canvas 就像一张纸，`translate` 是把纸挪一下位置，`rotate` 是把纸转一下角度。`save/restore` 是"我先记住现在纸的位置，画完再放回去"。

### 4. 画笔 Paint

Paint 是**画笔**，决定画出来的东西长什么样。

```kotlin
val paint = Paint().apply {
    color = Color.RED           // 颜色
    strokeWidth = 5f            // 线宽
    style = Paint.Style.STROKE  // 样式：FILL（填充）、STROKE（描边）、FILL_AND_STROKE
    isAntiAlias = true          // 抗锯齿（让边缘更平滑）
    textSize = 50f              // 文字大小
    typeface = Typeface.DEFAULT_BOLD  // 字体
}
```

**Paint.Style 三种样式**：

```
    FILL           STROKE       FILL_AND_STROKE
   ┌─────┐        ┌─────┐        ┌─────┐
   │█████│        │     │        │█████│
   │█████│        │     │        │█████│
   └─────┘        └─────┘        └─────┘
   填充内部         只画边框        填充+边框
```

## 基本用法：第一个自定义 View

### 例子1：画一个圆

```kotlin
/**
 * 最简单的自定义 View：画一个红色圆形
 */
class CircleView @JvmOverloads constructor(
    context: Context,
    attrs: AttributeSet? = null,
    defStyleAttr: Int = 0
) : View(context, attrs, defStyleAttr) {

    // 画笔（在构造函数中初始化，避免在 onDraw 中创建对象）
    private val paint = Paint().apply {
        color = Color.RED
        isAntiAlias = true  // 抗锯齿，让圆更平滑
        style = Paint.Style.FILL
    }

    override fun onDraw(canvas: Canvas) {
        super.onDraw(canvas)

        // 圆心在 View 中心，半径取宽高最小值的一半
        val cx = width / 2f
        val cy = height / 2f
        val radius = minOf(width, height) / 2f

        canvas.drawCircle(cx, cy, radius, paint)
    }
}
```

**使用**：

```xml
<com.example.CircleView
    android:layout_width="100dp"
    android:layout_height="100dp" />
```

### 例子2：支持 wrap_content

上面的 CircleView 有个问题：设置 `wrap_content` 时会占满父容器。因为我们没有重写 `onMeasure`。

```kotlin
class CircleView @JvmOverloads constructor(
    context: Context,
    attrs: AttributeSet? = null,
    defStyleAttr: Int = 0
) : View(context, attrs, defStyleAttr) {

    private val paint = Paint().apply {
        color = Color.RED
        isAntiAlias = true
        style = Paint.Style.FILL
    }

    // 默认大小（当 wrap_content 时使用）
    private val defaultSize = 200

    override fun onMeasure(widthMeasureSpec: Int, heightMeasureSpec: Int) {
        // 分别计算宽高
        val width = resolveSize(defaultSize, widthMeasureSpec)
        val height = resolveSize(defaultSize, heightMeasureSpec)

        // 设置测量结果（必须调用！）
        setMeasuredDimension(width, height)
    }

    /**
     * 根据 MeasureSpec 计算实际大小
     * @param desiredSize 期望的大小
     * @param measureSpec 父容器给的测量规格
     */
    private fun resolveSize(desiredSize: Int, measureSpec: Int): Int {
        val mode = MeasureSpec.getMode(measureSpec)
        val size = MeasureSpec.getSize(measureSpec)

        return when (mode) {
            MeasureSpec.EXACTLY -> size  // 精确值，直接用
            MeasureSpec.AT_MOST -> minOf(desiredSize, size)  // wrap_content，取较小值
            else -> desiredSize  // UNSPECIFIED，用默认值
        }
    }

    override fun onDraw(canvas: Canvas) {
        super.onDraw(canvas)

        val cx = width / 2f
        val cy = height / 2f
        val radius = minOf(width, height) / 2f

        canvas.drawCircle(cx, cy, radius, paint)
    }
}
```

> **提示**：Android 提供了 `View.resolveSize()` 方法做类似的事，但理解原理更重要。

### 例子3：自定义属性

让圆的颜色可以在 XML 中配置。

**步骤1：定义属性**（`res/values/attrs.xml`）

```xml
<?xml version="1.0" encoding="utf-8"?>
<resources>
    <declare-styleable name="CircleView">
        <attr name="circleColor" format="color" />
        <attr name="circleRadius" format="dimension" />
    </declare-styleable>
</resources>
```

**步骤2：读取属性**

```kotlin
class CircleView @JvmOverloads constructor(
    context: Context,
    attrs: AttributeSet? = null,
    defStyleAttr: Int = 0
) : View(context, attrs, defStyleAttr) {

    private var circleColor = Color.RED
    private var circleRadius = 0f  // 0 表示自动计算

    private val paint = Paint().apply {
        isAntiAlias = true
        style = Paint.Style.FILL
    }

    init {
        // 读取自定义属性
        context.obtainStyledAttributes(attrs, R.styleable.CircleView).apply {
            circleColor = getColor(R.styleable.CircleView_circleColor, Color.RED)
            circleRadius = getDimension(R.styleable.CircleView_circleRadius, 0f)
            recycle()  // 必须回收！
        }
        paint.color = circleColor
    }

    override fun onDraw(canvas: Canvas) {
        super.onDraw(canvas)

        val cx = width / 2f
        val cy = height / 2f
        // 如果设置了 circleRadius 就用它，否则自动计算
        val radius = if (circleRadius > 0) circleRadius else minOf(width, height) / 2f

        canvas.drawCircle(cx, cy, radius, paint)
    }
}
```

**步骤3：在 XML 中使用**

```xml
<!-- 需要添加命名空间 -->
<com.example.CircleView
    xmlns:app="http://schemas.android.com/apk/res-auto"
    android:layout_width="wrap_content"
    android:layout_height="wrap_content"
    app:circleColor="#FF5722"
    app:circleRadius="50dp" />
```

### 例子4：支持 padding

```kotlin
override fun onDraw(canvas: Canvas) {
    super.onDraw(canvas)

    // 考虑 padding
    val availableWidth = width - paddingLeft - paddingRight
    val availableHeight = height - paddingTop - paddingBottom

    // 圆心需要偏移 padding
    val cx = paddingLeft + availableWidth / 2f
    val cy = paddingTop + availableHeight / 2f
    val radius = minOf(availableWidth, availableHeight) / 2f

    canvas.drawCircle(cx, cy, radius, paint)
}
```

## 常见坑点

### 坑点1：在 onDraw 中创建对象

```kotlin
// ❌ 错误：每次绘制都创建新对象，导致频繁 GC
override fun onDraw(canvas: Canvas) {
    val paint = Paint()  // 每秒可能调用 60 次！
    paint.color = Color.RED
    canvas.drawCircle(cx, cy, radius, paint)
}

// ✅ 正确：在构造函数或 init 中创建
private val paint = Paint().apply {
    color = Color.RED
}

override fun onDraw(canvas: Canvas) {
    canvas.drawCircle(cx, cy, radius, paint)
}
```

**原因**：`onDraw` 可能每秒调用 60 次（动画时），频繁创建对象会触发 GC，导致界面卡顿。

### 坑点2：忘记调用 setMeasuredDimension

```kotlin
// ❌ 错误：没有设置测量结果
override fun onMeasure(widthMeasureSpec: Int, heightMeasureSpec: Int) {
    // 计算了一堆，但是忘记调用...
}

// ✅ 正确：必须调用 setMeasuredDimension
override fun onMeasure(widthMeasureSpec: Int, heightMeasureSpec: Int) {
    val width = resolveSize(defaultSize, widthMeasureSpec)
    val height = resolveSize(defaultSize, heightMeasureSpec)
    setMeasuredDimension(width, height)  // 必须调用！
}
```

### 坑点3：忘记 recycle TypedArray

```kotlin
// ❌ 错误：内存泄漏！
context.obtainStyledAttributes(attrs, R.styleable.CircleView).apply {
    circleColor = getColor(R.styleable.CircleView_circleColor, Color.RED)
    // 忘记 recycle()
}

// ✅ 正确：用完必须回收
context.obtainStyledAttributes(attrs, R.styleable.CircleView).apply {
    circleColor = getColor(R.styleable.CircleView_circleColor, Color.RED)
    recycle()  // 不能忘！
}

// ✅ 更安全：使用 use 扩展函数（需要 kotlin-stdlib-jdk7）
context.obtainStyledAttributes(attrs, R.styleable.CircleView).use {
    circleColor = it.getColor(R.styleable.CircleView_circleColor, Color.RED)
}  // 自动 recycle
```

### 坑点4：不处理 wrap_content

如果不重写 `onMeasure`，`wrap_content` 会和 `match_parent` 效果一样。

```kotlin
// View 默认的 onMeasure 实现（简化版）
protected void onMeasure(int widthMeasureSpec, int heightMeasureSpec) {
    setMeasuredDimension(
        getDefaultSize(getSuggestedMinimumWidth(), widthMeasureSpec),
        getDefaultSize(getSuggestedMinimumHeight(), heightMeasureSpec)
    );
}

// getDefaultSize 的逻辑
public static int getDefaultSize(int size, int measureSpec) {
    int mode = MeasureSpec.getMode(measureSpec);
    int specSize = MeasureSpec.getSize(measureSpec);

    switch (mode) {
        case MeasureSpec.UNSPECIFIED:
            return size;
        case MeasureSpec.AT_MOST:  // wrap_content
        case MeasureSpec.EXACTLY:  // match_parent
            return specSize;  // 都返回 specSize！
    }
    return size;
}
```

所以 `wrap_content` 和 `match_parent` 都会返回父容器给的大小。

### 坑点5：硬编码尺寸

```kotlin
// ❌ 错误：硬编码像素值，不同屏幕显示不一致
private val radius = 100  // 100 像素

// ✅ 正确：使用 dp 转换
private val radius = 100.dp  // 100dp

// dp 转 px 的扩展属性
val Int.dp: Float
    get() = this * Resources.getSystem().displayMetrics.density

val Float.dp: Float
    get() = this * Resources.getSystem().displayMetrics.density
```

## 小结

| 内容 | 要点 |
|-----|------|
| 坐标系 | 左上角为原点，X 向右，Y 向下 |
| MeasureSpec | 32位 int，高2位是模式，低30位是大小 |
| 三种模式 | EXACTLY（精确）、AT_MOST（最大）、UNSPECIFIED（不限） |
| Canvas | 画布，提供各种绑制方法 |
| Paint | 画笔，决定绑制样式 |
| 自定义属性 | attrs.xml 定义，obtainStyledAttributes 读取 |

**自定义 View 三件套**：
1. `onMeasure`：测量大小（处理 wrap_content）
2. `onLayout`：布局子 View（ViewGroup 才需要）
3. `onDraw`：绑制内容

## 面试题检验

### Q1：View 的坐标系是怎样的？left、x、translationX 的区别？

**结论**：Android 坐标系以屏幕左上角为原点，X 轴向右，Y 轴向下。

**区别**：
- `left/top`：View 的初始位置（相对于父容器）
- `translationX/Y`：View 的位移量（动画或手动设置）
- `x/y`：View 的实际位置 = left + translationX

**类比**：`left` 是你家的原始地址，`translationX` 是你搬家搬了多远，`x` 是你现在住的地址。

---

### Q2：MeasureSpec 的三种模式是什么？分别对应什么布局参数？

**结论**：

| 模式 | 含义 | 布局参数 |
|-----|------|---------|
| EXACTLY | 精确大小 | `100dp` 或 `match_parent` |
| AT_MOST | 最大不超过 | `wrap_content` |
| UNSPECIFIED | 不限制 | 通常在 ScrollView 中 |

**原理**：父容器根据自己的 MeasureSpec 和子 View 的 LayoutParams，计算出子 View 的 MeasureSpec。

---

### Q3：为什么自定义 View 不重写 onMeasure，wrap_content 会失效？

**结论**：因为 View 默认的 `onMeasure` 对 AT_MOST 和 EXACTLY 返回相同的值。

**原理**：`getDefaultSize()` 方法中，AT_MOST 和 EXACTLY 都返回 `specSize`，导致 `wrap_content` 和 `match_parent` 效果一样。

**解决**：重写 `onMeasure`，在 AT_MOST 模式下返回内容所需的大小。

---

### Q4：为什么不能在 onDraw 中创建对象？

**结论**：`onDraw` 可能每秒调用 60 次，频繁创建对象会导致 GC 抖动，界面卡顿。

**原理**：Android 使用 VSYNC 信号触发绘制，每 16.6ms 一次。如果每次都创建对象，就会频繁触发 GC，GC 时会 Stop The World，导致丢帧。

**最佳实践**：Paint、Path、Rect 等对象在构造函数中创建，或者用 `reset()` 方法复用。

---

### Q5：obtainStyledAttributes 为什么要 recycle？

**结论**：TypedArray 是从对象池获取的，不 recycle 会导致对象池耗尽，后续需要创建新对象。

**原理**：TypedArray 内部有个对象池，`obtainStyledAttributes()` 从池中取，`recycle()` 放回池中。如果不回收，池中的对象会越来越少，最终需要创建新对象，增加 GC 压力。
