# 大模型微调实战指南（代码生成任务）

> 目标：微调一个代码生成模型，让它能按照特定风格、技术栈生成符合要求的代码。
> 环境：Mac M1（本地推理）+ 云服务器（训练）

---

## 1. 环境方案选择

### 方案对比

| 方案 | 平台 | 显存 | 费用 | 易用性 | 推荐场景 |
|------|------|------|------|--------|---------|
| **Mac M1 本地** | MLX 框架 | 统一内存（16GB 可跑 7B） | 免费 | 中 | 推理/小规模微调 |
| **AutoDL 云服务** | RTX 4090（24G） | 24GB | ~2元/小时 | 高 | 主力训练平台 |
| **Google Colab** | T4/A100 | 15～40GB | 免费/付费 | 高 | 入门体验 |
| **Kaggle** | 2×T4 | 15GB×2 | 免费 | 高 | 免费训练 |

### 推荐方案

```
训练：AutoDL 云服务器（RTX 4090）
  ↓ 训练完毕，导出模型权重
推理：Mac M1 本地（用 Ollama 跑）
```

**AutoDL 注册与使用：** https://www.autodl.com

选实例时选 **RTX 4090（24GB）**，镜像选 `PyTorch 2.x + CUDA 12.x`，费用约 **1.5~2.5 元/小时**。

### Mac M1 本地能做什么？

Mac M1/M2/M3 使用**统一内存（Unified Memory）**，16GB 内存可以：

- 跑 7B 模型推理（用 Ollama）
- 用 MLX 框架做小规模微调（数据集 < 1000 条）
- 训练速度比 NVIDIA GPU 慢 3～5 倍，适合验证但不适合正式训练

### 3.3 自制数据集（低成本方案）

当你有特定业务需求（比如：让模型生成符合公司规范的代码），可以用 GPT 批量生成：

```python
import openai
import json

client = openai.OpenAI(api_key="your-key")

def generate_code_sample(topic: str) -> dict:
    prompt = f"""
    请生成一个关于"{topic}"的代码练习题，格式如下：
    {{
      "instruction": "用Python实现...",
      "input": "（如果有输入示例）",
      "output": "（完整的代码实现，包含注释）"
    }}
    只返回JSON，不要其他内容。
    """
    response = client.chat.completions.create(
        model="gpt-4o-mini",  # 便宜，够用
        messages=[{"role": "user", "content": prompt}]
    )
    return json.loads(response.choices[0].message.content)

topics = ["列表排序", "文件读写", "API请求", "数据库操作", "正则表达式"]
dataset = [generate_code_sample(t) for t in topics]
```

> **成本参考：** gpt-4o-mini 每 1000 条数据约花费 ¥2～5，非常划算。

### 3.4 数据格式规范

```json
  },

    "input": "[3, 1, 4, 1, 5, 9, 2, 6]",
    "output": "def second_largest(nums):\n    unique = sorted(set(nums), reverse=True)\n    return unique[1] if len(unique) >= 2 else None"
  }

```

### 3.5 数据清洗要点

```python
def clean_dataset(data: list) -> list:
    cleaned = []
    for item in data:
        # 过滤太短的输出（可能是无效数据）
        if len(item["output"]) < 20:
            continue
        # 过滤没有代码块的输出
        if "def " not in item["output"] and "class " not in item["output"]:
            continue
        # 去除首尾空白
        item["output"] = item["output"].strip()
        item["instruction"] = item["instruction"].strip()
        cleaned.append(item)
    return cleaned
```

## 5. 实战：LLaMA-Factory + AutoDL 微调 Qwen2.5-Coder

### Step 1：连接云服务器，安装环境

```bash
# 克隆 LLaMA-Factory
git clone --depth 1 https://github.com/hiyouga/LLaMA-Factory.git
cd LLaMA-Factory

# 安装依赖
pip install -e ".[torch,metrics]"

# 验证安装
llamafactory-cli version
```

### Step 2：准备数据集

将你的数据集文件（`my_code_dataset.json`）放到 `data/` 目录下，然后在 `data/dataset_info.json` 中注册：

```json
{
  "my_code_dataset": {
    "file_name": "my_code_dataset.json",
    "columns": {
      "prompt": "instruction",
      "query": "input",
      "response": "output"
    }
  }
}
```

### Step 3：启动 Web UI

```bash
llamafactory-cli webui
```

浏览器打开 `http://localhost:7860`，按照界面配置：

```
模型名称：   Qwen2.5-Coder-7B-Instruct
模型路径：   ./models/qwen2.5-coder-7b
微调方法：   LoRA
训练数据集： my_code_dataset
```

### Step 4：核心训练参数配置（代码生成推荐值）

```yaml
# LoRA 配置
lora_rank: 16           # 代码任务，16 足够
lora_alpha: 32          # 通常设为 rank 的 2 倍
lora_dropout: 0.05
target_modules: q_proj,v_proj,k_proj,o_proj   # 覆盖 attention 全部层

# 训练配置
learning_rate: 2e-4
num_train_epochs: 3
per_device_train_batch_size: 4
gradient_accumulation_steps: 4  # 等效 batch_size = 16
max_seq_length: 2048
warmup_ratio: 0.1

# 评估配置
val_size: 0.1           # 10% 数据用于验证
evaluation_strategy: steps
eval_steps: 100
save_steps: 200
```

### Step 5：监控训练过程

```
训练日志示例：

{'loss': 1.8234, 'learning_rate': 0.00018, 'epoch': 1.0}
```

### 6.1 定性评估（人工对话测试）

训练完成后，在 LLaMA-Factory Web UI 的 `Chat` 页面，加载微调后的模型，输入测试问题：

```
测试用例 1（基础功能）：
  问：写一个 Python 函数，实现二分查找
  看：代码是否正确，是否符合你要求的风格

测试用例 2（边界情况）：
  问：上面的函数如果列表为空怎么处理？
  看：模型能否理解上下文，给出合理修改

测试用例 3（业务场景）：
  问：用 FastAPI 写一个用户注册接口
  看：是否用了你微调数据中强调的最佳实践
```

### 6.2 定量评估（代码生成 Benchmark）

**HumanEval**（最常用的代码生成评测）：

```bash
pip install human-eval

# 用模型生成代码
python generate_solutions.py \
  --model_path ./output/my_model \
  --output_file solutions.jsonl

# 计算 pass@1 分数（多少题能一次通过）
evaluate_functional_correctness solutions.jsonl
```

**指标说明：**

| 指标 | 含义 | 参考值（7B模型） |
|------|------|----------------|
| pass@1 | 一次生成，代码通过率 | 微调前~45%，微调后期望~55%+ |
| pass@10 | 生成10次，至少1次通过率 | 参考值 ~80% |

## 7. 导出与本地部署

### Step 1：合并 LoRA 权重

在 LLaMA-Factory Web UI 的 `Export` 页面，或用命令：

```bash
llamafactory-cli export \
  --model_name_or_path ./models/qwen2.5-coder-7b \
  --adapter_name_or_path ./output/my_lora_checkpoint \
  --export_dir ./output/merged_model \
  --export_dtype bf16
```

合并后，`./output/merged_model` 就是完整的微调模型。

### Step 2：转换为 GGUF 格式（给 Ollama 用）

```bash
# 克隆 llama.cpp
git clone https://github.com/ggerganov/llama.cpp
cd llama.cpp && make

# 转换格式
python convert_hf_to_gguf.py ../output/merged_model \
  --outfile ../output/my-coder.gguf \
  --outtype q4_k_m    # 4bit 量化，M1 16GB 可流畅运行
```

### Step 3：用 Ollama 在 Mac M1 本地运行

```bash
# 安装 Ollama（Mac）
brew install ollama

# 创建 Modelfile
cat > Modelfile << 'EOF'
FROM ./output/my-coder.gguf
SYSTEM "你是一个专业的代码助手，擅长 Python 开发。请用简洁、规范的代码回答问题，并添加必要的注释。"
PARAMETER temperature 0.2
PARAMETER top_p 0.9
EOF

# 创建模型
ollama create my-coder -f Modelfile

# 启动对话
ollama run my-coder
```

## 8. 常见问题与避坑

### OOM（显存不够）

```
错误：CUDA out of memory

解决方案（按优先级）：
1. 减小 per_device_train_batch_size（改为 2 或 1）
2. 增大 gradient_accumulation_steps（保持等效 batch size）
3. 减小 max_seq_length（从 2048 改到 1024）
4. 改用 QLoRA（load_in_4bit=True）
5. 换更小的模型（7B → 3B）
```

### 模型输出重复

```
症状：模型不断重复同一段话

原因：
- 学习率太大，模型"崩溃"
- 训练数据中有大量重复内容

解决：
- 降低 learning_rate（2e-4 → 1e-4）
- 清洗数据中的重复项
- 生成时设置 repetition_penalty=1.1
```

### 微调后模型变"笨"了

```
症状：微调后，模型连基础问题都回答不好

原因：数据集质量差，或训练轮数太多（过拟合）

解决：
- 减少 num_train_epochs（从 5 改到 3）
- 混入少量通用对话数据（约占总数据 10%）
- 检查并清洗低质量训练数据
```

### Mac M1 本地 MLX 微调（小数据集备选方案）

```bash
# 安装 MLX-LM
pip install mlx-lm

# 直接在 Mac 上微调（适合 < 1000 条数据的快速实验）
python -m mlx_lm.lora \
  --model mlx-community/Qwen2.5-Coder-7B-Instruct-4bit \
  --train \
  --data ./data/my_dataset \
  --iters 1000 \
  --batch-size 4 \
  --lora-layers 16
```
