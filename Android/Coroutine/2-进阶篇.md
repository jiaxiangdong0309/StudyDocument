# 协程进阶篇

## 协程上下文（CoroutineContext）

### 什么是协程上下文？

**大白话理解**：协程上下文就像协程的"身份证+工作证"，记录了协程的各种配置信息——在哪个线程跑、出错怎么处理、叫什么名字等。

```kotlin
// 上下文是一个键值对集合，可以组合多个元素
val context: CoroutineContext = 
    Dispatchers.IO +           // 调度器：在 IO 线程执行
    CoroutineName("DataLoader") +  // 名字：调试用
    SupervisorJob()            // Job：控制协程生命周期
```

### 上下文的组成元素

| 元素 | 作用 | 示例 |
|-----|------|------|
| **Job** | 控制协程生命周期，父子关系 | `Job()`, `SupervisorJob()` |
| **Dispatcher** | 决定协程在哪个线程运行 | `Dispatchers.Main`, `Dispatchers.IO` |
| **CoroutineName** | 协程名字，调试时有用 | `CoroutineName("LoadUser")` |
| **CoroutineExceptionHandler** | 异常处理器 | 全局异常捕获 |

```kotlin
// 查看当前协程的上下文
viewModelScope.launch {
    println("Job: ${coroutineContext[Job]}")
    println("Dispatcher: ${coroutineContext[ContinuationInterceptor]}")
    println("Name: ${coroutineContext[CoroutineName]}")
}
```

### 上下文的继承与覆盖

```
┌─────────────────────────────────────────────────────────────────┐
│                    协程上下文继承规则                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  viewModelScope 上下文                                           │
│  ┌─────────────────────────────────────────────────────┐        │
│  │ Job = SupervisorJob                                  │        │
│  │ Dispatcher = Dispatchers.Main                        │        │
│  └─────────────────────────────────────────────────────┘        │
│                           │                                      │
│                           │ 继承（子协程继承父上下文）             │
│                           ▼                                      │
│  viewModelScope.launch(Dispatchers.IO) 上下文                    │
│  ┌─────────────────────────────────────────────────────┐        │
│  │ Job = 新创建的 Job（父 Job 是 SupervisorJob）          │        │
│  │ Dispatcher = Dispatchers.IO（覆盖了父的 Main）        │        │
│  └─────────────────────────────────────────────────────┘        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

```kotlin
viewModelScope.launch {
    // 继承 viewModelScope 的上下文，Dispatcher = Main
    println("外层协程线程: ${Thread.currentThread().name}")  // main
    
    launch(Dispatchers.IO) {
        // 覆盖 Dispatcher，其他继承父协程
        println("内层协程线程: ${Thread.currentThread().name}")  // DefaultDispatcher-worker-1
    }
    
    withContext(Dispatchers.Default) {
        // 临时切换上下文
        println("withContext 线程: ${Thread.currentThread().name}")
    }
}
```

## 异常处理机制

### 协程异常传播规则

这是协程最容易踩坑的地方！

**核心规则**：
1. `launch` 的异常会**立即向上传播**
2. `async` 的异常在 `await()` 时才抛出
3. 子协程异常会**取消父协程和所有兄弟协程**（除非使用 SupervisorJob）

```kotlin
// 演示异常传播
viewModelScope.launch {
    launch {
        delay(100)
        println("子协程 1")  // 不会执行！被子协程 2 的异常取消了
    }
    
    launch {
        throw Exception("子协程 2 出错了")  // 异常向上传播
    }
    
    launch {
        delay(100)
        println("子协程 3")  // 不会执行！
    }
}
// 结果：所有子协程都被取消，viewModelScope 也可能受影响
```

```
┌─────────────────────────────────────────────────────────────────┐
│                    普通 Job 的异常传播                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│                    ┌──────────────┐                             │
│                    │  父协程 Job   │ ← 收到子协程异常，取消所有子协程│
│                    └──────┬───────┘                             │
│                           │                                     │
│         ┌─────────────────┼─────────────────┐                   │
│         ▼                 ▼                 ▼                   │
│  ┌────────────┐   ┌────────────┐   ┌────────────┐              │
│  │ 子协程 1   │   │ 子协程 2   │   │ 子协程 3   │              │
│  │  (取消)    │   │  (异常)    │   │  (取消)    │              │
│  └────────────┘   └────────────┘   └────────────┘              │
│                         ↑                                       │
│                     抛出异常                                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### SupervisorJob：子协程异常不影响兄弟

```kotlin
// SupervisorJob：一个子协程失败不影响其他
val supervisor = SupervisorJob()

CoroutineScope(Dispatchers.Main + supervisor).launch {
    launch {
        delay(100)
        println("子协程 1 完成")  // ✅ 正常执行！
    }
    
    launch {
        throw Exception("子协程 2 出错了")  // 只影响自己
    }
    
    launch {
        delay(100)
        println("子协程 3 完成")  // ✅ 正常执行！
    }
}
```

```
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│                    ┌──────────────────┐                         │
│                    │ SupervisorJob    │ ← 不会因子协程异常而取消   │
│                    └──────┬───────────┘                         │
│                           │                                     │
│         ┌─────────────────┼─────────────────┐                   │
│         ▼                 ▼                 ▼                   │

│  │  (正常)    │   │  (异常)    │   │  (正常)    │              │

```

**viewModelScope 和 lifecycleScope 都使用 SupervisorJob**，所以一个协程失败不会影响其他。

### supervisorScope vs coroutineScope

```kotlin
// coroutineScope：一个子协程失败，其他都取消
suspend fun loadAllData() = coroutineScope {
    val user = async { getUser() }        // 失败 → 全部取消
    val orders = async { getOrders() }    // 被取消
    Pair(user.await(), orders.await())
}

// supervisorScope：子协程独立，互不影响
suspend fun loadAllDataIndependently() = supervisorScope {
    val user = async { getUser() }        // 失败 → 只影响自己
    val orders = async { getOrders() }    // 继续执行
    
    // 需要单独处理每个 async 的异常
    val userResult = runCatching { user.await() }
    val ordersResult = runCatching { orders.await() }
    
    Pair(userResult.getOrNull(), ordersResult.getOrNull())
}
```

### CoroutineExceptionHandler：全局异常处理

```kotlin
// 定义异常处理器
val exceptionHandler = CoroutineExceptionHandler { context, throwable ->
    Log.e("CoroutineError", "协程异常: ${throwable.message}", throwable)
    // 上报到 Crashlytics 等
    // Firebase.crashlytics.recordException(throwable)
}

// 使用异常处理器
class MyViewModel : ViewModel() {
    
    private val handler = CoroutineExceptionHandler { _, e ->
        _error.value = e.message
    }
    
    fun loadData() {
        // 把 handler 加入上下文
        viewModelScope.launch(handler) {
            throw Exception("加载失败")  // 会被 handler 捕获
        }
    }
}
```

**注意**：CoroutineExceptionHandler 只对 `launch` 生效，对 `async` 无效（async 的异常在 await 时抛出）。

### 异常处理最佳实践

```kotlin
class DataRepository {
    
    // 方式 1：返回 Result 包装
    suspend fun fetchUserSafe(): Result<User> = runCatching {
        api.getUser()
    }
    
    // 方式 2：返回 sealed class
    suspend fun fetchUser(): DataResult<User> {
        return try {
            val user = api.getUser()
            DataResult.Success(user)
        } catch (e: Exception) {
            DataResult.Error(e)
        }
    }
}

// 定义结果类
sealed class DataResult<out T> {
    data class Success<T>(val data: T) : DataResult<T>()
    data class Error(val exception: Exception) : DataResult<Nothing>()
}

// ViewModel 中使用
class UserViewModel(private val repo: DataRepository) : ViewModel() {
    
    fun loadUser() {
        viewModelScope.launch {
            when (val result = repo.fetchUser()) {
                is DataResult.Success -> _user.value = result.data
                is DataResult.Error -> _error.value = result.exception.message
            }
        }
    }
}
```

## Flow 详解

### Flow 是什么？

**大白话理解**：`suspend` 函数返回单个值，`Flow` 返回多个值（数据流）。就像水管，可以持续流出数据。

```kotlin
// suspend 函数：返回一个值
suspend fun getUser(): User

// Flow：返回多个值（数据流）
fun observeUsers(): Flow<List<User>>
```

### Flow vs LiveData

| 特性 | Flow | LiveData |
|-----|------|----------|
| **层次** | Kotlin 标准库 | Android 专属 |
| **生命周期** | 需要手动处理 | 自动感知 |
| **操作符** | 丰富（map, filter, flatMap...） | 很少（map, switchMap） |
| **背压** | 支持 | 不支持 |
| **线程** | 可指定 | 默认主线程 |
| **冷热流** | 冷流（Cold） | 热流（Hot） |

**推荐**：
- Repository 层：用 Flow
- ViewModel → UI 层：用 StateFlow（替代 LiveData）

### 创建 Flow

```kotlin
// 方式 1：flow 构建器
fun countDown(): Flow<Int> = flow {
    for (i in 10 downTo 0) {
        emit(i)  // 发射值
        delay(1000)
    }
}

// 方式 2：flowOf（类似 listOf）
val numbers = flowOf(1, 2, 3, 4, 5)

// 方式 3：集合转 Flow
val list = listOf(1, 2, 3)
val flow = list.asFlow()

// 方式 4：callbackFlow（将回调 API 转成 Flow）
fun locationUpdates(): Flow<Location> = callbackFlow {
    val callback = object : LocationCallback() {
        override fun onLocationResult(result: LocationResult) {
            // 发送位置到 Flow
            trySend(result.lastLocation)
        }
    }
    
    locationClient.requestLocationUpdates(request, callback, Looper.getMainLooper())
    
    // 当 Flow 被取消时清理资源
    awaitClose {
        locationClient.removeLocationUpdates(callback)
    }
}
```

### 收集 Flow

```kotlin
// 基本收集
lifecycleScope.launch {
    countDown().collect { value ->
        println(value)
    }
}

// 生命周期安全的收集（推荐！）
lifecycleScope.launch {
    repeatOnLifecycle(Lifecycle.State.STARTED) {
        viewModel.uiState.collect { state ->
            updateUI(state)
        }
    }
}

// 收集到 StateFlow/SharedFlow
val stateFlow: StateFlow<Int> = flow
    .stateIn(
        scope = viewModelScope,
        started = SharingStarted.WhileSubscribed(5000),
        initialValue = 0
    )
```

### Flow 操作符

```kotlin
// 转换操作符
fun processUserFlow(): Flow<UserUI> = userRepository.observeUsers()
    .map { users ->                    // 转换每个元素
        users.map { it.toUI() }
    }
    .filter { it.isNotEmpty() }        // 过滤
    .distinctUntilChanged()            // 去重（只有变化时才发射）

// 组合操作符
fun combinedData(): Flow<CombinedData> = combine(
    userFlow,
    settingsFlow,
    statsFlow
) { user, settings, stats ->
    CombinedData(user, settings, stats)
}

// 扁平化操作符
fun searchResults(query: Flow<String>): Flow<List<Result>> = query
    .debounce(300)                     // 防抖
    .filter { it.length >= 2 }         // 至少 2 个字符才搜索
    .flatMapLatest { searchQuery ->    // 取消之前的搜索，只保留最新
        searchRepository.search(searchQuery)
    }

// 错误处理
fun safeFlow(): Flow<Data> = dataFlow
    .catch { e ->                      // 捕获上游异常
        Log.e("Flow", "Error: ${e.message}")
        emit(Data.empty())             // 发射默认值
    }
    .onCompletion { cause ->           // 完成时回调（无论成功还是失败）
        if (cause != null) {
            Log.e("Flow", "Completed with error")
        }
    }

// 线程切换
fun dataOnIO(): Flow<Data> = flow {
    emit(fetchData())
}.flowOn(Dispatchers.IO)               // 上游在 IO 线程执行
```

### StateFlow 与 SharedFlow

**StateFlow**：热流，总是有一个当前值，适合 UI 状态

```kotlin
class UserViewModel : ViewModel() {
    
    // 私有可变的
    private val _uiState = MutableStateFlow<UiState>(UiState.Loading)
    // 公开只读的
    val uiState: StateFlow<UiState> = _uiState.asStateFlow()
    
    fun loadUser() {
        viewModelScope.launch {
            _uiState.value = UiState.Loading
            try {
                val user = userRepository.getUser()
                _uiState.value = UiState.Success(user)
            } catch (e: Exception) {
                _uiState.value = UiState.Error(e.message)
            }
        }
    }
}

sealed class UiState {
    object Loading : UiState()
    data class Success(val user: User) : UiState()
    data class Error(val message: String?) : UiState()
}
```

**SharedFlow**：热流，没有初始值，适合事件（一次性消费）

```kotlin
class EventViewModel : ViewModel() {
    
    // 事件流：显示 Toast、导航等一次性事件
    private val _events = MutableSharedFlow<Event>()
    val events: SharedFlow<Event> = _events.asSharedFlow()
    
    fun onButtonClick() {
        viewModelScope.launch {
            _events.emit(Event.ShowToast("点击成功"))
        }
    }
    
    fun onItemClick(item: Item) {
        viewModelScope.launch {
            _events.emit(Event.Navigate(item.id))
        }
    }
}

sealed class Event {
    data class ShowToast(val message: String) : Event()
    data class Navigate(val destination: String) : Event()
}

// 在 Activity 中收集事件
lifecycleScope.launch {
    repeatOnLifecycle(Lifecycle.State.STARTED) {
        viewModel.events.collect { event ->
            when (event) {
                is Event.ShowToast -> showToast(event.message)
                is Event.Navigate -> navigateTo(event.destination)
            }
        }
    }
}
```

### StateFlow vs SharedFlow vs LiveData

| 特性 | StateFlow | SharedFlow | LiveData |
|-----|-----------|------------|----------|
| **初始值** | 必须有 | 可选 | 可选 |
| **重复值** | 不发射 | 可发射 | 发射 |
| **订阅者** | 多个 | 多个 | 多个 |
| **生命周期** | 手动处理 | 手动处理 | 自动处理 |
| **使用场景** | UI 状态 | 事件 | 简单场景 |

## 结构化并发

### 什么是结构化并发？

**大白话理解**：结构化并发就像公司的组织架构——经理（父协程）离职了，下面的员工（子协程）也要离开。不会出现"野生员工"。

**三个核心原则**：
1. **父协程等待子协程**：父协程不会在子协程完成前结束
2. **父协程取消时，子协程也取消**：避免泄漏
3. **子协程异常会传播给父协程**：（除非 SupervisorJob）

```kotlin
viewModelScope.launch {  // 父协程
    val job1 = launch { delay(1000) }  // 子协程 1
    val job2 = launch { delay(2000) }  // 子协程 2
    
    // 父协程会等待 job1 和 job2 都完成
    println("子协程都完成了")
}

// 如果 viewModelScope 被取消（ViewModel 销毁）
// job1 和 job2 都会自动取消
```

### coroutineScope vs supervisorScope

```kotlin
// coroutineScope：并行执行，任一失败则全部取消
suspend fun fetchAllData(): Pair<User, Orders> = coroutineScope {
    val user = async { fetchUser() }
    val orders = async { fetchOrders() }
    
    // 如果 fetchUser 失败，fetchOrders 也会被取消
    Pair(user.await(), orders.await())
}

// supervisorScope：并行执行，失败互不影响
suspend fun fetchAllDataIndependently() = supervisorScope {
    val user = async { fetchUser() }
    val orders = async { fetchOrders() }
    
    // 如果 fetchUser 失败，fetchOrders 继续执行
    val userResult = runCatching { user.await() }
    val ordersResult = runCatching { orders.await() }
    
    Pair(userResult.getOrNull(), ordersResult.getOrNull())
}
```

## 实战最佳实践

### 1. Repository 层设计

```kotlin
class UserRepository(
    private val api: UserApi,
    private val userDao: UserDao,
    private val ioDispatcher: CoroutineDispatcher = Dispatchers.IO
) {
    // 单次获取
    suspend fun getUser(id: String): User = withContext(ioDispatcher) {
        // 先从缓存读取
        userDao.getUser(id)?.let { return@withContext it }
        
        // 缓存没有，从网络获取
        val user = api.getUser(id)
        userDao.insertUser(user)
        user
    }
    
    // 观察数据（数据库变化时自动更新）
    fun observeUser(id: String): Flow<User?> = userDao.observeUser(id)
        .flowOn(ioDispatcher)
    
    // 刷新数据
    suspend fun refreshUser(id: String) = withContext(ioDispatcher) {
        val user = api.getUser(id)
        userDao.insertUser(user)
    }
}
```

### 2. ViewModel 层设计

```kotlin
class UserViewModel(
    private val userRepository: UserRepository,
    private val savedStateHandle: SavedStateHandle
) : ViewModel() {
    
    private val userId: String = savedStateHandle["userId"] ?: ""
    
    // UI 状态
    private val _uiState = MutableStateFlow<UserUiState>(UserUiState.Loading)
    val uiState: StateFlow<UserUiState> = _uiState.asStateFlow()
    
    // 一次性事件
    private val _events = MutableSharedFlow<UserEvent>()
    val events: SharedFlow<UserEvent> = _events.asSharedFlow()
    
    init {
        // 观察数据库变化
        viewModelScope.launch {
            userRepository.observeUser(userId)
                .collect { user ->
                    _uiState.value = user?.let { UserUiState.Success(it) }
                        ?: UserUiState.Empty
                }
        }
        
        // 初始加载
        refresh()
    }
    
    fun refresh() {
        viewModelScope.launch {
            _uiState.value = UserUiState.Loading
            try {
                userRepository.refreshUser(userId)
                // 数据库更新后，observe 会自动更新 uiState
            } catch (e: Exception) {
                _uiState.value = UserUiState.Error(e.message)
                _events.emit(UserEvent.ShowError(e.message ?: "加载失败"))
            }
        }
    }
    
    fun onRetryClick() {
        refresh()
    }
}

sealed class UserUiState {
    object Loading : UserUiState()
    object Empty : UserUiState()
    data class Success(val user: User) : UserUiState()
    data class Error(val message: String?) : UserUiState()
}

sealed class UserEvent {
    data class ShowError(val message: String) : UserEvent()
}
```

### 3. UI 层收集

```kotlin
class UserActivity : AppCompatActivity() {
    
    private val viewModel: UserViewModel by viewModels()
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(binding.root)
        
        // 收集 UI 状态
        lifecycleScope.launch {
            repeatOnLifecycle(Lifecycle.State.STARTED) {
                viewModel.uiState.collect { state ->
                    when (state) {
                        is UserUiState.Loading -> showLoading()
                        is UserUiState.Empty -> showEmpty()
                        is UserUiState.Success -> showUser(state.user)
                        is UserUiState.Error -> showError(state.message)
                    }
                }
            }
        }
        
        // 收集事件
        lifecycleScope.launch {
            repeatOnLifecycle(Lifecycle.State.STARTED) {
                viewModel.events.collect { event ->
                    when (event) {
                        is UserEvent.ShowError -> showToast(event.message)
                    }
                }
            }
        }
        
        // 下拉刷新
        binding.swipeRefresh.setOnRefreshListener {
            viewModel.refresh()
        }
    }
}
```

### 4. 并行请求优化

```kotlin
// 串行执行（慢）
suspend fun loadDashboardSerial(): Dashboard {
    val user = getUser()           // 1 秒
    val orders = getOrders()       // 1 秒
    val notifications = getNotifications()  // 1 秒
    return Dashboard(user, orders, notifications)  // 总共 3 秒
}

// 并行执行（快）
suspend fun loadDashboardParallel(): Dashboard = coroutineScope {
    val user = async { getUser() }
    val orders = async { getOrders() }
    val notifications = async { getNotifications() }
    
    Dashboard(
        user = user.await(),
        orders = orders.await(),
        notifications = notifications.await()
    )  // 总共 1 秒（最长的那个）
}
```

### 5. 防抖与节流

```kotlin
// 搜索防抖
class SearchViewModel : ViewModel() {
    
    private val searchQuery = MutableStateFlow("")
    
    val searchResults: StateFlow<List<SearchResult>> = searchQuery
        .debounce(300)  // 300ms 防抖
        .filter { it.length >= 2 }  // 至少 2 个字符
        .distinctUntilChanged()  // 去重
        .flatMapLatest { query ->
            if (query.isEmpty()) {
                flowOf(emptyList())
            } else {
                searchRepository.search(query)
                    .catch { emit(emptyList()) }
            }
        }
        .stateIn(
            scope = viewModelScope,
            started = SharingStarted.WhileSubscribed(5000),
            initialValue = emptyList()
        )
    
    fun onQueryChange(query: String) {
        searchQuery.value = query
    }
}
```

## 横向对比

### 协程 vs RxJava

| 特性 | 协程 + Flow | RxJava |
|-----|------------|--------|
| 学习曲线 | 平缓 | 陡峭 |
| 代码可读性 | 像同步代码 | 链式调用 |
| 调试 | 友好 | 困难 |
| 包体积 | 小 | 大（约 2MB） |
| 操作符 | 够用 | 非常丰富 |
| 取消 | 自动（结构化并发） | 手动（Disposable） |
| Google 支持 | 官方推荐 | 第三方 |

**迁移建议**：新项目直接用协程，老项目逐步迁移。

### 什么时候不用协程？

1. **简单的一次性任务**：用 Handler 或 Executor 就够了
2. **已经在用 RxJava 且运行良好**：没必要为了用而用
3. **团队不熟悉 Kotlin**：协程是 Kotlin 专属

## 面试检验

### 进阶概念题

**Q1：协程的异常处理机制是怎样的？**

> **答案**：
> 1. **launch**：异常会立即向上传播给父协程，如果没有被处理，会导致应用崩溃
> 2. **async**：异常会被延迟到 `await()` 调用时才抛出
> 3. **异常传播规则**：子协程异常 → 取消所有兄弟协程 → 向上传播给父协程
> 4. **SupervisorJob**：打破传播链，子协程失败不影响兄弟
> 5. **CoroutineExceptionHandler**：全局异常处理器，只对 launch 生效

**Q2：SupervisorJob 和普通 Job 有什么区别？**

> **答案**：
> - **普通 Job**：一个子协程失败，会取消所有兄弟协程，并向上传播
> - **SupervisorJob**：一个子协程失败，不影响其他子协程，异常不会向上传播
> 
> viewModelScope 和 lifecycleScope 都使用 SupervisorJob，所以一个协程失败不会影响其他。

**Q3：Flow 和 LiveData 有什么区别？什么场景用哪个？**

> **答案**：
> - **Flow**：Kotlin 标准库，操作符丰富，需要手动处理生命周期
> - **LiveData**：Android 专属，自动感知生命周期，操作符少
> 
> 推荐：
> - Repository 层：用 Flow
> - ViewModel → UI：用 StateFlow（替代 LiveData）
> - 简单场景：LiveData 也可以

**Q4：什么是结构化并发？有什么好处？**

> **答案**：结构化并发是协程的核心设计原则，包括：
> 1. 父协程会等待所有子协程完成
> 2. 父协程取消时，子协程自动取消
> 3. 子协程异常会传播给父协程
> 
> 好处：
> - **避免协程泄漏**：没有"野生协程"
> - **简化生命周期管理**：跟随作用域自动处理
> - **异常可追溯**：异常会沿着层级传播

**Q5：StateFlow 和 SharedFlow 有什么区别？分别适合什么场景？**

> **答案**：
> | | StateFlow | SharedFlow |
> |--|-----------|------------|
> | 初始值 | 必须有 | 不需要 |
> | 重复值 | 不发射相同值 | 可以发射 |
> | 适用场景 | UI 状态（如加载状态） | 事件（如 Toast、导航） |
> 
> StateFlow 适合表示"当前状态"，SharedFlow 适合表示"发生了什么事件"。

**Q6：协程中如何正确处理超时？**

> **答案**：使用 `withTimeout` 或 `withTimeoutOrNull`：
> ```kotlin
> // withTimeout：超时抛出 TimeoutCancellationException
> try {
>     withTimeout(5000) {
>         api.fetchData()
>     }
> } catch (e: TimeoutCancellationException) {
>     showError("请求超时")
> }
> 
> // withTimeoutOrNull：超时返回 null
> val result = withTimeoutOrNull(5000) {
>     api.fetchData()
> } ?: defaultValue
> ```
