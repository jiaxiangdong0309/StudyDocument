# Activity 学习指南

## 概述

Activity 是 Android 四大组件之首，是用户与应用交互的**入口点**。每个 Activity 都代表一个屏幕界面，用户的点击、滑动、输入都通过 Activity 来响应。

> **一句话理解**：Activity 就像一个"舞台"🎭，你的 UI 组件（按钮、文本、图片）都是"演员"，Activity 负责搭建舞台、管理演出（生命周期）、处理观众互动（用户事件）。

## 为什么要深入理解 Activity？

| 场景 | 不理解 Activity | 深入理解 Activity |
|-----|----------------|------------------|
| 配置变更 | 屏幕旋转数据丢失，用户抓狂 | 优雅保存恢复，体验丝滑 |
| 内存管理 | 后台 Activity 被杀，返回白屏 | 正确处理重建，数据不丢 |
| 页面跳转 | 返回栈混乱，用户迷路 | 合理设计启动模式，导航清晰 |
| 性能优化 | 启动慢、卡顿，用户流失 | 优化启动流程，秒开体验 |

## 核心问题预览

### 基础篇必答题
1. Activity 的生命周期有哪些？各在什么时候调用？
2. onSaveInstanceState 和 onRestoreInstanceState 什么时候调用？
3. Activity A 启动 Activity B，生命周期回调顺序是什么？

### 进阶篇必答题
1. 四种启动模式的区别？各适用什么场景？
2. onSaveInstanceState 和 ViewModel 有什么区别？如何选择？
3. 如何优化 Activity 的启动速度？

1. Activity 的启动流程是怎样的？涉及哪些关键类？

## 相关技术

| 技术 | 关系 | 说明 |
|-----|------|------|
| Fragment | 内嵌组件 | Activity 的"子舞台"，实现界面模块化 |
| Lifecycle | 基础设施 | Activity 是 LifecycleOwner 的典型实现 |
| ViewModel | 数据容器 | 与 Activity 生命周期解耦的数据持有者 |
| Intent | 通信桥梁 | Activity 之间传递数据的信使 |
| Compose | 新范式 | Compose 中 Activity 角色弱化为容器 |
