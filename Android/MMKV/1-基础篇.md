# MMKV 基础篇

## 技术演进：为什么需要 MMKV？

### SharedPreferences 的三大痛点

SharedPreferences（以下简称 SP）伴随 Android 诞生至今，简单易用，但问题也很严重：

#### 痛点一：性能差，容易卡顿

```kotlin
// SP 的写入是"全量写入"
// 就算只改一个字段，也要把整个文件重新写一遍！
val sp = getSharedPreferences("config", Context.MODE_PRIVATE)
sp.edit().putString("key", "value").apply()

// 想象一下：你只想改日记本的一个字
// 但 SP 的做法是：把整本日记本撕了重写一遍
```

```
┌─────────────────────────────────────────────────────────────────┐
│                    SP vs MMKV 写入对比                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  SharedPreferences 写入流程：                                    │
│  ┌──────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐      │
│  │内存修改│───►│序列化全部│───►│ 写临时文件 │───►│ 重命名替换 │      │
│  └──────┘    └──────────┘    └──────────┘    └──────────┘      │
│      ↑              ↑              ↑              ↑             │
│     快             慢             慢             慢             │
│                                                                 │
│  MMKV 写入流程：                                                 │
│  ┌──────┐    ┌──────────┐                                       │
│  │内存修改│───►│ 追加写入 │  完成！                                │
│  └──────┘    └──────────┘                                       │
│      ↑              ↑                                           │
│     快             快                                           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### 痛点二：apply() 可能导致 ANR

很多人以为 `apply()` 是异步的，不会卡主线程。错！

```kotlin
// apply() 的真相：
// 1. 内存修改是同步的
// 2. 写文件是异步的
// 3. 但是！Activity 生命周期会等待所有 apply 完成！

override fun onPause() {
    super.onPause()
    // 如果之前有很多 apply() 还没写完
    // 这里会阻塞等待，造成 ANR！
    
    // 系统在 ActivityThread.handlePauseActivity 中会调用：
    // QueuedWork.waitToFinish()
    // 这会等待所有 pending 的 apply() 完成
}
```

微信团队的实际案例：
> 在微信主线程中，SP 相关的 ANR 占比一度高达 **50%** 以上！这也是腾讯开发 MMKV 的直接原因。

#### 痛点三：多进程不支持

```kotlin
// 进程 A 写入
val sp = getSharedPreferences("config", Context.MODE_PRIVATE)
sp.edit().putString("token", "abc123").apply()

// 进程 B 读取
val sp = getSharedPreferences("config", Context.MODE_PRIVATE)
val token = sp.getString("token", "")  // 可能读到旧值或空值！

// 为什么？
// 1. SP 在每个进程都有独立的内存缓存
// 2. 进程 A 写入后，进程 B 的缓存不会自动更新
// 3. MODE_MULTI_PROCESS 已废弃，而且也不可靠
```

### MMKV 的诞生

2018 年，腾讯开源了 MMKV，彻底解决了以上所有问题。它的核心武器就是：**mmap（内存映射）**。

> **大白话解释 mmap**：
> 
> 普通文件读写就像「用吸管喝奶茶」—— 每次只能吸一点点，中间还要经过嘴巴（系统调用）。
> 
> mmap 就像「把奶茶倒进大碗里直接喝」—— 文件内容直接映射到内存，读写就像操作内存一样快，而且系统会自动帮你同步到磁盘。

## 核心概念

### MMKV 的核心特性

| 特性 | 说明 | 带来的好处 |
|-----|------|----------|
| **mmap 内存映射** | 文件直接映射到内存 | 读写速度快，无需系统调用 |
| **增量更新** | 只追加修改的数据 | 写入极快，不全量重写 |
| **ProtoBuf 编码** | 二进制紧凑编码 | 存储空间小，解析快 |
| **CRC 校验** | 数据完整性检查 | 防止数据损坏 |
| **文件锁 + mmap** | 原生多进程支持 | 进程间数据实时同步 |

### MMKV vs SharedPreferences

| 对比项 | SharedPreferences | MMKV |
|-------|-------------------|------|
| 写入方式 | 全量写入 | 增量追加 |
| 编码格式 | XML 文本 | ProtoBuf 二进制 |
| 读取方式 | 首次加载到内存 | mmap 直接映射 |
| 多进程 | 不支持（MODE_MULTI_PROCESS 已废弃） | 原生支持 |
| ANR 风险 | 高（apply 堆积） | 无 |
| 加密 | 不支持 | 支持 AES 加密 |
| 性能 | 1x | 100x+ |

## 基本用法：快速上手

### 1. 添加依赖

```kotlin
// build.gradle.kts (Module)
dependencies {
    implementation("com.tencent:mmkv:1.3.2")  // 请使用最新版本
}
```

### 2. 初始化

```kotlin
// Application 中初始化
class MyApplication : Application() {
    
    override fun onCreate() {
        super.onCreate()
        
        // 初始化 MMKV，返回根目录路径
        val rootDir = MMKV.initialize(this)
        Log.d("MMKV", "MMKV root: $rootDir")
        // 默认路径：/data/data/{packageName}/files/mmkv
    }
}
```

### 3. 基本读写操作

```kotlin
// 获取默认实例
val kv = MMKV.defaultMMKV()

// 写入数据（无需 commit 或 apply，写入即生效！）
kv.encode("bool_key", true)
kv.encode("int_key", 42)
kv.encode("long_key", 123456789L)
kv.encode("float_key", 3.14f)
kv.encode("string_key", "Hello MMKV")
kv.encode("bytes_key", byteArrayOf(1, 2, 3))

// 读取数据
val boolValue = kv.decodeBool("bool_key", false)  // 第二个参数是默认值
val intValue = kv.decodeInt("int_key", 0)
val longValue = kv.decodeLong("long_key", 0L)
val floatValue = kv.decodeFloat("float_key", 0f)
val stringValue = kv.decodeString("string_key", "")
val bytesValue = kv.decodeBytes("bytes_key")

// 存储复杂对象（需要实现 Parcelable）
@Parcelize
data class User(val name: String, val age: Int) : Parcelable

kv.encode("user", User("张三", 25))
val user = kv.decodeParcelable("user", User::class.java)
```

### 4. 其他常用操作

```kotlin
val kv = MMKV.defaultMMKV()

// 检查 key 是否存在
val exists = kv.containsKey("some_key")

// 删除指定 key
kv.removeValueForKey("some_key")

// 删除多个 key
kv.removeValuesForKeys(arrayOf("key1", "key2", "key3"))

// 获取所有 key
val allKeys = kv.allKeys()

// 获取存储数据的总大小
val totalSize = kv.totalSize()

// 获取实际使用的大小
val actualSize = kv.actualSize()

// 清空所有数据
kv.clearAll()

// 同步数据到文件（正常情况不需要调用，系统会自动同步）
kv.sync()

// 异步同步
kv.async()
```

### 5. 使用命名实例（推荐）

```kotlin
// 不同业务使用不同的实例，数据隔离，便于管理
val userKV = MMKV.mmkvWithID("user_data")
val configKV = MMKV.mmkvWithID("app_config")
val cacheKV = MMKV.mmkvWithID("cache")

// 用户模块
userKV.encode("user_id", "12345")
userKV.encode("is_vip", true)

// 配置模块
configKV.encode("theme", "dark")
configKV.encode("language", "zh-CN")

// 缓存模块
cacheKV.encode("last_sync_time", System.currentTimeMillis())
```

### 6. 实现 SharedPreferences 接口（无缝迁移）

MMKV 实现了 `SharedPreferences` 接口，可以无缝替换：

```kotlin
// MMKV 可以当 SharedPreferences 用
val sp: SharedPreferences = MMKV.defaultMMKV()

// 使用 SP 的 API 风格
sp.edit()
    .putString("key", "value")
    .putInt("count", 100)
    .apply()

val value = sp.getString("key", "")
val count = sp.getInt("count", 0)

// 也可以直接替换系统 SP
class MyPreferences {
    // 以前
    // private val sp = context.getSharedPreferences("config", Context.MODE_PRIVATE)
    
    // 现在
    private val sp: SharedPreferences = MMKV.mmkvWithID("config")
}
```

## 实际应用场景

### 场景一：用户登录状态管理

```kotlin
object UserManager {
    private val kv = MMKV.mmkvWithID("user_session")
    
    var isLoggedIn: Boolean
        get() = kv.decodeBool("is_logged_in", false)
        set(value) { kv.encode("is_logged_in", value) }
    
    var userId: String
        get() = kv.decodeString("user_id", "") ?: ""
        set(value) { kv.encode("user_id", value) }
    
    var token: String
        get() = kv.decodeString("token", "") ?: ""
        set(value) { kv.encode("token", value) }
    
    fun login(userId: String, token: String) {
        this.userId = userId
        this.token = token
        isLoggedIn = true
    }
    
    fun logout() {
        kv.clearAll()
    }
}

// 使用
UserManager.login("12345", "abc123")
if (UserManager.isLoggedIn) {
    // 已登录
}
```

### 场景二：App 配置管理

```kotlin
object AppConfig {
    private val kv = MMKV.mmkvWithID("app_config")
    
    // 主题模式
    var isDarkMode: Boolean
        get() = kv.decodeBool("dark_mode", false)
        set(value) { kv.encode("dark_mode", value) }
    
    // 语言设置
    var language: String
        get() = kv.decodeString("language", "auto") ?: "auto"
        set(value) { kv.encode("language", value) }
    
    // 是否首次启动
    var isFirstLaunch: Boolean
        get() = kv.decodeBool("first_launch", true)
        set(value) { kv.encode("first_launch", value) }
    
    // 上次打开时间
    var lastOpenTime: Long
        get() = kv.decodeLong("last_open_time", 0)
        set(value) { kv.encode("last_open_time", value) }
}
```

### 场景三：搜索历史记录

```kotlin
object SearchHistory {
    private val kv = MMKV.mmkvWithID("search_history")
    private const val KEY_HISTORY = "history_list"
    private const val MAX_SIZE = 20
    
    fun add(keyword: String) {
        val history = getAll().toMutableList()
        // 移除重复项
        history.remove(keyword)
        // 添加到开头
        history.add(0, keyword)
        // 限制数量
        if (history.size > MAX_SIZE) {
            history.removeLast()
        }
        // 保存（使用 StringSet）
        kv.encode(KEY_HISTORY, history.toSet())
    }
    
    fun getAll(): List<String> {
        return kv.decodeStringSet(KEY_HISTORY, emptySet())?.toList() ?: emptyList()
    }
    
    fun clear() {
        kv.removeValueForKey(KEY_HISTORY)
    }
}
```

### 场景四：缓存策略

```kotlin
class CacheManager(private val mmkvId: String) {
    private val kv = MMKV.mmkvWithID(mmkvId)
    
    // 带过期时间的缓存
    fun <T : Parcelable> put(key: String, value: T, expireMs: Long) {
        kv.encode(key, value)
        kv.encode("${key}_expire", System.currentTimeMillis() + expireMs)
    }
    
    inline fun <reified T : Parcelable> get(key: String): T? {
        val expireTime = kv.decodeLong("${key}_expire", 0)
        if (expireTime > 0 && System.currentTimeMillis() > expireTime) {
            // 已过期，删除缓存
            kv.removeValuesForKeys(arrayOf(key, "${key}_expire"))
            return null
        }
        return kv.decodeParcelable(key, T::class.java)
    }
    
    fun isExpired(key: String): Boolean {
        val expireTime = kv.decodeLong("${key}_expire", 0)
        return expireTime > 0 && System.currentTimeMillis() > expireTime
    }
}

// 使用
val cache = CacheManager("api_cache")
cache.put("user_info", userInfo, 60 * 60 * 1000)  // 缓存 1 小时
val cached = cache.get<UserInfo>("user_info")
```

## 常见问题与陷阱

### 1. 忘记初始化

```kotlin
// ❌ 错误：没有初始化就使用
class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        val kv = MMKV.defaultMMKV()  // 崩溃！
    }
}

// ✅ 正确：在 Application 中初始化
class MyApplication : Application() {
    override fun onCreate() {
        super.onCreate()
        MMKV.initialize(this)  // 先初始化
    }
}
```

### 2. 存储复杂对象的限制

```kotlin
// ❌ 错误：直接存储普通类
data class User(val name: String, val age: Int)  // 没有实现 Parcelable
kv.encode("user", user)  // 编译错误

// ✅ 正确：实现 Parcelable
@Parcelize
data class User(val name: String, val age: Int) : Parcelable
kv.encode("user", user)  // OK

// ✅ 替代方案：转成 JSON 字符串存储
val gson = Gson()
kv.encode("user", gson.toJson(user))
val user = gson.fromJson(kv.decodeString("user", ""), User::class.java)
```

### 3. 默认值的坑

```kotlin
// ⚠️ 注意：decodeString 可能返回 null
val value = kv.decodeString("key", "default")
// 如果 key 存在但值为空字符串，返回 ""
// 如果 key 不存在，返回 "default"
// 如果 key 存在但值为 null，返回 null（不是 default！）

// ✅ 安全写法
val value = kv.decodeString("key", "") ?: ""
```

### 4. 大数据存储

```kotlin
// ⚠️ 不建议存储超大数据
// MMKV 适合存储配置、状态等小数据
// 不适合存储图片、视频等大文件

// ❌ 不推荐
val bigData = ByteArray(10 * 1024 * 1024)  // 10MB
kv.encode("big_data", bigData)

// ✅ 大文件应该用文件存储
File(cacheDir, "big_file").writeBytes(bigData)
```

### 5. 线程安全

```kotlin
// ✅ MMKV 本身是线程安全的，可以在任意线程读写
// 但是复合操作需要自己加锁

// ❌ 非原子操作，可能有并发问题
val count = kv.decodeInt("count", 0)
kv.encode("count", count + 1)

// ✅ 复合操作加锁
synchronized(lockObj) {
    val count = kv.decodeInt("count", 0)
    kv.encode("count", count + 1)
}
```

### 写入性能测试

| 操作 | SharedPreferences | MMKV | 提升倍数 |
|-----|-------------------|------|---------|
| 单次写入 | 5-10ms | 0.01-0.05ms | 100-500x |
| 批量写入(1000次) | 5000ms+ | 50ms | 100x |

| 操作 | SharedPreferences | MMKV | 提升倍数 |

| 后续读取 | 相当 | 相当 | 1x |

```kotlin
fun benchmark() {
    val sp = getSharedPreferences("test", Context.MODE_PRIVATE)
    val kv = MMKV.mmkvWithID("test")
```

## 面试检验

### 基础概念题

**Q1：MMKV 是什么？为什么比 SharedPreferences 快？**

> **答案**：MMKV 是腾讯开源的高性能键值存储框架。比 SP 快的原因：
> 1. **mmap 内存映射**：文件直接映射到内存，读写无需系统调用
> 2. **增量更新**：只追加新数据，不全量重写文件
> 3. **ProtoBuf 编码**：二进制格式，比 XML 更紧凑、解析更快
> 4. **无锁设计**：内部使用 CAS 等无锁技术，并发性能好

**Q2：SharedPreferences 的 apply() 为什么会导致 ANR？**

> **答案**：`apply()` 虽然是异步写文件，但有个隐藏的同步点：
> 1. 每次 `apply()` 都会把任务加入 QueuedWork
> 2. Activity 在 `onPause()`、`onStop()` 等生命周期回调时，会调用 `QueuedWork.waitToFinish()`
> 3. 这个方法会**阻塞等待**所有 pending 的 apply 完成
> 4. 如果短时间内有大量 apply，主线程就会被阻塞，导致 ANR
> 
> MMKV 没有这个问题，因为它的写入是直接写到 mmap 映射的内存，系统会异步同步到磁盘，不会阻塞主线程。

**Q3：MMKV 适合存储什么类型的数据？**

> **答案**：MMKV 适合存储：
> - 配置项（主题、语言、开关等）
> - 用户状态（登录状态、Token 等）
> - 缓存数据（小型缓存、过期标记等）
> - 小型结构化数据（用户信息、设置等）
> 
> **不适合**：
> - 大文件（图片、视频）—— 用文件存储
> - 复杂关系数据 —— 用 SQLite/Room
> - 需要复杂查询的数据 —— 用数据库

**Q4：如何实现从 SharedPreferences 到 MMKV 的平滑迁移？**

> **答案**：MMKV 提供了迁移 API：
> ```kotlin
> val kv = MMKV.mmkvWithID("myID")
> val sp = getSharedPreferences("oldSP", Context.MODE_PRIVATE)
> kv.importFromSharedPreferences(sp)
> sp.edit().clear().apply()  // 清空旧数据
> ```
> 
> 也可以实现 SharedPreferences 接口实现无缝替换（详见进阶篇）。

**Q5：MMKV 的数据安全吗？如果 App 崩溃会丢数据吗？**

> **答案**：MMKV 的数据安全性有保障：
> 1. **mmap 保证**：写入内存后，操作系统会负责同步到磁盘，即使 App 崩溃也不会丢失
> 2. **CRC 校验**：每次写入都有校验，检测数据损坏
> 3. **文件锁**：多进程写入有文件锁保护，不会出现数据错乱
> 
> 但如果手机突然断电（不是正常关机），理论上有极小概率丢失最后一次写入。这是 mmap 机制的固有特性。
