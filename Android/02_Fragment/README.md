# Fragment 学习指南

## 概述

Fragment 是 Android 中**可复用的 UI 组件**，它有自己的生命周期，可以在 Activity 中动态添加、移除、替换。Fragment 的诞生解决了 Android 平板适配和界面模块化的问题。

> **一句话理解**：如果 Activity 是"房子"，Fragment 就是"房间"。一套房子可以有多个房间，房间可以重新装修（替换），也可以单独拿出来放到另一套房子里用。

## 为什么要深入理解 Fragment？

| 场景 | 不理解 Fragment | 深入理解 Fragment |
|-----|----------------|------------------|
| 界面复用 | 复制粘贴代码，维护噩梦 | 一个 Fragment 多处使用，代码清爽 |
| 平板适配 | 手机平板两套代码 | 同一套 Fragment 组合出不同布局 |
| 生命周期 | 各种崩溃、数据丢失 | 正确处理生命周期，稳定可靠 |
| 页面导航 | 自己造轮子，Bug 频出 | 配合 Navigation 组件，优雅导航 |
| 性能优化 | 懒加载不生效，卡顿 | 正确实现懒加载，丝滑体验 |

## 核心问题预览

### 基础篇必答题
1. Fragment 的生命周期有哪些？与 Activity 的对应关系是什么？
2. add、replace、hide、show 的区别是什么？
3. commit、commitAllowingStateLoss、commitNow 的区别是什么？

### 进阶篇必答题
1. Fragment 与 Activity 之间如何通信？有哪些方式？
2. ViewPager + Fragment 如何实现懒加载？
3. Fragment 的 setRetainInstance 有什么用？已废弃后如何替代？

### 源码篇必答题
1. Fragment 的生命周期是如何被分发的？
2. FragmentTransaction 的 commit 是同步还是异步？为什么？
3. Fragment 的状态是如何保存和恢复的？

## 相关技术

| 技术 | 关系 | 说明 |
|-----|------|------|
| Activity | 宿主容器 | Fragment 必须依附于 Activity 存在 |
| Lifecycle | 基础设施 | Fragment 也是 LifecycleOwner |
| ViewModel | 数据共享 | Activity 与 Fragment 共享 ViewModel |
| ViewPager2 | 常见搭配 | 实现左右滑动切换页面 |
| Navigation | 导航方案 | 官方推荐的单 Activity 多 Fragment 架构 |
