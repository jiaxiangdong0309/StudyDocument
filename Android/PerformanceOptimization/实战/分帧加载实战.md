# 分帧加载实战（IdleHandler）

## 前言

复杂首页可能有十几个模块，如果一次性全部渲染，耗时可能接近 100ms，远超 16.6ms 的帧时间，用户会感知到明显卡顿。

**分帧加载**的核心思想：把大任务拆成小任务，在主线程空闲时逐个执行，每帧都不超时，用户无感知。

本文档深入讲解 IdleHandler 的原理、使用方式、以及如何解决其「执行时机不可控」的致命问题。

## 二、IdleHandler 原理

### 2.1 Android 消息循环机制

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Android 消息循环机制                                       │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   主线程的 MessageQueue：                                                    │
│                                                                             │
│   ┌─────┐   ┌─────┐   ┌─────┐   ┌─────┐                                    │
│   │ Msg │ → │ Msg │ → │ Msg │ → │ Msg │ → ...                              │
│   │  1  │   │  2  │   │  3  │   │  4  │                                    │
│   └─────┘   └─────┘   └─────┘   └─────┘                                    │
│                                                                             │
│   Looper.loop() 的工作流程（伪代码）：                                        │
│                                                                             │
│   while (true) {                                                           │
│       Message msg = queue.next();  // 取下一条消息                          │
│                                                                             │
│       if (msg != null) {                                                   │
│           // 有消息，处理它                                                  │
│           msg.target.dispatchMessage(msg);                                 │
│       } else {                                                             │
│           // ✅ 队列为空！这时候会执行 IdleHandler                           │
│           // 这就是「主线程空闲」的时机                                       │
│           for (IdleHandler idler : mIdleHandlers) {                        │
│               boolean keep = idler.queueIdle();                            │
│               if (!keep) {                                                 │
│                   // 返回 false，移除这个 IdleHandler                       │
│                   mIdleHandlers.remove(idler);                             │
│               }                                                            │
│           }                                                                │
│       }                                                                    │
│   }                                                                        │
│                                                                             │
│   关键洞察：                                                                 │
│   - IdleHandler 在消息队列为空时执行                                         │
│   - 此时主线程没有其他事情要做，执行任务不会造成卡顿                           │
│   - 非常适合做「不紧急但需要在主线程执行」的任务                               │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 IdleHandler 基本用法

```kotlin
// 添加 IdleHandler
Looper.myQueue().addIdleHandler {
    // 这段代码会在主线程空闲时执行
    doSomething()
    
    // 返回值：
    // true  - 保留这个 IdleHandler，下次空闲继续执行
    // false - 移除这个 IdleHandler，只执行一次
    false
}

// 移除 IdleHandler（如果需要）
val idleHandler = MessageQueue.IdleHandler { false }
Looper.myQueue().addIdleHandler(idleHandler)
// 稍后移除
Looper.myQueue().removeIdleHandler(idleHandler)
```

### 2.3 IdleHandler 适用场景

| 场景 | 说明 | 示例 |
|-----|------|------|
| 延迟初始化 | 非首屏必须的初始化操作 | 预加载下一页数据 |
| 分帧加载 | 把大任务拆成小任务 | 首页多模块加载 |
| 预热 | 提前准备可能用到的资源 | WebView 预创建 |
| 埋点上报 | 非紧急的数据上报 | 页面曝光统计 |

## 三、IdleHandler 的致命问题

### 3.1 执行时机不可控

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    IdleHandler 执行时机不可控                                │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   场景：用户疯狂滑动列表                                                     │
│                                                                             │
│   消息队列状态：                                                             │
│   ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐                 │
│   │Touch│ │Touch│ │Touch│ │Scroll│ │Draw │ │Touch│ │Draw │ → 源源不断      │
│   │Event│ │Event│ │Event│ │Event │ │Frame│ │Event│ │Frame│                 │
│   └─────┘ └─────┘ └─────┘ └─────┘ └─────┘ └─────┘ └─────┘                 │
│                                                                             │
│   问题：消息队列永远不为空，IdleHandler 永远没机会执行！                       │
│                                                                             │
│   用户体验：                                                                 │
│   - 用户快速滑到底部                                                        │
│   - 底部模块还没加载（因为 IdleHandler 还没执行）                             │
│   - 用户看到空白！❌                                                        │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 解决方案：三重保障机制

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    分帧加载的三重保障机制                                     │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│                        ┌─────────────────────┐                              │
│                        │    模块需要加载      │                              │
│                        └──────────┬──────────┘                              │
│                                   │                                         │
│                                   ▼                                         │
│                    ┌──────────────────────────────┐                         │
│                    │  保障1: IdleHandler 空闲加载  │                         │
│                    │  （最理想，完全无感知）        │                         │
│                    └──────────────┬───────────────┘                         │
│                                   │                                         │
│                          IdleHandler 没执行？                                │
│                                   │                                         │
│                    ┌──────────────┴───────────────┐                         │
│                    ▼                              ▼                         │
│   ┌─────────────────────────────┐  ┌─────────────────────────────┐         │
│   │ 保障2: 滑动触发立即加载      │  │ 保障3: 超时兜底强制加载      │         │
│   │ （用户滑到位置，不能空白）   │  │ （等太久了，不能一直不加载） │         │
│   └─────────────────────────────┘  └─────────────────────────────┘         │
│                                                                             │
│   三重保障确保模块一定会被加载！                                              │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 四、完整实现

### 4.1 增强版分帧任务调度器

```kotlin
/**
 * 增强版分帧任务调度器
 * 
 * 三重保障：
 * 1. IdleHandler：主线程空闲时执行（最优）
 * 2. 滑动触发：用户滑到模块位置时立即执行（兜底）
 * 3. 超时机制：超过指定时间强制执行（最终兜底）
 */
class EnhancedDelayTaskDispatcher(
    private val defaultTimeout: Long = 3000L  // 默认 3 秒超时
) {
    
    // 待执行的任务，用 LinkedHashMap 保持插入顺序
    private val pendingTasks = LinkedHashMap<String, DelayTask>()
    
    // 已完成的任务
    private val completedTasks = mutableSetOf<String>()
    
    // 主线程 Handler
    private val mainHandler = Handler(Looper.getMainLooper())
    
    // 是否已启动 IdleHandler
    private var isIdleHandlerAdded = false
    
    // IdleHandler 实例
    private val idleHandler = MessageQueue.IdleHandler {
        executeNextTask()
        // 还有任务就继续监听
        synchronized(pendingTasks) {
            pendingTasks.isNotEmpty()
        }.also { hasMore ->
            if (!hasMore) isIdleHandlerAdded = false
        }
    }
    
    /**
     * 添加延迟任务
     * 
     * @param taskId 任务唯一标识（用于去重和手动触发）
     * @param priority 优先级，数值越小越先执行
     * @param timeout 超时时间，超过这个时间强制执行
     * @param runnable 任务内容
     */
    fun addTask(
        taskId: String,
        priority: Int = Priority.NORMAL,
        timeout: Long = defaultTimeout,
        runnable: () -> Unit
    ): DelayTask {
        // 如果任务已完成或已存在，跳过
        if (taskId in completedTasks) return DelayTask.COMPLETED
        
        synchronized(pendingTasks) {
            if (taskId in pendingTasks) {
                return pendingTasks[taskId]!!
            }
            
            val task = DelayTask(taskId, priority, timeout, runnable)
            pendingTasks[taskId] = task
            
            // 启动 IdleHandler（保障1）
            ensureIdleHandler()
            
            // 启动超时计时器（保障3）
            scheduleTimeout(task)
            
            return task
        }
    }
    
    /**
     * 立即执行指定任务（保障2：滑动触发时调用）
     * 
     * 场景：用户滑动到某个模块位置，但该模块还没加载
     * 此时不等 IdleHandler，直接执行
     */
    fun executeNow(taskId: String) {
        val task = synchronized(pendingTasks) {
            pendingTasks.remove(taskId)
        } ?: return
        
        // 取消超时计时器
        task.cancelTimeout()
        
        // 立即执行
        executeTask(task)
    }
    
    /**
     * 批量立即执行
     */
    fun executeNowIfPending(vararg taskIds: String) {
        taskIds.forEach { executeNow(it) }
    }
    
    /**
     * 检查任务是否已完成
     */
    fun isCompleted(taskId: String): Boolean {
        return taskId in completedTasks
    }
    
    /**
     * 取消所有任务（页面销毁时必须调用）
     */
    fun cancelAll() {
        synchronized(pendingTasks) {
            pendingTasks.values.forEach { it.cancelTimeout() }
            pendingTasks.clear()
        }
        
        if (isIdleHandlerAdded) {
            Looper.myQueue().removeIdleHandler(idleHandler)
            isIdleHandlerAdded = false
        }
    }
    
    // ========== 私有方法 ==========
    
    private fun ensureIdleHandler() {
        if (!isIdleHandlerAdded) {
            isIdleHandlerAdded = true
            Looper.myQueue().addIdleHandler(idleHandler)
        }
    }
    
    /**
     * 执行下一个任务（IdleHandler 调用）
     */
    private fun executeNextTask() {
        val task = synchronized(pendingTasks) {
            // 按优先级排序，取优先级最高的（数值最小）
            pendingTasks.values
                .minByOrNull { it.priority }
                ?.also { pendingTasks.remove(it.taskId) }
        } ?: return
        
        task.cancelTimeout()
        executeTask(task)
    }
    
    /**
     * 执行任务
     */
    private fun executeTask(task: DelayTask) {
        if (task.isCancelled) return
        
        val startTime = SystemClock.elapsedRealtime()
        
        try {
            task.runnable()
            completedTasks.add(task.taskId)
        } catch (e: Exception) {
            Log.e("DelayTask", "任务 ${task.taskId} 执行失败", e)
        }
        
        val cost = SystemClock.elapsedRealtime() - startTime
        if (cost > 16) {
            // 单个任务超过 16ms，警告（任务粒度需要拆小）
            Log.w("DelayTask", "任务 ${task.taskId} 耗时 ${cost}ms，建议拆分")
        }
    }
    
    /**
     * 调度超时执行（保障3）
     */
    private fun scheduleTimeout(task: DelayTask) {
        val timeoutRunnable = Runnable {
            // 超时了，从队列移除并强制执行
            val pendingTask = synchronized(pendingTasks) {
                pendingTasks.remove(task.taskId)
            }
            
            if (pendingTask != null && !pendingTask.isCancelled) {
                Log.w("DelayTask", "任务 ${task.taskId} 超时，强制执行")
                executeTask(pendingTask)
            }
        }
        
        task.timeoutRunnable = timeoutRunnable
        mainHandler.postDelayed(timeoutRunnable, task.timeout)
    }
    
    /**
     * 优先级常量
     */
    object Priority {
        const val CRITICAL = -1  // 最高优先级
        const val HIGH = 0       // 高优先级
        const val NORMAL = 5     // 普通优先级
        const val LOW = 10       // 低优先级
    }
    
    /**
     * 任务封装
     */
    class DelayTask(
        val taskId: String,
        val priority: Int,
        val timeout: Long,
        val runnable: () -> Unit
    ) {
        @Volatile
        var isCancelled = false
            private set
        
        var timeoutRunnable: Runnable? = null
        
        fun cancel() {
            isCancelled = true
            cancelTimeout()
        }
        
        fun cancelTimeout() {
            timeoutRunnable?.let {
                Handler(Looper.getMainLooper()).removeCallbacks(it)
            }
            timeoutRunnable = null
        }
        
        companion object {
            val COMPLETED = DelayTask("", 0, 0) {}
        }
    }
}
```

### 4.2 在首页中使用

```kotlin
/**
 * 首页：三重保障的分帧加载
 */
class HomeActivity : AppCompatActivity() {
    
    private val dispatcher = EnhancedDelayTaskDispatcher(
        defaultTimeout = 3000L  // 3秒超时
    )
    
    private lateinit var scrollView: NestedScrollView
    
    // 模块 ID 常量
    object Modules {
        const val BANNER = "banner"
        const val CATEGORY = "category"
        const val FLASH_SALE = "flash_sale"
        const val RECOMMEND = "recommend"
        const val AD = "ad"
    }
    
    // 记录各模块在页面中的 Y 坐标（实际项目可动态计算）
    private val modulePositions = mapOf(
        Modules.CATEGORY to 300,
        Modules.FLASH_SALE to 500,
        Modules.RECOMMEND to 800,
        Modules.AD to 1200
    )
    
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_home)
        
        scrollView = findViewById(R.id.scroll_view)
        
        // 第一步：立即加载首屏核心内容（不用 IdleHandler）
        loadBanner()
        
        // 第二步：添加分帧任务（保障1：IdleHandler）
        scheduleDelayTasks()
        
        // 第三步：监听滚动（保障2：滑动触发）
        setupScrollListener()
    }
    
    /**
     * 首屏核心内容，同步加载
     */
    private fun loadBanner() {
        findViewById<ViewStub>(R.id.stub_banner).inflate()
        bindBannerData()
    }
    
    /**
     * 添加分帧任务
     */
    private fun scheduleDelayTasks() {
        // 分类入口：高优先级，2秒超时
        dispatcher.addTask(
            taskId = Modules.CATEGORY,
            priority = EnhancedDelayTaskDispatcher.Priority.HIGH,
            timeout = 2000L
        ) {
            loadModule(Modules.CATEGORY)
        }
        
        // 秒杀模块：高优先级
        dispatcher.addTask(
            taskId = Modules.FLASH_SALE,
            priority = EnhancedDelayTaskDispatcher.Priority.HIGH,
            timeout = 2000L
        ) {
            loadModule(Modules.FLASH_SALE)
        }
        
        // 推荐列表：普通优先级，3秒超时
        dispatcher.addTask(
            taskId = Modules.RECOMMEND,
            priority = EnhancedDelayTaskDispatcher.Priority.NORMAL,
            timeout = 3000L
        ) {
            loadModule(Modules.RECOMMEND)
        }
        
        // 广告位：低优先级，5秒超时（不着急）
        dispatcher.addTask(
            taskId = Modules.AD,
            priority = EnhancedDelayTaskDispatcher.Priority.LOW,
            timeout = 5000L
        ) {
            loadModule(Modules.AD)
        }
    }
    
    /**
     * 监听滚动，提前加载即将可见的模块（保障2）
     * 
     * 关键：用户滑到哪里，就立即加载哪里，不等 IdleHandler
     */
    private fun setupScrollListener() {
        var lastScrollY = 0
        
        scrollView.setOnScrollChangeListener { _, _, scrollY, _, _ ->
            val screenHeight = scrollView.height
            // 提前 1.5 屏加载，给加载留出时间
            val preloadThreshold = (screenHeight * 1.5).toInt()
            
            lastScrollY = scrollY
            
            // 遍历所有模块，检查是否需要提前加载
            modulePositions.forEach { (moduleId, moduleTop) ->
                // 如果模块已加载，跳过
                if (dispatcher.isCompleted(moduleId)) return@forEach
                
                // 计算模块距离当前视口的距离
                val distanceToViewport = moduleTop - (scrollY + screenHeight)
                
                // 如果模块即将进入视口（或已在视口内）
                if (distanceToViewport < preloadThreshold) {
                    // 关键：立即执行，不等 IdleHandler！
                    dispatcher.executeNow(moduleId)
                    Log.d("HomeActivity", "滑动触发加载: $moduleId")
                }
            }
        }
    }
    
    /**
     * 加载模块
     */
    private fun loadModule(moduleId: String) {
        Log.d("HomeActivity", "加载模块: $moduleId")
        
        when (moduleId) {
            Modules.CATEGORY -> {
                findViewById<ViewStub>(R.id.stub_category).inflate()
                bindCategoryData()
            }
            Modules.FLASH_SALE -> {
                findViewById<ViewStub>(R.id.stub_flash_sale).inflate()
                bindFlashSaleData()
            }
            Modules.RECOMMEND -> {
                findViewById<ViewStub>(R.id.stub_recommend).inflate()
                bindRecommendData()
            }
            Modules.AD -> {
                findViewById<ViewStub>(R.id.stub_ad).inflate()
                bindAdData()
            }
        }
    }
    
    override fun onDestroy() {
        super.onDestroy()
        // 页面销毁时必须取消所有任务！
        // 否则：1. 内存泄漏  2. 访问已销毁的 View 导致崩溃
        dispatcher.cancelAll()
    }
    
    // ... 数据绑定方法省略
    private fun bindBannerData() { /* ... */ }
```

## 七、进阶：更智能的方案

### 7.1 基于 View 可见性自动触发

```kotlin
/**
 * 智能模块加载器：基于 View 可见性自动触发
 * 
 * 优点：不用手动维护模块位置，自动检测可见性
 */
class SmartModuleLoader(
    private val scrollView: NestedScrollView,
    private val dispatcher: EnhancedDelayTaskDispatcher
) {
    
    // 模块 ID 与 ViewStub 的映射
    private val moduleStubs = mutableMapOf<String, ViewStub>()
    
    // 已加载的模块
    private val loadedModules = mutableSetOf<String>()
    
    /**
     * 注册模块
     * 
     * @param moduleId 模块唯一标识
     * @param stub ViewStub
     * @param loader 加载逻辑（inflate 后的数据绑定）
     */
    fun registerModule(moduleId: String, stub: ViewStub, loader: () -> Unit) {
        moduleStubs[moduleId] = stub
        
        // 添加到分帧任务
        dispatcher.addTask(moduleId) {
            inflateAndLoad(moduleId, loader)
        }
    }
    
    /**
     * 开始监听滚动
     */
    fun startWatching() {
        // 监听滚动变化
        scrollView.viewTreeObserver.addOnScrollChangedListener {
            checkVisibility()
        }
        
        // 首次检查（可能有些模块一开始就可见）
        scrollView.post { checkVisibility() }
    }
    
    /**
     * 检查模块可见性
     */
    private fun checkVisibility() {
        val scrollBounds = Rect()
        scrollView.getHitRect(scrollBounds)
        
        // 扩大检测范围（提前一屏加载）
        scrollBounds.bottom += scrollView.height
        
        moduleStubs.forEach { (moduleId, stub) ->
            if (moduleId in loadedModules) return@forEach
            
            // 检查 ViewStub 是否在可见范围内
            val stubLocation = IntArray(2)
            stub.getLocationOnScreen(stubLocation)
            
            val stubRect = Rect(
                stubLocation[0],
                stubLocation[1],
                stubLocation[0] + stub.width,
                stubLocation[1] + (stub.layoutParams?.height ?: 0)
            )
            
            // 即将可见，立即加载
            if (Rect.intersects(scrollBounds, stubRect)) {
                dispatcher.executeNow(moduleId)
            }
        }
    }
    
    private fun inflateAndLoad(moduleId: String, loader: () -> Unit) {
        if (moduleId in loadedModules) return
        loadedModules.add(moduleId)
        
        moduleStubs[moduleId]?.inflate()
        loader()
    }
}
```

### 7.2 使用方式

```kotlin

    private lateinit var moduleLoader: SmartModuleLoader
    private val dispatcher = EnhancedDelayTaskDispatcher()
    
    override fun onCreate(savedInstanceState: Bundle?) {
```

## 八、注意事项

### 8.1 任务粒度要小

```kotlin
// ❌ 错误：一个大任务，超过 16ms
dispatcher.addTask("loadAllModules") {
    loadModule1()  // 10ms
    loadModule2()  // 10ms
    loadModule3()  // 10ms
    // 总共 30ms，会造成卡顿！
}

// ✅ 正确：拆分成多个小任务
dispatcher.addTask("module1") { loadModule1() }  // 10ms
dispatcher.addTask("module2") { loadModule2() }  // 10ms
dispatcher.addTask("module3") { loadModule3() }  // 10ms
// 每个任务都不超过 16ms
```

### 8.2 生命周期管理

```kotlin
// ❌ 错误：忘记取消任务
override fun onDestroy() {
    super.onDestroy()
    // 没有调用 dispatcher.cancelAll()
    // 后果：
    // 1. IdleHandler 持有 Activity 引用 → 内存泄漏
    // 2. 任务执行时访问已销毁的 View → 崩溃
}

// ✅ 正确：页面销毁时取消所有任务
override fun onDestroy() {
    super.onDestroy()
    dispatcher.cancelAll()  // 必须调用！
}
```

### 8.3 不要依赖执行顺序

```kotlin
// ❌ 错误：假设任务一定按顺序执行
dispatcher.addTask("task1") { 
    data = loadData()  // 假设这个先执行
}
dispatcher.addTask("task2") { 
    bindData(data)  // 假设这个后执行
}
// 问题：如果 task2 被滑动触发先执行，data 还是 null！

// ✅ 正确：任务之间不要有依赖
dispatcher.addTask("task1") { 
    val data = loadData()
    bindData(data)  // 数据加载和绑定在同一个任务里
}
```

### 8.4 何时用哪种触发方式

| 触发方式 | 触发时机 | 优点 | 缺点 |
|---------|---------|------|------|
| **IdleHandler** | 主线程空闲时 | 完全无感知 | 时机不可控 |
| **滑动触发** | 用户滑到附近 | 精准，按需加载 | 需要计算位置 |
| **超时兜底** | 超过指定时间 | 最终保障 | 可能造成轻微卡顿 |

**最佳实践**：三种方式组合使用，互为兜底。

## 九、面试回答模板

> **面试官**：首页模块很多，你们是怎么优化加载速度的？
>
> **回答**：
>
> 我们首页有 12 个模块，如果一次性全部渲染，耗时接近 100ms，用户感知明显卡顿。
>
> **解决方案：分帧加载 + 三重保障**
>
> 1. **任务拆分**：把首页模块按优先级分档
>    - P0：首屏核心（Banner）→ 同步执行
>    - P1：高优先级（分类入口）→ IdleHandler + 2秒超时
>    - P2：普通优先级（推荐列表）→ IdleHandler + 3秒超时
>    - P3：低优先级（底部广告）→ IdleHandler + 5秒超时
>
> 2. **三重保障机制**：
>    - 保障1：IdleHandler 空闲加载（最优）
>    - 保障2：滑动触发立即加载（用户滑到哪，哪里就加载）
>    - 保障3：超时强制加载（兜底）
>
> 3. **配合 ViewStub**：非首屏模块使用 ViewStub 延迟 inflate
>
> **为什么需要三重保障？**
> IdleHandler 的执行时机不可控，如果用户一直操作，消息队列一直有消息，IdleHandler 永远不会执行。所以需要滑动触发和超时机制作为兜底。
>
> **效果**：首屏渲染时间从 100ms 降到 35ms，且不会出现用户滑到某个位置看到空白的情况。
