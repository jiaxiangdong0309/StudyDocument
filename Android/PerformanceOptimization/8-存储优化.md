# 存储优化 (Storage Optimization)

## 为什么要做存储优化？

存储就像家里的柜子——东西放得乱、取得慢，用着就不舒服。存储优化影响 App 启动速度、页面加载速度和用户体验。

**存储问题的影响**：

| 问题 | 表现 |
|-----|------|
| 读写慢 | 数据加载慢、卡顿 |
| 占用大 | 用户存储空间不足 |
| 数据丢失 | 异常时数据损坏 |

## 一、Android 存储方式

### 1.1 存储方式对比

| 方式 | 特点 | 适用场景 |
|-----|------|---------|
| SharedPreferences | 轻量 KV 存储，XML 格式 | 少量配置数据 |
| MMKV | 高性能 KV 存储，mmap | 替代 SP，性能更好 |
| SQLite / Room | 关系型数据库 | 结构化数据、复杂查询 |
| 文件存储 | 原始文件读写 | 大文件、二进制数据 |
| DataStore | Jetpack 新组件，协程支持 | 替代 SP，更安全 |

### 1.2 存储位置

```
/data/data/com.example.app/           # 内部存储（App 私有）
├── shared_prefs/                     # SharedPreferences
├── databases/                        # SQLite 数据库
├── files/                            # 内部文件
└── cache/                            # 缓存文件

/storage/emulated/0/Android/data/com.example.app/  # 外部存储（App 私有）
├── files/
└── cache/
```

## 二、SharedPreferences 优化

### 2.1 SP 的问题

```kotlin
// SP 的性能问题：
// 1. 首次读取会加载整个 XML 到内存
// 2. 每次 commit() 都是全量写入
// 3. ANR 风险：主线程等待 SP 加载完成
```

### 2.2 SP 使用最佳实践

```kotlin
// ❌ 错误示例
class BadSpUsage {
    
    fun bad(context: Context) {
        // 每次都获取新的 SP 实例
        val prefs = context.getSharedPreferences("config", Context.MODE_PRIVATE)
        
        // 存储大量数据
        prefs.edit()
            .putString("big_data", hugeJsonString)  // ❌ 大数据不应该用 SP
            .commit()  // ❌ 同步提交，可能阻塞主线程
            
        // 频繁调用
        repeat(100) {
            prefs.edit().putInt("count", it).apply()  // ❌ 频繁写入
        }
    }
}

// ✅ 正确示例
class GoodSpUsage(context: Context) {
    
    // 单例持有 SP 实例
    private val prefs = context.getSharedPreferences("config", Context.MODE_PRIVATE)
    
    fun saveSettings(key: String, value: String) {
        prefs.edit()
            .putString(key, value)
            .apply()  // ✅ 异步提交
    }
    
    // 批量写入
    fun saveMultiple(data: Map<String, Any>) {
        prefs.edit().apply {
            data.forEach { (key, value) ->
                when (value) {
                    is String -> putString(key, value)
                    is Int -> putInt(key, value)
                    is Boolean -> putBoolean(key, value)
                }
            }
        }.apply()
    }
}
```

### 2.3 使用 MMKV 替代 SP

MMKV 是腾讯开源的高性能 KV 存储，使用 mmap 内存映射：

```kotlin
// 添加依赖
implementation 'com.tencent:mmkv:1.3.2'

// 初始化
MMKV.initialize(context)

// 使用
val kv = MMKV.defaultMMKV()

// 写入（立即生效，无需 apply/commit）
kv.encode("key_string", "value")
kv.encode("key_int", 123)
kv.encode("key_bool", true)

// 读取
val str = kv.decodeString("key_string", "default")
val num = kv.decodeInt("key_int", 0)
val bool = kv.decodeBool("key_bool", false)
```

**MMKV vs SP**：

| 特性 | SharedPreferences | MMKV |
|-----|------------------|------|
| 写入方式 | 全量写入 XML | 增量写入 |
| 读取方式 | 首次加载全部 | mmap 按需读取 |
| 性能 | 较慢 | 快 100 倍 |
| 多进程 | 不支持 | 支持 |
| 数据加密 | 不支持 | 支持 |

### 2.4 使用 DataStore

Jetpack DataStore 是 SP 的现代替代方案：

```kotlin
// 添加依赖
implementation "androidx.datastore:datastore-preferences:1.0.0"

// 创建 DataStore
val Context.dataStore by preferencesDataStore(name = "settings")

// 定义 Key
val COUNTER_KEY = intPreferencesKey("counter")
val NAME_KEY = stringPreferencesKey("name")

// 读取（Flow）
val counterFlow: Flow<Int> = context.dataStore.data
    .map { preferences ->
        preferences[COUNTER_KEY] ?: 0
    }

// 写入（挂起函数）
suspend fun incrementCounter() {
    context.dataStore.edit { preferences ->
        val currentValue = preferences[COUNTER_KEY] ?: 0
        preferences[COUNTER_KEY] = currentValue + 1
    }
}
```

**DataStore 优势**：
- 协程支持，避免主线程阻塞
- Flow 响应式数据
- 类型安全
- 数据一致性保证

## 三、数据库优化

### 3.1 使用 Room

```kotlin
// Entity
@Entity(tableName = "users")
data class User(
    @PrimaryKey val id: Int,
    @ColumnInfo(name = "name") val name: String,
    @ColumnInfo(name = "email") val email: String
)

// DAO
@Dao
interface UserDao {
    @Query("SELECT * FROM users")
    fun getAll(): Flow<List<User>>
    
    @Query("SELECT * FROM users WHERE id = :id")
    suspend fun getById(id: Int): User?
    
    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun insert(user: User)
    
    @Delete
    suspend fun delete(user: User)
}

// Database
@Database(entities = [User::class], version = 1)
abstract class AppDatabase : RoomDatabase() {
    abstract fun userDao(): UserDao
    
    companion object {
        @Volatile
        private var INSTANCE: AppDatabase? = null
        
        fun getInstance(context: Context): AppDatabase {
            return INSTANCE ?: synchronized(this) {
                Room.databaseBuilder(
                    context.applicationContext,
                    AppDatabase::class.java,
                    "app_database"
                ).build().also { INSTANCE = it }
            }
        }
    }
}
```

### 3.2 数据库查询优化

#### 避免在循环中查询

### 3.3 事务优化

```kotlin

interface UserDao {
    
    @Insert
    suspend fun insertAll(users: List<User>)
    
    @Transaction
    suspend fun replaceAll(users: List<User>) {
        deleteAll()
        insertAll(users)
    }

    suspend fun deleteAll()
}
```

## 四、文件存储优化

### 4.1 异步 IO

```kotlin
// ❌ 主线程 IO
fun bad() {
    val content = File("path").readText()  // 阻塞主线程
}

// ✅ 异步 IO
suspend fun good() = withContext(Dispatchers.IO) {
    File("path").readText()
}
```

### 4.2 缓冲 IO

```kotlin
// ❌ 无缓冲，频繁系统调用
fun badWrite(data: ByteArray) {
    FileOutputStream("path").use { fos ->
        data.forEach { byte ->
            fos.write(byte.toInt())  // 每个字节一次系统调用
        }
    }
}

// ✅ 使用缓冲
fun goodWrite(data: ByteArray) {
    BufferedOutputStream(FileOutputStream("path")).use { bos ->
        bos.write(data)  // 缓冲后批量写入
    }
}
```

### 4.3 mmap 内存映射

```kotlin
// 大文件使用 mmap
fun readLargeFile(file: File): MappedByteBuffer {
    FileInputStream(file).channel.use { channel ->
        return channel.map(
            FileChannel.MapMode.READ_ONLY,
            0,
            channel.size()
        )
    }
}
```

### 4.4 清理缓存

```kotlin
// 定期清理过期缓存
fun cleanCache(cacheDir: File, maxAge: Long) {
    val threshold = System.currentTimeMillis() - maxAge
    
    cacheDir.listFiles()?.forEach { file ->
        if (file.lastModified() < threshold) {
            file.delete()
        }
    }
}

// 限制缓存大小
fun trimCache(cacheDir: File, maxSize: Long) {
    val files = cacheDir.listFiles()?.sortedBy { it.lastModified() } ?: return
    
    var totalSize = files.sumOf { it.length() }
    
    for (file in files) {
        if (totalSize <= maxSize) break
        totalSize -= file.length()
        file.delete()
    }
}
```

## 五、序列化优化

### 5.1 选择合适的序列化方式

| 方式 | 速度 | 大小 | 可读性 | 适用场景 |
|-----|------|------|-------|---------|
| JSON | 中 | 大 | 好 | API 通信、配置文件 |
| Protobuf | 快 | 小 | 差 | 高性能场景、存储 |
| Parcelable | 快 | - | - | Android IPC |
| Serializable | 慢 | 大 | - | 简单场景 |

### 5.2 Parcelable vs Serializable

```kotlin
// ❌ Serializable 较慢
data class BadUser(
    val id: Int,
    val name: String
) : Serializable

// ✅ Parcelable 更快
@Parcelize
data class GoodUser(
    val id: Int,
    val name: String
) : Parcelable
```

### 5.3 使用 kotlinx.serialization

```kotlin
// 添加依赖
plugins {

implementation "org.jetbrains.kotlinx:kotlinx-serialization-json:1.6.2"
```

## 七、面试题精选

### Q1：SharedPreferences 有什么性能问题？

**答**：
1. **全量读取**：首次访问会加载整个 XML 到内存
2. **全量写入**：每次 commit 都重写整个文件
3. **ANR 风险**：主线程会等待 SP 初始化完成
4. **不支持多进程**：多进程访问可能数据不一致

**解决方案**：使用 MMKV 或 DataStore。

### Q2：MMKV 为什么比 SP 快？

**答**：
1. **mmap**：使用内存映射文件，减少数据拷贝
2. **增量写入**：只写入修改的数据，不是全量重写
3. **Protobuf**：使用 Protobuf 编码，更紧凑
4. **无锁设计**：读操作无锁，写操作使用文件锁

### Q3：数据库查询如何优化？

**答**：
1. **添加索引**：为经常查询的字段添加索引
2. **只查需要的字段**：避免 SELECT *
3. **分页查询**：使用 LIMIT 分页
4. **避免 N+1 查询**：使用 JOIN 替代循环查询
5. **使用事务**：批量操作放在事务中
6. **WAL 模式**：提升并发性能

### Q4：如何避免主线程 IO？

**答**：
1. 使用协程 `withContext(Dispatchers.IO)`
2. 使用 RxJava `subscribeOn(Schedulers.io())`
3. 使用 WorkManager 处理后台任务
4. Room 的 suspend 函数自动切换线程

### Q5：DataStore 相比 SP 有什么优势？

**答**：
1. **协程支持**：异步 API，不会阻塞主线程
2. **Flow**：响应式数据流
3. **类型安全**：编译期检查
4. **数据一致性**：事务性更新
5. **错误处理**：通过 Flow 传递异常
