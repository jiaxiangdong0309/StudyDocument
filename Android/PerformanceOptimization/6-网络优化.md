# 网络优化 (Network Optimization)

## 为什么要做网络优化？

网络就像高速公路——堵车时再快的车也跑不起来。弱网环境、请求过多、数据过大都会影响用户体验。

**网络问题的影响**：

| 问题 | 用户感知 |
|-----|---------|
| 请求慢 | 加载时间长、白屏 |
| 请求失败 | 功能不可用、数据丢失 |
| 流量大 | 消耗用户流量、费用 |

## 一、网络基础

### 1.1 HTTP 请求流程

```
┌─────────────────────────────────────────────────────────────────┐
│                      HTTP 请求完整流程                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│   DNS 解析  →  TCP 握手  →  TLS 握手  →  发送请求  →  接收响应     │
│   (查 IP)     (建连接)    (加密协商)   (上行)      (下行)         │
│                                                                 │
│   ┌─────┐    ┌─────┐    ┌─────┐    ┌─────┐    ┌─────┐          │
│   │50ms │    │50ms │    │100ms│    │50ms │    │100ms│          │
│   └─────┘    └─────┘    └─────┘    └─────┘    └─────┘          │
│                                                                 │
│   总耗时 = DNS + TCP + TLS + 请求 + 响应 ≈ 350ms（理想情况）       │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 影响网络性能的因素

| 因素 | 说明 | 优化方向 |
|-----|------|---------|
| RTT（往返时延） | 客户端到服务器的往返时间 | 减少握手次数、CDN |
| 带宽 | 网络传输速度 | 压缩数据、减少传输量 |
| 丢包率 | 数据包丢失比例 | 重试策略、协议优化 |
| 连接复用 | 同一连接发送多个请求 | 连接池、HTTP/2 |

```kotlin
class Repository {
    
    private val memoryCache = LruCache<String, Data>(100)
    private val diskCache = DiskLruCache(...)
    
    suspend fun getData(id: String): Data {
        // 1. 先查内存缓存
        memoryCache.get(id)?.let { return it }
        
        // 2. 再查磁盘缓存
        diskCache.get(id)?.let { data ->
            memoryCache.put(id, data)
            return data
        }
        
        // 3. 最后请求网络
        val data = api.getData(id)
        memoryCache.put(id, data)
        diskCache.put(id, data)
        return data
    }
}
```

### 5.3 DNS 优化

```kotlin
// 自定义 DNS 解析
val client = OkHttpClient.Builder()
    .dns(object : Dns {
        override fun lookup(hostname: String): List<InetAddress> {
            // 1. 先查本地缓存
            dnsCache.get(hostname)?.let { return it }
            
            // 2. 使用 HTTPDNS
            val ip = httpDns.resolve(hostname)
            if (ip != null) {
                val addresses = listOf(InetAddress.getByName(ip))
                dnsCache.put(hostname, addresses)
                return addresses
            }
            
            // 3. 降级到系统 DNS
            return Dns.SYSTEM.lookup(hostname)
        }
    })
    .build()
```

**HTTPDNS 优势**：
- 避免 DNS 劫持
- 更快的解析速度
- 更精准的调度

### 6.2 重试策略

```kotlin
// 使用 OkHttp 拦截器实现重试
class RetryInterceptor(private val maxRetries: Int = 3) : Interceptor {
    
    override fun intercept(chain: Interceptor.Chain): Response {
        var request = chain.request()
        var response: Response? = null
        var exception: IOException? = null
        
        repeat(maxRetries) { attempt ->
            try {
                response = chain.proceed(request)
                if (response?.isSuccessful == true) {
                    return response!!
                }
            } catch (e: IOException) {
                exception = e
            }
            
            // 指数退避
            val delay = (2.0.pow(attempt) * 1000).toLong()
            Thread.sleep(delay)
        }
        
        throw exception ?: IOException("Max retries exceeded")
    }
}
```

### 6.3 请求优先级

```kotlin
// 区分请求优先级
enum class Priority { HIGH, NORMAL, LOW }

class PriorityDispatcher {
    
    private val highQueue = ConcurrentLinkedQueue<Request>()
    private val normalQueue = ConcurrentLinkedQueue<Request>()
    private val lowQueue = ConcurrentLinkedQueue<Request>()
    
    fun enqueue(request: Request, priority: Priority) {
        when (priority) {
            Priority.HIGH -> highQueue.add(request)
            Priority.NORMAL -> normalQueue.add(request)
            Priority.LOW -> lowQueue.add(request)
        }
    }
    
    fun getNext(): Request? {
        return highQueue.poll() 
            ?: normalQueue.poll() 
            ?: lowQueue.poll()
    }
}
```

### 6.4 弱网检测

```kotlin
// 检测网络质量
class NetworkQualityMonitor {
    
    fun getNetworkQuality(): NetworkQuality {
        val connectivityManager = context.getSystemService<ConnectivityManager>()
        val network = connectivityManager?.activeNetwork
        val capabilities = connectivityManager?.getNetworkCapabilities(network)
        
        val downBandwidth = capabilities?.linkDownstreamBandwidthKbps ?: 0
        
        return when {
            downBandwidth > 10000 -> NetworkQuality.EXCELLENT
            downBandwidth > 2000 -> NetworkQuality.GOOD
            downBandwidth > 500 -> NetworkQuality.MODERATE
            else -> NetworkQuality.POOR
        }
    }
}
```

## 八、监控与诊断

### 8.1 网络监控

```kotlin
// 使用 OkHttp EventListener 监控请求
class NetworkEventListener : EventListener() {
    
    private var startTime = 0L
    
    override fun callStart(call: Call) {
        startTime = System.currentTimeMillis()
    }
    
    override fun callEnd(call: Call) {
        val duration = System.currentTimeMillis() - startTime
        // 上报请求耗时
        Analytics.report("network_request", mapOf(
            "url" to call.request().url.toString(),
            "duration" to duration
        ))
    }
    
    override fun callFailed(call: Call, ioe: IOException) {
        // 上报请求失败
        Analytics.report("network_error", mapOf(
            "url" to call.request().url.toString(),
            "error" to ioe.message
        ))
    }
}
```

## 九、面试题精选

### Q1：网络优化有哪些方法？

**答**：

**减少请求次数**：
- 请求合并
- 接口聚合
- 预加载

**减少数据量**：
- Gzip 压缩
- 精简响应数据
- 使用 Protobuf

**缓存策略**：
- HTTP 缓存
- 业务缓存（内存 + 磁盘）
- 增量更新

**连接优化**：
- 连接复用
- HTTP/2
- HTTPDNS

### Q2：如何处理弱网环境？

**答**：
1. **合理的超时设置**：不要太短导致频繁失败
2. **重试机制**：指数退避重试
3. **请求优先级**：重要请求优先
4. **降级策略**：加载低质量图片、显示缓存数据
5. **网络检测**：检测网络质量，调整策略

### Q3：HTTP/1.1 和 HTTP/2 的区别？

**答**：

| 特性 | HTTP/1.1 | HTTP/2 |
|-----|---------|--------|
| 连接复用 | 有限（6个并发） | 多路复用 |
| 头部压缩 | 无 | HPACK |
| 服务端推送 | 无 | 支持 |
| 二进制协议 | 否（文本） | 是 |
| 队头阻塞 | 有 | 连接级别无 |

### Q4：HTTPS 为什么比 HTTP 慢？如何优化？

**答**：HTTPS 多了 TLS 握手，增加 1-2 个 RTT。

**优化方法**：
1. **TLS 1.3**：减少握手次数
2. **Session 复用**：跳过完整握手
3. **OCSP Stapling**：优化证书验证
4. **证书优化**：使用 ECC 证书

### Q5：如何设计一个高效的缓存策略？

**答**：
1. **分层缓存**：内存 → 磁盘 → 网络
2. **缓存更新**：设置合理的过期时间，支持增量更新
3. **缓存淘汰**：使用 LRU 算法
4. **缓存预热**：启动时预加载常用数据
5. **缓存降级**：网络失败时返回过期缓存
