# Kotlin 语法基础篇（Kotlin Syntax Fundamentals）

## Kotlin 语法到底在解决什么问题？

### 历史背景

Kotlin 出现前，Android 开发里最让人头疼的不是“不会写业务”，而是这些老问题：

1. 一堆样板代码，真正的业务逻辑只有几行。
2. `NullPointerException` 像地雷，线上一踩一个准。
3. Java 的“静态工具类 + 匿名内部类 + Getter/Setter”写久了，很啰嗦。
4. 想表达“把一段逻辑当参数传来传去”，成本偏高。

Kotlin 的思路不是推翻 JVM，而是做三件事：

- **把高频正确写法变短**。
- **把高频错误写法变难**。
- **把语言表达能力提到足够支撑现代 Android 架构**。

### 通俗理解

Java 像手动挡汽车，稳定、扎实，但很多动作都得你自己踩。

Kotlin 更像自动挡：

- 常见操作它帮你省掉。
- 危险动作它提前提醒你。
- 但底层还是同一套发动机，最终都跑在 JVM 上。

## Kotlin 语法地图

先建立整体地图，后面再逐个拆：

| 类别 | 代表语法 | 核心价值 |
|-----|---------|---------|
| 变量 | `val`、`var` | 先约束可变性，减少副作用 |
| 类型系统 | `String`、`Int`、`?` | 把空安全放进语言层 |
| 函数 | 默认参数、命名参数、单表达式函数 | 少写重载和样板 |
| 条件表达式 | `if`、`when` | 条件也能直接返回值 |
| 类与对象 | `class`、`data class`、`object` | 减少模板代码 |
| 空安全 | `?.`、`?:`、`!!`、`let` | 降低空指针风险 |
| 集合操作 | `map`、`filter`、`associate` | 更自然的数据处理 |
| 高阶能力 | lambda、扩展函数、委托 | 支撑 DSL 和现代架构 |

## 变量：`val` 和 `var`

### 定义

- `val`：引用不可重新赋值。
- `var`：引用可以重新赋值。

```kotlin
val name = "Alice"
var age = 18

// age 可以改
age = 19

// name 不能再指向新的对象
// name = "Bob" // 编译报错
```

### 为什么 Kotlin 要先区分“可变”和“不可变”？

因为很多 bug，本质上不是“代码不会跑”，而是**状态被谁改了、什么时候改的、在哪改的说不清**。

`val` 的设计哲学是：

- 默认假设你的值不该乱改。
- 真要改，再显式写 `var`。

这跟 Java 最大的差别不是语法，而是**默认立场**。

### `val` 是不是绝对不可变？

不是。`val` 只保证**引用不变**，不保证**对象内部状态不变**。

```kotlin
val users = mutableListOf("A", "B")
users.add("C") // 合法，因为变的是集合内部内容

// users = mutableListOf("X") // 非法，因为这是重新赋值
```

一句话记忆：

- `val` 管的是“门牌号不能换”
- 不一定管“屋子里家具能不能动”

### 最优写法建议

1. **默认先写 `val`，只有确实需要重赋值时才改成 `var`。**
2. 如果既想引用不变，也想内容尽量不变，优先选只读接口：

```kotlin
val users: List<String> = listOf("A", "B")
```

3. ViewModel / UseCase / Repository 里的状态流转，优先“外部只读，内部可写”：

```kotlin
private val _state = MutableStateFlow(UiState())
val state: StateFlow<UiState> = _state
```

## Kotlin 为什么没有真正的 `static`？

Kotlin 故意不把“静态成员”当一等语法主角，而是用更清晰的对象模型替代。

### 1. `object`：单例对象

```kotlin
object LogUtil {
    fun d(msg: String) {
        println(msg)
    }
}
```

适合：

- 工具类
- 单例管理器
- 无状态公共能力

### 2. `companion object`：类的伴生对象

```kotlin
class User private constructor(val name: String) {
    companion object {
        fun create(name: String): User {
            return User(name.trim())
        }
    }
}

val user = User.create("Alice")
```

适合：

- 工厂方法
- 常量
- 和类强相关、但不依赖实例的方法

### 3. `const val`：编译期常量

```kotlin
object ApiConfig {
    const val BASE_URL = "https://api.example.com"
}
```

只有 `String` 和基本类型才能用 `const val`，而且必须在顶层、`object` 或 `companion object` 中。

### 为什么 Kotlin 要这么设计？

因为 Java 的 `static` 很方便，但也容易让代码一路滑向：

- 全局状态过多
- 工具类膨胀
- 面向对象外壳下，实际全是过程式调用

Kotlin 的思路是：

- 你想做全局能力，可以，但请显式用 `object`
- 你想表达“跟类绑定”，就用 `companion object`

也就是说，它想让“静态”这件事更有语义，而不是到处乱飞。

## 类型推导与显式类型

Kotlin 支持类型推导：

```kotlin
val count = 3
val title = "Kotlin"
```

也支持显式声明：

```kotlin
val count: Int = 3
val title: String = "Kotlin"
```

### 什么时候该显式写类型？

推荐显式类型的场景：

1. 对外暴露的 API。
2. 属性初始化不够直观时。
3. 泛型过深、推导结果不明显时。

```kotlin
val userCache: MutableMap<String, List<User>> = mutableMapOf()
```

原因很简单：**内部局部变量可以靠上下文理解，对外接口不能靠猜。**

## 函数：Kotlin 为什么爱“少写重载”？

### 默认参数

```kotlin
fun showToast(message: String, duration: Int = 2) {
    println("$message, duration = $duration")
}

showToast("保存成功")
showToast("保存成功", duration = 5)
```

### 命名参数

```kotlin
fun createUser(name: String, age: Int, vip: Boolean) {}

createUser(name = "Alice", age = 18, vip = true)
```

### 单表达式函数

```kotlin
fun isAdult(age: Int): Boolean = age >= 18
```

### 为什么这样设计？

因为 Java 里很多重载，本质上只是为了补默认值：

```java
showToast("保存成功");
showToast("保存成功", 2);
showToast("保存成功", 2, true);
```

Kotlin 直接从语言层解决这个问题，目的就是：

- 少写一堆重载
- 调用点更可读
- 参数顺序不容易写错

## 条件表达式：`if` 和 `when`

Kotlin 把条件判断做成了**表达式**，也就是它本身可以直接返回值。

```kotlin
val score = 80
val level = if (score >= 60) "及格" else "不及格"
```

`when` 是更强的分支表达式：

```kotlin
fun describeStatus(code: Int): String = when (code) {
    200 -> "成功"
    401 -> "未登录"
    404 -> "未找到"
    else -> "未知状态"
}
```

### 为什么 `when` 比 `switch` 更强？

因为它不只支持常量比较，还支持：

- 范围匹配
- 类型判断
- 条件表达式

```kotlin
fun parse(value: Any): String = when (value) {
    is Int -> if (value in 1..10) "1 到 10 之间的整数" else "整数"
    is String -> "字符串"
    else -> "其他"
}
```

## 空安全：Kotlin 的核心卖点

### 可空与不可空

```kotlin
val name: String = "Alice"
val nickname: String? = null
```

`String` 不能放 `null`，`String?` 才能。

### 常用语法

```kotlin
val length = nickname?.length ?: 0
```

这里同时用到了：

- `?.`：安全调用
- `?:`：空值兜底

### `!!` 为什么不推荐？

```kotlin
val length = nickname!!.length
```

`!!` 的意思其实是：

> “编译器你别管，我赌它现在一定不为空。”

赌输了就直接崩。

### 最优写法建议

1. 优先用 `?.` 和 `?:`。
2. 需要判空后继续操作时，用 `let`。
3. 除非你对生命周期和数据来源 100% 确认，否则少用 `!!`。

## 类：`data class`、主构造、属性声明

### 基本类

```kotlin
class User(
    val id: Long,
    var name: String
)
```

### `data class`

```kotlin
data class UserUiModel(
    val id: Long,
    val name: String,
    val avatar: String
)
```

`data class` 会帮你生成常用能力：

- `equals()`
- `hashCode()`
- `toString()`
- `copy()`
- `componentN()`

### 为什么 `data class` 这么受欢迎？

因为 UI 状态、接口模型、数据库实体，很多场景本质上就是“数据容器”，没必要手搓模板代码。

## 集合与常见遍历写法

```kotlin
val users = listOf("Alice", "Bob", "Cindy")

val result = users
    .filter { it.startsWith("A") }
    .map { it.uppercase() }
```

### 为什么 Kotlin 集合写法更流畅？

因为它把“操作数据”看得比“控制循环”更重要。

Java 往往在写：

- 先定义结果集合
- 再 `for`
- 再 `if`
- 再 `add`

Kotlin 直接让你表达“我要什么结果”，而不是“我要怎么一步步搬箱子”。

## 基础篇最该记住的最优写法

### 1. 默认 `val`，必要时才 `var`

```kotlin
val user = repository.getUser()
```

### 2. 默认参数替代重复重载

```kotlin
fun loadPage(page: Int = 1, pageSize: Int = 20) {}
```

### 3. 顶层函数或 `object` 替代臃肿工具类

```kotlin
fun String.toMd5(): String = TODO()
```

### 4. `data class` 管数据，普通 `class` 管行为

```kotlin
data class Article(val id: Long, val title: String)
```

### 5. 先用空安全语法，不要先写 `!!`

```kotlin
val title = article?.title ?: "默认标题"
```

## 基础篇常见误区

| 误区 | 正确认识 |
|-----|---------|
| `val` 就是绝对不可变 | 它只保证引用不重新赋值 |
| Kotlin 没有静态能力 | 有，只是换成了 `object` / `companion object` |
| `!!` 很方便 | 方便，但风险最大 |
| 类型推导越多越高级 | 可读性比“省几个字”更重要 |
| `data class` 什么都能用 | 更适合纯数据，不适合承载复杂业务行为 |

## 面试题

### 1. `val` 和 `var` 有什么区别？

**结论**：`val` 不能重新赋值，`var` 可以。

**原理**：Kotlin 把可变性前置到语法层，默认鼓励不可变引用，减少状态漂移和副作用。

**例子**：`val list = mutableListOf(1)` 仍然能 `add`，因为没改引用，只改了对象内容。

### 2. Kotlin 为什么没有 `static`？

**结论**：不是不能做静态，而是用 `object`、`companion object` 这些语义更清晰的方式替代。

**原理**：Kotlin 想减少无意义的全局状态和工具类堆积，让“全局能力”“类级能力”“实例能力”有更明确边界。

**例子**：工具单例适合 `object`，工厂方法适合 `companion object`。

### 3. 为什么 Kotlin 要把空安全做到语言层？

**结论**：为了在编译期尽量挡住空指针，而不是等线上崩。

**原理**：类型系统区分可空与不可空，编译器会强制你在使用 `String?` 前先处理空值。

**例子**：`name.length` 可以直接用，`nickname.length` 不行，必须 `nickname?.length`。

### 4. 默认参数相比 Java 重载好在哪里？

**结论**：更少样板代码，调用点更清晰。

**原理**：默认值和命名参数让很多“只是参数个数不同”的重载没有存在必要。

**例子**：`showToast(message = "成功", duration = 2)` 比维护 3 个重载更直观。
