# Kotlin 语法进阶篇（Kotlin Syntax Advanced）

## 为什么 Kotlin 真正的威力在“进阶语法”？

基础语法让你“能写 Kotlin”，但进阶语法才决定你写出来的是：

- 只是 Java 的翻译版
- 还是 Kotlin 风格、可维护、可扩展、可优化的代码

Kotlin 最有辨识度的地方主要集中在三块：

1. **高阶函数与 lambda**：函数可以像数据一样传递。
2. **作用域函数**：让对象初始化、判空、链式处理更自然。
3. **扩展、委托、密封类**：把“表达业务意图”这件事变得更顺手。

## 高阶函数（Higher-Order Function）

## 什么是高阶函数？

满足任一条件就是高阶函数：

1. 函数参数里接收另一个函数。
2. 函数返回值是另一个函数。

```kotlin
fun <T> List<T>.forEachAction(action: (T) -> Unit) {
    for (item in this) action(item)
}
```

这里的 `action` 就是函数类型参数，所以 `forEachAction` 是高阶函数。

### 通俗理解

普通函数像“自己把活干完的员工”。

高阶函数像“项目经理”:

- 它不一定亲自干活
- 它负责把“规则”或“动作”当参数接进来，再安排执行

### 为什么 Kotlin 这么重视高阶函数？

因为很多重复代码，本质上只是“流程一样，具体动作不一样”。

比如列表遍历：

```kotlin
val users = listOf("A", "B", "C")
users.forEach { println(it) }
```

底层遍历流程是固定的，变化的只有“对每个元素做什么”。高阶函数正好把这部分变化抽出来。

## Lambda 表达式

### 基本写法

```kotlin
val add: (Int, Int) -> Int = { a, b -> a + b }
```

### 常见简化

```kotlin
users.filter { it.length > 1 }
```

这里的 `it` 是**单参数 lambda 的默认参数名**。

### 为什么是 `it`？

因为单参数 lambda 很常见，如果每次都手写参数名会很啰嗦。于是 Kotlin 给了一个默认名字 `it`，意思接近“这个东西”。

但注意：

- `it` 适合短 lambda
- 一旦逻辑变复杂，最好自己起名字

```kotlin
users.map { userName -> userName.uppercase() }
```

最优实践：

- 短小表达式用 `it`
- 嵌套 lambda、业务含义强时，不要硬用 `it`

## 作用域函数总览

Kotlin 最常见的五个作用域函数：

| 函数 | 上下文对象名字 | 返回值 | 典型用途 |
|-----|---------------|-------|---------|
| `let` | `it` | lambda 最后一行 | 判空后转换、临时作用域 |
| `run` | `this` | lambda 最后一行 | 对象配置后直接产出结果 |
| `with` | `this` | lambda 最后一行 | 对一个对象集中操作 |
| `apply` | `this` | 对象本身 | 初始化、链式配置 |
| `also` | `it` | 对象本身 | 附加日志、校验、埋点 |

## 为什么 `apply` 里是 `this`，`let` 里是 `it`？

这是 Kotlin 设计里非常重要的一组语义区分。

### 1. `apply` 的目标是“配置对象本身”

```kotlin
val paint = Paint().apply {
    color = Color.RED
    textSize = 16f
}
```

这里的重点是：

- 你就在操作“当前对象自己”
- 大多数场景是连续设置属性或调用成员函数

所以用 `this` 最自然，甚至可以省略 `this`，让代码像“在对象内部写初始化逻辑”。

如果 `apply` 也用 `it`，心智模型就会更接近下面这种伪代码：

```text
it.color = Color.RED
it.textSize = 16f
```

这反而啰嗦，因为 `apply` 本来就是“进到对象里面配它自己”。

### 2. `let` 的目标是“把对象当参数传进去做一次处理”

```kotlin
val name: String? = " Alice "
val length = name?.let {
    it.trim().length
} ?: 0
```

这里的重点不是“配置 name 自己”，而是：

- 把它作为一个普通参数拿来用
- 做转换
- 产出另一个结果

所以 `it` 更贴切，语义是“把这个值交给你处理一下”。

### 一句话记忆

- `this` 风格：你正站在对象内部操作它。
- `it` 风格：你把对象当外部参数拿来使用。

## 五个作用域函数怎么选？

## 1. `let`

### 适合场景

- 判空后继续处理
- 把 A 转成 B
- 控制变量作用域

```kotlin
val avatarUrl = user?.avatar?.let { url ->
    cdnHost + url
}
```

### 不推荐场景

- 只是为了“显得 Kotlin”
- 连续嵌套多个 `let`

## 2. `apply`

### 适合场景

- 创建对象后立刻配置
- Builder 风格初始化

```kotlin
val dialog = AlertDialog.Builder(context).apply {
    setTitle("提示")
    setMessage("确定删除吗？")
}.create()
```

### 为什么返回对象本身？

因为它的核心任务不是“计算新结果”，而是“把对象配好再还给你继续链式调用”。

## 3. `also`

### 适合场景

- 做附加动作但不打断主链路
- 日志、埋点、调试

```kotlin
repository.getUser()
    .also { println("请求到了用户: $it") }
```

### 为什么 `also` 返回对象本身？

因为它像流水线旁边插一个观察员：

- 看一下
- 记一下
- 但不改主流程结果

## 4. `run`

### 适合场景

- 对对象做一段操作后产出结果

```kotlin
val text = user.run {
    "$name - $age"
}
```

## 5. `with`

### 适合场景

- 对已有对象集中调用多个成员

```kotlin
with(binding) {
    title.text = "Kotlin"
    desc.text = "作用域函数"
}
```

### 为什么现在很多人更常用 `run` / `apply`，少用 `with`？

因为 `with` 不是扩展函数，链式组合能力不如 `run` / `apply` 自然。

## 扩展函数（Extension Function）

### 基本写法

```kotlin
fun String.hidePhone(): String {
    return replaceRange(3, 7, "****")
}
```

### 为什么 Kotlin 需要扩展函数？

因为很多场景你只是想：

- 给已有类补一个顺手的方法
- 不想继承
- 也不想再新建一个 `xxxUtils`

扩展函数本质上更像：

> “给这个类型增加一种调用姿势”

而不是“真的改了这个类的源码”。

### 设计权衡

优点：

- 调用自然
- 代码聚合度更好
- 少写工具类

限制：

- **静态分发**，不是多态重写
- 不适合承载复杂状态

## 委托属性（Delegated Property）

### 常见写法

```kotlin
class UserPreferences(context: Context) {
    private val sp = context.getSharedPreferences("user", Context.MODE_PRIVATE)

    var token: String by PreferenceDelegate(sp, "token", "")
}
```

### `by lazy`

```kotlin
val viewModel by lazy {
    UserViewModel(repository)
}
```

### 为什么委托有价值？

因为很多属性访问逻辑不是简单“取字段”：

- 首次访问才初始化
- 读写时要同步到 SP / MMKV
- 读写时要做校验、通知或缓存

委托把这些重复横切逻辑抽出去，业务属性本身就干净了。

## `data class`、密封类、枚举怎么选？

| 语法 | 适合场景 | 为什么 |
|-----|---------|-------|
| `data class` | UI 状态、DTO、VO | 重点是装数据 |
| `sealed class` / `sealed interface` | 状态机、结果类型、事件分支 | 分支可穷举，`when` 更安全 |
| `enum class` | 固定常量集合 | 简单稳定，但表达力不如密封类 |

### 推荐写法：结果状态用密封类

```kotlin
sealed interface UiResult {
    data object Loading : UiResult
    data class Success(val data: List<String>) : UiResult
    data class Error(val msg: String) : UiResult
}
```

为什么比 `Int code` 好？

- 分支更清晰
- `when` 可穷举
- 数据和状态绑定在一起

## Kotlin 进阶最优写法

### 1. 判空转换优先 `?.let {}`，不要先 `if (x != null)` 再重复写变量名

```kotlin
val displayName = user?.name?.let { it.trim() } ?: "游客"
```

### 2. 初始化对象优先 `apply`

```kotlin
val intent = Intent(context, DetailActivity::class.java).apply {
    putExtra("id", 1001L)
}
```

### 3. 附加日志优先 `also`，不要污染主逻辑返回值

```kotlin
val result = loadConfig().also { println("config = $it") }
```

### 4. 复杂 lambda 不要滥用 `it`

```kotlin
orders.groupBy { order -> order.userId }
```

### 5. 优先扩展函数，而不是无边界膨胀的 `Utils`

```kotlin
fun Context.showShortToast(msg: String) {
    Toast.makeText(this, msg, Toast.LENGTH_SHORT).show()
}
```

### 6. 状态分支优先密封类，而不是魔法字符串或状态码

```kotlin
when (result) {
    UiResult.Loading -> showLoading()
    is UiResult.Success -> showList(result.data)
    is UiResult.Error -> showError(result.msg)
}
```

## 实战踩坑

### 1. 作用域函数套太多，代码会更难读

```kotlin
// 不推荐：可读性很差
user?.let {
    it.profile?.also { profile ->
        profile.avatar?.let { avatar ->
            println(avatar)
        }
    }
}
```

建议：

- 两层以上嵌套就考虑拆局部变量
- 语义比“函数式味道”更重要

### 2. 扩展函数不要伪装成成员函数能力

扩展函数不能访问私有成员，也不是动态分发。别把它当“偷偷给类打补丁”。

### 3. `data class` 不是万能业务类

它很适合装数据，但如果类里有复杂生命周期、缓存、副作用，普通类通常更合适。

## 面试题

### 1. 什么是高阶函数？

**结论**：参数接收函数或返回函数的函数，就是高阶函数。

**原理**：它把“变化的动作”抽成参数，固定流程复用，提升表达力和抽象能力。

**例子**：`list.filter { it > 0 }` 里 `filter` 就是高阶函数。

### 2. 为什么 `apply` 用 `this`，`let` 用 `it`？

**结论**：因为两者目标不同，一个偏“配置对象自己”，一个偏“把对象当参数处理”。

**原理**：`apply` 需要频繁访问成员，所以 `this` 更自然，甚至可省略；`let` 主要做转换和判空处理，用 `it` 能强调“这是传入的值”。

**例子**：初始化 `Intent` 用 `apply` 很顺，判空后转字符串长度更适合 `let`。

### 3. `apply` 和 `also` 的区别是什么？

**结论**：都返回对象本身，但 `apply` 偏配置，`also` 偏附加动作。

**原理**：`apply` 用 `this`，适合连续设置成员；`also` 用 `it`，适合日志、校验、埋点等旁路动作。

**例子**：`Intent(...).apply { putExtra(...) }`；`user.also { log(it) }`。

### 4. 扩展函数的本质是什么？

**结论**：本质是静态函数，只是调用语法像成员函数。

**原理**：编译器会把接收者当成普通参数传入，不会真的往原类里塞方法，也没有动态分发。

**例子**：`"12345678901".hidePhone()` 本质上还是在调用一个普通静态函数。

### 5. 为什么密封类比状态码更适合表达 UI 状态？

**结论**：因为分支穷举、安全、可携带数据。

**原理**：密封类把状态集合封闭住，`when` 检查更完整，不容易漏分支。

**例子**：`Loading / Success / Error` 比 `0 / 1 / 2` 更直观，也不容易写错。
