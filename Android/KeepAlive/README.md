# App 保活（Keep Alive）

## 学习导航

> **定位**：App 保活是 Android 开发中的"灰色地带"，涉及进程管理、系统机制、厂商适配等多方面知识。学习保活技术的核心目的是**理解 Android 系统的进程管理机制**，而不是为了做"流氓软件"。

### 学习路线

```
理解进程优先级 → 了解系统限制演进 → 掌握合规方案 → 认识边界与取舍
```

### 三篇概览

| 篇章 | 核心内容 | 适合人群 |
|-----|---------|---------|
| **基础篇** | 进程优先级、LMK 机制、基础保活方案 | 所有开发者 |
| **进阶篇** | 各版本限制、厂商适配、合规方案实战 | 中高级开发者 |
| **源码篇** | AMS 进程管理、OOM_ADJ 算法、LMK 原理 | 对系统原理感兴趣的开发者 |

## 核心问题预览

### 基础篇核心问题

1. **Android 为什么要杀后台进程？** → LMK 机制、内存管理策略
2. **进程优先级是如何划分的？** → 五级进程优先级、oom_adj 值
3. **最简单的保活方案是什么？** → 前台服务

### 进阶篇核心问题

1. **为什么之前的保活方案都失效了？** → Android 各版本后台限制演进
2. **双进程守护还能用吗？** → 原理、现状、厂商封杀
3. **如何做到合规保活？** → WorkManager、FCM、厂商推送

### 源码篇核心问题

1. **系统是如何决定杀哪个进程的？** → OOM_ADJ 计算算法
2. **LMK 是如何工作的？** → Low Memory Killer 原理
3. **前台服务为什么能保活？** → 服务优先级提升原理

|-----|---------|------|

## 学习建议

### 正确的学习态度

1. **理解机制比记住方案更重要**：保活方案会过时，但系统机制的理解是长久的
2. **合规优先**：Google 和厂商不断加强后台限制，黑科技方案终将被封杀
3. **用户体验至上**：保活的目的是提供更好的服务，不是为了"活着"

### 不应该做的事

- ❌ 用保活技术做"牛皮癣"软件
- ❌ 绕过系统限制强行存活
- ❌ 消耗用户电量和流量
- ❌ 在不需要后台能力的 App 中强行保活

### 应该做的事

- ✅ 理解系统为什么要限制后台
- ✅ 在需要后台能力时选择合规方案
- ✅ 尊重用户选择，提供关闭选项
- ✅ 优化后台任务，减少资源消耗

## 技术演进时间线

```
Android 4.x  ：保活黄金时代，各种黑科技横行
Android 5.0  ：JobScheduler 出现，鼓励统一调度
Android 6.0  ：Doze 模式登场，深度休眠限制后台
Android 7.0  ：Doze 增强，移动时也进入省电
Android 8.0  ：后台服务限制，5秒必须转前台
Android 9.0  ：省电桶（App Standby Buckets）
Android 10   ：后台定位限制
Android 11   ：前台服务类型强制声明
Android 12   ：前台服务启动限制（不能从后台启动）
Android 13   ：通知权限需动态申请
Android 14   ：前台服务类型细化，强化限制
Android 15   ：进一步限制前台服务的滥用
```
