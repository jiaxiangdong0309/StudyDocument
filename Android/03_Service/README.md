# Service 学习指南

## 概述

Service 是 Android 四大组件之一，专门用于在**后台执行长时间运行的操作**。与 Activity 不同，Service 没有用户界面，即使用户切换到其他应用，Service 也可以继续运行。

> **一句话理解**：Service 就像一个**幕后工作者**🔧，Activity 是站在台前表演的演员，而 Service 是在后台默默搬道具、调灯光的工作人员——用户看不见它，但没有它整个演出就跑不起来。

## 为什么要深入理解 Service？

| 场景 | 不理解 Service | 深入理解 Service |
|-----|----------------|------------------|
| 音乐播放 | 切换应用音乐就停，用户骂娘 | 后台播放丝滑，体验一流 |
| 文件下载 | 退出 App 下载中断，重来一遍 | 后台稳定下载，断点续传 |
| 消息推送 | 收不到消息，用户流失 | 及时推送，用户粘性高 |
| 数据同步 | 耗时操作卡住界面，ANR 频发 | 后台静默同步，界面流畅 |
| 进程保活 | App 被杀就死透，无法唤醒 | 合理保活，关键功能不中断 |

4. 如何实现进程保活？有哪些常见策略？

## Service 与其他组件的关系

| 技术 | 关系 | 说明 |
|-----|------|------|
| Activity | 协作组件 | Activity 负责界面，Service 负责后台任务 |
| BroadcastReceiver | 触发器 | 可通过广播启动 Service |
| ContentProvider | 数据源 | Service 可操作 ContentProvider 进行数据同步 |
| WorkManager | 替代方案 | 现代化的后台任务调度，推荐优先使用 |
| Coroutine | 协作工具 | 在 Service 中使用协程处理异步任务 |
| Binder/AIDL | 通信机制 | Service 跨进程通信的底层实现 |

## 技术演进时间线

```
Android 版本演进对 Service 的影响：

Android 1.0  ─── Service 诞生，后台任务的标准方案
     │
Android 3.0  ─── IntentService 引入，简化异步任务
     │
Android 5.0  ─── JobScheduler 引入，系统级任务调度
     │
Android 8.0  ─── ⚠️ 重大变化：后台执行限制，必须用前台服务
     │
Android 9.0  ─── 前台服务需要 FOREGROUND_SERVICE 权限
     │
Android 10   ─── 后台位置访问限制
     │
Android 11   ─── 前台服务类型细分（camera、microphone 等）
     │
Android 12   ─── 前台服务启动限制更严格
     │
Android 14   ─── 前台服务类型必须明确声明
     │
现在        ─── 推荐 WorkManager，Service 仅用于特定场景
```
