# WebView 基础篇

> 目标：理解 WebView 的核心概念，能独立完成一个功能完整、配置正确的内嵌 H5 页面。

---

## 一、技术演进：WebView 为什么会出现？

早期 App 更新需要重新发版，用户下载新包才能看到新内容。在「活动页」「营销页」「公告」这类高频变更场景里极其笨重。

| 方案 | 优点 | 缺点 |
|------|------|------|
| **原生 Native** | 性能好、体验顺滑 | 改一行字也要发版 |
| **内嵌 H5（WebView）** | 动态更新、开发快 | 首屏慢、白屏、交互受限 |

WebView 本质是把一个**浏览器内核**嵌入到 Android App 里。Android 4.4 之前用 WebKit，4.4 之后换成 **Chromium**（和 Chrome 浏览器同款内核），Android 5.0 开始 WebView 作为独立 APK 可通过 Google Play 单独升级。

---

## 二、核心概念：三大组件分工

用「餐厅」来类比：

- **WebView**：整个餐厅，负责承载一切
- **WebViewClient**：服务员，处理「页面加载」相关的事（跳转、加载完成、加载失败）
- **WebChromeClient**：厨房主管，处理「浏览器特性」相关的事（JS 弹窗、进度条、文件上传）

| 回调 | 属于谁 | 触发时机 |
|------|--------|----------|
| `onPageStarted` | WebViewClient | 页面开始加载 |
| `onPageFinished` | WebViewClient | 页面加载完成 |
| `shouldOverrideUrlLoading` | WebViewClient | 页面跳转前拦截 |
| `shouldInterceptRequest` | WebViewClient | 每个资源请求拦截（含 JS/CSS/图片）|
| `onReceivedError` | WebViewClient | 加载出错 |
| `onReceivedHttpError` | WebViewClient | HTTP 错误（4xx/5xx）|
| `onProgressChanged` | WebChromeClient | 加载进度变化 |
| `onReceivedTitle` | WebChromeClient | 页面标题变化 |
| `onJsAlert/Confirm/Prompt` | WebChromeClient | JS 弹窗 |
| `onShowFileChooser` | WebChromeClient | 文件选择（上传）|

## 三、标准初始化配置

### 3.1 布局

```xml
<!-- res/layout/activity_webview.xml -->
<WebView
    android:id="@+id/webView"
    android:layout_width="match_parent"
    android:layout_height="match_parent" />
```

### 3.2 Activity 完整示例

```kotlin
class WebViewActivity : AppCompatActivity() {

    // 持有 WebView 引用，不要在 XML 中写死，方便后续手动销毁
    private var webView: WebView? = null

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        setContentView(R.layout.activity_webview)

        webView = findViewById<WebView>(R.id.webView).apply {
            setupSettings(this)
            webViewClient = buildWebViewClient()
            webChromeClient = buildWebChromeClient()
            loadUrl("https://example.com")
        }
    }

    private fun setupSettings(webView: WebView) {
        webView.settings.apply {
            javaScriptEnabled = true          // 开启 JS（必须，否则 H5 无法正常运行）
            domStorageEnabled = true          // 开启 DOM Storage（localStorage 依赖此项）
            useWideViewPort = true            // 让页面按 viewport meta 设置宽度
            loadWithOverviewMode = true       // 缩放到屏幕宽度
            mixedContentMode =
                WebSettings.MIXED_CONTENT_ALWAYS_ALLOW  // 允许 https 页面加载 http 资源（按需开启）
            cacheMode = WebSettings.LOAD_DEFAULT        // 优先使用缓存
            databaseEnabled = true
            setSupportZoom(false)             // 禁止双指缩放，保持 App 内体验一致
            builtInZoomControls = false
        }
    }

    private fun buildWebViewClient() = object : WebViewClient() {

        override fun shouldOverrideUrlLoading(
            view: WebView,
            request: WebResourceRequest
        ): Boolean {
            val url = request.url.toString()
            // 拦截自定义 scheme（如 myapp://），交给原生处理
            if (url.startsWith("myapp://")) {
                handleNativeScheme(url)
                return true  // true = 我处理，WebView 不再加载
            }
            return false  // false = 交给 WebView 正常加载
        }

        override fun onReceivedError(
            view: WebView,
            request: WebResourceRequest,
            error: WebResourceError
        ) {
            // 只处理主框架错误，避免图片等子资源错误误触发错误页
            if (request.isForMainFrame) {
                showErrorPage()
            }
        }
    }

    private fun buildWebChromeClient() = object : WebChromeClient() {

        override fun onProgressChanged(view: WebView, newProgress: Int) {
            // 更新进度条，100 时隐藏
            progressBar.isVisible = newProgress < 100
            progressBar.progress = newProgress
        }

        override fun onJsAlert(
            view: WebView, url: String, message: String, result: JsResult
        ): Boolean {
            // 拦截 JS alert，用原生 Dialog 替代，避免浏览器默认弹窗样式不统一
            AlertDialog.Builder(this@WebViewActivity)
                .setMessage(message)
                .setPositiveButton("确定") { _, _ -> result.confirm() }
                .setCancelable(false)
                .show()
            return true  // true = 我处理了，不再走系统默认行为
        }
    }

    override fun onBackPressed() {
        // 优先让 WebView 返回上一页，而不是直接关闭 Activity
        if (webView?.canGoBack() == true) {
            webView?.goBack()
        } else {
            super.onBackPressed()
        }
    }

    override fun onDestroy() {
        // 必须手动销毁，防止内存泄漏（见常见坑章节）
        webView?.apply {
            stopLoading()
            settings.javaScriptEnabled = false
            clearHistory()
            removeAllViews()
            destroy()
        }
        webView = null
        super.onDestroy()
    }

    private fun showErrorPage() { /* 展示错误占位图 */ }
    private fun handleNativeScheme(url: String) { /* 解析自定义 scheme 并执行原生操作 */ }
}
```

## 四、页面加载方式

```kotlin
// 加载远程 URL
webView.loadUrl("https://example.com")

// 加载本地 assets 文件（离线页面）
webView.loadUrl("file:///android_asset/index.html")

// 加载 HTML 字符串（动态生成内容）
webView.loadData(
    "<h1>Hello</h1>",
    "text/html",
    "UTF-8"
)

// 加载带 base URL 的 HTML 字符串（需要相对路径资源时用这个）
webView.loadDataWithBaseURL(
    "file:///android_asset/",  // baseUrl，相对路径基准
    htmlContent,
    "text/html",
    "UTF-8",
    null
)
```

> **loadData vs loadDataWithBaseURL**：如果 HTML 里有相对路径引用（`./style.css`），必须用 `loadDataWithBaseURL`，否则资源加载会失败。

## 五、安全配置：必须重视

### 5.1 addJavascriptInterface 的风险

```kotlin
// ❌ 危险写法：API 17 以下，所有方法均可被 JS 调用，包括反射执行任意代码
webView.addJavascriptInterface(MyBridge(), "Android")

class MyBridge {
    fun doSomething() { ... }  // JS 可直接调用任意方法，包括通过反射拿到 Runtime 执行 shell
}

// ✅ 安全写法：所有暴露给 JS 的方法必须加 @JavascriptInterface 注解（API 17+）
class MyBridge {
    @JavascriptInterface  // 只有加了这个注解的方法才能被 JS 调用
    fun showToast(msg: String) {
        Toast.makeText(context, msg, Toast.LENGTH_SHORT).show()
    }
}
```

**@JavascriptInterface 注解的意义**：API 17 之后，WebView 只允许被 `@JavascriptInterface` 标注的方法被 JS 调用，其他方法对 JS 不可见，杜绝了反射攻击路径。

### 5.2 禁止加载本地文件（防止 file 域攻击）

```kotlin
webView.settings.apply {
    // 禁止 file:// 协议的页面访问其他 file:// 文件，防止 H5 读取本地敏感文件
    allowFileAccessFromFileURLs = false
    allowUniversalAccessFromFileURLs = false

    // 如果不需要加载本地文件，直接禁用
    allowFileAccess = false
}
```

### 5.3 校验来源，防止恶意页面调用 Bridge

```kotlin
class MyBridge(private val allowedHosts: Set<String>) {

    @JavascriptInterface
    fun getUserToken(): String {
        // 在 Bridge 内部校验当前 URL，拒绝非白名单域名的调用
        val currentUrl = webView.url ?: return ""
        val host = Uri.parse(currentUrl).host ?: return ""
        if (host !in allowedHosts) {
            return ""  // 拒绝非授权域名
        }
        return getToken()
    }
}
```

## 六、常见坑

### 坑 1：内存泄漏（最常见）

**现象**：退出包含 WebView 的页面后，内存没有释放，Activity 泄漏。

**原因**：WebView 内部持有 Activity 的 Context，如果 WebView 没有正确销毁，GC 无法回收 Activity。

```kotlin
// ❌ 错误：在 XML 中直接引用，且 onDestroy 没有手动销毁
// Activity 退出后，WebView 内部 native 层还持有引用

// ✅ 正确做法：动态创建 + 使用 ApplicationContext + onDestroy 手动销毁
class WebViewActivity : AppCompatActivity() {

    private var webView: WebView? = null

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        // 用 ApplicationContext 避免 WebView 持有 Activity 引用
        webView = WebView(applicationContext).also {
            setContentView(it)
        }
    }

    override fun onDestroy() {
        webView?.apply {
            parent?.let { (it as ViewGroup).removeView(this) }  // 先从父 View 移除
            stopLoading()
            clearHistory()
            removeAllViews()
            destroy()  // 释放 native 资源
        }
        webView = null
        super.onDestroy()
    }
}
```

### 坑 2：shouldOverrideUrlLoading 在 POST 请求时不触发

**现象**：H5 通过 form POST 跳转，`shouldOverrideUrlLoading` 没有回调。

**原因**：该回调只针对 GET 请求（URL 跳转），POST 请求不会触发。

**解法**：如果需要拦截 POST，改用 `shouldInterceptRequest`，在里面拦截特定 URL + 检查 method。

### 坑 3：Android 9 禁止 HTTP 明文流量

**现象**：Android 9（API 28）以上，加载 `http://` 的页面或资源失败。

**解法**：
```xml
<!-- AndroidManifest.xml -->
<application
    android:usesCleartextTraffic="true" ...
    android:networkSecurityConfig="@xml/network_security_config">
```

```xml
<!-- res/xml/network_security_config.xml -->
<network-security-config>
    <domain-config cleartextTrafficPermitted="true">
        <domain includeSubdomains="true">example.com</domain>
    </domain-config>
</network-security-config>
```

### 坑 4：`onPageFinished` 不等于页面渲染完成

**现象**：`onPageFinished` 回调了，但页面还是白屏或内容不全。

**原因**：`onPageFinished` 只代表主文档 HTML 加载完毕，JS 还没执行完，图片可能还在加载。

**解法**：让 H5 在 JS 逻辑执行完毕后通过 JS Bridge 主动通知 Native，而不是依赖 `onPageFinished`。

### 坑 5：多进程 WebView 崩溃后白屏

**现象**：Android 8.0+ 的 WebView 运行在独立进程，该进程崩溃后 WebView 显示白屏，App 无感知。

**解法**：
```kotlin
// 在 WebViewClient 里捕获渲染进程崩溃（API 26+）
override fun onRenderProcessGone(view: WebView, detail: RenderProcessGoneDetail): Boolean {
    if (!detail.didCrash()) return false  // 系统主动回收，忽略
    webView?.destroy()
    webView = null
    recreateWebView()  // 重新创建 WebView 并加载页面
    return true  // true = 我处理了，App 不会跟着崩
}
```

## 七、面试检验

**Q1：WebViewClient 和 WebChromeClient 各负责什么？**

> **结论**：WebViewClient 管「加载过程」，WebChromeClient 管「浏览器特性」。
> **原理**：WebViewClient 的回调都是页面加载生命周期（开始/完成/错误/拦截），WebChromeClient 的回调都是 Web 标准 API 的原生实现（alert/confirm/进度/文件选择）。

**Q2：为什么 WebView 容易导致内存泄漏？如何避免？**

> **结论**：WebView 内部 native 层持有 Context 引用，Activity 销毁时若未手动 destroy，native 层不释放导致 Activity 泄漏。
> **解法**：① 动态创建时传入 ApplicationContext；② onDestroy 中先 removeView 再 destroy；③ 使用独立进程（进程退出后内存自然释放）。

**Q3：shouldOverrideUrlLoading 返回 true 和 false 分别意味着什么？**

> **true** = 应用自己处理这次跳转，WebView 不加载；**false** = 让 WebView 正常加载这个 URL。

**Q4：Android 9 以上 WebView 加载 HTTP 资源失败怎么解决？**

> Android 9（API 28）默认禁止明文流量。解法：配置 `android:networkSecurityConfig`，针对特定域名开启 `cleartextTrafficPermitted="true"`。

**Q5：`addJavascriptInterface` 有什么安全风险？**

> API 17 以下，所有方法均可被 JS 通过反射调用，包括 `Runtime.exec()` 执行任意 shell 命令。API 17+ 必须用 `@JavascriptInterface` 注解标注才可被 JS 调用，其余方法对 JS 不可见。
