# Binder 机制

## 技术定位

Binder 是 Android 系统的**进程间通信（IPC）核心机制**，是理解 Android 系统架构的关键。

**一句话理解**：Binder 就像一个"跨公司的快递系统"——两家公司（进程）之间不能直接走动，但可以通过快递（Binder）互相寄东西、传话，甚至远程指挥对方干活。

## 核心问题预览

### 基础篇

1. **为什么 Android 要设计 Binder？** 传统 IPC 方式有什么问题？
2. **Binder 通信涉及哪几个角色？** 它们各自的职责是什么？
3. **什么是 AIDL？** 它和 Binder 是什么关系？
4. **为什么说 Binder 只需要一次数据拷贝？**

### 进阶篇

5. **Binder 的线程模型是怎样的？** 服务端是多线程还是单线程？
6. **Binder 传输数据有大小限制吗？** 为什么？
7. **如何实现双向通信？** 服务端如何回调客户端？
8. **Binder 死亡通知是什么？** 怎么使用？

### 源码篇

9. **mmap 在 Binder 中起什么作用？**
10. **ServiceManager 是如何注册和查找服务的？**
11. **Binder 的引用计数是怎么管理的？**
12. **Binder 的设计有哪些可借鉴之处？**
