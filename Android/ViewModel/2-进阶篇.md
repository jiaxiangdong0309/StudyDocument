# ViewModel 进阶篇

## 高级特性

### 1. SavedStateHandle：进程恢复的救星

**问题场景**：ViewModel 只能在配置变更时保留数据，但如果 App 在后台被系统杀死，ViewModel 也会随之消失。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                     进程被杀死的场景                                         │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  1. 用户填写表单 → 2. 切到后台 → 3. 系统内存不足，杀死 App                    │
│                                  → 4. 用户返回 App → 数据全没了！❌           │
│                                                                             │
│  配置变更：ViewModel ✅ 存活                                                 │
│  进程被杀：ViewModel ❌ 死亡                                                 │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

**SavedStateHandle 来救场**：

```kotlin
class FormViewModel(
    private val savedStateHandle: SavedStateHandle
) : ViewModel() {
    
    // 方式一：获取 LiveData，自动保存和恢复
    val userName: LiveData<String> = savedStateHandle.getLiveData("userName", "")
    val email: LiveData<String> = savedStateHandle.getLiveData("email", "")
    
    // 方式二：直接读写
    var searchQuery: String
        get() = savedStateHandle["query"] ?: ""
        set(value) { savedStateHandle["query"] = value }
    
    // 方式三：使用 StateFlow（Kotlin 协程）
    val userNameFlow: StateFlow<String> = savedStateHandle.getStateFlow("userName", "")
    
    fun updateUserName(name: String) {
        savedStateHandle["userName"] = name
    }
}

// 使用时无需自定义 Factory，系统自动注入
class FormActivity : AppCompatActivity() {
    private val viewModel: FormViewModel by viewModels()
}
```

**SavedStateHandle vs onSaveInstanceState**：

| 特性 | SavedStateHandle | onSaveInstanceState |
|-----|-----------------|---------------------|
| 位置 | ViewModel 内部 | Activity/Fragment |
| 数据类型 | 支持 LiveData/StateFlow | 只能存 Bundle |
| 使用体验 | 更方便，与 ViewModel 配合好 | 需要手动处理 |
| 大小限制 | 同样有限制（<1MB） | 同样有限制 |

**大白话**：SavedStateHandle 就是把 `onSaveInstanceState` 的能力搬到了 ViewModel 里，用起来更顺手。

### 2. viewModelScope：协程的最佳拍档

```kotlin
class NetworkViewModel : ViewModel() {
    
    private val _users = MutableLiveData<List<User>>()
    val users: LiveData<List<User>> = _users
    
    fun loadUsers() {
        // viewModelScope 的好处：
        // 1. 自动绑定 ViewModel 生命周期
        // 2. ViewModel 销毁时自动取消协程
        // 3. 默认在主线程启动
        viewModelScope.launch {
            try {
                // 切到 IO 线程做网络请求
                val result = withContext(Dispatchers.IO) {
                    repository.fetchUsers()
                }
                _users.value = result
            } catch (e: Exception) {
                // 处理异常
            }
        }
    }
    
    // 不需要手动取消！onCleared() 时自动取消
}
```

**对比传统方式**：

```kotlin
// ❌ 传统方式：需要手动管理
class OldViewModel : ViewModel() {
    private val job = Job()
    private val scope = CoroutineScope(Dispatchers.Main + job)
    
    override fun onCleared() {
        super.onCleared()
        job.cancel()  // 容易忘记！
    }
}

// ✅ 使用 viewModelScope
class NewViewModel : ViewModel() {
    // 直接用，不用管生命周期
    fun doWork() = viewModelScope.launch { /* ... */ }
}
```

### 3. Fragment 之间共享数据

这是 ViewModel 最常用的高级特性之一：

```kotlin
// 共享的 ViewModel
class CartViewModel : ViewModel() {
    
    private val _cartItems = MutableLiveData<List<CartItem>>(emptyList())
    val cartItems: LiveData<List<CartItem>> = _cartItems
    
    val totalPrice: LiveData<Double> = cartItems.map { items ->
        items.sumOf { it.price * it.quantity }
    }
    
    fun addItem(item: CartItem) {
        val current = _cartItems.value.orEmpty().toMutableList()
        current.add(item)
        _cartItems.value = current
    }
    
    fun removeItem(itemId: String) {
        _cartItems.value = _cartItems.value.orEmpty().filter { it.id != itemId }
    }
}

// 商品列表 Fragment
class ProductListFragment : Fragment() {
    
    // 使用 activityViewModels 获取共享的 ViewModel
    private val cartViewModel: CartViewModel by activityViewModels()
    
    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)
        
        binding.btnAddToCart.setOnClickListener {
            val item = CartItem(id = "1", name = "商品", price = 99.0, quantity = 1)
            cartViewModel.addItem(item)
        }
    }
}

// 购物车 Fragment
class CartFragment : Fragment() {
    
    // 同样使用 activityViewModels，拿到的是同一个实例
    private val cartViewModel: CartViewModel by activityViewModels()
    
    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)
        
        cartViewModel.cartItems.observe(viewLifecycleOwner) { items ->
            adapter.submitList(items)
        }
        
        cartViewModel.totalPrice.observe(viewLifecycleOwner) { total ->
            binding.textTotal.text = "总计：¥$total"
        }
    }
}
```

### 4. Navigation 作用域的 ViewModel

当使用 Navigation 组件时，可以在导航图级别共享 ViewModel：

```kotlin
class CheckoutFragment : Fragment() {
    
    // 在整个结账流程（nav_checkout）内共享
    private val checkoutViewModel: CheckoutViewModel by navGraphViewModels(R.id.nav_checkout)
    
    // 只在当前 Fragment 使用
    private val localViewModel: LocalViewModel by viewModels()
}
```

```xml
<!-- nav_graph.xml -->
<navigation xmlns:android="http://schemas.android.com/apk/res/android"
    android:id="@+id/nav_checkout">
    
    <fragment android:id="@+id/addressFragment" />
    <fragment android:id="@+id/paymentFragment" />
    <fragment android:id="@+id/confirmFragment" />
    
</navigation>
```

**适用场景**：多步骤流程（如结账、注册向导），流程内的 Fragment 需要共享数据。

## 实战经验

### 1. 状态管理最佳实践

**推荐：使用密封类管理 UI 状态**

```kotlin
// 定义 UI 状态
sealed class UiState<out T> {
    object Loading : UiState<Nothing>()
    data class Success<T>(val data: T) : UiState<T>()
    data class Error(val message: String, val retry: (() -> Unit)? = null) : UiState<Nothing>()
}

// 在 ViewModel 中使用
class UserViewModel(
    private val repository: UserRepository
) : ViewModel() {
    
    private val _state = MutableStateFlow<UiState<User>>(UiState.Loading)
    val state: StateFlow<UiState<User>> = _state.asStateFlow()
    
    fun loadUser(id: String) {
        viewModelScope.launch {
            _state.value = UiState.Loading
            
            repository.getUser(id)
                .onSuccess { user -> 
                    _state.value = UiState.Success(user) 
                }
                .onFailure { e -> 
                    _state.value = UiState.Error(
                        message = e.message ?: "未知错误",
                        retry = { loadUser(id) }  // 提供重试功能
                    )
                }
        }
    }
}

// 在 UI 层使用
class UserFragment : Fragment() {
    
    private val viewModel: UserViewModel by viewModels()
    
    override fun onViewCreated(view: View, savedInstanceState: Bundle?) {
        super.onViewCreated(view, savedInstanceState)
        
        viewLifecycleOwner.lifecycleScope.launch {
            viewModel.state.collect { state ->
                when (state) {
                    is UiState.Loading -> {
                        binding.progressBar.isVisible = true
                        binding.content.isVisible = false
                        binding.errorView.isVisible = false
                    }
                    is UiState.Success -> {
                        binding.progressBar.isVisible = false
                        binding.content.isVisible = true
                        binding.errorView.isVisible = false
                        showUser(state.data)
                    }
                    is UiState.Error -> {
                        binding.progressBar.isVisible = false
                        binding.content.isVisible = false
                        binding.errorView.isVisible = true
                        binding.textError.text = state.message
                        binding.btnRetry.setOnClickListener { state.retry?.invoke() }
                    }
                }
            }
        }
    }
}
```

### 2. 单次事件处理（导航、Toast 等）

**问题**：LiveData 在配置变更后会重新发送最后一个值，导致 Toast 重复弹出、重复导航。

```kotlin
// ❌ 问题代码
class BadViewModel : ViewModel() {
    private val _showToast = MutableLiveData<String>()
    val showToast: LiveData<String> = _showToast
    
    fun doSomething() {
        _showToast.value = "操作成功"
        // 屏幕旋转后，又会弹出一次！
    }
}
```

**解决方案一：使用 Channel + Flow**

```kotlin
class GoodViewModel : ViewModel() {
    
    // 使用 Channel 发送单次事件
    private val _events = Channel<UiEvent>(Channel.BUFFERED)
    val events = _events.receiveAsFlow()
    
    sealed class UiEvent {
        data class ShowToast(val message: String) : UiEvent()
        data class Navigate(val destination: String) : UiEvent()
    }
    
    fun doSomething() {
        viewModelScope.launch {
            // Channel 发送的事件只会被消费一次
            _events.send(UiEvent.ShowToast("操作成功"))
        }
    }
}

// 在 Fragment 中观察
viewLifecycleOwner.lifecycleScope.launch {
    viewModel.events.collect { event ->
        when (event) {
            is UiEvent.ShowToast -> Toast.makeText(context, event.message, Toast.LENGTH_SHORT).show()
            is UiEvent.Navigate -> findNavController().navigate(event.destination)
        }
    }
}
```

**解决方案二：使用 Event 包装类**

```kotlin
// Event 包装类，确保只消费一次
open class Event<out T>(private val content: T) {
    
    private var hasBeenHandled = false
    
    fun getContentIfNotHandled(): T? {
        return if (hasBeenHandled) {
            null
        } else {
            hasBeenHandled = true
            content
        }
    }
    
    fun peekContent(): T = content
}

// 使用
class EventViewModel : ViewModel() {
    
    private val _toastEvent = MutableLiveData<Event<String>>()
    val toastEvent: LiveData<Event<String>> = _toastEvent
    
    fun showToast(message: String) {
        _toastEvent.value = Event(message)
    }
}

// 观察
viewModel.toastEvent.observe(viewLifecycleOwner) { event ->
    event.getContentIfNotHandled()?.let { message ->
        Toast.makeText(context, message, Toast.LENGTH_SHORT).show()
    }
}
```

## 横向对比

### ViewModel vs MVP 的 Presenter

| 特性 | ViewModel | Presenter |
|-----|-----------|-----------|
| 生命周期感知 | ✅ 自动处理 | ❌ 需要手动管理 |
| 配置变更存活 | ✅ 自动存活 | ❌ 随 View 销毁 |
| View 引用 | ❌ 不持有 | ✅ 持有（需要处理泄漏） |
| 测试难度 | 简单，无 View 依赖 | 需要 Mock View |
| Google 官方支持 | ✅ Jetpack 组件 | ❌ 第三方模式 |

### ViewModel vs Compose 的 State

```kotlin
// ViewModel 方式（适用于 View 系统和 Compose）
class CounterViewModel : ViewModel() {
    private val _count = MutableStateFlow(0)
    val count: StateFlow<Int> = _count.asStateFlow()
    
    fun increment() { _count.value++ }
}

// Compose 纯 State 方式（仅限简单场景）
@Composable
fun Counter() {
    var count by remember { mutableStateOf(0) }
    Button(onClick = { count++ }) {
        Text("Count: $count")
    }
}
```

| 特性 | ViewModel + StateFlow | Compose State |
|-----|----------------------|---------------|
| 配置变更存活 | ✅ | ❌（需要 rememberSaveable） |
| 进程恢复 | ✅ SavedStateHandle | ✅ rememberSaveable |
| 复杂业务逻辑 | ✅ 适合 | ❌ 会让 Composable 臃肿 |
| 简单 UI 状态 | 可以但没必要 | ✅ 更简洁 |

**大白话**：简单的 UI 状态用 Compose State，复杂的业务逻辑还是用 ViewModel。

## 边界认知

### ViewModel 不适合的场景

1. **跨 Activity 共享数据**
   - ViewModel 作用域是单个 Activity
   - 解决方案：使用 Repository、DataStore、数据库等

2. **持久化数据**
   - ViewModel 在进程被杀死后也会丢失（SavedStateHandle 有大小限制）
   - 解决方案：Room、DataStore、SharedPreferences

3. **后台任务**
   - ViewModel 在 Activity 销毁后也会销毁
   - 解决方案：WorkManager、Service

4. **大量数据缓存**
   - ViewModel 存在内存中，大量数据会 OOM
   - 解决方案：磁盘缓存、数据库

### 常见误区

```kotlin
// ❌ 误区1：在 ViewModel 中保存大量数据
class BadViewModel : ViewModel() {
    // 10000 张高清图片的 Bitmap 列表？内存爆炸！
    val images = mutableListOf<Bitmap>()
}

// ❌ 误区2：把 ViewModel 当成万能胶水
class GodViewModel : ViewModel() {
    // 用户、订单、商品、设置... 全塞进来？
    // 应该拆分成多个 ViewModel
}

// ❌ 误区3：在 ViewModel 中做 UI 操作
class UiViewModel : ViewModel() {
    fun showDialog(context: Context) {
        // 不要这样！ViewModel 不应该知道 UI 细节
        AlertDialog.Builder(context).show()
    }
}
```

## 性能优化

### 1. 避免重复创建 ViewModel

```kotlin
// ❌ 每次都创建新的 ViewModelProvider
fun getViewModel(): MyViewModel {
    return ViewModelProvider(this).get(MyViewModel::class.java)
}

// ✅ 使用 by viewModels() 委托，自动缓存
private val viewModel: MyViewModel by viewModels()
```

### 2. 合理拆分 ViewModel

```kotlin
// ❌ 一个巨大的 ViewModel
class GodViewModel : ViewModel() {
    // 用户相关
    val user = MutableLiveData<User>()
    fun loadUser() { /* ... */ }
    
    // 订单相关
    val orders = MutableLiveData<List<Order>>()
    fun loadOrders() { /* ... */ }
    
    // 商品相关
    val products = MutableLiveData<List<Product>>()
    fun loadProducts() { /* ... */ }
    
    // 越来越多...
}

// ✅ 按职责拆分
class UserViewModel : ViewModel() { /* 用户相关 */ }
class OrderViewModel : ViewModel() { /* 订单相关 */ }
class ProductViewModel : ViewModel() { /* 商品相关 */ }

// 在 Fragment 中按需使用
class ProfileFragment : Fragment() {
    private val userViewModel: UserViewModel by viewModels()
    private val orderViewModel: OrderViewModel by viewModels()

```

### 3. 及时清理资源

```kotlin
class ResourceViewModel : ViewModel() {
    
    private var webSocket: WebSocket? = null
    private var locationListener: LocationListener? = null
    
    fun connect() {
        webSocket = createWebSocket()
    }
    
    override fun onCleared() {
        super.onCleared()
        // 清理资源！
        webSocket?.close(1000, "ViewModel cleared")
        webSocket = null
        
        locationManager.removeUpdates(locationListener)
        locationListener = null
    }
}
```

## 面试检验

### 进阶问题

**Q1：SavedStateHandle 和 onSaveInstanceState 有什么区别？什么时候用哪个？**

> **答案**：两者底层机制相同，都是利用系统的状态保存机制，都有大小限制（约 1MB）。区别在于：
> - SavedStateHandle 在 ViewModel 内部使用，与 ViewModel 的数据管理方式一致，支持 LiveData/StateFlow
> - onSaveInstanceState 在 Activity/Fragment 中使用，需要手动处理 Bundle
> 
> **推荐**：业务数据用 SavedStateHandle，纯 UI 状态（如滚动位置、Tab 索引）可以用 onSaveInstanceState。

**Q2：如何在 ViewModel 中处理单次事件（如 Toast、导航）？**

> **答案**：LiveData 在配置变更后会重新发送最后一个值，不适合单次事件。有两种常用方案：
> 1. **Channel + Flow**：事件只会被消费一次，是推荐方案
> 2. **Event 包装类**：用标志位标记是否已处理
> 
> 核心原则是确保事件只被消费一次，避免重复弹窗或重复导航。

**Q3：viewModelScope 和普通 CoroutineScope 有什么区别？**

> **答案**：
> - `viewModelScope` 是 ViewModel 自带的协程作用域，生命周期与 ViewModel 绑定
> - 当 `onCleared()` 调用时，viewModelScope 中的所有协程会**自动取消**
> - 普通 CoroutineScope 需要手动管理生命周期，容易忘记取消导致泄漏
> 
> 在 ViewModel 中**强烈推荐**使用 viewModelScope。

**Q4：Fragment 之间如何通过 ViewModel 共享数据？原理是什么？**

> **答案**：使用 `by activityViewModels()` 获取共享的 ViewModel。原理是两个 Fragment 都使用 Activity 的 ViewModelStore 来获取 ViewModel，由于 ViewModelStore 是同一个，所以获取到的 ViewModel 实例也是同一个。
> 
> 还可以使用 `navGraphViewModels()` 在导航图范围内共享，适用于多步骤流程。

**Q5：ViewModel 适合存储什么数据？不适合存储什么数据？**

> **答案**：
> - **适合**：UI 状态、用户输入的临时数据、从网络/数据库加载的数据缓存
> - **不适合**：
>   - 大量数据（如大量图片 Bitmap）→ 内存问题
>   - 需要持久化的数据 → 用数据库/DataStore
>   - 跨 Activity 共享的数据 → 用 Repository 模式
>   - 后台长时间运行的任务 → 用 WorkManager

**Q6：为什么要用 StateFlow 而不是 LiveData？**

> **答案**：
> - StateFlow 是 Kotlin 协程的一部分，与协程配合更好
> - StateFlow 支持 Flow 操作符（map、filter、combine 等）
> - StateFlow 在 Compose 中支持更好
> - LiveData 的生命周期感知在某些场景下更方便
> 
> **实际选择**：新项目推荐 StateFlow，老项目 LiveData 也没问题。两者可以混用。
